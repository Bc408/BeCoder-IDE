# Beacon 技术研究与后续验证

更新：2026-10-23。本文是工程研究入口；产品规则见[PRD](prd.md)、[架构](architecture.md)与[Notebook 设计](notebook.md)，当前覆盖见[实现状态](implementation-status.md)。研究建议不等于实施授权，源码存在入口不等于真实旅程通过。

## 已落地的工程方向

原先上下文工具、证据链、工程蓝图和 Notebook 技术候选已由当前代码覆盖，其重复文档不再作为任务入口。继续维护时从实际所有者和接口出发：

| 所有者 | 当前入口与维护边界 |
| --- | --- |
| 原生工作区协调 | `src/vs/platform/beacon/`：根有效性、存储、共享队列、单会话租约与 revision；不锁整个工作区代替对话占用 |
| 窗口和页面 | `src/vs/workbench/contrib/becoder/electron-browser/beaconPages.ts`：只取调用窗口实际打开的内存模型/已加载页面，异步复核页面身份与版本，不 resolve backing file |
| Runner/CPH 事实 | `extensions/danielpinto8zz6.c-cpp-compile-run/src/`、`extensions/becoder.cph/src/`：执行者采集真正编译的主代码、输入、实际结果和覆盖；不能由聊天事后补造 |
| Notebook 文档 | `extensions/becoder.notebook/`：serializer、用户 input 运行、原生编辑/保存、图片和输出；关联按编辑器根，行为证据按笔记实际 Beacon 归属 |
| 会话与模型 | `extensions/becoder.beacon/src/`：固定当前请求、按需工具、会话独立材料、协议调用/结果和人可理解的失败反馈 |

保持“用户行为提前形成事实 → 宿主说明情况/来源/入口 → 模型按需读取”。不要求先注入正文、固定摘要/详情两轮或堆叠更多审查模型。原始运行产物是可淘汰缓存；会话实际消费的独立材料、用户笔记和记忆才按重要资产保护。

主代码记录必须与实际编译输入绑定，不能凭前后 hash/mtime 相同宣称 GCC 读到同一份代码。维护镜像编译时同时检查原目录 cwd、头文件搜索、`__FILE__`、诊断路径、C/C++、字符集、debugger 和 PCH 语义。首版不保存本地头文件历史快照，不能宣称完整环境可重现。受控竞态验证使用明确屏障，不靠 sleep 猜时点。

页面版本、运行 revision、捕获时点、采集遗漏、返回截断和模型推断分别表达。PTY 合并流不伪装 stdout/stderr 分离，用户键入/终端回显不自动等于完整 stdin，程序退出不等于样例通过，CPH 通过不等于 OJ AC。

## 共用验证场景

1. 当次编译 V1 与当前未保存 V2 可同时解释，旧提交和真实本地结果不混用；无输出不诊断为已证实死循环。
2. 已选根但未聊天/未配置模型的用户运行也采集证据；根外/无根不错误落盘。Notebook 结果与独立证据、Runner/CPH 队列各自保留生命周期。
3. Blackout 可以读当前打开页，却不能回读其磁盘/隐藏记录；Spot 根外打开页不扩大文件读权；Flood 不绕过会话隔离。显式继承只复制已加载内容。
4. 根切换、失效恢复、主动切档、返回主页、迟到确认、显式空输入、关窗/reload/崩溃及双窗口占用，不串草稿或覆盖较新输入。
5. 材料读取固定版本，保存失败不返回假成功；队列淘汰不破坏已消费快照；返回截断和源采集不完整分别反馈。
6. Notebook 使用最新完整编辑稿备份，运行/改写互斥，其他窗口 dirty 冲突和取消如实反馈；失败不额外要求自建回滚或自动运行。
7. 四站页面与额外查询分别验证；登录壳、验证码、权限拒绝、分页、源码缺失、重判、单位和个人信息许可都不能靠模拟成功掩盖。
8. 连续压缩、分支重答、换服务、图片和超长输出后仍保留当前用户决定、工具调用/结果及真实验证状态；记忆不能把一次错误或 AC 固化成能力画像。
9. tips 用户修改/撤销被后续请求尊重；模型自写、status/dream 或外部材料不生成许可。此项检验 prompt 行为，不引入宿主许可门。
10. 用相同材料比较诊断、摘要、笔记独立复习价值和实际 token/耗时；源码/格式通过不证明教学效果。

## 证据纪律

文档检查仅验证结构、编码、链接和语义一致性；源码检查、生产 Webview、staged 应用、直接包/Setup、真实账号与负责人验收分别记录。历史研究的外部固定提交可用于理解机制，平台接口、软件版本和许可证需要实际选型时刷新，不把旧网页观察当作当前可用性保证。

测试先用脱敏/合成材料核对版本、协议、权限及保存边界，再按实际授权调用模型、账号或 GUI。已有授权内自主纠错；若证据暴露已确认体验无法保留、平台缺关键材料或费用带来实质取舍，再给具体事实和替代方向交负责人决定。
