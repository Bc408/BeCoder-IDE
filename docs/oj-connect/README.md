## 产品定位

OJ Connect 是随 BeCoder 分发的统一内置扩展，面向洛谷、AtCoder、Codeforces、牛客和蓝桥。以 vscode-luogu 的核心刷题体验为标杆，用户围绕当前 C/C++ 源码，通过快捷键看题、提交和查看本次评测结果。每个站点在扩展内部拥有独立适配模块。

左侧侧栏用于统一管理这五个站点的登录状态与登录／退出入口。2026-11-15 已确认侧栏与普通内置浏览器共用对应站点会话；登录打开官网，退出同时对共享会话生效，其他站点不受影响。当前源码已加入双站入口与自动摘要更新，未接入三站不提供登录动作；真实登录／退出及新提交体验仍需新构建验收。详细设计见[洛谷会话与交互修复设计](../superpowers/specs/2026-11-15-oj-connect-luogu-session-design.md)。找题在内置浏览器中完成；独立题面页与独立评测记录页由 OJ Connect 提供。样例管理和本地测试继续使用内置 CPH。

## 已确认的主流程

### 从已有源码看题与提交

1. 聚焦源码编辑器。按 Ctrl+Alt+P，结合站点目录和文件名识别题目，打开独立题面页。
2. 按需在题面点击“导入 CPH”，为这份源码准备样例和本地测试。
3. 编写、调试完成后，在源码编辑器按 Ctrl+Alt+S 提交当前编辑内容，包括未保存修改。
4. 正常情况下自动发送并打开独立评测记录页，持续更新等待、评测中和最终结果。登录使用内置浏览器；洛谷图片验证码沿用插件输入框，AtCoder 验证沿用网页。洛谷同次提交中已输入答案被明确拒绝三次后停止并提示用户到内置浏览器提交、手动认证，不加入新的认证形式；首次挑战、留空刷新与取消不计数。

看题和提交使用同一套题目识别规则。无法定位题目时提示用户输入题号或链接；不会在多个站点之间后台试投代码。

### 从内置浏览器导入

1. 用户在内置浏览器找到题目，点击 Import。
2. OJ Connect 将源码导入当前打开的工作区文件夹下的站点子目录；目录不存在时自动创建。
3. 同时打开该 `.cpp` 和 OJ Connect 独立题面页。
4. 若目标目录已有这道题的同名 `.cpp`，直接打开已有源码和题面，保留磁盘内容及未保存编辑稿。
5. 用户在题面点击“导入 CPH”后，才为这份源码建立 CPH 样例与测试关联。

浏览器 Import 与题面“导入 CPH”是两个用户动作。后一步复用前一步打开的源码，不再生成第二份解答文件。重复导入不自动覆盖用户修改过的样例。

## 目录设置与题目猜测

| 站点 | 默认子目录 |
| --- | --- |
| 洛谷 | `luogu` |
| Codeforces | `codeforces` |
| AtCoder | `atcoder` |
| 蓝桥 | `lanqiao` |
| 牛客 | `nowcoder` |

例如打开工作区文件夹 `c++` 后导入洛谷题，源码放入 `c++/luogu/`。目录名允许用户在 OJ Connect 插件设置界面修改；导入路径和按目录识别站点共用这套设置。修改设置不自动移动已有文件。

题目猜测采用简单规则：识别到配置中的站点目录时，在该站点内按文件名提取题号；未识别到站点目录时，尝试通过文件名的站点特征／前缀判断。格式不匹配或该站找不到题目时提示用户输入，不静默改用另一个站点。

浏览器导入的默认文件名应使用该站可反向解析的题目标识。例如洛谷的 `P1001.cpp`、AtCoder 的 `abc086_a.cpp`；各站具体格式在对应适配与测试中定义。比赛上下文属于站点题目标识的一部分，不能为了简化文件名而将不同比赛题目混为同一道。

不新增持久的“源码—题目绑定库”，不新增移动／重命名后的关联冲突处理机制。实现以文件位置、文件名和本次操作上下文为依据。上游插件读取既有 CPH 配置的实现是参考证据，不代表 OJ Connect 已决定用 CPH 元数据覆盖上述目录规则。

## 题面与评测界面

独立题面页展示站点与题号、标题、题目正文、公式、图片、输入输出说明、样例，以及站点提供的时间／内存限制。按洛谷插件保留紧凑的“导入 CPH”“提交当前文件＋语言”操作区；标题链接通向原题。提交后自动进入本次记录，无常驻的查看结果／原题按钮行。网页登录、验证及必要的原站操作留在内置浏览器中。

提交后自动打开独立评测记录页，源码和题面继续保留。记录页展示正式提交 ID、题目、语言、评测状态，以及站点提供的分数、耗时、内存和编译错误。没有提供的字段不伪造；保留站点原始状态和正式记录链接。等待、失败、超时和无法唯一确认本次记录均需明确呈现，不能用旧 AC 代替新结果。

五站登录摘要应与实际使用的浏览器会话一致。无法读取或尚未检查时显示未知／不可用，不以“存在 Cookie”或“打开公开提交页”推断已登录。侧栏不扩展成题库、社交或比赛监控入口。

各站共用题面页、评测记录页和操作流程，由站点适配器提供内容、状态与必要的原站交互。完整裁剪、共同数据和适配契约见[共同流程与洛谷接入设计](shared-workflow-design.md)。
