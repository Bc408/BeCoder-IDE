# AtCoder 基本刷题流程首版

本文保留核心侧 MVP 各阶段的过程与证据，早期章节中的“当前／尚未”仅指该增量时点。2026-11-12 快捷键自动提交已验收；当前产品要求和插件化职责以 [OJ Connect 产品与开发入口](oj-connect/README.md)及[技术架构](oj-connect/architecture.md)为准，独立题面与评测页尚待迁移实施。

目标：在现有内嵌浏览器与 CPH 中完成登录、打开题目、导入样例、关联源码、准备提交、网页确认和查看评测。题目页明确显示将提交的文件与语言；读取编辑器当前内容，包括未保存修改。登录与验证码由用户操作，Beacon 不取得交题能力。

体验参照：[yltx/vscode-luogu](https://github.com/yltx/vscode-luogu)、其 Wiki，以及负责人提供的 4.18.2 VSIX。重点参照题目页保留源码文档、文件名可见、语言选择、提交防重和评测自动衔接。账号处理与 CPH 接点按 BeCoder 现有所有者实现；本轮没有复制其业务代码或图标素材入产品。

所有者：browserView 宿主校验 view/window/页面身份并执行固定 AtCoder 表单适配；浏览器编辑器控件记住本窗口源码、选择语言并调用宿主；现有 CPH 负责导入和测试。已有详情读取探针复用，不新增通用浏览器脚本、Cookie 导出或整站框架。

实施顺序：

1. 增加固定 task URL 与表单适配，真实语言选项从当前表单取得。用官网现行 contest.js 已确认的 input-open-file change/FileReader 链路传递内存源码，使 Ace 与原始 textarea 同步。先在真实 Electron 合成页面中验证跨隔离世界文件事件、未保存文本、Unicode 和草稿保护。
2. 在题目页外的浏览器工具栏显示源码文件名、语言、导入样例及准备提交操作；切到网页仍保留源码引用，文档销毁后失效。显式替换网页草稿，页面变化、关闭、超时或语言不符时停止；不自动点击网页 Submit，不自动重发。
3. 网站接收最终用户确认并显示评测。验证能否精确关联本次 ID，保留不确定状态；不会以列表旧 AC 或最新记录直接充当本次结果。当前详情读取用于正式 ID 的源码/判题核验。
4. 负责人以已结束练习题完成一次导入→编写→本地测试→提交→结果，再用第二次代码版本检查关联。未通过的环节继续实施，不以表单填充成功冒充完整提交旅程。

保护：不修改学生现有 C/C++ 文件，不覆盖网页草稿，不改变信任/隐私设置，不为测试自动提交错误代码。原生网页呈现保留公式、图片、验证码及账号状态；第一版不扩展题库搜索、比赛监控、社交或 Notebook。

验证：先写回归测试并观察失败，再实现；使用已有 tsc/mocha 与真实 Electron 探针。正式矩阵为客户端类型检查、变更文件零警告 ESLint、相关 CSS 检查、OI 扩展编译、Windows staged 构建（120/120/300 秒对应仓库规则）。执行前核对入口并在忽略目录记录命令/退出码/失败。运行截图、网站真实链路和负责人验收单独成立；本轮不构建 Setup、不提交或推送。

## 当前首个可操作增量

新增命令面板入口 `Open AtCoder Problem`，接受官方题目链接。题目页顶部工具栏提供 Sign in to AtCoder、Import Samples、Choose Source、语言选择、Prepare Submission 和 Refresh Languages；最近活动的本窗口 C/C++ 文档在切回题面后仍保留，文件名/完整路径可核对，准备时读取内存模型当前内容。已有网站草稿先确认替换，代码通过网站原有文件读取事件同步到 Ace 与 textarea，网页最终 Submit 仍由用户确认。

这是完整七步流程的前半段。网站原生提交后会显示结果入口，但当前增量还没有实现独立的本次提交 ID 自动关联和统一评测面板，不将网站列表里的最新 AC 当成本次成功。后续围绕真实准备提交、用户确认、返回页面的实际行为继续完成这一段。

当前验证：14 项路由/读取单测通过；真实 Electron 合成提交表单中，跨隔离世界 FileReader、源码换行/Unicode、草稿保护、错误题号拒绝与零自动提交均通过。类型检查、模块分层、零警告 ESLint 与 CSS 检查通过；CSS 仍有现有及新增样式的设计 token 建议，未将建议视为错误。OI 扩展编译已通过；新工具栏在真实 AtCoder 页面的布局和行为仍待当前构建后验收。

带工具栏 staged 构建已通过（107.92 秒，`tmp/oj-connect-audit/basic-staged.json/log`），沿用独立 Portable 数据目录启动。已交负责人按打开题目→登录→刷新语言→选择源码→准备提交实测，先不发送。正式网站上表单适配、工具栏布局及已有草稿交互仍待反馈；当前未宣称完整提交/评测闭环完成。

## Ctrl+Alt+S 本轮实施范围

负责人明确要求先完成源码编辑器快捷键交题并返回结果。命令只在本地 C/C++ 源码编辑器上下文绑定 Ctrl+Alt+S，固定当前内存文本为 LF 快照，不保存或修改文件。与上游 Share 快捷键冲突时仅在该上下文提高本命令优先级，其他语言/视图保留原行为。文件名 abc086_a.cpp、abc-86_a.cpp 可定位 abc086_a；无法定位时询问官方题目链接。语言首次选择后按 C/C++ 族记住有效选项，网页已有草稿显式确认替换。

发送由固定本地宿主方法执行网站原生 requestSubmit 一次；登录/表单不可用则结束并提示人工登录后重新按键。验证码未完成时等待官网就绪；需要人工验证时由用户在同一页完成，成功后继续原快捷键提交，无需另点 Submit。不会读取/导出凭据或给 Beacon 注册交题工具。发送前读取同会话 submissions/me 的合法列表作为基线；未识别的登录/验证模板不是空历史。只有观察到该 view 返回自己的列表后才处理新记录，并以比基线更新的 ID、题目、语言、账号和完整源码共同核对。多个候选或不一致时为待确认，不选择最新旧 AC，也不再次提交。

唯一候选确认后打开该正式详情，读取/跟踪原始状态直至终态，并在应用工具栏显示正式 ID、账号、状态和分数，保留网站完整评测页面。等待上限两分钟，Stop AtCoder Submission Tracking 仅停止跟踪；关闭 view/取消后不重开已关闭页面，不宣称撤回提交。当前代码待完整合成旅程、构建和真实快捷键验收，前文人工验证不能代替此轮自动关联验收。

本轮进度：18 项单测通过；独立真实 Electron 使用实际主服务方法走通合成的原生提交、返回 own-list、新 ID 核对、完整源码匹配、打开正式详情与 AC/100 返回，并验证歧义拒绝、验证码等待零发送和取消零重发。已保留 `scripts/test-atcoder-shortcut.cjs` 及 HTML fixture，测试入口/输出见忽略目录 shortcut-validation.md。源码类型、分层、ESLint、CSS 与扩展编译检查已取得通过记录。负责人关闭旧测试版后，快捷键新版 staged 构建退出 0（92.44 秒，`tmp/oj-connect-audit/shortcut-staged.json/log`）；真实网站的快捷键提交与自动返回结果仍待该版本验收，合成测试不能代替此项。

## 验证成功后自动继续发送的修正

负责人首轮快捷键实测报告新记录 `80777468`，但验证码显示成功后仍需手动点网页 Submit；因此该版尚未达到快捷键提交目标，不能将记录产生等同于无额外点击验收。源码确认：发送函数在验证码暂未就绪时返回 false，宿主忽略该返回值并只等评测记录。真实 Electron 加入延迟就绪用例，旧逻辑复现“验证已成功但不发送”。

修正为宿主在本次两分钟时限内检查同一页面、同一表单、源码及语言，等待就绪后执行一次原生 requestSubmit；等待时只滚动一次，避免持续抢占页面位置。不自动操作验证码。隔离世界的被动 submit 观察器记录用户手动发送，防止等待期间重复发送；取消/结束后移除观察器，修改网页代码或表单则停止，验证晚到也不恢复已取消请求。该行为只属于 Ctrl+Alt+S；独立 Prepare Submission 按钮仍仅准备网页草稿。

扩展 Electron 集成测试已验证延迟成功后无需手点即可返回新 ID/AC、手动提交被官网暂时阻止时不自动补发、取消后晚到验证零发送、网页草稿变更零发送与观察器清理。18 项单测仍通过；日志见忽略目录 `shortcut-resume-validation.md`。新修正版构建与真实网站无需手点 Submit 的验收分别记录，不以合成页面结果替代后者。

修正版 staged 构建退出 0（91.88 秒，`tmp/oj-connect-audit/resume-staged.json/log`），构建前已确认独立测试版退出。沿用原独立 Portable 数据与测试源码交负责人再次按 Ctrl+Alt+S；真实网站上验证成功后无需手点 Submit、自动关联新记录与展示终态的验收仍待反馈。
