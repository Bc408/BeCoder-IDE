# AtCoder 体验补全前的状态与讨论准备

日期：2026-11-16。本文保留进入体验补全讨论前的源码快照与问题清单，不是当前实现清单。随后负责人已确认[体验补全设计](../superpowers/specs/2026-11-16-atcoder-experience-design.md)并批准实施；语言偏好、独立提交页面、持续跟踪和 CE 输出已进入后续候选。最新实现及验收状态见[开发入口](README.md#当前实现状态)，下表不再重新开启已确认的讨论。

## 本轮已知问题收敛

- 登录：移除浏览器响应头权限策略改写，改为在页面脚本运行前声明不支持通行密钥。旧改写触发洛谷首页 `download.gz` 的情况已在同版本 Electron 匿名会话两次复现；无改写的两组对照均无下载。本地 fixture 覆盖密码表单、压缩页面、缓存、跳转和主动下载，不代表已人工验证真实账号。
- 提交：AtCoder 取得可能发送的证据后才登记待核对任务。验证码等待取消、草稿变化等确定未发送情况不再误报受理不明；未发送时不会关联其他新记录。正式回执和只读核对不再等待记录页导航，结果读取仍独立进行。
- 查询：旧通知查询绑定自己的任务；同任务重复查询共享一次请求，旧结果不清空新任务。关闭／取消／停用后的迟到读取不恢复页面映射或结果缓存；新读取等待原取消清理完成。
- 显示：仅将实际测试点表的数据行映射为卡片，排除测试集汇总和表头。等待、评测中的整体状态显示转圈，即使尚无测试点；停止跟踪及终态停止动画。
- 去冗余：移除旧 AtCoder `submit`／`revealResult` 桥接链及无发送入口的 `viewRecord`／`stopTracking` 面板动作，保留当前共同流程和站点必要差异。

## 讨论前的体验差异

下表来自讨论前源码与当轮回归；不是新的需求承诺，也不把合成测试当成线上测量。

| 使用环节 | 洛谷当前基线 | AtCoder 当前实现与待讨论点 |
| --- | --- | --- |
| 看题 | 快捷键打开共同题面，常规请求不依赖网页标签 | 共同题面已复用，但读取先取得对应网页，再请求原始 HTML。等待受页面加载影响；需讨论普通看题是否也应不依赖题目网页 |
| 题面语言 | 展示站点提供的内容语言 | 已提供日／英内容选择，当前取首个可用内容作为默认；需讨论默认语言及选择是否应跨题沿用 |
| 提交语言 | 站点语言选项与快捷键共用窗口内偏好 | 已共用语言选择与偏好机制；可用选项来自当前原站表单，准备前仍需加载表单。无需为对齐而强行统一语言 ID |
| 发起提交 | 同一浏览器会话直接请求，图片验证码按原插件输入；连续拒绝后提示浏览器手动认证 | 原生网页表单提交；需要时展示网页验证，完成后自动继续。网页已有草稿会要求替换确认；需讨论正常路径是否应一直留在编辑器，以及何时才展示浏览器 |
| 拿到正式记录 | 正式 ID 交付后打开共同结果页 | 先从本次新记录与源码核对取得 ID，再打开共同结果页；本轮已去掉回执阶段额外导航。真实端到端延迟尚未重新测量 |
| 等待与结果更新 | 记录推送驱动共同结果页 | 每轮读取详情后间隔两秒查询，仍依赖承载页面；两分钟一轮超时后可继续查询原记录。需讨论可接受的刷新节奏和等待反馈，不先假设必须复制推送协议 |
| 结果细节 | 已映射站点提供的分组、测试点和编译信息 | 已映射状态、分数、时间、内存、源码及测试点。CE 编译诊断尚未映射；补全前应核对真实页面及可读权限 |
| 登录侧栏 | 与内置浏览器共享会话 | 同样共用持久会话，但没有可用的站点承载页面时摘要可能未知。需讨论启动后摘要的预期，不新增独立账号库 |

## 当时提出的下一轮验证与边界

先按一个普通 C++ 题的完整过程记录用户动作和等待：登录 → 浏览器 Import → 编辑器／题面 → CPH → Ctrl+Alt+S → 网页验证（如需）→ 新 ID → 等待 → 最终结果。再分别检查无需验证、需要人工验证、取消、CE、WA、页面关闭与查询失败。每轮只提交负责人授权的题目和源码，不为测速重复发题。

优先对齐可见动作、等待提示、正式记录归属和结果信息；传输路线、表单和验证方式允许站点不同。具体架构变动需以真实差异和测量为依据。第三方难度数据、更多语言支持、新认证、比赛管理、提交队列和持久题目绑定均不随本轮自动加入。

讨论建议先聚焦一个边界：**AtCoder 正常看题与提交时，用户是否应始终留在源码／共同面板，只在确实需要登录或人工验证时展示浏览器。** 这会决定后续先优化承载页面，还是调整读取／准备路径；本轮不预先实施该选择。
