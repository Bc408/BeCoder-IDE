# Beacon `.4` 的 Pro 覆盖补齐与新变体验证

执行日期：2026-11-22。状态：生产提示 `2026-11-22.4` 保持不变，Pro 的十类固定案例已分批覆盖，并完成四类新变体及一次输入格式纠正组。本轮启动 36 次场景、127 次生成请求，保留一次 length、一次超时及三次输入不合约的实验。Pro 仍有查询事实错误与解释缺陷，未达到完整教学质量及负责人体验验收。此前 Pro 的 P05/P06/P07 共九次样本及 Flash 结果见[第二轮报告](prompt-evaluation-2026-11-22.md)，不覆盖、不重新挑样。

## 目的与边界

上一轮发现 Flash 开放式讲解会主动加入错误的必要条件，直接追问却能答对；同提示的 Pro 局部样本有所改善。局部更好不代表所有能力合格。本轮将对象/版本、用户要求变化、不可用材料、恶意文本和查询撤销补齐，再用未用于调词的变体检验迁移；不据此更改用户日常模型配置，不新增自动选模型或审查模型。

请求仍经过冻结的实际 generator、ChatSession 与 ContextTools，工具目录先行、正文按需读，后轮继承实际回答和协议。提示、provider 与其 130 个生产输入通过哈希校验；无生产源码变化，不重建应用。上一轮 `.4` staged 仍为同源候选，不代表桌面运行或真人体验已验收。

只使用合成题目和账号；P10 与新授权变体的 web 返回均为进程内固定结果，真实网络仅调用已授权模型服务及模型列表。不读取学生原始历史或产品 SecretStorage，私有 API 文件只在进程内读密钥，证据排除认证头和原始错误体。临时 model 选择为 `deepseek-v4-pro`，不写回用户配置。

## 执行条件

模型列表在本轮重新读取，alias 与实际 SSE 身份单列；没有公开权重 digest，不能宣称与前组固定权重或并发时完全相同采样。默认思考、8192 生成上限、180 秒/轮保持，temperature 0 若被 SDK 省略按实际记录。每类三次，最多三个独立场景并行，每个场景内部各轮按顺序执行，无隐藏场景重放。

补齐固定七类共 21 次，保留前九次后可描述为分批覆盖十类，不能称单批随机化全量对照。新变体单独 12 次，不与固定 P01–P10 混分。每组证据使用新目录，失败、取消和未执行均保留；不补采成功直到凑够通过。

本地证据根：`tmp/beacon-prompt-eval/20261122-generalization-03/`。`pro-remaining/` 保存固定补齐；`novel-cases.json` 与 `criteria.md` 保存新输入及判断依据；`pro-novel/` 保存原新变体输出；`novel-cases-corrected.json` 与 `pro-u02-corrected/` 保存 U02 格式纠正及单独结果。旧九次证据仍位于上一轮 `pro-probe-v4/`，其时间与参数独立保留。

第一组执行过程中，临时 runner 的预算帮助函数作了等价提取，已加载的 Node 进程没有重载；生产输入和场景未变，但第一组未保存原 runner 文件的字节摘要。因此不能宣称该组包装脚本可逐字节复现。出站请求和工具协议完整保留，后两组另存实际 runner 源码及摘要；这一复现局限不能隐去。

## 新变体输入

四个变体是先写输入与判定事实，再冻结并执行；没有依据回答重写题目或排除失败。

| 标签 | 输入变化 | 核验事实 |
| --- | --- | --- |
| U01 | 宿主 target 是逆序复制，首问明确点名另一个计数文件；次问纠正为当前文件 | 首问检查 >= 与 >，次问检查 src[n-i] 与 n-1-i；必须跟随最新明确对象，不能套旧结论 |
| U02 | 加权求和旧稿同时有初始化、漏项和 32 位乘法风险；新版本全部修复 | 新稿 total=0、i<n、1LL 提升乘法且 long long 累加，样例为 42；旧 WA 只属于版本 11，新稿版本 12 没有新运行/判题 |
| U03 | 用户已懂递推，只追问 cur=0、ans=LLONG_MIN 为何适用于全负数 | 输入 -11、-4、-9，状态依次 (-11,-11)、(-4,-4)、(-9,-4)；先更新 cur 再更新 ans 保证候选非空，不强迫换首元素初始化 |

## 新变体实际结果与输入纠正

原新变体组 12 次场景、55 次请求，约 203.80 秒，CLI exit 0；21 个实际用户轮均完成，34 次 tool_calls、21 次 stop，HTTP 均为 200。完成运输不代表输入或教学质量合格。

U02 的 OJ 页面正文被编写成普通文本，而实际 `ContextTools` 对 `oj-problem` / `oj-record` 按 JSON 解析。夹具外壳检查通过，实际读取失败。这是本轮输入编写及前置验证的遗漏，不能归因于生产读取错误或模型无法理解完整题意。原 U02 三次及其反复读取失败完整保留，计入调用成本，但不作为“已供应全部材料”的模型质量样本。

纠正只将原有题面、样例、旧稿绑定说明包装为结构化 JSON，并显式放入已给定的 V11 源码；提问、代码版本、判定标准不变。实际生产工具的离线检查先复现原输入失败，再确认纠正后六次页面读取全部成功。随后仅 U02 三次使用独立 runner 和新目录执行，不覆盖原组，不因回答好坏挑选重跑。纠正文件 SHA-256 为 `d5817af3fa6b6110fe8399f10a81f9deb13e8857174f49bd2df81be8b4f6c794`。

纠正组实际 3 次场景、12 次请求，约 194.77 秒，CLI exit 1 / incomplete。两次完整结束，均实际读取 V12，识别三项修复，并明确旧 WA 绑定 V11、V12 只有静态判断，未捏造运行或 AC。另一次首轮完成，第二轮在 180 秒期限内未结束，无完整回答、工具读取或 finish_reason，用量也缺失；应记超时，不能记 length 或版本区分通过。该组一份首轮解释在承认未初始化后，仍写出“当前只加前三项……14”，未在该处说明这是局部表达式之和、不是可预测的程序输出；另一份把代码缺陷直接等同于正式 WA 的已证实原因，表述仍须审慎。

## 收敛判断与下一步

本轮否定了“换 Pro 就能通过全部质量门槛”的判断。对象更正、读取当前稿和撤销后的零查询在多个变体成立，但历史材料被称为最新、WA 过度推论、正确代码旁的错误必要条件，以及未完成回答仍是实质缺口。提示词是软约束，既不能从局部成功推成强保证，也不能把本轮模型错误归咎于 4B。

下一步优先收敛证据表达与讲解中的额外断言：让历史/当前、静态检查/真实结果、读取时间/材料来源事实始终有明确依据；针对“代码正确但解释错误”设置可独立核对的事实清单。新一轮若修改提示，应先登记具体失败与未见迁移题，再按同输入对照，不能堆叠针对样例的结论或反复补采直到成功。当前没有足够证据启动压缩；压缩需沿用这份完整上下文基线，不能以缩短上下文掩盖已有问题。

本轮只新增本地评估与文档，不修改生产提示或用户模型配置，不重建应用。此前工程验证与 `.4` staged 保留原有范围，仍不等于教学质量、真实桌面流程或负责人体验验收。未实施自动压缩、记忆、自动换模型或新的宿主许可机制。
