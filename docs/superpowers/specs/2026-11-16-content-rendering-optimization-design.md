# 内容渲染性能优化、能力统一与去冗余设计

日期：2026-11-16。状态：负责人已认可目标、职责边界、渐进渲染和迁移顺序，随后明确授权跳过逐步方案请示，持续实施与测试。本文作为实施依据；实现与验收分别记录，不构成性能改善或运行验收记录。

## 1. 目的与依据

改善 OJ Connect 题面与 Beacon 消息的阅读、代码显示和复制体验，同时减少重复解析、全量更新和并行维护的渲染实现。统一范围包含 Markdown 流程及其相关内容能力，不局限于代码高亮。

依据为负责人本轮确认、[产品方向](../../../VISION.md)、[OJ Connect 共同流程](../../oj-connect/shared-workflow-design.md)以及 [Beacon 正式文档](../../beacon/README.md)。现状与合成基准见[渲染调查](../../oj-connect/rendering-review-2026-11-16.md)。本设计描述目标实现，不把研究建议或历史测试当作已交付结果。

开发基线为 `OJ_connect` 的 `3b029438`。该提交是本地开发快照，提交说明已记录 hygiene 未通过；其扩展测试结果不等于完整源码、构建或负责人验收通过。后续实施须分别处理受影响的检查，不继续默认跳过提交钩子。

负责人最新决定覆盖此前主题同步讨论：代码块固定采用随包的 BeCoder One Monokai 配色，不读取用户当前语法配色，不引入主题同步接口、监听或配置项。页面容器沿用自身现有主题机制。

## 2. 用户可见结果

- 打开题面或消息后尽快阅读正文和代码，高亮在后台补齐；高亮进度不阻塞阅读、滚动与复制。
- Beacon 的新增代码在相应文字显示时立即出现，高亮尚未完成的尾部显示原文。正文保留现有平滑输出、停止／完成及 reduced-motion 行为。
- 两处共用语言识别、语法高亮、公式与代码内容组件。OJ 题面、样例和编译输出的复制按钮延续已确认的叠页图标；Beacon 代码复制使用同一底层能力，保留消息整体复制入口。
- 未知语言、资源加载失败或着色超出预算时保留完整原文。普通渲染失败在当前界面反馈，不自动打开官网，不触发提交或认证。
- 洛谷既有方言、题面语言选项、正文与样例语义保持；AtCoder 原生 HTML 保留其题面语义。

本轮不调整 OJ 登录、验证码失败上限、源码快照、目录猜题、CPH 导入、提交或正式记录跟踪，不扩展 Beacon 的权限、会话存储和资产能力。Notebook 及其他 Markdown 消费者不随本轮自动迁入。

## 3. 优化重点与删减对象

| 当前成本或重复能力 | 目标处理 | 需要保留的保证 |
| --- | --- | --- |
| OJ 安全预解析、上游输出 HTML 后再解析／遍历／序列化 | 同一内容树完成方言转换和作者内容清洗，输出直接供展示的结构 | 作者样式不能影响产品 UI；公式与代码字面量不受误删 |
| OJ Shiki、HTML 路径 highlight.js 与 Beacon 着色各自维护 | 共用一条高亮主路径、语言资产与固定配色 | 既有支持语言有回归样本；未知语言立即可读 |
| 高亮后的大量 HTML token 随正文传输和再次遍历 | 传递代码原文与语言，展示侧异步着色 | 复制独立于高亮 DOM；不丢代码空白 |
| Beacon 每个动画帧重新解析全文 | 数据变化合并解析，动画仅推进已解析内容的显示 | 平滑输出、公式暂态和最终 Markdown 语义保持 |
| Worker 虽增量计算，却全量传输、全量重建 spans | 复用稳定代码行，只传递并更新变化行 | 多行语法状态正确传播，过期结果不覆盖新内容 |
| 一次装入全部 grammar，代码块短暂卸载就冷启动 | grammar 本地按需加载，运行资源由当前 Webview 统一拥有 | 离线可用，关闭时释放，无跨页面业务共享 |
| 两边重复的数学、代码、复制与内容清洗实现 | 移入共享源码，消费者保留明确的差异策略 | 统一机制不扩大内容权限 |

旧路径在对应行为与性能验证通过后移除。迁移期间保留的对照仅用于开发验证，不作为发布后的多引擎回退链。移除依赖前检查宿主、Webview、构建、测试和许可的全部消费者。

## 4. 共享能力及职责

共享模块放在现有 `extensions/becoder.shared` 下，按源码和静态资产被两处分别构建；该目录不新增可激活扩展或跨进程全局服务。模块围绕以下实际职责组织，不建立通用适配器注册框架。

| 所有者 | 职责 |
| --- | --- |
| 共享内容解析 | Markdown／HTML 解析、方言转换、作者内容清洗、链接规则、代码／数学语义节点 |
| 共享内容组件 | 安全内容树展示、公式、代码块、复制和必要的局部样式 |
| 共享代码处理 | 语言别名、本地 grammar、固定配色、Worker 生命周期、变化行着色与结果版本核对 |
| OJ 容器与适配 | 取得题面、选择题面语言、题目头部、样例与 CPH、提交和结果操作 |
| Beacon 消息容器 | 接收消息、平滑显示、滚动、停止与完成、会话切换和原有权限边界 |

共享组件分别适配 OJ 当前 React 18 与 Beacon 当前 React 19 的构建，不为此强制升级或共享 React 运行时。新增内容能力保持小接口，构建资产复用不意味着跨 Webview 共享可变状态。

## 5. 共同内容流程

```text
Markdown → 基础解析及方言转换 ──┐
                               ├→ 作者内容清洗 → 内容树／代码与数学节点
原生 HTML → 解析及站点语义适配 ─┘
    → 共用内容组件 → OJ 题面或 Beacon 消息容器
    → 代码原文先显示 → 共用高亮处理 → 更新变化行
```

内容树复用现有 mdast／HAST 生态，只为代码和数学等实际展示需要保留语义节点，不另造完整文档格式。作者输入先按消费者策略清洗，之后才生成可信公式与代码样式；作者不能伪造可信节点或通过类名、属性侵入产品控件。

OJ 静态题面由扩展宿主调用共享解析模块，向 Webview 发送清洗后的内容树和代码原文，避免把已着色 HTML 往返传输。Beacon 在消息展示侧调用同一解析模块，并按数据变化合并调度。共享解析模块保持无 DOM 业务依赖，分别验证 Node 与 Webview 环境；不为统一而强迫两者跨进程调用对方。

共同机制保留三个明确输入策略：

- 洛谷：沿用上游已验证的 directives、callout、合并表格、数学、受限 HTML、图片、相对链接和嵌入转链接处理。优先提取现有上游实现并保留来源，不重写已有语法。其仅返回 HTML 的公开接口须在实际拥有 AST 的位置最小调整，消除额外输出往返。
- AtCoder：原生 HTML 直接解析为内容树，保留公式、样例、列表和表格语义，不转回 Markdown。站点 DOM 与数据抽取仍归现有适配层。
- Beacon：保留换行、不完整公式／代码围栏等消息规则及现有图片、raw HTML 限制。洛谷允许的内容不会因此自动对模型输出开放。

静态解析结果缓存与高亮缓存分别只缓存自己拥有的结果。保留 OJ 既有有界缓存和并发去重能力，迁移为内容树后按输入、方言及内容策略区分；解析缓存不存高亮 token，不因配色重复解析。Beacon 的临时展示缓存留在当前页面内存，不改变历史或 Blackout 留存规则。

## 6. 代码、公式与复制

高亮优先收敛到已有 Beacon 的 TextMate／Oniguruma 基础，修正其全量传输、全文 spans 更新和尾部展示问题；复用随包语法与 One Monokai 资产。以同一套静态及流式样本验证该方案，若无法满足验收门槛，先提供实测和替代设计，不在产品里继续叠加 Shiki／highlight.js 回退链。

grammar 按需从随包资源装载，索引包含语言别名、入口和依赖／注入关系。资源路径由构建生成的索引限定；未知语言显示普通代码。按需加载不依赖公网。CSP 只增加实际必需的本地资源与 Worker 能力，不能为此开放任意网络、任意脚本或消息命令。

同一 Webview 的代码块共用一个着色执行器。每块拥有自身语言、文本版本和连续行状态；只合并同一块尚未开始的旧版本工作。结果核对页面／块身份和文本版本；页面切换、删除、取消或资源重建后，旧结果不得重新挂回。代码中部变化须向后重算至语法状态稳定，不能假设只追加尾行。

新增原文不等待着色；仅当语言相同且旧结果对应的原文仍是当前内容的精确前缀时，才可保留旧前缀高亮，新尾部同时以普通文本显示。Worker 故障或计算超预算时保留原文并释放失效状态，后续实际内容更新可以重新处理，不对同一失败版本反复重试。生命周期跟随当前 Webview，避免每块卸载都销毁共享资源；关闭页面时释放 Worker、监听和对象 URL。

公式共用 KaTeX 与既有安全选项、样式和字体，按数学源文及显示模式缓存；未变化的公式不随动画帧重复计算。未完成输入按既有暂态规则显示，完成后用共同静态语义确认。公式错误局限于当前内容块，其他正文仍可读。

复制以内容源中提取的代码字符串为准，保留代码内部空白和末尾换行，不从高亮 spans 拼回源码。样例和编译输出继续使用各自权威原文，CPH 输入不经过 Markdown 清洗。共用按钮的成功反馈、键盘可达性和无障碍标签；代码块使用一个横向滚动所有者，按钮不制造额外滚动条。固定代码配色和相应背景成套使用，避免与页面底色混搭后不可读。

## 7. Beacon 流式更新

解析调度与显示动画分开。新的消息源文触发一次合并后的解析工作；动画帧只推进内容的可见范围，不重新触发全文 Markdown、公式或代码计算。首轮合并等待上限为 50ms，持续输入亦不得将计时不断重置到输出结束；这不包含计算耗时，实际可见延迟另行测量。相同源文只处理一次，显示动画不产生新的解析任务。

首轮优化使用现有完整解析器和稳定节点复用，不先开发完整增量 Markdown 解析器。解析仍可处理当前全文，但频率由数据变化决定；相同内容和展示动画不重复解析。通过节点内容及身份比较复用未变化的子树和代码行，引用定义等变化仍可使相关旧节点失效。

不能按空行简单切块：表格、列表、引用定义、raw HTML 和围栏存在跨段语义。待解析的新增内容以安全文本呈现，解析完成后替换对应范围，防止内容重复、丢失或把未清洗 HTML 临时插入页面。源文替换、截短和重新生成走版本重置，不能当作普通追加。

消息完成或停止后，以届时已接收的完整源文执行共同静态解析确认最终展示；渲染收尾不重新请求模型，也不改变原有模型请求的停止语义。会话切换与页面关闭取消未完成的显示工作，迟到结果不得污染其他消息。现有滚动跟随、用户上翻位置及 reduced-motion 行为作为回归要求保留。

## 8. 迁移顺序与复杂度约束

1. 固定现状样本、截图与分段性能基线，记录冷／热加载、解析、高亮、传输、DOM 提交和可见增长停顿。
2. 先以共同内容层接入 OJ 静态题面及 Beacon 已完成消息，核对方言、清洗、公式、代码和复制行为。
3. 收敛代码处理和资产加载，接入变化行更新；两个消费者都验证通过后删除被替代的代码与依赖。
4. 将 Beacon 流式更新接到同一内容层，分离解析和动画，复用稳定节点，修复新增尾部等待高亮的问题。
5. 完成真实 Webview 对照、受影响回归和负责人验收，再收尾旧入口、构建配置与许可登记。

不增加每块 Monaco、主题子系统、跨扩展渲染 RPC 服务或站点通用插件框架。额外优化必须由具体基准瓶颈支持；若首轮仍有成本，先区分解析、token 化、传输和 DOM，而不是同时引入完整增量解析、全文虚拟化及多套缓存。

## 9. 验证与验收

### 行为与视觉

代表性样本覆盖洛谷提示块／合并表格／受限 HTML／图片、AtCoder 原生题面、多语言切换、Beacon 换行／不完整数学／围栏、未知语言、长单行、空代码、多块代码及精确复制。语言包含 C/C++、Python、Java、JavaScript、C#、Kotlin、Lua、Haskell、OCaml、Julia 和 Pascal，以定位旧覆盖缺口并记录各语言实际状态。

验证恶意作者样式、事件／链接／嵌入不能突破容器，代码字面量不被当成 HTML；版本乱序、语言切换、内容替换、Worker 失败、页面关闭和多消息并发不能污染显示。分别检查两种 React 构建及 Worker 资源在实际 Webview CSP 中的加载。

截图使用相同内容、窗口宽度和缩放，检查正文、代码背景、公式、单层滚动、按钮与空块。页面的浅色、深色和高对比环境均检查可读性；代码块始终使用固定配色，不据此承诺跟随编辑器主题。测试通过与负责人页面效果验收分别记录。

### 性能

沿用调查样本：100 个小代码块；100／1000／3000 行代码；多公式题面；2000 行基础上每 30ms 追加一行、共 100 行。补测两个生产 Webview，使用固定环境，分开报告冷启动、热更新与缓存命中，不用 Node 宿主耗时替代页面可见耗时。

每项前后至少运行 5 次，报告各次结果与中位数；流式额外报告全部增长间隔的 p95、最大停顿和主线程长任务。正文动画主动延迟与解析／高亮造成的等待分开计量，不把文字提前显示等同于完整高亮已经加速。

通过条件：静态首次可读及热开无超出基线波动范围的回退；长代码高亮和流式增长停顿有超过测量波动的稳定改善；新增代码在高亮未完成时仍可见并可完整复制；动画帧不再驱动重复全文解析；未变化代码行不再全量回传和重建。若仅减少模块数量而这些指标未改善，则不能宣称本轮性能目标达成。

### 工程与交付

实施计划列出并预检实际可用的共享模块、两扩展、client、OI 编译及相关 lint／分层检查。任何正式失败与重跑独立记录；检查依据最终源码，不继承开发快照的失败豁免。

使用本地固定内容先完成性能与页面核对，不需要为渲染验证反复提交真实 OJ 解答。后续 stage 构建、真实应用验收及可能的真实账号回归分别按届时授权执行；本设计不授权 Setup、发布或推送。

## 10. 构建、许可与进入实施的条件

共享模块及资源由两个扩展各自的现有构建接入，完整分发所需 Worker、grammar、WASM、KaTeX 字体和固定配色；本地按需加载路径也须进入打包核对。依赖以仓库现有锁定版本为起点，只有有依据的选型变化才调整版本。

复用洛谷、Beacon、grammar 与主题代码保留各自版权、许可证和修改记录；不把 `becoder.shared` 现有许可当成给全部迁入代码重新许可的依据。删除依赖时同步核对实际 bundle、来源登记及 ThirdPartyNotices，避免保留失效声明或遗漏新资源。

本设计自审检查目标完整、权限及职责一致、迁移可分步和验收可操作。负责人已明确授权持续优化与测试，按同会话实施计划自主执行，不再逐步请求方案许可；超出本设计的发布和破坏性操作仍不属于授权范围。
