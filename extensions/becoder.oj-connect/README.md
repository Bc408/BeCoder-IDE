# OJ Connect

BeCoder 内置刷题扩展，当前源码接入洛谷、AtCoder 与牛客 ACM；牛客候选的真实验收状态见开发入口。需要包含对应浏览器宿主的 BeCoder 构建。

聚焦 C/C++ 源码，**Ctrl+Alt+P** 查看题面，**Ctrl+Alt+S** 提交当前编辑稿（含未保存内容），正式 ID 确认后打开共同评测页。题面可选择站点语言，快捷键沿用同一选择；尚未取得可用语言时在提交时选择。洛谷使用内置浏览器同一持久会话直接请求，常规操作无需保留网页；验证码按上游图片面板输入，留空刷新。AtCoder 按快捷键才建立本次官网提交页，正常验证后将源码直接放入完整表单请求发送一次，共用持久登录，不覆盖用户已有网页草稿；取得正式回执即释放任务页，结果查询独立进行；快捷键提交、受理核对和结果跟踪全程不自动显示网页。未登录时提示从侧栏主动登录后重新提交；原站验证在后台自动就绪时继续同一任务，若在期限内仍需人工验证则结束尚未发送的任务并提示主动到内置浏览器手动提交。保留用户自行打开的网页。

牛客仅接入公开 ACM 标准输入输出题及已结束、公开、个人可提交的比赛题。常规题面、编译器、单次发送和结果使用同一原生 Session，不创建网页；验证码拒绝提示主动到内置浏览器手动提交。题霸函数模板题、PAT、进行中／私有／团队／付费比赛及未核准题型不支持，不切换到另一判题通道。缺少正式分数、代码长度或测试点时省略，不将通过率当分数；“本次提交源码”指本地实际发送的快照，不表示已回读官网源码。牛客评测状态沿用洛谷完整英文名称，悬停显示中文说明。

AtCoder 题面首次默认英文，主动选择的日／英偏好跨题、跨重启保留，缺失时仅对本题回退。三站分别按 C／C++ 保存本站编译器 ID，互不覆盖；同一站点的题面和快捷键使用同一选择。AtCoder 首次须明确选择，打开题面不会自动记下首项；洛谷无偏好时沿用首项，已有偏好失效则保持未选择，提交时要求重新选择。输入格式保留数学排版；样例输入／输出采用双栏，对应说明置于该组下方。

三站题面统一使用“时间限制”“内存限制”“题目难度”“题目标签”，限制值沿用洛谷的简洁单位格式（如 `2.00s`、`256.00MiB`），有语言区别时仅采用 C/C++；无法确认的值省略。难度和标签保留站点特色，缺失不显示。CPH 和提交按钮仅显示图标，悬停和无障碍名称保留动作说明。

内置浏览器的 OJ Connect 分体按钮固定执行 **Get Problem**：按当前题页在工作区的站点子目录创建／打开 `.cpp`，同时打开共同题面，不自动初始化 CPH。右侧菜单保留 **Get Problem** 和 **Import to CPH** 两项；主按钮不支持当前页面时置灰，箭头仍可展开。Import to CPH 继续使用 Competitive Companion 解析页面；三站支持题目采用相同站点目录和 adapter 文件名，其他题源保留 CPH 默认行为。

题面上的 CPH 图标将结构化样例关联到该题面绑定的源码。两种 CPH 入口复用同一文件，已有源码和未保存稿保留，仅新建源码执行 CPH 模板；替换已有样例仍需确认。缺失限制会在 CPH 明示使用本地默认限制，不伪造网站数据。

`becoder.ojConnect.directories` 默认 `luogu`、`codeforces`、`atcoder`、`lanqiao`、`nowcoder`，设置修改不会移动已有文件。直接父目录优先，再猜文件名；失配提示输入，不建持久绑定库。例：`luogu/P1001.cpp`、`atcoder/abc086_a.cpp`、`nowcoder/18204.cpp`、`nowcoder/5657_A.cpp`；牛客保留公开题库／比赛身份，无站点目录时不从纯数字或通用比赛文件名猜测牛客；显式上下文例 `P1001@123.cpp`、`tenka1-2019-beginner@tenka1_2019_a.cpp`。无目录的 `AT_abc086_a.cpp` 有歧义时提示，不静默选站。

设置页搜索 `OJ Connect` 可调整以下设置。编译器与题面语言是跨项目的个人设置，页面选择写入对应设置，不另存隐藏偏好：

| 设置（前缀 `becoder.ojConnect.`） | 用途 |
| --- | --- |
| `luogu.cCompiler`、`luogu.cppCompiler` | 分别保存洛谷 C／C++ 的语言 ID，含本站支持的 `:o2` 后缀 |
| `atcoder.cCompiler`、`atcoder.cppCompiler` | 分别保存 AtCoder C／C++ 的数字语言 ID |
| `nowcoder.cCompiler`、`nowcoder.cppCompiler` | 分别保存牛客 ACM 的数字语言 ID，首次提交从实际目录选择 |
| `atcoder.statementLanguage` | 默认英文 `en`，可选日文 `ja`；本题缺失时仅临时回退 |
| `panelLocation` | 新题面／评测页的位置；默认 `auto` 复用源码右侧编辑组，否则并排；已有面板不移动 |

建议从题面或提交时的实际语言目录选择版本；清空编译器设置表示尚无偏好。旧版 AtCoder 本机偏好首次激活时迁入设置，不覆盖已有显式值，迁移成功才删除旧键。迁移写入失败会提示并保留未迁移项，扩展仍可使用。

独立 OJ Connect 活动栏入口提供五站登录摘要和已接入站点的登录／个人主页入口，与内置浏览器共用登录。退出登录在官网页面完成。CF、蓝桥显示“尚未接入”。没有题库、比赛、社交或专栏入口。

每窗口一项提交；洛谷明确验证码拒绝后人工输入可继续，同一次提交中已输入答案连续被拒绝三次即停止，并在右下角提示“请到内置浏览器中提交，并手动完成认证。”首次挑战、留空刷新和取消不计入次数，不实现新的认证形式。受理不明只查询，不能自动重交。发送后不提供取消提交；关闭记录只停止本地跟踪，线上评测继续。三站每轮本地自动跟踪约 120 秒，到期或查询失败保留正式记录和最后状态，允许继续查询同一 ID，不重交；洛谷推送、AtCoder 官网 Interval 与牛客 2 秒查询分别保留。状态保留原站标识并提供中文解释，CE 显示实际可读的编译诊断。AtCoder 返回评测进度总数时，沿用洛谷蓝色测试点卡片与白色转圈；尚无数量时只显示整体等待，不虚构点数。扩展重启不恢复任务或最近记录；三站的各自编译器偏好与 AtCoder 题面语言通过用户设置保留。

洛谷推送失败后停止本地跟踪，保留最后结果并提供“继续查询”；点击后重新读取同一正式记录，按需重建推送，不自动重连。隐藏或未知状态显示原始信息与说明，停止自动查询及转圈，允许手动继续查询；正常排队和评测状态仍自动更新。

题面与评测前端按 vscode-luogu 4.20.0 对齐，直接复用其核心 React 组件、CSS 与宿主 Markdown 渲染链，移除题解、比赛及其他外围能力；原组件及必要适配对照见 UPSTREAM.md。

开发命令：`npm run typecheck`、`npm run build`、`npm test`、`npm run test-render`。构建包含站点脚本、Webview JS/CSS、KaTeX 字体；运行时无外部 npm 依赖。许可与来源见 UPSTREAM.md、ThirdPartyNotices.txt。设计、当前检查和真实验收分别见 [开发入口](../../docs/oj-connect/README.md)。本次三站共同界面仍需负责人在新构建验收。

侧栏只在 OJ 名称上提供入口：未登录打开官网登录页，已登录进入个人主页；状态文字不可点击。图标在登录后亮起。退出登录请在内置浏览器的官网页面完成。
