# 使用指南

[返回项目首页](../README.md) · [文档目录](README.md)

本页说明当前源码对应的使用方式；已发布安装包的功能以对应版本为准。

## 安装与首次启动

BeCoder 通过面向 64 位 Windows 10 及更高版本的 Setup 安装程序发行。打开安装包即申请管理员权限，原生和 Portable 两种模式共用此入口。

- **原生应用版（推荐）：** 创建系统级 Windows 卸载登记和卸载器，由 Inno Setup 直接在公共开始菜单 Programs 目录创建 `BeCoder.lnk`。每台电脑只认可一份原生安装；重新安装请选择已登记目录，改换目录前先卸载。无需独立快捷方式程序或安装中途提权。
- **完全 Portable 版：** 不创建卸载登记或开始菜单入口，不向注册表写入安装状态。支持多份独立副本，可整体复制到可移动存储介质或其他 Windows 电脑。不能覆盖已登记的原生安装目录。

1. 运行 Setup 并选择安装模式和专用安装文件夹。路径只能包含 ASCII 字符、总长度不得超过 70 个字符，并且不能直接使用磁盘根目录。默认路径为 `%LOCALAPPDATA%\Programs\BeCoder`。
2. 两种模式中的“创建桌面快捷方式”均默认勾选。向可移动存储介质安装时建议取消勾选。
3. 第一次正常启动时，BeCoder 会打开随安装提供的 `coding\helloCoder.cpp` 示例。只有这个由安装程序提供的入门文件夹会被自动信任。

安装完成后的 BeCoder 目录是自包含目录，可以整体移动。不同 Portable 副本分别保存独立的应用数据和工具链；手动移动原生安装不会自动更新 Windows 卸载登记。

## 从题目到提交

1. 打开并信任自己的竞赛工作区。从首页进入 OJ，或在 OJ Connect 侧栏点击站点名称，在内置浏览器完成官网登录；退出也在官网操作。
2. 在支持的题目页面点击浏览器工具栏的 **Get Problem**，在工作区的站点子目录创建或复用 `.cpp`，同时打开独立题面；已有源码可按 **Ctrl+Alt+P** 看题。题面和源码保持关联，已有代码与未保存修改保留。
3. 在题面点击 CPH 图标，将样例关联到同一源码；也可从浏览器按钮右侧菜单选择 **Import to CPH**，直接导入样例。Get Problem 本身不初始化 CPH，替换已有样例会要求确认。
4. 编写解答，按 **Ctrl+Alt+B** 运行 CPH 样例，按 **Ctrl+Alt+D** 聚焦评测器。支持编辑、添加、删除样例和从 JSON 导入样例，也可单独重跑、查看输出差异或停止当前运行。CPH 元数据保存在工作区的 `.cph` 目录中。
5. 在题面选择本站的 C／C++ 编译器，聚焦源码按 **Ctrl+Alt+S**，或点击题面的提交图标，主动提交当前编辑稿（含未保存修改）。OJ Connect 展示本次提交的阶段和正式评测结果；蓝桥在准备时先显示阶段页，确认记录后同页更新。

OJ Connect 已接入洛谷、AtCoder、Codeforces、牛客 ACM 和蓝桥公开普通练习，各站支持范围见 [扩展使用说明](../extensions/becoder.oj-connect/README.md)。CF 仅支持普通公开比赛题的赛后 Practice；牛客限已支持的公开 ACM 题型和已结束比赛；蓝桥不含考试、进行中比赛或课程 lab。更广的 CPH 样例解析范围不等于交题范围；不支持的题源仍可在官网手动提交。

五站分别保存 C／C++ 编译器偏好；洛谷、AtCoder、CF、牛客从本站目录按 C++20／C17 基准向上择优，蓝桥使用已批准的本站 C++17／唯一 C 选项。未登录时部分站点可从已采证目录预选，提交前仍核对当前官网选项；本地编译器与网站编译器是两套独立设置。

每窗口同时只进行一项提交。需要手动认证时按提示主动进入内置浏览器；受理不明时使用 **继续查询**，不会自动重交。关闭记录页只停止本地跟踪，不能撤销官网评测。题目链接默认在内置浏览器打开；外部打开只通过明确标注的菜单动作进行。

本地样例通过不等于在线评测通过。本地 `debug(...)`、`dout` 是 BeCoder 辅助功能，提交到没有这些定义的 OJ 前，需要移除相关调用或自行提供兼容定义。

CPH 跟随最近获得输入焦点的 C/C++ 源码，但不会主动展开侧栏或切换当前侧栏视图（如资源管理器、搜索或扩展），需要自行点开 CPH 查看；切到题面、终端或样例输入框时保留当前题目。切到未关联源码时显示原有空界面，关闭当前源码且没有其他 C/C++ 源码接替时也回到空界面。切题前自动保存样例；保存失败保留编辑内容并提示失败。评测中保留当前运行界面，结束后对齐最近聚焦且仍打开的源码。当前窗口内保留各题的上次结果；源码修改后标注结果来自上次运行，重新评测后更新。

**CPH 样例导入**的内置解析器覆盖 Codeforces、AtCoder、洛谷、蓝桥杯、牛客、SPOJ、CSES、HDOJ、AcWing、LibreOJ（含归档站），以及明确支持的 DMOJ 站点：DMOJ、MOI Arena、Le Quy Don Online Judge、VNOI Online Judge、A.Y. Jackson Online Judge。导入仅支持非交互式、标准输入输出的 C/C++ 题目，不支持依赖 PDF 或额外资源的题目，也不会自动支持任意 DMOJ/Hydro 实例。网站结构变化、登录要求和访问限制可能导致解析失败；参见[解析器验证边界](../extensions/becoder.cph/test/fixtures/OJ-SOURCES.md)。

## 首页与浏览历史

标题栏的主页按钮会聚焦已打开的首页，没有首页时新建一页；标签栏的 **＋** 总是新建首页。内置浏览器工具栏的主页按钮则让当前标签回到首页，之后仍可后退到原网页。首页和网页共用原生浏览器标签，不另建开始页。

可以关闭最后一个首页或全部编辑器，保持空编辑区；需要时再点击主页按钮。首页网站链接在宽屏每行最多显示七个，其余链接自动换行。

首页底部的 **启动时显示欢迎页** 可调整启动设置；上次会话页面的恢复仍按原生规则处理。

`workbench.browser.colorTheme` 默认跟随 BeCoder：按当前主题的深浅性设置网页偏好，首页沿用 BeCoder 主题颜色；也可以固定浅色或深色。深色模式使用 Chromium 自动深色渲染，并尊重网页自身的配色方案声明。普通网页与 OJ Connect 打开的登录页面使用同一设置。

首页搜索框与地址栏共用 `workbench.browser.searchEngine`。在原生设置中的 `workbench.browser.customSearchEngines` 登记引擎名称及含 `{query}` 的 HTTP/HTTPS 模板，再把名称填入搜索引擎设置；查询内容会自动编码。内置引擎和 `none`（仅输入网址）继续可用。

在 **设置 → 扩展 → BeCoder IDE 功能** 中，“首页：网站列表”登记名称和 HTTP/HTTPS URL，“首页：显示的网站”控制显示内容与顺序。默认显示 Codeforces、AtCoder、洛谷、蓝桥杯和牛客；HDOJ 等已登记站点可自行加入显示列表。先在前者添加名称与 URL，再在后者加入相同名称；修改立即生效，清空显示列表会隐藏该区域。添加快捷入口不会自动增加题目解析或交题能力。

首页的新建 C、C++ 文件会建立相应语言的未保存文件，保存时原生对话框会按语言提供后缀；新建 BeCoder NoteBook 沿用现有文件夹与 `.bcnb` 保存流程。最近文件不放在首页，统一从浏览器工具栏右侧的 **历史记录** 打开，与网页记录分组显示并一起搜索。清除网页历史不会清除最近文件。

## 编译与输出

运行、使用输入运行和 CPH 共用 Runner 的内置 GCC、语言标准设置、受校验的编译参数和私有子进程环境。CPH 旧的 C/C++ Args 设置已弃用并忽略。本地编译使用 `-O2`、`-Wall`、`-DDEBUG` 和 UTF-8。左下角齿轮菜单的“生成 gch 缓存”会清除工具链中的旧缓存，按当前用户 C++ 配置在万能头旁生成可选的 `bits/stdc++.h.gch`，验证 GCC 命中后才报告成功。缓存不随安装包交付，也不属于工具链健康检查的必需资产；缺失或不兼容时，C++11/14/17/20/23 使用普通头文件编译。生成期间会显示进度，请保持 BeCoder 开启直至完成；重复生成请求会直接拒绝。修改 C++ 编译设置后，如需匹配的新缓存，可再次生成。不隐式添加 CPH、ONLINE_JUDGE 宏或解答程序的静态链接参数。

BeCoder 在启动时检查工具链清单及编译器、语言服务的关键文件；检查失败时提供获取最新 Setup 重新安装的入口。这不是对所有头文件的持续监控；GCC 在编译时遇到缺失头文件，会通过编译诊断报告。

BC 的运行和使用输入运行通过 ConPTY 呈现 stdout/stderr，不再由两条独立的 JavaScript 管道回调合并输出；程序语言与运行库本身的缓冲规则仍然有效。使用输入运行在编译前保存同目录 `input` 文件的快照，将字节无回显地送入 stdin，并在文件结束时关闭输入。CPH 则保留独立 stdout/stderr 管道：stdout 用于答案比较，stderr 单独展示，默认不影响判定。CPH 的可执行文件和运行目录归当前请求私有，因此相对文件访问行为与在源码目录运行的 BC 不同。CPH 是样例测试工具，不提供沙箱或等同线上 OJ 的内存限制执行能力。

可选的 CPH 自定义检查器使用用户安装的 Python，这是私有 C/C++ 工具链之外的明确例外。调用协议为 `python script input-file actual-output-file`，退出码为零表示通过，不向检查器传递期望输出。普通 C/C++ 样例评测无需 Python。

当前产品不包含通用 MCP 客户端、Debug/GDB、Source Control/Git 图形界面或远程开发。Git 仍可作为外部命令在原生终端中使用。

## 界面与布局密度

Modern UI 默认开启，提供圆角、悬浮侧栏与底部面板，以及更新后的编辑器标签、菜单和对话框样式。默认布局在工作台各区域之间保留间距。

打开“管理”齿轮菜单，选择 **布局密度 → 默认** 或 **紧凑**。紧凑布局移除工作台区域之间的间隙，并缩小内部间距，为内容留出更多空间。切换立即生效，选择保存在 `window.density.layout` 设置中，对应值为 `default` 或 `compact`。

若希望使用经典工作台界面，可在设置中关闭 `workbench.experimental.modernUI`。布局密度仅在 Modern UI 开启时生效；这两项设置已有的值优先于默认值。

## Beacon 与学习材料

点击编辑器右上角Beacon按钮打开助手，在其独立设置页配置模型。各窗口独立选择Beacon工作区；Spot／Flood需要正常根，Blackout聊天使用临时内存。主动添加文件、代码／Notebook／PDF选区先进入可查看、可移除的草稿，再由用户发送；Runner、CPH、Notebook运行及必要收尾时不排队发送。

候选源码用法见[Beacon扩展说明](../extensions/becoder.beacon/README.md)：正常所选根持续采集用户行为，Blackout仅关闭Beacon持久来源能力；代码由模型主动读取时同次保存，发送不捕获。五类共享队列、历史代码和同步摘要的源码与验收边界见[实施状态](beacon/implementation-status.md)，源码接通不替代真实五站和负责人体验验收。

## 数据与卸载

应用设置、用户安装扩展、缓存、旧版历史与解压工具链仍位于安装目录的 `data`，不与系统 Visual Studio Code 共用。Beacon 将工作区会话保存在所选根的 `.beaconWork`，源码关联笔记使用编辑器根下独立的 `.notebook`；这些工作区资产与安装私有数据分开。

向已有安装目录重新安装时，Setup 会在确认后完整删除并替换该目录，包括私有 `data`、`coding` 及自行存放的源码或学习资产。先备份需要的所有文件，不要把配置导出当作完整备份。只有安装目录外的用户工作区、`.beaconWork` 和 `.notebook` 不属于替换范围。

原生应用版通过 Windows 卸载入口删除 Setup 安装的程序文件、整个 `data` 目录、所有权标记、卸载登记及所创建的快捷方式；自行添加且不在 `data` 中的文件可能保留。安装目录外的用户工作区、`.beaconWork` 和 `.notebook` 保持不变。Portable 版不创建卸载器；关闭 BeCoder 后删除完整安装目录即可，曾选择创建的桌面快捷方式需手动删除。两种模式均不修改 PATH，不创建文件关联、协议注册、服务或启动任务。

## 扩展与更新

Open VSX 是 BeCoder 唯一配置的在线扩展源，同时支持安装本地 VSIX。BeCoder 受保护的内置组件不能由扩展市场替换，不兼容的 Microsoft C/C++ 扩展包会被阻止。

当前关闭了应用更新功能和相关设置，BeCoder 不会在应用内检查更新。新版本可从 [GitHub Releases](https://github.com/Bc408/BeCoder-IDE/releases) 获取，并由用户明确执行替换安装。
