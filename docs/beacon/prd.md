## 1. 定位与用户价值

BeCoder 提供准备好的 Windows 算法竞赛编程环境。Beacon 是其中以算法与编程学习为核心的长期陪伴式助手：理解正在讨论的代码与结果，帮助用户学习，将有价值的经历沉淀为个人资产。

算法导师是全产品不可抹去的核心能力与职业底色。称呼、相处方式和未来开放的表达配置可以变化，导师能力与不协助明确作弊的底线保持有效。人格及语言风格暂缓细化；导师愿景不构成替代真人教师或情感伴侣子系统的交付承诺。

核心用户包括初学者、进阶学习者和竞赛选手。典型求助为红色波浪线、编译失败、样例错误、递归与数据结构理解、疑似栈溢出或死循环、OJ RE 与越界、复杂度与卡常、题目知识点和完整解法。

用户写代码不一定在做题，题目也可能来自多网页、比赛 PDF 或主动材料。没有明确题目关联仍可正常求助。Runner 提供直接灵活的终端调试，CPH 提供便捷样例评测及接近赛场的体验；不强制用户先用 CPH。

产品价值是减少搬运材料、保持代码与结果可辨、持续适配教学、形成可独立复习的笔记，并把资产控制权交给用户。

## 3. 模式、权限与主动材料

| 可用条件 | 档位 | 文件及工作区记录读取 | 写入及本地留存 |
| --- | --- | --- | --- |
| 未选择工作区 | blackout | 无自由本地文件/工作区记录读取；可用主动材料和当前打开页面内容 | 不创建工作区聊天或学习资产 |
| 已选择且可用工作区 | blackout，用户主动选择 | 不新增该区历史、记忆、运行材料或文件读取；可继续使用切档前已加载上下文、主动材料和当前打开页面内容 | 临时输入/消息不落盘；宿主仅窄清理已接受分流发送消费的来源草稿 |
| 已选择且可用工作区 | spot，首次选择工作区后的默认档位 | 所选工作区范围内 | 工作区内有限学习资产写入，自身资产存入 `.beaconWork` |
| 已选择且可用工作区 | flood，用户主动选择 | 扩展至本机允许的文件 | 可写对象仍限学习资产；自身资产仍归所选工作区 |
| 已选择但不可用的工作区 | blackout，自动降级 | 无自由本地文件/工作区记录读取；可用主动材料和当前打开页面内容 | 不读取该区持久化资产；保留选择并提示原因 |

界面执行硬约束：三档入口始终显示；只有当前选择的 Beacon 工作区有效时，Spot 和 Flood 才能切换。首次选择工作区默认进入 Spot；用户主动进入 Blackout 会保留有效根，之后可以从 Blackout 恢复为 Spot/Flood。无选择或根不可用时只允许 Blackout；根失效会保留原选择、退出对话详情并隐藏该根历史和资产。Blackout 时工作区入口显示隐身或故障图标，但仍可打开选择器。

**页面读取是三档共有能力。** 模型可按需自由读取本窗口用户当前打开的 BeCoder 编辑器页面内容，包含编辑器最新未保存文本和已经打开的本人 OJ 提交代码/判题详情页；页面可能含个人信息，默认用户已知情可被 Beacon 阅读，不因页面含个人信息另弹首次许可。spot 页面读取也不因对应文件在 Beacon 根外而被当作根外文件读取。读取的是当前页面内容，不意味着取得对应本地文件的读权，不能借此从磁盘重读、补读引用/邻接文件、读取已关闭页面或自行打开未打开文件。凭据等已排除敏感内容的过滤和会话隔离仍执行。

**进一步联网查询个人信息须有明确许可，不限算法竞赛或 OJ。** 进一步联网查询个人信息仍须依据真实用户的明确许可及适用范围，已有匹配许可可以复用，缺失或超出范围时由模型先问询。负责人于 2026-10-14 确认采用 prompt 软约束，不新增宿主许可凭据、审批门或查询意图分类拦截；页面、登录状态、flood 和模型自行追加的记忆不能被当作用户新许可。本地根/档位/会话隔离、敏感信息过滤及学习资产写入条件继续由宿主执行。用户许可和限制可由主模型简单追加到 teach tips；blackout 不消费持久化许可记忆。

添加文件、拖入文件入口常驻。代码、PDF、Notebook 选区通过右键打开 Beacon，将所选内容加入可查看、可移除的草稿，用户补充问题后发送；右键动作不直接调用模型。

主动添加外部文件只授权当时采集该文件；不包含父目录、相邻或引用文件，也不授权持续追读。发送后材料固定为当时快照，更新需重新提供、由当前页面读取能力取得，或由当前档位独立授权文件读取。blackout 可用主动内容、当前打开页面及主动切档前已加载的继承上下文，不能借选区/附件/页面或继承从磁盘补读未提供材料，不落盘草稿、历史或附件，不通过工作区记忆入口消费持久化记忆；用户独立编辑和保存文档不受 Beacon 档位限制。

所有读取路径执行敏感信息过滤。本地材料权限与资产写入条件由宿主执行；联网个人信息的问询/许可规则按上文由 prompt 引导。网页、附件和模型文字不能扩大授权。本地无痕不等于模型服务商无记录；材料发送去向应可理解。

允许 Beacon 管理自身记录和记忆；用户明确要求时，可形成或修改 Notebook、讲义、图示等学习资产。不能替学生新建或改写 C/C++ 源文件，不能自主执行 Shell、运行或停止程序、登录或交题。正常学习时可以在回答和笔记中提供完整解法及教学代码。

spot 不能写根外 Notebook，不因拖入而取得写权限。说明限制，由用户调整工作区或切换 flood 后重新发起；不自动改根、提权或排队执行。Notebook 目标与保护规则见其正式设计。

## 4. 工作区与历史导航

### 4.1 选择与恢复

Beacon 主页同时承担工作区选择、历史选择和新聊天入口。唯一工作区控件紧挨连接设置按钮左侧；连接设置页不重复提供。Spot/Flood 收起显示文件夹名，悬停整体向左展开为绝对路径，点击后再向下整体展开。无根时显示“选择工作区”，悬停增加“选择后可使用 Spot / Flood”说明。主动 Blackout 显示隐身圆形图标，故障降级显示红色圆形感叹号；悬停保留状态图标，展开绝对路径及“未使用”/“出现问题”，点击仍打开同一面板。长路径中间省略，保留盘符和末级文件夹，完整路径由悬停提示提供，相邻按钮保持原位。

面板顶部为当前绝对路径及取消选择 `×`，下方历史不重复当前根，最底为“添加新工作区”。当前项取消后去重移入最近列表首项，保持面板打开并连续移动；历史项 `×` 仅移除最近记录，也保持面板打开。悬停只展开信息，点击才打开列表；鼠标离开控件与面板整体后关闭，键盘焦点仍在面板时保持，Esc 关闭并归还焦点。

已有聊天打开后进入详情页，详情页不显示工作区控件，也拒绝延迟到达的工作区切换消息。用户退出对话回到主页后，才可切换工作区；历史列表随宿主确认的工作区状态刷新。Spot/Flood 主页首次输入文字或添加材料时允许建立不进历史列表的持久化草稿对话，首次发送后转为正式历史聊天。空白主页不自动创建实体；Blackout 的草稿和首次发送均只在内存中存在。

工作区草稿包含未发送文字与附件，归对应对话保存、跨重启恢复，不按窗口另建草稿库。返回主页保留详情草稿并恢复主页草稿；详情页在主页有草稿时，右上角按钮改为“已有未发送草稿”及不同图标，点击回主页恢复；主页无草稿时显示“新聊天”，点击保留详情草稿并回空白主页。主页右上角始终为“新聊天”，点击清空主页文字、附件和对应持久化草稿，不删除正式历史或原详情草稿。草稿只回填输入框，不增草稿列表或标签。

切换工作区分别保存/恢复对应草稿，不复制输入或材料。主动切档保持当前页面、文字和已捕获附件，空输入同样替换目标侧旧草稿；不合并、不询问、不提供被替换草稿找回入口。Spot/Flood 继续同一对话。跨越 Blackout 与持久化类别后，首次新问题被宿主接受时才建立新对话；发送前切回来源类别则继续来源对话。分流前保留来源占用，来源消息不变；接受后清除本次消费的来源草稿版本，失败或迟到确认不得清掉后续新输入。

新对话继承当前已加载消息、附件、工具结果和协议材料的独立完整快照，不重读原文件、不追踪来源后续变化、不开放其他会话读取。Blackout 转入 Spot/Flood 并发送明确允许完整临时上下文保存到新持久化对话，不回写此前来源；删除来源不影响副本。当前 Webview 连续展示，在新问题之前显示细线分隔及“已继承上文，开始临时对话”或“已继承上文，建立持久化对话”；分隔信息归新对话保存，不作为模型消息。接受前失败保留输入；接受后模型网络失败不回填已成为消息的草稿。完整状态与导航边界见[三档切换与对话继承](mode-conversation-design.md)。

用户主动选择目录时，由 BeCoder 建立或核对该根下合法可用的 `.beaconWork` 资产目录，不要求编辑器先打开该文件夹；准备失败如实说明，不静默替换同名普通文件或改用其他落盘位置。

每个 BeCoder 窗口独立选择并记住 Beacon 工作区，重启恢复各自选择；最近 Beacon 工作区列表跨窗口共享，便于快速选择。编辑器文件或文件夹切换不自动改变 Beacon 根，打开普通文件夹、运行或评测也不初始化 Beacon 工作区。

同一工作区的默认恢复位置由最后关闭窗口留下的页面、对话及输入状态决定，不按最后输入时间决定。最后关闭窗口输入为空也恢复空白，不寻找更早非空草稿。重启可恢复主页或详情，直接回填对应输入；目标已被其他窗口占用时静默回主页，不提示、不抢占。其他活窗口不随默认恢复引用变化而切换页面。Blackout 临时草稿不跨重启保存；实现与验证边界见[专项方案](workspace-ui-draft-design.md)及[实现状态](implementation-status.md)。

`.beaconWork` 与 `.notebook` 独立，可以位于不同根。前者保存会话、日志、独立附件、材料快照、近期记录及工作区记忆；后者保存源码关联笔记。

有效工作区准备好后，BeCoder 随用户的 Runner、CPH 和 Notebook 运行行为开始记录该工作区内对 Beacon 能力有帮助的全套事实，包括真正使用的代码/输入、编译信息、实际结果及版本和来源。采集与落盘不依赖 Beacon 对话是否打开、模型是否配置或正在请求；只记录已发生行为，不额外执行程序或调用模型。具体字段、容量与持久化协议由技术方案确定。

### 4.2 切换与失效

本窗口仍有相关任务执行、回答未结束或必要数据未落盘时，直接拒绝本次工作区或档位切换，气泡说明原因。任务结束后由用户重试；其他窗口独立选择不受影响。

空闲工作区切换只在主页进行，并刷新为目标工作区的历史列表和可恢复主页草稿；用户可打开已有对话或直接输入。当前对话及草稿、附件、快照、归档状态留在原工作区，不迁移或复制；单纯切根不自动新建对话，也不将临时上下文带入目标区。主动切档与切根不同，按第 4.1 节在首次接受新问题时独立继承。

工作区被移动、改名或暂时不可访问时，保留原选择并提示不可用，降级为 blackout；主页不显示该工作区历史、记忆或运行材料。详情页退出至 blackout 主页，不静默替换路径或创建其他落盘位置。恢复访问后重新开放 spot/flood。自动故障降级不套用主动切档的延迟分流规则。用户主动进入 blackout 保留根选择、当前页面及已加载上文，主页仍隐藏该区历史，停止新增持久资产消费；恢复 Spot/Flood 后才重新开放相应读取。普通保存失败应单独说明，不能显示为保存成功；既有内容及原归属保持。

### 4.3 共享历史与单窗口对话

每个窗口只显示当前工作区的历史，不设跨工作区统一历史。多个窗口选择同一工作区时共用该区历史和资产；当前选择仍各自独立。

同一对话不能同时在多个窗口打开，包括归档对话。其他窗口尝试打开时仅提示“此对话已在其他窗口打开”，不提供切换入口。原窗口释放该对话后，其他窗口可以打开。跨窗口占用识别与异常释放由技术设计解决。

未发送草稿对话复用同一占用规则；另一窗口可从空白主页建立独立草稿。保存后离开某对话释放其占用，不因有草稿永久锁定；自动重启恢复遇占用按第 4.1 节静默回主页，区别于用户主动点击历史的占用提示。

## 5. 对话、材料与运行上下文

### 5.1 自然求助

用户保持代码、Runner 和相关资料页面打开，直接问“为什么这次编译错误了”。BeCoder 已随用户行为采集并落盘合法范围内的证据；Beacon 向模型说明当前对象、材料来源/版本、记录覆盖情况，以及可用工具和信息入口，引导模型按需读取足够材料。充分上下文不等于在首次请求自动塞入代码、输入和输出全文，也不让用户先整理材料清单。

当前对象提示默认跟随编辑文件，允许手动固定文件或题目并恢复跟随。多题关联、材料选择和补读策略属于技术研究；不强制每次指定题目，不因页面打开就认定其题面与当前代码对应。实际来源、缺失、截断和代码版本应可辨。

执行者可在程序运行中采集现场证据，读取机制不以强制停止程序为前提；这不表示输入区可在执行占用时发送新请求。Runner、CPH、Notebook 运行及必要清理/证据收尾期间，Beacon 使用暗淡禁用发送箭头，文字和附件保留，拒绝发送不排队或补发；仅真实回答显示暂停。没有输出不能直接断言死循环；编译诊断、终端、CPH 和 OJ 判定须区分。可以对照当次运行快照与当前未保存代码，但“看起来改好了”不能冒充重新运行验证。

### 5.2 近期运行队列与行为证据

每个有效 Beacon 工作区分别维护 Runner Run/Run With Input 合计约 10 次，以及 CPH 约 10 轮完整评测的 FIFO 队列，彼此独立。源码必须位于发起窗口当前有效 Beacon 工作区内才持久化；范围外运行照常进行，记录仅临时可用，不写入其他工作区。

Runner/CPH 的原始运行产物是可淘汰的近期缓存，不按受保护的用户资产处理。采用朴素实用的队列即可，合理控制存储占用；损坏、淘汰或清理这些缓存不需要扩展成复杂的资产恢复体系。用户笔记、会话已消费的独立材料、附件和记忆仍按各自规则管理，不能随原始缓存清理。

取得当次主代码快照并开始编译后，成功、编译失败、运行失败或取消均占一次；编译尚未开始的失败不计。CPH 一轮含多个样例仍算一条。保存实际代码、输入和对应结果，完整输入受容量上限约束，超限明确不完整。首版不另存本地头文件历史快照。

记录被本会话实际使用后，会话保存自己的材料快照，队列淘汰不破坏已保存证据。Notebook 每份 input 仍仅保留最近结果；工作区内 Notebook 用户运行同时产生独立的 `.beaconWork` 行为证据，不进入或挤占 Runner/CPH 两条队列。该证据绑定真正运行的笔记、程序块、input 块、代码/input 和实际结果；保留及容量规则进入技术设计，不默认套用两条 FIFO 的次数。临时记录能否读取仍受档位及材料授权约束；当前打开页面已有结果可经页面入口读取，但页面不能授权完整历史记录查询。

### 5.3 会话隔离、压缩与管理

当前会话不搜索、读取或合并其他会话的消息、摘要、附件及内部材料；同题、同工作区和 flood 都不解除隔离。用户主动跨临时/持久化档位发送时，只复制当前已加载上下文为新对话独立快照；这是明确继承入口，不是跨会话检索或持续读取许可。允许使用独立工作区记忆，不能借追溯记忆来源取回其他对话。

每个持久化会话独立保存实际使用材料和附件。同一文件用于多个会话时分别保存，不建共享大附件池或跨会话引用计数。

接近模型上下文容量时可自动压缩较早内容，近期优先保留原文，界面提示。完整留存历史不因此删除，必要时可回读本会话自身材料；blackout 只在临时内存中处理。

归档保留完整会话，仅移出普通历史列表；归档列表可阅读、取消归档，回到原工作区后再继续发送。归档会话只读，附件不搬迁。

删除经确认移除该对话记录及其专属材料、附件，不连带删除已形成的记忆、Notebook、讲义、图示、用户源码或近期队列原始记录。记忆的后续纠正与删除由其自身入口管理。

## 6. 教学记忆与 dream

只设工作区记忆，聚焦算法、编程学习和竞赛。由主对话模型判断值得保留的观察；用户可查看、添加、直接编辑文本，后续交流热更新，无需重启或新建会话。

| 对象 | 使用与维护 |
| --- | --- |
| teach tips | 简短教学理念、风格和适配指导，初始内置，默认带入；也可记用户明确的网络个人信息查询许可/限制；首版主模型只需简单追加，不自主改写旧内容；用户通过查看和直接编辑把关记忆质量，模型追加不能新增或扩大用户许可 |
| student status | 有时间跨度的学习与教学观察，按需读取；日常模型仅追加，旧内容由用户手动编辑或主动 dream 整合 |

追加保持克制，允许不追加，不逐条批准。记忆质量交由用户通过查看和直接编辑把关，不建立复杂的自主维护、优化或质量审查系统。轻量告知采用“Beacon thought that”式方向，让学生了解 Beacon 的观察；不展示内部推理、不把猜测说成事实，不用单次错误或 AC 固化能力标签。教学适配不能改动全产品底线。

用户在记忆页面主动点击 dream，成功后整合结果直接成为当前 status；旧完整 status 默认作为人类可读的记忆归档保存，历次保留，不采用运行队列淘汰规则。归档可查看、在 Beacon 内不可编辑，默认不参与日常对话或教学适配。

用户手动取消记忆归档时，将内容朴素追加回现有 status，不覆盖、不自动去重或智能合并；需要整合再主动 dream。归档保存当时理解，不保证正确。记忆归档、会话归档与 Notebook 备份各自独立，删除来源会话不撤销派生记忆。

## 7. Notebook 与 OJ

Notebook 是 BeCoder 的独立核心能力，可手动编写并由用户主动运行 C/C++。文字、公式、图片、代码折叠、多组 input 和最近实际结果共同构成可持续丰富的笔记。

关联笔记按编辑器打开根、源码相对目录和完整文件名定位，例如 `比赛/A.cpp` 对应 `.notebook/比赛/A.cpp.bcnb`。内容互相独立，源码改名、移动或删除不带动笔记及备份同步。无打开文件夹时禁止新建和关联，已有笔记仍可独立打开使用。

用户显式请求 Beacon 整理或修改，目标明确且合法后直接综合当前会话及授权材料，不再次圈素材，不跨会话补故事。已有笔记以最新编辑稿含未保存修改为基准，完整备份后直接改写；改写失败沿用原生编辑/保存处理和实际状态反馈，不要求强制保住或恢复原稿，不额外实现回滚体系。备份为同目录最近一份 `.bcnb-backup`，像普通 Notebook 使用，不参与关联、不提供专用恢复入口。

后续题目档案能力目标完整覆盖洛谷、Codeforces、AtCoder、[蓝桥云课题库](https://www.lanqiao.cn/problems/)。用户在内置网页自行登录、提交和查看判题，再向 Beacon 求助或整理；外部浏览器主动材料路径保留。

三档可按页面能力读取用户已经打开的本人提交代码和判题详情，不另行请求个人信息查询许可；不能借此导航、补请求或读取未打开记录。spot/flood 进一步通过网络查询某平台某账号本人记录时，按第 3 节的个人信息查询规则说明范围并取得用户明确许可，之后在许可范围内按需读本人同题相关提交代码与判题详情，不人为限定固定条数，不逐条弹窗或后台同步账号。

用户许可和限制可记入当前工作区的 teach tips，与 student status 分开。模型依据真实用户决定、适用平台/账号/题目范围和最新撤销行动，不跨工作区自动继承；具体表达由工程方案确定，不新增宿主许可台账、审批门或查询意图分类器。不因撤销自动整理 status，也不从 status/dream 或模型自写 tips 恢复已撤销许可。登录、页面打开和 flood 不替代进一步网络查询的许可；blackout 可以读当前打开页，但不自动查额外本人记录或持久化许可记忆。

材料足够真实有用就直接整理并说明缺失，缺关键依据可能写错核心事实时简短询问。未 AC、解法未完成或部分记录不可得不单独拒绝。质量目标是一个月后无需原聊天仍能理解关键解法，忠于个人探索与真实验证，不虚构成功经历。五部分骨架及全部运行、关联、保护细则以 Notebook 正式设计为准。

## 8. 基础体验与验收目标

模型服务包括 DeepSeek、百炼、Moonshot、Ollama，每家一组连接/密钥，配置相互隔离。模型获取先形成临时候选，确认后替换集合和能力，保留同 ID 名称/生成参数；取消或失败不改配置。只有供应商级启停，聊天模型由用户选择；测试与启用、当前选择相互独立。活动回复固定开始时设置，改动只影响后续请求。

视觉、推理、工具能力只存支持/不支持；服务未明确否定时默认支持，完整服务能力列表的缺失项按不支持处理，可由用户修正。不维护安装内能力目录，不按任意型号猜能力。容量缺失使用可修改的 32768 上下文、24576 输入、8192 输出 Token 默认值，并按已知上下文约束缺失项；默认配置不证明实际能力。能力同步清除手动修正并保留生成参数，冲突在下次请求前明确阻止，不静默删改。

地址和模型详情分别保存/取消，密钥单独添加/更换或直接删除。密钥不默认回显；用户主动显示时仅进入当前设置页临时状态，隐藏/关闭即清除，普通快照不含明文。模型 ID 不在详情中修改，容量直接数字输入；不增加模型类型、音视频或价格设置。完整现行流程见[Beacon 使用与设置](../../extensions/becoder.beacon/README.md)。

图片输入受模型视觉能力约束，不悄悄 OCR、换服务或丢弃图片。联网与文件权限独立，默认开启且有开关，保留免额外搜索密钥的方向；实际第三方可用性另行核查。

暂停保留部分回答，继续作为新请求衔接；重新回答及编辑用户消息延续已有分支语义。新建、重命名、复制、稳定代码与公式渲染、滚动跟随、窄侧栏与无障碍保持可用。未配置、关闭或请求失败不破坏编辑、Runner、CPH 等基础流程。

| 验收旅程 | 必须成立的结果 |
| --- | --- |
| 首次使用与重启 | 模式硬约束有效，窗口恢复独立选择，历史显示正确工作区，最近列表可快速选择 |
| 切换与路径失效 | 忙时拒绝，空闲不迁移；失效保留根并开放 blackout，恢复后重新开放持久化模式 |
| 双窗口 | 历史共享而根选择独立；同一对话第二次打开仅提示 |
| 自然求助 | 说明情况及工具/信息入口，模型按需取得材料；代码与实际运行对应，缺失及推测可辨；执行占用时保留草稿并拒绝发送，不排队 |
| 页面与文件分层 | 三档可读用户当前打开页面含未保存内容；blackout 不沿页面路径读磁盘/隐藏记录，spot 根外打开页不等于根外文件读权 |
| 个人信息与查询许可 | 已打开本人信息页面默认知情可读；额外网络查询取得/复用明确许可，prompt 尊重最新撤销，tips 追加不产生授权，不新增宿主许可台账 |
| 记录留存 | 工作区准备后随区内用户行为记录 Runner/CPH/Notebook 证据，不等模型请求；两条队列各自淘汰，Notebook 证据独立，已用于会话的快照独立保留 |
| 长期交流 | 压缩不删除完整历史，隔离不被记忆或 flood 绕过，教学变化可见且可编辑 |
| 主动 dream | 成功直接生效，旧 status 可读归档；取消归档仅追加 |
| 归档与删除 | 用户能区分操作，记忆与独立笔记不因来源对话被删除而消失 |
| Notebook 完整体验目标 | 四条流程完整；v2.0.0 验收当前已实现部分，未实现流程在后续交付时验收 |
| 教学诚信 | 正常学习可完整讲解，明确作弊请求不因角色配置获协助，不监控或凭页面指控 |

这些是需求验收目标；当前已实现范围、局部验收与未验证场景见[实现状态](implementation-status.md)，不能由本表推定全部通过。

旧“不缓存分发社区题解”、零遥测、独立持久化开关等意向留在来源材料，需专项评审；不改变本稿三档硬约束或扩大已批准能力。

## 10. 少量仍需产品决定的事项

1. 后续已确认能力的版本排期、分批交付与受限模型的可用体验，需技术事实支持后决定；v2.0.0 仅交付当前已实现能力的范围已确认。
2. 自动压缩、记忆和 tips 更新带来的调用费用怎样告知，是否提供相关控制。
3. dream 失败/取消、工作区资产的导出/分享/删除等管理范围；不重议已定归档及来源删除不影响记忆。
4. 赛事规则不明确时怎样询问、解释与提供允许的替代帮助；底线已定，具体情境仍需研究。
5. 内置网页精确选区、父子 Notebook 建议被拒绝时确实存在的目标冲突，仅在真实流程证明需要时补齐。

控件位置、并发协议、目录内部格式、容量、上下文关联和 prompt 列入界面或技术设计。历史导航、跨根队列、主动切档后首次发送的独立继承及两条分隔文案均已确认，不再作为待议项反复询问。
