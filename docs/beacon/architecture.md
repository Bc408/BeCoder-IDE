# Beacon 总体架构

修订：2026-11-24。负责人允许方案收敛；[新实施计划](../superpowers/plans/2026-11-24-beacon-context-tools-rebuild.md)已获负责人实施批准，当前状态见[实现状态](implementation-status.md)。本轮主文为[工具设计基线](../superpowers/specs/2026-11-23-beacon-tool-interface-simplification-design.md)。

## 1. 产品与分工

Beacon跟随学生当下的学习活动取得代码、题意和真实结果，作算法与编程教学。Notebook是独立、可选的学习文档，普通求助不以笔记为入口。

原功能owner提供事实；harness采集、持久化并确定性整理；LLM选择讨论对象、按需取材和教学。工程层不把解码、事件归并或字段适配转嫁给模型，也不固定当前题目。

run目录与正文都不嵌入题目身份、标题、URL或题目候选，不透传CPH原始题目配置，关联由LLM判断。CPH仅保check结果，不保存检查器类型、配置、路径、代码、命令或诊断；检查器代码沉淀留后续事项，对拍检查器／随机生成器另作设计。

## 2. 数据流

1. 用户五站Get Problem／Import to CPH形成problem读题记录。
2. 用户Runner、CPH或Notebook每份程序的一次编译及关联input运行结束后形成run记录；同一程序多input一条，多个程序分别入队。
3. OJ Connect完整取得最终测评结果后入verdict；同站同题可靠实际提交代码完全相同替换旧结果，代码缺失时保存并跳过去重。
4. LLM按需readCurrentCode取得所有当前可见分屏C/C++页面的完整dirty稿，只正常返回，不读后台标签或另存副本。
5. LLM按oj＋problemId调用fetchProblem，复用OJ Connect核心解析取干净题面，只进入上下文。
6. 专用能力不足时，沿原权限用文件、普通页面、主动材料或browseWeb补充。

这些链路不新增运行、交题、登录、Shell或后台个人历史查询。发送问题不自动读代码或绑定对象。

## 3. 所有者

| 所有者 | 职责 |
| --- | --- |
| 编辑器／页面owner | 允许查看的代码／普通页面、实际文件身份、dirty内容和版本，不为读取打开资源 |
| OJ Connect／浏览器 | 五站身份和只读题面解析、用户看题与测评内容，核心用户操作独立 |
| Runner／CPH／Notebook执行层 | 本次执行输入、编译复用、独立进程、取消、输出、状态与清理；不依赖Beacon队列或工作区 |
| 采集适配层 | 消费执行事实，按程序形成记录，统一字段、来源差异及8KiB输出保留；不参与执行控制 |
| harness／Store／Coordinator | 根资格、三个共享队列、工程整理、权限、原子发布与同版读取，不另建代码存储 |
| 工具与provider | 语义化接口、校验、实际结果与预算，通用工具不作被裁切来源旁路 |
| 会话与协议 | 原消息、真实工具交换、有效分支、摘要和恢复，重放不执行 |
| 系统提示 | 导师规则、环境认知、按需取材、事实表达，内部身份默认不搬给学生 |

模型写Notebook等输出内容的工具本轮移除，后续另行搭建；用户独立编辑、保存和运行保留。

## 4. 数据归属

| 数据 | 归属和生命周期 |
| --- | --- |
| problem | 当前.beaconWork共享13条，按problem（oj＋problemId）与filePath共同去重；同题同路径删除旧项，新ID、新viewedAt入队尾；不同路径分别占位，不保存题面正文 |
| run | 当前根共享30条，三来源共用；每份程序一次编译及关联input为一条，结束入队不去重；合计编译／程序输出8KiB |
| verdict | 当前根20条，完整最终结果才入队；同站同题实际代码完全相同替换旧结果入尾，缺代码保存但不去重 |
| 当前代码／模型联网题面 | 实际返回进普通上下文，无专门队列、缓存、独立全文或历史回读库 |
| 消息／附件／草稿／私有材料 | 按会话和有效分支隔离，共享记录不授其他聊天访问权 |
| 摘要 | 有效历史的输入投影，保原始历史，不改变业务队列 |
| 源码／Notebook | 独立用户资产，不随业务队列淘汰，不由本轮模型工具写入 |

运行稿和提交稿只作为原记录一部分存在。独立代码快照全部撤回，旧的整段对话跨分支代码回读例外同时取消。

三个记录工具分别注册：readProblemRecord／readRunRecord／readVerdictRecord，空参列保留记录简短目录，带ID读完整已整理正文。目录按需，不每次自动注入；模型不再协调producer／revision／part，不增加记录分页。正文超本次上下文按既定机制压缩，不再次裁剪。

Notebook批量点击时固定本次代码与input，同一代码块本次编译一次、各input独立运行；代码块仅按C/C++从1计序号。编译失败跳过本块input继续其他块，input错误／TLE／OLE继续后续，用户停止结束批次。一个Notebook批量内多个程序分别形成记录；执行层与采集适配层解耦。

## 5. 题目与兜底

五站正式题面统一由fetchProblem取得，独立聊天搜索开关；problem只提供用户看题行为。模型取题不制造看题记录，不调用完整Get／Import／面板动作。

不再将独立题目线索工具、多来源逐层解析、本地题面与联网选择作为固定链路。LLM结合用户话语、记录、页面文件信息及授权文件判断，不足才澄清，不建永久绑定库。

非五站CPH题可由inspectFile读取.cph目录内对应.prob元数据，取得原题链接后在搜索开启时由browseWeb获取。五站完整闭环承诺不扩大到其他题源；配置样例与实际运行分别表达。readPage覆盖其余普通非C/C++页面，PDF和复杂提取本轮暂不展开。

## 6. 模式与权限

软件采集以发起窗口正常所选Beacon根为资格，无根／异常不采集、不写替代位置。有效根在Blackout也持续采集三个业务队列，不依赖聊天或模型。

Blackout关闭Beacon持久目录与读取，不建镜像或缓存旁路，当前代码仍可读。切回只看到仍保留记录，不补采；fetchProblem仍可只读联网，browseWeb由搜索开关控制。Spot／Flood不扩大生产根，各工具保原敏感过滤和真实权限。

运行／测评事实通过持久记录供给，不从功能面板、终端渲染或Notebook输出字段绕行；主动提供的材料保用户材料身份。模型不写学生源码、不自主运行／停止／登录／交题。

## 7. 协议、压缩与验收

完成交换保原名、参数和真实配对；中断恢复和协议重放不再执行。弃分支不恢复旧消息、许可或材料；新工具不因旧历史获得已撤销能力。换模型仍按provider／baseURL／model兼容性处理私有字段。

[同步压缩](context-compaction.md)保当前模型、90%／60%和一步一次恢复，批次闭合后切换，提交成功才发布。本轮只清除代码队列依赖，不重设计压缩算法。

工具划分、目录／整读、代码范围、队列生命周期、五站题号及run字段方案已收敛；新计划已补齐工程接线、兼容策略与验证范围，已获负责人确认并进入本会话Native实施。文档校验不等于源码、模型或五站体验验收；旧计划与评估只保历史身份。
