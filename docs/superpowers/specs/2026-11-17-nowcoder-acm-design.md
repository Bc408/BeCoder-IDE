# 牛客 ACM 接入 OJ Connect 设计

日期：2026-11-17。状态：负责人已选择与官网 ACM 手动提交一致的链路，并确认本页的文件命名和三站统一等待边界，要求落盘及准备下一步工作。本文是已批准的实施设计，不是负责人验收声明。配套[协议证据](../../oj-connect/nowcoder-protocol-evidence.md)与[实施计划](../plans/2026-11-17-nowcoder-acm.md)一起阅读；负责人后续已授权源码实施、测试和干净 stage；未授权提交或推送。实施状态与证据见开发入口。

## 目的与当前基线

在 BeCoder 内完成牛客 ACM 的源码→看题／导入→本地样例→快捷键提交→本次正式结果，沿用已认可的洛谷核心使用体验。牛客的题目身份、语言、成绩和权限按官网事实处理，不为视觉一致伪造数据。

编写前基线为 `OJ_connect@cf721434d959b23bc68175cf50369ad56db570cd`，跟踪 `origin/OJ_connect`，工作树干净。设计编写时产品只装配洛谷和 AtCoder；牛客仅有目录配置、侧栏占位和 CPH 既有题面解析器，没有 OJ Connect 牛客 adapter、宿主提交或结果实现。此前真实测试是隔离协议探针，不能代替产品闭环。

共同产品约束由 [OJ Connect 入口](../../oj-connect/README.md)、[架构](../../oj-connect/architecture.md)、[共同流程设计](../../oj-connect/shared-workflow-design.md)及负责人最新决定拥有。洛谷 4.20.0 固定参考为 `987ca974b5419230a07b59a195ec44026e16f6f4`；直接复用现有迁入组件，不再写一套牛客页面。

## 选型决定与适用范围

采用官网 ACM 现行 `/nccommon/submit_cd` 与 `/nccommon/status` 路线。研究中生成的 `855…` 记录与负责人手动提交的记录形态一致；同题同源码对照中，现代 ACM 记录虽然 AC，但官网成绩与代码长度尚未对齐。选择依据是目标业务结果吻合，不是“旧接口必然更可靠”。

ID 当前以 `8` 开头只是观测，不作为协议条件或客户端校验规则。有效正式 ID 按正整数处理。不得通过自行补算分数／长度掩盖官网记录差异。

首批范围：

- `https://ac.nowcoder.com/acm/problem/{problemId}` 的公开 ACM 标准输入输出题。
- `https://ac.nowcoder.com/acm/contest/{contestId}/{index}` 中已结束、公开、个人可提交的 ACM 题。保留比赛身份，不加入比赛列表、监控或排名功能。
- 用户编写完整 C／C++ 程序；具体语言只显示当前题目在该链路实际允许的选项。现有真实发送覆盖 C++，C 的真实验收须另列。

不接入 www practice／题霸函数模板、PAT、团队／私有／付费／进行中比赛、远程自测、题解、题库管理。SPJ／交互题及明确超出已验证题型的入口不推定支持。不会把不支持的入口静默改投到公开题库，也不建立现代备用通道。

## 用户流程

1. 左侧 OJ Connect 牛客行显示当前共享会话可确认的账号；登录动作主动打开官网。普通浏览器登录与插件登录是同一持久 Session，没有第二套账号存储。
2. 聚焦源码按 Ctrl+Alt+P，按站点目录与文件名定位题目，失败提示输入匹配的题号／完整 ACM URL，不自动打开官网替代插件题面。
3. 在内置浏览器找到支持的题目后点击 Import，在当前工作区的配置牛客直子目录创建／打开 `.cpp` 并显示共同题面；默认目录 `nowcoder`。已有源码与未保存稿不覆盖。
4. 题面的“传送至 CPH”显式复用该源码和真实样例；Import 不自动创建第二份源码或初始化 CPH 数据。
5. Ctrl+Alt+S 固定当前源码快照，包含未保存内容；选择本题允许的 C／C++ 编译器，按牛客与语言族分别保存偏好。准备时显示现有进度，编辑器仍可操作。
6. 通过同一 Session 单次发送；取得正式 ID 即释放发送占用、打开共同评测页，不等待官网记录页、最终判定或非必要源码回读。
7. 独立读取该 ID 的最新状态。等待／评测中用现有洛谷蓝色动画；有真实测试点才显示点位，没有则只显示整体状态。终态保留原站状态及可得字段。

正常准备、发送、回执及评测不创建、导航或展开内置浏览器标签；也不使用隐藏 BrowserWindow 或 webContents。需要登录、权限或人工认证时在插件提示，由用户主动进入官网，不实现新认证流程，不自动续投。

### 简单且可逆的题目标识

沿用目录优先、文件名猜测和失配输入，不引入绑定数据库。负责人已确认下列命名，保留原始题目入口，不自动转换提交归属；这不是牛客官网编号规范：

| 场景 | `ProblemRef.nativeId` | 规范 URL 路径 | 导入文件示例 |
| --- | --- | --- | --- |
| 公开题库 | `problem/18204` | `/acm/problem/18204` | `nowcoder/18204.cpp` |
| 比赛题 | `contest/5657/A` | `/acm/contest/5657/A` | `nowcoder/5657_A.cpp` |

在已识别的牛客目录反向解析 `18204`／`18204.cpp` 和 `5657_A`／`5657_A.cpp`，用户输入还接受 `5657/A` 及上述完整官网 URL。无站点目录的纯数字或通用比赛文件名不用于全站自动猜测，避免抢占其他 OJ 身份；在输入框或明确站点上下文中再解析。比赛 index 以官网身份校验，不猜内部 questionId。非支持 URL、不匹配的站点目录和有歧义输入明确提示。

## 单一请求链路与职责

```text
当前源码快照 + ProblemRef
  → 牛客 adapter / 固定宿主命令
  → 当前窗口、存储范围及账号对应的原生 Session
  → 获取必要元数据和该路线实际语言
  → /nccommon/submit_cd（一次）
  → 正式 RecordRef → 共同评测页
  → /nccommon/status（只读、串行查询）
```

| 所有者 | 职责 |
| --- | --- |
| 现有扩展共同层 | 源码快照、目录／输入、语言选择及偏好、并发提示、题面、导入与评测页 |
| 牛客 adapter | 实现现有 `OjAdapter`，固定站点身份和文件名，将受限宿主结果交给共同层 |
| 牛客协议模块 | 静态身份／题面／语言与状态映射，形成现有 `ProblemDocument`、`RecordSnapshot`，不另建领域模型体系 |
| 受限 bridge 与原生 Session client | 任务句柄、窗口／会话／账号绑定、固定端点、一次发送、取消后不晚发、请求及尝试资源释放 |
| CPH | 同源码样例关联与本地运行；已有不属于本批范围的 parser 保持原行为 |

新增 `NowcoderAdapter`、`CommandNowcoderHost` 和站点专用的原生 client／bridge，沿用洛谷“业务操作＋真实会话”的组织方式，但不复制其 CSRF、验证码和推送机制。共同控制器和 DTO 只补实际需要的三站枚举／校验；不搭建通用带登录态 HTTP API、策略工厂或插件注册框架。

扩展／Webview 不接收 Cookie、短期授权或任意请求入口。宿主从当前存储范围取得原生 Session，无浏览器页面时仍能使用。已准备任务和正式记录绑定原窗口、存储范围与账号；登录／退出或切换会话使旧操作失效。超时／读取失败是 unknown，不能误报退出。普通会话字段轮换不能触发无限刷新。

### 协议身份与发送

公开题库显示号、比赛题号与内部 `questionId` 不等价。同一题的公开入口与比赛入口也不能互相替代：

| 入口 | `questionId` | `tagId` | `subTagId` | `doneQuestionId` |
| --- | --- | --- | --- | --- |
| 公开 18204 | 235780 | 4 | 0 | 18204 |
| 5657/A | 235780 | 4 | 1 | 5657 |

这是实测样本，不是硬编码映射表。元数据通过官网读取并校验；静态提取 `window.pageInfo` 的所需字面量，不执行远程脚本。语言来自 ACM 现行配置及题目规则，不混用现代 configs 的 `id`、`languageId` 或洛谷／AtCoder 编号。本轮没有证明生产所需的完整无网页语言获取已闭环，先完成实施计划任务 1 的证据门槛。

正式 POST 为 `application/x-www-form-urlencoded`，业务字段为 `questionId`、`tagId`、`subTagId`、`doneQuestionId`、`content`、`language`、`languageName`。`content` 是当前源码快照；上下文、语言与语言名由宿主核准，不接受任意 URL／字段由 Webview 传入。未知／不完整返回不能当成功。

不每次提交串行刷新全侧栏；只做本次发送需要的身份与权限核验。同次已取得的元数据直接复用，暂不增加跨任务缓存、预热或后台准备。任务 1 如发现必须新增运行时解析依赖，应先记录具体解析对象、现有能力缺口、版本与许可影响，不将研究目录的 Acorn 作为隐式生产依赖。

## 发送与记录生命周期

- 沿用共同提交 busy 约束；重复快捷键立即反馈，不排队。宿主句柄单次消费，双调用、迟到准备、取消及销毁不能产生第二次 POST。
- 未发送失败返回 `not-sent`；已经发送但响应丢失／不完整返回 `unconfirmed`。不把网络错误当明确拒绝，不自动重发，也不切换接口。
- 正式 ID 到达后返回 `record`，不要求再等详情页面加载；结果页失败仍保留 ID，继续查询不回到交题阶段。
- 受理不明时仅作显式只读确认；没有唯一记录证据就维持未确认。不能用列表最新 AC、同题最近记录或 ID 前缀认领本次提交。历史／源码读取不足时不增加复杂猜测器。
- 负责人已决定三站统一沿用洛谷的本地等待边界：每轮自动跟踪约 120 秒，到期停止本轮跟踪，保留 ID 和最后状态，允许显式继续查询；新一轮只查询已有记录，不重交。关闭结果页可以提前停止本地跟踪，不表示评测失败或撤回提交。该新决定取代此前 AtCoder 不设整轮截止的对应要求；当前候选已在共同 RecordController 移除 AtCoder 特判；合成期限回归与真实网站验收分别记录。
- 统一的是本地等待、超时提示和继续查询行为，不强行统一站点协议和查询频率：洛谷保留推送，AtCoder 保留有效官网 Interval／既有回退，牛客初版沿用共同层 2 秒查询间隔。读取不重叠，不另加三套期限配置或通用调度器。
- 关闭结果页、扩展停用、窗口关闭及范围切换，释放对应请求／监听／句柄；不退出账号、不影响其他 OJ。结束旧任务不能删除新任务资源。

## 共同题面、评测与字段语义

复用 `webview/luogu/`、现有共享内容清洗、公式、高亮及复制控件。牛客正文保留原 HTML 语义，不转成 Markdown 再解析。样例说明紧随对应样例；难度、标签、限制有准确来源才展示。已有 CPH parser 可参考选择器和样例提取，但不把它覆盖 PAT 等场景的全部逻辑纳入 OJ Connect。

等待中不显示分数、耗时／内存的占位零值；终态的真实 0 分可以显示，缺失分数不补 0。`rightHundredRate` 不是比赛分数；全站个人历史与单场比赛可能分别按 100 和 50 等尺度展示，不在客户端自行换算。状态接口缺少正式分数时先省略；任何新增成绩读取都必须有实际字段来源，且不阻塞初始结果页。

已观测状态 0／1／2 为等待或评测中，5 为 AC，4 为 WA，12 为 CE，14 为内部错误；其余状态需按当前官网表核对，不能用 `status >= 3` 一律当成功终态。`code:0`、错误对象或缺失 ID 均不能替代记录结构校验。返回的 ID 必须匹配目标记录。

只有通过数／总数时显示真实汇总，不制造单点表或“第几个点”的判定。`isShowTestCase=false` 时不绘制假点位；CE 的 0/0 不显示。编译输出可直接取 `memo`，不等源码详情。源码核对尚未执行则 `not-checked`，不可访问则 `unavailable`；不能为追求 matched 给发送增加阻塞请求。

时间、内存的单位必须由当前官网格式器／实页核准；研究探针的原数不能直接拼接 ms／KB。CE 记录源码可能带精确标记的诊断 JSON 前缀，只有新增源码读取确有需要时按已验证结构分离；不得无条件删首行或按 `#include` 猜起点。
