## 不重新开题的核心边界

- Beacon 工作区按窗口独立选择和记住；最近列表共享，同工作区共享历史与独立记忆。无工作区时仅 blackout 可选；有效工作区可选三档，用户主动 blackout 时保留根选择但暂停消费该区资产；失效根保留选择并降为 blackout。
- 工作区选择和历史列表只在 Beacon 主页出现；已有聊天详情页不显示也不接受工作区切换。主页首次输入可建立不进历史的草稿对话，首次发送转为正式聊天；单纯切根不搬运对话或材料。主动切档保持页面与输入；Spot/Flood 共用当前身份，跨临时/持久化类别后首次接受新问题才创建独立完整快照并清除被消费的来源草稿，不回写来源消息。同一对话只能在一个窗口打开；自动恢复遇占用静默回主页，用户主动打开遇占用仍说明原因。
- `.beaconWork` 与 `.notebook` 独立，允许不同根。Notebook 的源码关联按编辑器打开根、相对路径和完整源码文件名匹配，内容独立；不跟随源码改名、移动或删除。
- 用户选择工作区时由 BeCoder 建立并确保合法可用的 `.beaconWork` 资产目录，随后随该窗口工作区内 Runner/CPH/Notebook 用户运行行为落盘对 Beacon 有帮助的完整证据，不等到模型请求才开始采集。Runner/CPH 两条约 10 次 FIFO 独立；Notebook 行为证据独立、不挤队列，每份 input 仍仅保留最近结果；根外行为不写入该区。
- 三档均允许按需读取本窗口用户当前打开的编辑器页面内容，包含未保存修改、已打开的本人 OJ 提交代码/判题详情；页面可能含个人信息，默认用户已知情可被 Beacon 阅读，不额外询问。页面读取不授予对应磁盘文件、目录、引用文件或隐藏记录的读取权；凭据过滤和会话隔离仍有效。blackout 可继续展示及继承切档前已加载上下文，但不新增工作区历史、行为记录或持久化记忆读取，不落盘临时输入和消息；宿主仅可窄清理已接受发送消费的来源草稿。
- 进一步联网查询个人信息仍须依据真实用户的明确许可及适用范围，已有匹配许可可以复用，缺失或超出范围时由模型先问询。负责人于 2026-10-14 确认采用 prompt 软约束，不新增宿主许可凭据、审批门或查询意图分类拦截；页面、登录状态、flood 和模型自行追加的记忆不能被当作用户新许可。本地根/档位/会话隔离、敏感信息过滤及学习资产写入条件继续由宿主执行。
- 外部单文件主动添加不授权目录或持续追读。有限写入只面向自身资产和明确请求的学习资产，不改学生 C/C++ 源文件，不自主执行或交题。
- 记忆仅工作区级：主模型维护 tips，status 日常追加，用户可直接编辑；dream 主动整合并保存旧 status 的可读归档。删除来源对话不删除派生记忆或独立学习资产。
- Notebook 四条完整流程、洛谷/Codeforces/AtCoder/蓝桥云课题库内置网页优先流程、主模型简单追加 tips 已明确首版，不擅自缩水或延期。

上述摘要用于导航，完整规则以各归属章节为准。人格细化、整体剩余版本范围及少量产品取舍仍见 PRD，不用技术候选方案替负责人作产品决定。
