# Beacon 输出质量优化要点

> 2026-11-25适用性说明：Q01–Q17保留原观察编号和案例依据，建议按当前[工具合同](../tool-contract.md)整理。问题已出现不等于尚未修复，工程回归通过也不等于模型质量已达标；最新实测见[提示词专项报告](../evaluation/2026-11-25-prompt-quality-report.md)，前轮工具重构证据保留在[原报告](../evaluation/2026-11-24-context-tools-rebuild-report.md)。

> 本轮已收敛的[提示词调优设计](../../superpowers/specs/2026-11-25-beacon-prompt-quality-design.md)进一步限定：system只保简短原则，具体问答／好坏示例仅用于评测；工具说明解释用途和字段，产品知识正文只陈述事实，不嵌入模型行为指导。下文保留原问题证据，不将旧建议视为已批准实施。

原观察日期：2026-11-23。依据负责人补充 `beacon_tips.txt`、当轮 DeepSeek Flash 测试及问答复核；2026-11-25修订已被架构替代的建议。本文维护质量问题和改进方向，不是实施计划或全部修复声明。

**目标：让 Beacon 读准材料、讲清问题，把内部取证过程消化成有帮助的教学回答。** 当前基础取材通路已可用，但回答仍有工程汇报过多、教学范围失控、证据含义误读和压缩后中断等不足。

## 1. 负责人新增的三项体验要求

- **少汇报自身行为。** 默认不报记录 ID、哈希、版本号、路径和文件名，不逐项介绍“我读了什么”。多文件确需消歧或用户明确追问来源时，才用最少标识说明。
- **少解释工具局限。** 信息缺口不影响所问内容时不展开；确实影响结论时简短说明，能自行补读就先补读，避免把取材困难变成教学主体。
- **不搬运整个编辑器。** 用户就在 BeCoder 中看着自己写的代码，回答通常只引用问题行、必要局部或最小改动；用户要求完整解答或完整代码时再提供。

这些要求优化的是回答方式，不撤销真实取证、必要的不确定性说明或用户要求的详细讲解，也不要求隐藏错误。

| Q02 | 缺字段、未截断、覆盖、选择器、保存机制等说明过长，把回答写成工具报告 | 先判断缺口是否影响当前问题；无影响则略去，有影响用一句话限定结论并补读。工具描述明确哪些是内部核对字段、哪些限制需要告诉用户 | 负责人反馈；G08-01、G11-01 |
| Q03 | 无须展示整稿时仍整份复制当前代码，再解释用户已经知道的部分 | 确立“用户与 Beacon 共处编辑器”的环境认知；调试优先引用关键表达式或小片段，直接定位原因与改法。完整代码按用户要求给，不设全局禁令 | 负责人反馈；是否需要整稿按原问判断，不将完整解答请求本身判错 |

| Q06 | 一点问题分成很多标题、表格和重复小结，内部字段直接写进教学；反复声明“未运行”也会打断阅读 | 简单问题用连贯短段，确有比较才用表格。把 `sourceVerification: matched` 转成“那次提交用的是旧稿”。需要区分推导与实测时在关键处说明一次，不靠固定免责声明凑完整性 | 负责人反馈；G09-05、G10-02、G15-03 |

优化后的表达示意，不是固定回答模板：

| 情况 | 更合适的表达 |
| --- | --- |
| 循环漏项 | “`i<n` 会在 `i=n` 时退出，所以少加了最后一项。让循环包含 `n` 就能修正这个边界。” |

| Q07 | 问“刚才运行”，却只读当前代码讲一般原理；问对照，却没分别取得相关稿件 | 按问题选择证据：执行事实读对应凭证，当前改动读最新稿，历史比较读相应版本。概念问答不强制工具；不设每问必读流程或宿主对象绑定 | 测试观察：G07-05；G03-02未完成要求的第二次读取 |
| Q08 | 旧selector局部返回曾被当成整条记录；“没读到”变成“没有保存”，过早要求贴材料 | 新记录工具已整读，旧selector建议撤回。继续区分“空值／未读取／未采集／淘汰”；目录不是正文，保存头尾不等于原输出可恢复。通用读取确有截断时才沿其范围续读 | 旧测试观察：G08-01、G11-01；当前需保护的事实语义 |
| Q09 | 旧工具把对话快照保存说成源文件保存，混淆落盘与已读范围 | 独立代码快照已移除，不再设计snapshotSave。当前读取只取得可见编辑稿，不能称已保存／修改源码；运行稿与提交稿属于各自记录，不代表当前稿已验证 | 旧测试观察：G04-06、G09-05；L09、L11多轮；当前架构已替代其工程处理 |
| Q10 | 局部修复与整体验证的措辞混淆；需防止旧判词被转移到当前稿，也避免“未验证”掩盖已经能判断的改动 | 模型内部核对实际版本与来源，外部自然说明。将“这一处已修正”“尚未实际重测”“整体是否通过”分开：静态分析可以确认局部修复，不必等运行才允许讲清代码逻辑 | 改进与保护：G15-03、L10；G10-02已有正确区分，应保留 |
| Q11 | 多题／多文件线索冲突时选错来源；按熟悉题号的记忆补出未读题意 | 当前题意材料不足时，五站用fetchProblem；problem只记行为，不存题面。用户已给题面或有效历史已足够时不强制重复取题。题号／文件名只是线索，冲突无法消解才简短澄清，不从预训练记忆补造题意 | 测试观察：G02-07、G05-04、G15-03；按现行题面入口修订 |

| Q13 | 主判断正确，附加说明却出现算术、循环执行或范围错误，削弱整段可信度 | 作答前核对关键数值、前提和最小例子：从1开始的循环在n=1时是零次执行，不是i取0；n≤1000时n(n+1)不超过1001000。少作无关断言，定向评测具体事实，不把一切归为措辞问题 | 测试观察：G15-05、G16-07 |

## 4. 工具与压缩对输出质量的影响

| 编号 | 当前细节问题 | 优化方向与可用手段 | 依据 |
| --- | --- | --- | --- |
| Q14 | 调用漏传 `operation`，报错后仍反复提交同类错误；续页缺页面／版本参数 | 对齐工具schema、说明与运行时校验；错误指出具体缺项、合法范围及相应调用形态。模型收到错误后修正参数；重复无进展时停止无效尝试，避免靠更多工具轮次硬撑 | 14次参数无效；其中G11-05 r1、G11-08 r2合计13次缺operation |
| Q15 | 没必要时刷新联网，明确要求刷新时却只读旧题面；读取动作多却未补齐所问事实 | 区分有效历史已有题意与本次联网观测；五站fetchProblem是正式取题入口，不重建“已存题面／联网”双链路。显式刷新需新观测，材料足够则停止取材，以必要事实是否取得判断完成 | 测试观察：G02-06、G06-03；G08-01；现行重构样本亦有额外读取 |
| Q16 | 摘要结构非法导致本轮无答；后面恢复成功掩盖中途多次失败 | 单独设计摘要输出协议：核实模型／适配器的受约束输出能力，在既定有界恢复合同内研究格式修复。保留严格校验和有效原文，不靠任意去尾标或吞字段放行。按每轮可用性验收，失败面向用户给简短明确状态 | G15有10/40次最终失败；36条轨迹432轮中14轮失败空答 |
| Q17 | 摘要新增禁令、改变目标或漏掉纠正，后续虽能回答却被旧摘要带偏 | 分开评估结构与语义：保留用户最新目标、教学深度、真实限制、代码／执行版本和已完成事实；摘要自己的工作限制不能变成用户禁令。用等价的无压缩／压缩多轮对照验证 | 测试观察：G15-05、G15-04；L10–L12 |

Q16、Q17涉及压缩合同与模型行为，具体方案仍待设计；本文不预先批准新增重试、换模型或静默截断。工具说明能减少误读，但无法保证消除推理与教学错误，需要真实问答复测。

## 5. 按问题选处理层，避免只堆提示词

| 处理层 | 优先处理什么 | 应落到哪里 |
| --- | --- | --- |
| 导师提示与环境认知 | Q01–Q07、Q10–Q13、Q15中的教学与取材判断 | `prompts.ts`只保简短导师原则；成功／失败对照仅留评测。用途／参数归工具说明，产品知识按主题读取，不逐例追加禁令 |
| 工具契约与返回表达 | Q08、Q09、Q14、Q15中的范围、身份和调用歧义 | `contextToolContract.ts`及通用工具的schema／描述、`contextTools.ts`结果／错误，Provider负责注册；沿当前简洁接口，不恢复旧快照、选择器或操作并集 |
| 摘要与恢复链路 | Q16、Q17的可用性和连续性 | 现有 `compaction.ts`、provider与会话提交边界；格式成功和语义忠实分别验证 |
| 评测与人工审阅 | 判断上述调整是否有效、是否引入副作用 | 原始问答、实际模型可见工具结果、每轮状态及人工裁决；自动裁判只作辅助 |

不建议用正文后处理去删文件名、代码块或免责声明：容易误删必要定位、完整代码请求和真实失败说明。输出简洁应主要来自正确的模型取舍；证据正确性由工具事实、权限与协议合同继续保障。

## 6. 下一阶段优先级与验收要点

1. **先核当前正确性与连续可用性。** 以最新样本中的check／程序状态混淆、反事实推导、整数范围及旧压缩瓶颈为重点；旧快照和选择器机制已撤回，不把旧失败直接记作当前工具缺陷。
2. **并行改善教学表达。** Q01–Q06及Q12先用小范围提示／工具说明对照观察；尤其检查删掉工程汇报后，是否更直接回答了学生的问题，而不只是字数更少。
3. **再扩展自然学习验收。** 加入不同算法、真实改稿、用户纠正、提示转完整解答、多题切换和自然长对话；保留未用于调优的案例，避免继续只重复求和模板。

每份回答至少审阅以下六点，不规定统一字数、段落数或固定结尾：

- **答中问题：** 回应本轮对象、目标和教学深度，没有自行改写用户意图。
- **讲解有效：** 原因和下一步清楚，跳过已知内容；需要详细时讲透，只要提示时不泄露整解。
- **表达克制：** 无不必要的整稿复制、身份字段、取材汇报、无关扩展和重复结论。
- **事实有据：** 正确区分当前／历史、推导／执行、读取／保存、局部／完整、程序状态／check；不以缺固定免责声明扣分。
- **取材恰当：** 读对来源、所需部分已取得，能补读就补读；概念可直接回答，真正歧义才澄清。
- **对话连续：** 每轮能正常答复，压缩后目标与限制不漂移；后轮成功不能抹去前轮失败。

自动评分应把教学相关性、冗余、具体事实错误、工具选择和连续可用性分开；人工修正裁判误报、漏报时保留原判。G13的28/39不是实际分支正确率，案例机制通过率也不是逐次tool正确率。不能通过要求模型每轮复述证据与免责声明来提高评分。
