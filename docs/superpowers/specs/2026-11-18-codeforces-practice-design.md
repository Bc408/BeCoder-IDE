# Codeforces 赛后练习接入设计

日期：2026-11-18。状态：负责人已确认方案并授权实施；[实施计划](../plans/2026-11-18-codeforces-practice.md)对应的生产候选正在完成最终检查。本文是已批准的设计，不是 stage 构建或产品验收声明。

依据：[产品方向](../../../VISION.md)、[OJ Connect 产品入口](../../oj-connect/README.md)、[当前架构](../../oj-connect/architecture.md)、[共同流程设计](../../oj-connect/shared-workflow-design.md)及[本轮 CF 协议证据](../../oj-connect/codeforces-protocol-evidence.md)。负责人最新决定优先于历史文档。洛谷前端继续使用当前已迁入的组件，不另起 CF 页面。

## 1. 目的、基线与边界

让 CF 与现有三站一样，围绕用户当前 C/C++ 源码完成浏览器获取题目、独立题面、同源码 CPH 样例、快捷键提交和本次正式评测。重点是提交链路简洁、正确且可核对，沿用已认可的洛谷核心体验，保留 CF 的身份和结果差异。

落盘前基线为 `OJ_connect@ff6111dcea268bb1132f5cd9cdc91d7c6ce9cd06`，工作区干净，领先 `origin/OJ_connect` 一次提交。扩展装配洛谷、AtCoder、牛客三个适配器；CF 只有目录配置、侧栏占位、站点图标和已有 CPH 解析能力，没有 OJ Connect 的提交／结果适配。本轮四次实交均为独立临时探针，不是产品接入。

负责人确认首期仅支持普通公开比赛题的赛后练习。支持官网 `codeforces.com` 的普通 problemset／contest 题目入口；Gym、进行中比赛、虚拟参赛、私有／团队／group 入口及镜像域名不在本期范围。不得通过丢弃路径上下文，将这些入口静默改成普通练习。

以常规完整 C/C++ 程序为目标，编译器必须是当次官方表单提供的选项。已采证真实发送覆盖 C++17／C++20，不补写 C 已真实验收的结论；明确的特殊题型不得因样例可解析就推定具备提交支持。题型与赛后权限必须在实施时有可验证来源，见第 9 节。

原有三站的题目识别、认证、提交与结果协议保持不变；浏览器主题、主页、下载、微信登录和 Beacon 能力不纳入本轮重构。Beacon 不获得登录、提交或修改用户源码的权限。

## 2. 题目身份与文件命名

负责人选择与 AtCoder 相近的命名形式：**赛场号、下划线、官方题号的小写形式**。官方题号没有数字就不能自行添加数字。

| 内容 | 规则／示例 |
| --- | --- |
| 默认目录 | `codeforces`，沿用已有目录设置 |
| 默认文件名 | `codeforces/4_a.cpp`、`codeforces/1700_a.cpp` |
| 站内身份 | `ProblemRef.nativeId` 使用 `4/A`；题号按官网身份规范化 |
| 规范题目 URL | `https://codeforces.com/contest/4/problem/A` |
| 同题入口 | `/problemset/problem/4/A` 与 `/contest/4/problem/A` 在本期赛后练习上下文统一 |
| 明确站点内的输入 | `4_a`、`4_a.cpp`、`4/A` 及上述两类完整官网 URL |

官方题号如果本身带数字，保留该数字；这不意味着为 `1700` 场 A 题添加 `1`。导入生成的文件名必须可按同一规则反向解析。既有 `.c`／`.cc`／`.cxx` 源码仍遵守共同源码读取规则，不改变浏览器默认创建 `.cpp` 的行为。

直接父目录优先。`luogu/CF4A.cpp` 仍归洛谷；`codeforces/4_a.cpp` 才是 CF 原站入口。目录失配、歧义或站点未知时复用现有输入确认，不静默改投站点。`4_a` 这类通用比赛文件名不新增无上下文的跨站抢占规则。

不增加源码与题目绑定数据库、不扫描 CPH 私有数据覆盖用户目录身份，也不自动移动或重命名已有源码。

## 3. 浏览器入口与共同题面

1. 侧栏沿用已有轻量 WebviewView 和 CF 图标。只有名称是导航入口，状态文字静态、无退出按钮；未登录主动打开官网登录页，已登录打开可信摘要提供的个人页。
2. 正常网页登录和 OJ Connect 共用当前窗口、当前存储范围的持久 Session，不复制账号或 Cookie，不建立第二套登录状态。
3. 内置浏览器的“获取题目”在支持入口创建／打开配置目录下的规范 `.cpp`，并打开共同题面。已有文件与未保存内容不覆盖。
4. “导入至 CPH”继续使用已有 Companion／CPH 能力；支持 CF 时采用同一目录、题目标识和文件名。其他题源的 CPH 默认行为不改变。
5. 获取题目后，题面中的“传送至 CPH”必须关联刚打开的同一源码，不产生第二份文件，不在重复导入时静默覆盖用户样例。

复用已有 CPH Codeforces 解析器的题面／样例提取能力和共同内容清洗、公式、高亮、复制管线，不把解析器的全站支持范围等同于本期提交范围。不复制第三方扩展的完整界面、账号库或提交框架。

题面采用现有统一布局、紧凑 CPH／提交图标、语言选择和响应式元数据区。正文保持真实题面结构，样例说明保留对应语义。时间限制、内存限制沿用已确认的 C/C++ 展示和洛谷式简洁单位格式；题目难度、标签等只在有可靠来源时展示，不制造占位字段或为 CF 再建一套排版。

## 4. 单一提交路径

```text
当前源码快照 + 规范 ProblemRef
  → CF adapter／受限宿主业务命令
  → 当前窗口、存储范围及账号对应的原生 Session
  → 并行读取官方表单与本场本人记录边界
  → 从当次表单选择／校验 CF 编译器
  → 原生同 Session 请求发送一次
  → 明确回执 + 新 ID／题目／语言／源码唯一核对
  → 共同评测页，按该 ID 独立查询
```

按 Ctrl+Alt+S 或题面提交动作时固定源码快照，包括未保存修改；显示现有提交进度，之后编辑不改变本次发送内容。准备与发送沿用现有并发约束，再次触发立即提示正在处理，不排队、不记待发源码。

只在本次提交动作后准备官方表单与本人记录；不因扩展激活、打开文件、获取题目或登录提前预热。表单 GET 与本人记录 GET 可以并行，但两份结果必须属于同一账号和仍有效的会话范围。空本人列表是合法首次提交场景，不能照搬探针中的“必须已有记录”限制；必须确认这是完整有效的本人列表，不能将解析失败视为空列表。

编译器目录来自当次官方表单。偏好按 `codeforces` 及 C／C++ 语言族独立保存，沿用现有设置机制，不与其他站点共享 ID。原偏好失效时提示重新选择，不静默切换版本，不永久硬编码采证中的语言 ID。

宿主构造已核准的普通练习表单请求；保留官方必要隐藏字段与数据编码，只设置本次题目、所选语言和源码。短期令牌及凭据留在宿主内存，不交给扩展／Webview，不记录到日志。必要的服务器字面量复用已有 Acorn 静态解析能力，禁止执行远程脚本。临时探针使用的 JSDOM 是开发工具，不因探针可行就变成新的生产依赖。

采用显式绑定原生 Session 的 `net.request`，手动处理提交重定向。采证已验证 `Session.fetch` 的手动重定向会抛出 `Redirect was cancelled`，不能用它读取提交 3xx。仅接收同源、同比赛、符合预期的回执目标；未知目标或 307／308 不自动跟随重发源码。表单内 `name=action` 会遮蔽浏览器 `form.action`，解析必须取得实际 action 属性并校验固定目标。

不为正常准备、发送、核对或结果查询创建／导航／展开浏览器页面，也不建立隐藏 BrowserWindow、承载网页或常驻提交页。人工登录、官网验证仍由用户主动在普通内置浏览器完成；没有要求免除网站正常认证。

## 5. 回执、错误与生命周期

HTTP 成功、某个重定向、列表第一行或旧 AC 均不能单独代表本次提交受理。使用发送前边界、新 ID、目标题目、账号、所选语言及源码的唯一匹配确认正式记录。源码比对仅规范换行，不删空白或重排代码。记录不唯一、源码缺失或不匹配都不能报成功。

| 状态 | 行为 |
| --- | --- |
| 准备失败且明确未发源码 | 返回 `not-sent`，说明原因；用户可重新发起 |
| 官方明确未登录 | 插件提示登录，用户主动打开既有官网入口 |
| 挑战、403、网络或结构读取失败 | 提示验证／读取问题；登录摘要为未知，不能仅凭这些响应断言退出 |
| POST 已发出或不能排除发出，回执未确认 | 返回 `unconfirmed`，保留本次必要核对信息；只查询、不自动重交、不切换备用路线 |
| 官网明确拒绝本次请求 | 根据可验证的原站错误说明结束；不把不完整返回当成明确拒绝 |
| 新记录已唯一确认 | 交付 `record` 并释放发送占用；结果页打开失败也保留正式 ID，不回到提交阶段 |
| 结果读取失败或本地等待结束 | 保留正式记录及最后状态，允许“继续查询”，不重新提交 |

发送前允许取消准备；发送后不提供“撤回提交”或暗示可以取消服务端判题的按钮。关闭评测页停止本地跟踪，不代表评测失败。受理不明的主动查询不重新获取源码并再次发送。

任务、请求、已确认记录与未确认尝试绑定所属窗口、Session 存储范围和账号。明确退出、账号／范围变化使旧任务失效；普通 Cookie 轮换不能直接造成掉线或清空正在确认的记录。发送前复查有效性，取消／销毁后的迟到响应不能触发发送；已发请求的迟到正式回执须按原任务身份处理，不能污染新任务。

不逐层增加重试、会话指纹服务或后台恢复框架。沿用当前请求中断、临时任务和尝试记录机制，释放只影响对应任务资源，不清登录数据、不关闭用户标签、不干扰其他 OJ。确认阶段已经读到的结果在共同层可用时复用，避免为相同初始数据立即重复请求。

## 6. 评测页与字段语义

负责人已确认复用现有洛谷式组织和控件：

- 信息行显示题目、评测状态、提交时间、语言、代码长度及终态耗时／内存；CF 不显示用户字段。
- 有真实分数才显示分数；等待及未知分数不补 `0`。AC 不自行换算成 `100`。
- 等待和评测中使用现有蓝色转圈；采用完整英文状态、中文悬停说明，同时保留 `Running on test 18` 等原站进度。
- 测试点位于分隔线后的“测试点信息”区域，复用已有卡片及悬浮信息。只展示实际返回的点位与数据；从正在测试的序号不能推造总数或剩余卡片。
- CE 以独立编译输出区显示净化后的诊断。CE 返回的占位 testCount 不生成真实测试点。

优先使用已采证的官网精确记录读取接口。`waiting`／`compilationError` 的字符串 `true`／`false` 必须显式解析，不能按 JavaScript truthiness 判断。状态与编译输出可能含 HTML，必须提取文本或经过既有安全管线，不能直接插入页面。源码保持原始文本，不执行。

源码字符数不等于 UTF-8 字节数。代码长度、提交时间、耗时与内存只采用已核对的字段和单位；缺失则省略。原始字节内存需正确换算，不能拼接错误单位。保留 CF 原始状态和正式记录链接；未知状态明确显示，不强制归成成功或一般终态。

沿用共同 `RecordController`：每轮约 120 秒，读取完成后按现有间隔串行查询，不重叠；到期保留 ID 与最后结果，允许显式继续查询。CF 初版复用共同 2 秒间隔，不新增独立轮询配置、推送框架或 API 备用轮询。

## 7. 实现职责与去冗余边界

| 所有者 | 本轮职责 |
| --- | --- |
| 扩展 `src/adapters/codeforces/` | 题目身份、文件名、现有 `OjAdapter` 契约及宿主结果适配 |
| 共同扩展层 | 源码快照、输入／目录、CF 编译器偏好、同源码 CPH、进度、题面与评测页面；仅补必要枚举、校验和字段呈现 |
| `browserOjConnectFeature.ts` 及受限 bridge | 固定业务命令、所属窗口／Session 范围、单次任务句柄、取消／释放和正式回执交接 |
| 原生 CF Session client／协议模块 | 当前会话请求、官方表单与账号解析、当前语言、一次 POST、手动回执、唯一记录核对和结果读取 |
| 现有 CPH 与共享内容能力 | 已有 CF 题面／样例解析、本地测试、安全内容、公式及代码渲染 |

遵循洛谷的业务节奏和明确所有者，采用已验证的 CF 传输；不将洛谷的 Node HTTPS、验证码、CSRF manager 或推送直接复制成 CF 协议。

不复制一整套共同页面或控制器，不将既有三站借机改成通用站点工厂。新增函数和模块须有实际消费者；探针的菜单、调试端口、单次放行器和数据目录不进入产品。只删除本轮替换后确认无引用的实现，不按名称清理其他站点或浏览器基础能力。

不新增账号库、API 密钥、通用带登录态的 HTTP／脚本接口、持久题目绑定、常驻预热、页面池、自动重交、跨提交队列或备用提交路线。

## 8. 已验证事实与性能目标

四次隔离实交均产生正式记录，题目／语言／源码核对一致且 Accepted，其中一次为全新正常登录、此前未请求题面或提交页的会话。具体 ID、阶段耗时、传输对照及限制见[协议证据](../../oj-connect/codeforces-protocol-evidence.md)。

证据足以支持“不预先运行提交页”的接入选择，不足以给出长期可靠率、p95、固定快捷键延迟或其他题目场景的完成声明。优化目标是消除非必要页面导航、串行读取和重复解析；不得通过弱化本次记录确认来缩短计时。

产品实测应分别记录按键、准备、发送、正式 ID 确认、面板首绘、首次结果与观察终态；首次模块加载也计入完整体验，不把约 0.59 秒 POST 回执当作完整快捷键耗时。仅保留必要脱敏计时，不建设持久遥测系统。

## 9. 实施前与实施中的验证门槛

以下在实施计划中安排核对，不直接写成已经具备的能力：

1. 用当前官方可读材料确认比赛已结束、处于普通练习且题型／权限匹配；不能凭 contest URL、比赛编号或“能显示题面”推断范围。
2. 已有 CPH 能力如何在主进程不引入新生产 JSDOM 的前提下复用；官方表单与账号、空本人列表及分页的结构须有真实材料和边界测试。
3. 正常登录／退出、账号切换和 Session 轮换的实际信号；挑战不能误报掉线。侧栏继续复用现有刷新机制，不另建轮询。
4. 待判、AC／WA／CE 及可观测其他状态的解释；时间／内存、代码长度、提交时间与测试点数据逐项核准来源，未知则省略或明确显示未知。
5. 既有记录、并发同题提交、分页边界和多条源码相同候选的核对；找不到或不唯一时维持受理不明，不选“最新一条”。

若这些门槛要求扩大支持范围、新认证、新依赖、隐藏页面、备用链路或其他明显复杂度，先说明证据与取舍，再与负责人对齐；不能将探针代码直接当作生产实现。

## 10. 检查、许可与交付

本地回归覆盖：目录优先／歧义、文件名可逆、受限命令与来源校验、动态编译器及偏好失效、空列表、旧记录排除、同题并发、源码不符、未知回执、302／未知目标／307／308、字符串布尔、未知状态、HTML 诊断、取消晚到、窗口销毁及账号／范围变化。故障与竞态优先用可控本地响应验证，不靠大量真实交题制造故障。

实际渲染检查覆盖共同题面／评测、深浅主题、窄宽布局、真实测试点和无总数进度、无分数占位及 CF 特有原始进度。测试通过不替代截图检查或负责人验收。

产品运行必须在隔离实例进行，覆盖获取题目→同源码 CPH→未保存源码快捷键→正式 ID／源码→评测，以及主动登录和读取失败提示。沿用负责人已有受控测试授权，使用已结束公开题；任何不明确受理均不自动重交。
