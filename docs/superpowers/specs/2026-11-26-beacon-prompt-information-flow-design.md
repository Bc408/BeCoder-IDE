## 1. 目的与设计方法

**设计好信息出现的位置、时机和含义，让LLM自然取得当前需要的上下文。**

Beacon在BeCoder中承担算法与编程教学；业务owner提供真实事实，harness负责授权、投影、组装与预算，LLM决定讨论对象、取材和讲解。本轮重构模型可见语义入口的分工，不以删字数、提高调用次数或规定工具顺序作为目标。

BFS是人的设计遍历顺序：先联合入口，再横向比较九工具，接着各来源结果，最后核对回流及全部连接。实际请求中的system、消息与工具声明并列提供；模型可以直接回答、直接按ID／latest读取，也可以取得结果后继续选择来源。摘要、续答是回接，不是额外的固定问答步骤。

负责人已确认：

| 决定 | 确定的范围 |
| --- | --- |
| A范围 | 文字、投放位置、必要的阶段工具声明和返回包装可以调整；结构变化逐项书面明确 |
| 首层环境 | 每次回答开始提供真实模式、所选Beacon根、该根的activityCollectionEligible；不把采集资格当模型读取权 |
| 运行结果释义 | 确定性短notes随相关结果返回，与record事实分开，不入队 |
| 模型失败 | error:{code,message}保可靠原因及已知可行处理；原UI与旧历史兼容 |
| 摘要声明 | 只提供确有可读固定记录的工具，必需id用合法ID枚举；无固定记录时无工具 |

生产提示统一英文，中文是审阅语义，不拼入请求。工程检查、有限模型观察、stage与负责人验收分别计量。设计阶段未授权Git提交／推送、模型API、构建、启动或发行；后续负责人已批准实施计划中的扩展build与离线验证，其余边界保持。

## 3. 模型可见入口全表

| 位置与消费时机 | 所有者 | 内容与处理 |
| --- | --- | --- |
| 普通请求system | prompts／Provider | 稳定导师职责、极简产品定位、共同事实与授权原则 |
| 普通请求宿主段 | ContextTools.describe＋prompts | 回答开始时模式／根／采集资格、页面元数据、当时的时间值 |
| 实际工具声明 | contextToolContract／Provider | 九工具用途和参数；仅注册当前真正提供的能力 |

| 文件／页面 | FileTools／page owner | 真实正文、范围、游标、已知状态；不扩展读取范围 |
| 网页 | webTools | 实际sources，搜索摘录／正文区别、局部与集合缺失、额度失败 |
| 产品知识 | productInfo与随包资源 | 七主题产品事实与运行宿主发行版本，按需整篇读 |
| 模型失败 | 对应owner分类＋同一模型投影 | 安全具体code／message；未知只说明当前来源未读取成功 |
| 工具媒体兼容包装 | Provider.fileMessages | 保原toolCallId／toolName归属的图片媒体，不冒充新用户请求 |
| 历史普通协议 | session／protocol | 原完成工具交换及适用正文；不改旧结果或重新生成notes |
| 摘要子请求 | compaction＋阶段工具声明 | 摘要任务、旧摘要、有效前缀、保留尾部及真实合法固定ID |

| 暂停续答 | session＋Provider | 宿主明确实际追加语义，保完成工具事实、按需新取材 |
| 编辑／重答／换模型 | session／protocol | 工程裁定有效消息与兼容私有字段，不靠提示遮蔽弃分支 |
| 连接测试的独立请求 | Provider.testModelConnection | 保现有Reply with OK.，不接聊天、宿主目录或导师system |
| 搜索服务的下游任务文字 | webTools | 保现有公开搜索objective，消费者为检索服务，不把它混入导师system |

活动UI、本地化通知、设置页帮助与模型不消费的诊断不是LLM提示入口。第三方SDK自动生成的错误表示需在实施预检确认其实际出站位置；不能漏过框架层后仍声称所有失败均已统一。

## 4. 首次请求与能力发现

1. 核心采用第1轮候选，保持教学深度、用户语言与代码风格、材料版本、推理／实测区别、只读和真实用户授权。纯概念及材料充分的请求允许直接回答。
2. 所选根及采集资格来自同一捕获scope，模式与实际注册一致；Blackout的所选根不能用已裁切的文件roots代替。已确认无根用null，未知省略；不把未知伪造成false或Blackout。
3. 时间、目录取得发生在回答开始附近，不声称原子观测或每个工具步骤刷新。页元数据不是正文，不证明更早状态；实时读取可取得更晚状态。
4. 提示版本保内部版本身份，拟定下一版为2026-11-26.4，实施时统一替换受控版本与对应断言。产品版本仍由运行宿主提供。仅删去模型正文中的提示版本，不据此新增日志系统或虚称已有诊断输出。
5. 普通工具名称、接受的参数集合与硬能力保持；第2轮仅改用途和属性说明。原互斥参数／范围校验继续执行，不新增工具、include投影、记录分页或强制取材流程。
6. inspectFile动态范围仍在其本身说明中，明确workspace／computer及真实相对基准。首层采集根不替代该访问说明；none时不注册。

## 5. 结果的语义与模型投影

### 5.1 正常／部分／空结果

保各工具原有成功顶层结构。可选外层notes采用第3轮条件表，主要服务模型面对的字段含义、保留范围和现存后续位置。只由应用根据实际来源、字段和本地分支产生；没有相关说明就省略。每个结果内去掉重复句子，不新增跨轮去重缓存。

三队列列表说明当前可用近期范围、新项在前，不代表完整历史；run／verdict目录不冒充详情。空列表成功，latest无匹配项not_found，指定记录不可用不擅自确定淘汰原因。代码／题面／产品知识有自明字段时不机械添加来源长模板。

run详情按实际来源区分总体流程、编译、进程、CPH check、合流或分流、未执行和未知输入。hash解释完整实际源码只归一化CRLF→LF，不代表验证或cell身份。Notebook执行坐标与当前全本坐标各有时点。workingDirectory只解释为该次执行目录，不猜CPH保存位置。

新格式截断前缀、旧格式分离head／tail和缺失计数分开解释；缺失计数为0不能说中段缺失。永久未保存部分无本记录全文入口。文件／页面的真实nextOffset可以帮助继续定位；搜索、网页、已截断run不能凭truncated自动生成offset。页面非零offset末段没有nextOffset时不诱导继续到越界。

网页来源文本不完整与本地预算省略来源集合分别表达。本地预算无法收纳任何来源时返回budget；返回了部分来源则保正文并说明遗漏；真正没有来源才是成功空结果。判断只取该次owner分支，不从结果自然语言猜测。

### 5.2 失败投影

模型可见的工具失败目标形态为error:{code,message}。保原ok:false和已有安全path，不强制统一所有成功形状。安全具体原因在分类点保留，message复用已有合适文案；未知原因用小型保守结果。取消、超时中断请求没有完成结果时不伪造一份工具完成事实。

文件保原UI code和字符串error合同，另以安全分类信息供模型投影形成结构化原因。native的会话owner与Notebook内容owner分别解释；OJ登录／解析／网络原因只沿真实题面读取链的明确代码识别，不从通用网站失败猜未登录，不改提交流程或加登录探测。

执行前SDK参数校验失败、工具抛错和已执行失败需逐路径确认；若SDK默认error-text绕过普通toModelOutput，实施计划必须安排同一安全模型失败投影进入实际下一请求和留存协议，不只改活动UI。参数反馈只说明被拒绝的组合或所需字段，不把整份工具说明塞进message，也不自动修参重放。若框架路径无法在现有边界内保证，先说明具体限制再修订接线，不能悄悄改权限、重试或适配协议。

### 5.3 三出口及历史兼容

新执行的toModelOutput、onToolExecutionEnd完成事实及protocol.result共用同一确定性投影。网页投影显式保notes，Context及文件失败保持同义。图片继续保媒体part，不能把base64改为待阅读文字。

原始message.toolResults[].output保现有字段，history校验仍可读取原数据。旧protocol按已保存内容回放，不重新生成notes、不把旧错误重写成新结构、不重新执行工具。必要的新模型投影只留在实际新交换里，不新增历史迁移、外部索引或材料库。所有实际新增文本、schema及媒体进入真实请求计量。

## 6. 摘要与后续请求

摘要采用第4轮独立system和输入分隔，输出仍只有summary字符串的JSON。不继续回答历史问题；保学习目标、已有理解、用户修正、版本、时序、原观察与推理差别。原问题和尾部保持原话／媒体表示，不把助手断言重复成已验证事实。

已采用阶段声明按kind＋ID的真实fixed集合生成：每个存在可读记录的工具只收必需id，其enum为该工具合法ID；没有fixed或该模式无历史读权时无相应工具。普通目录、latest与filePath不出现在摘要schema。schema、用途、实际校验与计量同源，执行层fixed及scope检查继续兜底。

摘要完成后恢复普通工具及导师system，历史摘要只作参考。现行同模型、闭合交换切点、输出预留、90%触发／60%目标和一步一次恢复保持；60%目标尚未真正传给生成器的已知实现差距不在本轮宣称解决，也不另建动态摘要目标接口。

续答控制文字只在用户明确继续时出现，真实追加到原回答末尾，允许按需取材。编辑旧问题仅换正文并保原附件，删去后续弃分支；重答保有效前缀；换模型沿现行来源兼容性过滤推理内容和providerOptions。失败历史只回放完成配对，暂停历史保已接受正文，不重演未完成工具。

附件标题说明“随这条消息提供”，工具图片媒体标题说明“来自前面那份记录中的工具结果”，逐图保原调用标识。它们不是当前文件的新观察，也不产生新用户请求或额外权限。普通／摘要的媒体准备与硬容量检查使用同一路径。

## 8. 产品知识的整体核对

七主题是已有的模型专用英文产品知识，本轮保留2026-11-26.3正文，按此前完整英文／中文对照审阅。独立审阅者已逐篇对照前四轮相关入口，未发现需改的事实或衔接冲突。它与结果notes的职责不同：用户问产品如何工作时需要整篇主题，模型刚读到一条记录时需要局部字段说明。同一事实适度出现于两个相应位置，不构成必须删除的重复。

| 主题 | 保留的知识职责 | 与新信息入口的关系 |
| --- | --- | --- |
| overview | Code - OSS定位、工具链、产品组件、官方仓库及七主题入口 | system只放极简环境，版本由真实返回提供 |
| problems | Get／Import、代码文件／样例关系、五站与CPH额外题源 | 工具用途读用户活动，题面由fetchProblem取得 |
| runner | Run／Run With Input、编译环境、debugger.h、gch、输入／输出与计时 | run notes解释眼前结果，主题说明产品使用和环境 |
| cph | .cph/*.prob位置、单点／全部、编译与检查、检查器支持范围 | 不从workingDirectory猜保存位置，不沉淀检查器代码 |
| notebook | 独立学习文档、全本编号、输入关联及运行行为 | 当前cell与执行时位置分别说明，现场不混执行结果 |
| oj-connect | 五站支持、真实会话与用户提交、终态及源码核验 | verdict是那次提交结果，不是隐藏数据或当前代码验证 |
| beacon | 模式、采集、近期队列、失败资格、额度及历史生命周期 | 首层报告本次状态，主题解释一般规则，notes解释实际片段 |

```cpp

#endif
```

不得改为可变参数宏、自动修改学生代码或加入模型操作命令。独立主题审查限定核对当前七篇与四轮候选的语义一致性，未作源码或外站真实流程验证；不能据此扩大站点支持或将知识改写成模型动作口诀。

## 9. 设计覆盖与效果验收

### 9.1 静态与离线验证

先确认真实命令入口及输入文件，再由实施计划冻结精确检查矩阵。最低验证对象为：

- 导师核心、宿主投影、九工具文字和实际模型收到的声明一致；无工具／无根／Blackout／Spot／Flood／搜索开关保持原边界。
