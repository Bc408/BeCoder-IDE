# OJ Connect 洛谷会话与交互修复设计

日期：2026-11-15。状态：负责人已确认本文设计并明确批准实施；实现与验证记录见 docs/oj-connect/session-repair-2026-11-15.md。本文不是实现完成或运行验收记录。

## 目的与权威

使洛谷的快捷键看题、提交、评测反馈对齐 vscode-luogu 4.20.0，消除正常操作依赖完整官网页面加载的额外等待。独立 OJ Connect 图标和侧栏统一管理账号；插件与 BeCoder 内置浏览器使用同一站点会话。

基准为本地完整上游 v4.20.0，提交 987ca974b5419230a07b59a195ec44026e16f6f4。保留既有[共同流程设计](../../oj-connect/shared-workflow-design.md)及目录猜题、同源码 CPH、源码保护要求；本设计更新其中侧栏仅展示登录摘要的旧限制。既有[整体复审](../../oj-connect/review-4.20.0.md)不等于真实网络交互已经对齐。

当前分支 OJ_connect，工作区包含此前未提交的双站开发，不覆盖或整理这些变更。本次设计只针对洛谷请求／提交／推送链路及账号管理入口；AtCoder 已有提交事务继续保留。CF、牛客、蓝桥仍显示未接入，不因列出账号行而宣称支持。

## 已确认的用户行为

- 活动栏提供独立 OJ Connect 图标；侧栏仅用于各站登录管理，不增加题库、社交或比赛入口。
- 点击登录打开内置浏览器官网登录页。完成登录后自动更新侧栏；在同一会话的普通内置浏览器页面中登录亦生效。
- 从侧栏退出某站，该站在插件与共享会话的内置浏览器中同时退出；其他站不受影响。官网退出后侧栏也应反映变化。
- Ctrl+Alt+P 打开插件题面；普通网络／解析失败在插件内提示和重试，不自动展开官网。
- Ctrl+Alt+S 固定按键时的源码快照，使用对应会话发送；正式 rid 返回即交付回执并打开结果面板，不等待官网记录页加载。
- 洛谷评测按原插件推送流程持续更新。只在确实需要登录或人工验证时显示交互入口，完成后继续当前任务。
- 明确验证码拒绝可按原插件流程继续；发送结果不明时只核对，不自动重发。

## 职责及复用边界

| 所有者 | 目标职责 |
| --- | --- |
| OJ Connect 应用／展示层 | 快捷键、目录猜题、不可变源码快照、语言偏好、侧栏及题面／结果面板、任务取消和进度 |
| 洛谷适配层 | 原站业务、响应转换、CSRF 生命周期、验证码续交、正式回执与 record.track 订阅流程 |
| 浏览器宿主 | 真正的浏览器 session、窗口所有权、固定站点操作、HTTP／推送传输、人工登录与验证、请求取消及释放 |

业务归属不等于必须在扩展进程执行。原插件 Axios 的凭据获取及 Cookie Header 写入不能直接搬入扩展；以宿主提供的同会话传输替代，原业务逻辑和可测试的纯管理器尽量保留。扩展不保存第二份 Cookie，不接收凭据，不获得任意 URL／脚本／Header 的通用执行权限。

具体复用：上游 src/utils/api.ts 的 getProblemData、submitCode、fetchResult 业务顺序，src/utils/csrfTokenManager.ts 的缓存／并发去重／会话失效机制，src/utils/websocket.ts 与 src/features/record.ts 的订阅握手、status_push、终态详情及关闭释放。保留原 MIT 声明并登记裁剪和适配；不重写已有渲染器、控件或增设统一网页引擎。账号代际检查、源码快照、窗口归属及受理不明禁止重交属于必要适配。

## 会话与账号生命周期

每次业务操作绑定明确的宿主会话和账号代际。普通内置浏览器和侧栏登录必须选择同一持久 session；不将任意一个已打开网页当作认证权威。暂存／隔离浏览器会话继续保持隔离，不能静默合并其账号或更改既有存储范围。

登录页导航完成、相关会话变更、显式刷新以及业务明确报告认证失效时，触发合并去重的登录摘要检查。Cookie 变化只表示需要检查，不直接证明登录成功。读取失败显示未知，不自动判定已退出；不得导出 Cookie 作比对。事件来源及公开页面与摘要请求的竞态在宿主内处理，避免持续重取完整题目 HTML。

退出调用该站点受支持的退出流程，成功后刷新摘要并失效该站的 CSRF、准备任务和账号相关缓存。不清空整个浏览器存储，不清其他域数据。退出失败明确提示，不能仅修改侧栏文字伪装退出成功。已经拿到的正式记录仍保留；退出后的读取遵守网站当前权限。

## 正常请求和提交

常规请求绑定 session，脱离目标题目／记录页面的 URL 和完整加载状态。宿主暴露题面读取、提交、记录读取、订阅、登录摘要及退出等有限业务操作。具体采用 Electron 会话网络能力还是固定后台承载页，须经同会话只读验证后决定；两种实现均不得回到等待目标网页完整加载的路径。

题面沿用上游内容接口，配置只在必要时获取并合并并发请求。CSRF 缓存按原管理器生命周期适配，以会话／账号代际失效，不能把全部 HTML 重取当作每个请求的默认前置。提交前保留账号和语言有效性检查，但复用同一次准备所得信息，避免当前两轮重复题目 HTML＋配置。禁止无证据复用跨账号缓存。

POST 获得合法 rid 后立即绑定题目、源码任务和正式回执，打开结果面板并释放发送占用。查询或面板失败不能撤销该回执，也不能触发重发。正式记录读取和推送独立于发送锁，不为未完成任务增加等待队列。

验证码明确拒绝沿用原 submitCode 的继续语义；交互结果只继续原任务的源码、语言和目标。具体验证码展示形式优先复用原插件，必要的官网挑战才展示浏览器；不为所有失败打开网站。

## 取消、错误和推送

宿主从任务创建时即记录取消状态，在读取脚本、调度和实际发送前复查；取消不能只依赖网页中已经存在的状态。准备、网络请求、交互和释放均有可中断的生命周期。取消后及时释放占用；未发送则结束，发送受理不明则只读核对，晚到的合法正式回执仍保留。禁止为实现即时释放而允许旧任务晚发源码。

错误分为普通失败、需要登录、需要人工验证和受理不明。仅明确交互状态触发展开页面；不能以任意异常或“页面数据缺失”推断用户必须登录。请求超时与等待人工输入分别管理；不把原插件六秒网络超时机械用于整段人工交互。

推送复用原 record.track 订阅与状态机，终态补取正式详情。记录 ID 和本窗口任务身份必须保持一致；关闭面板、会话失效、取消订阅或窗口退出时释放连接。握手失败明确提供重试，不以永久轮询伪装推送成功。断线后的只读恢复不重交源码。具体握手的 Origin、会话携带及服务器接受行为须实测，不凭源码臆定。

## 修复顺序与实施前验证

1. 先验证同一 session 的题面／记录只读请求、真实账号摘要以及 WebSocket 握手。不得导出凭据或为验证自动提交。传输不成立时先回到设计讨论，不堆页面补丁。
2. 修复宿主取消竞态和无条件展开浏览器；使正式回执不再等待记录网页导航。记录读取必须同步脱离页面依赖，不能仅删除 await。
3. 引入同会话有限传输，复用原请求／CSRF 管理，消除重复准备请求。
4. 复用推送生命周期，完善统一侧栏登录／退出与自动摘要更新，运行双站回归。

这是修复依赖顺序，不是已经批准的逐文件实施计划。传输验证应先完成；账号事件与 WebSocket 的实际可用能力决定后续具体接口，不先创建通用框架。

## 验收与证据

实现时先以受控场景复现：普通读取失败误弹浏览器；有效 rid 后记录页慢加载；准备中取消；脚本启动前取消；POST 后取消／超时；账号切换；验证码拒绝及继续；推送终态、断线和面板释放。保留源码一致、精确 rid、未知受理不重发和无队列测试。

真实验证分别记录快捷键→POST、POST→rid、rid→结果面板、推送到达→界面更新。两款插件使用同一题目／语言和接近的网络条件，分别统计冷暖请求、验证码与网站判题耗时；不以本地渲染 benchmark 或 fixture 冒充真实端到端性能。不预设未经测量的毫秒 SLA。

负责人验收包含：侧栏登录和普通内置浏览器双向一致、退出仅影响对应站点；正常看题不展开官网；源码快捷键提交后迅速交付正式记录、持续更新结果；慢网取消不堵塞下一次任务且不晚发旧源码。真实测试提交需在既有明确授权范围内进行；AtCoder 原闭环不得回退。

产品源码、构建、包验证与真实运行分别记录；历史通过结果不验证未来修改。实现阶段按拥有者先跑聚焦检查，再执行 AGENTS.md 要求的验证；不在本文编写阶段构建或运行产品。设计与计划均不隐含 Git 提交、推送、Setup 或清理授权。
