# Beacon 实时代码工具与本对话快照队列

修订日期：2026-11-22。状态：按负责人最新已接受决定统一改写，待本轮书面审阅；产品尚未按此合同实施或验证。本文是当前代码工具与队列合同，低层接口另标“阶段计划提案”，不以旧审阅回执或本次文档改写授权产品代码。

产品行为依据：[工具读取与近期队列修订](decisions/context-queues.md)。接口与任务已由[当前执行计划](../superpowers/plans/2026-11-22-beacon-foundation-implementation.md)第2节及Task 1、4–8承接，仍是待书面审阅的阶段计划提案，不表示新产品批准。能力映射：[能力需求](prd.md)的 CTX01–03、EVD04–05、READ04–06、CHAT03、HIST01–03、LONG01–04。本文不重写历史报告或不可变原件。

## 1. 已确定的职责与边界

LLM决定何时主动调用当前编辑器代码读取工具。Spot／Flood下harness在同次调用取得真实完整代码并保存本对话快照队列，再按既有整读、局部或分页返回；Blackout只保留当前页普通读取，代码队列能力直接关闭。当前稿包含未保存修改；保存正文和返回内容对应同一次观测、同一真实版本，不能再读一次后用新稿替代。

没有独立的模型保存工具、模型删除工具或模型快照价值评估流程。用户发送、继续、重答、工具续轮以及运输重试本身均不捕获代码；真实工具调用才发生读取与同次保存。模型生成的代码、整段聊天搜索结果、片段拼凑和保存时重新读取均不是快照内容来源。

这类写入仅管理 Beacon 自身的当前对话材料，不修改学生 C/C++ 文件，不执行、停止、登录或交题，也不以“用户请求生成笔记”为前置。原有页面身份、当前根、档位、敏感过滤、会话所有权和目标校验仍适用。

当前对话快照与共享执行凭证各有职责。Runner／CPH／Notebook／OJ 中的真实编译稿／提交稿属于其原凭证，不自动进入对话代码队列；本对话代码快照也不能冒充任何一次执行或判题通过。

## 2. 实时读取的语义

1. 讨论对象由LLM结合用户问题、对话和工具观测判断，harness不建立发送时／会话级对象绑定。工具调用可指定打开页面ID；未指定时读取调用当下的活动代码页，每次主动读取取当时版本。
2. 从当前内存编辑器取得完整代码，含 dirty，记录其真实文件／页面身份、版本和实际取得时点。harness 用同一份捕获内容完成保存及工具返回，不让 LLM 重生成正文。
3. 工具可按既有能力只向模型返回部分或分页。保存的是完整原稿，返回覆盖仍如实表达；“完整快照已保存”不能变成“模型已读完整份代码”。原有敏感过滤不得被目录、保存或历史回读绕过，读取表示和返回覆盖分别说明。
4. 在同一回答内，学生编辑后 LLM 可再次主动读到新稿，无需先发送另一条消息。新观测与旧快照分别表达，不能把旧读取缓存标作最新。
5. 页面关闭、对象不可读、身份或权限变化等导致读取失败时，返回实际失败；不拿旧快照冒充当前读取成功，不由这次失败操作调整队列。

调用正常结束即释放队列之外的本次临时资源，不为未来独立保存另留未保存全文，不建立额外跨调用原稿缓存、读取引用期限或“回答结束再释放”的机制。完整正文只由Spot／Flood的本对话持久队列保留；Blackout没有替代队列，只正常返回当前页实际读取。实际返回片段沿普通工具协议进入上下文。

## 3. 队列、去重与次序

| 项目 | 已确认行为 |
| --- | --- |
| 作用域 | 当前对话私有，Spot／Flood下可用；Blackout直接裁切该来源的目录／读取／写入，无替代队列；其他对话不可读取，不是应用全局代码库 |
| 数量 | 默认 10 份，成功写入／晋升后按队列自动淘汰；不依赖摘要或模型删除清单 |
| 同文件同内容 | 完整内容相同且快照仍在队列时复用，移至队尾，不重复占位 |
| 同文件内容变化 | 新增一份快照，保留各自真实内容与身份，按容量淘汰 |
| 不同文件同内容 | 不以正文相同合并文件来源 |
| 历史读／继续分页 | 不新增快照，不晋升、不刷新队列次序 |
| 已淘汰内容 | 不为复用另建查询库、永久索引或额外全文保留；只能通过新的真实编辑器读取形成新观测 |

同文件同内容的复用不抹掉真实来源。[当前执行计划](../superpowers/plans/2026-11-22-beacon-foundation-implementation.md)第2节与Task 1已写明接口提案：复用时保留原ID及首次捕获的version／observedAt／capturedAt，仅更新lastObservedAt／lastObservedVersion；工具本次观测元数据按实际version／observedAt另行返回，与复用快照的首次捕获元数据分开，不把旧捕获时点或版本冒充本次读取，也不改写首次记录。不得伪造执行时间、用户查看时间或代码变化；字段仍待本轮书面审阅。

列举只提供来源、时间、版本和可读入口，不把 10 份完整正文全部装入每次请求。曾列出的快照不保证以后仍在，实际读取时按当前队列状态检查。

## 4. 单份容量与失败合同

完整代码正文最多 **256 KiB＝262144 个 UTF-8 字节**。只计算正文，不以 token、UTF-16 字符数、文件磁盘编码字节或 JSON 转义后的长度替代。容量约束针对完整快照；工具的实际返回覆盖另按既有整读／分页能力表达。

| 情形 | 工具反馈 | 队列结果 |
| --- | --- | --- |
| 读取成功且保存成功 | 返回实际代码覆盖、真实版本与时点，以及真实可读快照入口 | 新增或复用晋升，按10份规则自动淘汰 |
| 读取成功但完整正文超限 | 仍返回实际代码覆盖，明确未保存／超限，不提供伪造的可回读快照 ID | 不新增、不晋升、不淘汰，原队列保持 |
| 读取成功但保存或晋升落盘失败 | 仍返回实际代码，明确读取成功、保存失败，不承诺后续可从队列读回这次观测 | 原队列保持，不先发布新次序或淘汰旧快照 |
| 读取失败 | 返回真实读取失败，不伪造代码或保存成功 | 不因这次调用调整原队列 |
| 历史快照已淘汰／读取失败 | 明确已淘汰、不可用或实际读取错误 | 不以当前稿补齐，不新建副本 |

Blackout返回本窗口已打开代码编辑页的正文、文件名和路径，以及保存能力disabled／blackout，不调用队列保存，不提供快照ID，也不提供临时替代引用。代码队列和其他持久化来源的目录／读取／写入在可用操作说明及执行层都关闭，已有缓存也不构成旁路。

不保存截断副本、不以一次保存失败撤销已经接受的问题，也不阻止模型依据实际返回的代码继续讲解。保存成功不是发送或实时读取前置。

失败保原队列包含失败的新写、重复项晋升及其联动淘汰。实现需要在实际保存成功后才对外发布新目录，不能先删旧条目再尝试保存新稿。具体原子发布、元数据、作用域校验和取消接线见[当前执行计划](../superpowers/plans/2026-11-22-beacon-foundation-implementation.md)第2节、Task 1／4／6；这些是已写入但待审阅的接口提案。取消后仍按已真实完成的操作反馈，不能用推测状态冒充成功或失败；不另增通用事务框架。

## 5. 历史读取、分页与分支

每份快照的内容身份固定。历史工具读取指定快照时，只返回该快照的真实内容；读取历史不等于重新观测当前编辑器。

代码队列不为跨次分页 pin 住旧快照。若第1页返回后发生其他真实代码读取并按容量淘汰，后续页明确返回该快照已淘汰；不能改读新版、拼接两版或额外保全文。已经实际返回的片段仍按工具协议保留，但不证明完整快照仍在队列。

共享近期精确凭证的规则与此不同：producer/id/revision 首次成功读取后，在本回答固定该版以供后续部分读，不被期间更新或淘汰混版；首次成功读之前已失效则明确失败。该既定一致性规则不扩展为代码快照的跨调用保护，也不把实时编辑器永远锁在第一次读取版本。

代码队列按整个对话管理。编辑旧问题或重新回答不隐藏、删除或禁止读取原分支已经取得的代码快照；列举与读取不要求原工具消息仍是有效历史，不维护分支成员关系。仍按默认10份、实际次序自动淘汰，其他对话不可访问。

这项例外仅适用于本对话代码快照。旧分支消息、要求、许可和其他分支私有材料继续排除；其内存命中和 material 原生回退都需检查有效分支。代码可读不恢复旧权限、旧要求、旧摘要，也不使历史执行结果变成对新稿的验证。

协议回放保留原调用与结果身份，不重新执行读存或晋升。工具已完成而后续回答被中断时，合法有效历史内的完成事实应保留；分支改变后代码快照能否读按上述整段对话规则判断，其他完成事实仍按有效历史规则处理。

## 6. 档位、会话与工作区

- **Spot／Flood：** 在当前合法对话和真实权限内同次读存，不扩大代码来源、根或学习资产写入种类；Flood 不开放别的聊天快照。
- **Blackout：** 相对Spot／Flood仅朴素裁切持久化来源能力。代码快照及其他持久上下文来源的目录、读取、写入均不可用；不建立内存镜像队列或替代引用。当前打开代码编辑页含dirty的正文、文件名和路径仍可正常tool返回，但保存能力disabled，不调用持久存储、不提供快照入口；已加载对话内容按正常上下文处理。
- **切档／切根／分流：** 沿用既有任务冲突、独立分流和已加载消息／工具结果复制规则；选根或切回持久化不自动捕获当前稿，不暗中导入旧对话未加载队列正文。不因切回持久化补捕获先前Blackout读稿；新对话可通过新的真实读取建立自身队列。
- **归档／删除：** 归档只读，不能通过新读存暗改归档队列；取消归档后按正常规则继续。经确认删除当前对话时，其专属快照随本对话处理，不级联共享题面／执行凭证或学生资产。

这里代码读取／快照操作属于Beacon消费与本对话材料管理，Blackout不调用其持久能力；软件层的用户行为采集是另一链路：已选工作区正常时，Get Problem、Runner、CPH、Notebook、OJ记录在三档均照常采集落盘。未选根或根异常则不生产这些持久材料，不能将Blackout误作全软件停止写入。

持久化不可用时反馈真实状态，不写替代目录、不借其他对话／根保存，也不把临时成功表述成已落盘。具体并发或取消接线遵守现有所有权和作用域校验，不能新增等待队列或自动重放。

## 7. 与题目材料、执行凭证及压缩的关系

共享队列限当前 `.beaconWork`，Runner／CPH／Notebook／OJ 四个 producer 各20条；Get Problem 独立13条，按题目＋代码文件去重，保存实际用户查看时间和解析题面正文。用户再Get同题同文件才更新正文／时间并移队尾；同题不同文件分别保留。模型读取不修改用户行为队列。

宿主给出真实Get记录、CPH关联和现有文件名／目录解析线索，LLM结合提问选讨论对象，冲突不明则问用户。不建永久强绑定库或宿主强制优先级。当前代码快照只是一个代码版本，不因保存而决定正在讨论哪题，也不重写旧凭证的代码与题目身份。

Spot／Flood题面默认读Get Problem保存正文，Blackout直接调OJ Connect联网取得题面，不读编辑器题目页。LLM可按需通过现有五站只读链路补取或显式刷新，结果仅入上下文；不增加缓存、题库或队列，不回写Get正文、viewedAt或次序，不创建源码、导入CPH或展示／切换面板，登录仍由用户完成。失败如实反馈，不把旧题面叫作最新。Runner／CPH／Notebook运行结果和OJ测评记录只有持久化记录这一等来源，不为Blackout或其他档位增设对应功能页面读取旁路。Notebook文档本身仍按独立资产规则处理。

长会话首版使用当前会话模型同步压缩。实际请求前检查，工具批次闭合后整理；`B=min(最大输入额度,总窗口−本次输出预算)`，90%B为主动线，约60%B为目标。同待发步骤最多一次整理修复；整理自身和取材后的请求仍计量但不递归整理，装不下则停止，取材有界。

压缩管理有效输入，不物理删除代码快照，不产出 `discardSnapshotIds`，不需要模型保存／删除工具。代码队列独立自动淘汰。原始历史、真实工具交换和已返回片段不因压缩被删除；受影响有效前缀摘要在编辑／重答后失效，合法前缀可继续使用，摘要不能恢复旧要求或许可。淘汰后尚未返回的快照正文不保证可回读。

## 9. 验收合同与未完成事项

下列为后续实施必须承接的回归场景，**本轮未执行产品测试**：

1. 发送、继续、重答及协议回放零隐式读存；模型主动读才同次捕获／保存，来源不是聊天搜索或模型重写。
2. 同回答先读V1、dirty改为V2后再主动读，分别返回真实版本；每次保存与返回来自同一次捕获，无第二读替换。
3. 同文件同内容复用并晋升，内容变化新增，不同文件同内容不合并；历史读与继续分页不晋升；第11份按队列规则淘汰。
4. 262144 UTF-8字节可保存，超过时返回实际代码并明确未保存；包含多字节中文、换行及JSON转义字符，不按token或序列化长度算。
5. 新写和重复项晋升分别模拟保存失败：仍返回实际代码、不造保存成功／可读ID；旧队列、正文及次序保持，联动淘汰不先发布。
6. 历史分页目标被淘汰后如实失败，不以新版补页、不额外pin；共享精确凭证首次读固定的规则单独通过。
