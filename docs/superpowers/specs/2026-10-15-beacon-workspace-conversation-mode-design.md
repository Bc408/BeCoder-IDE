# Beacon 工作区、聊天与能力档位交互重组

日期：2026-10-15  
状态：上一轮方案记录；控件、草稿与恢复规则由[最新方案](../../beacon/workspace-ui-draft-design.md)修订，本文不作为这些部分的现行实施依据  
范围：Beacon 主 Webview、工作区上下文协调、历史绑定与相关正式文档

## 1. 目的

Beacon 的工作区、聊天和能力档位目前分散在同一页面的不同位置，用户难以判断当前聊天归属、切换工作区后的结果，以及三档能力实际消费哪些资产。本设计以“工作区是一级容器，聊天是该容器中的主要用户对象”为基础，重新组织状态与页面结构。

目标是让用户在任何时刻都能回答三件事：当前是否在使用一个工作区、当前聊天属于哪里、Beacon 此刻能读取哪些材料。页面布局只呈现已由状态机确定的操作，不以提示文字弥补状态歧义。

## 2. 已确认的产品规则

- Beacon 工作区按窗口选择；最近工作区列表跨窗口共享。
- 工作区拥有其聊天、记忆、运行记录和学习资产；聊天固定归属一个工作区，不能迁移。
- 已有聊天只能由一个窗口打开；其他窗口不复制或抢占。
- 点击“新聊天”只回到 Beacon 主页的干净输入状态。首次发送才创建并持久化聊天实体。
- 已打开的已有聊天详情页不提供工作区选择入口。用户先退出详情页，回到 Beacon 主页，才能切换工作区。
- 左下角始终显示 Blackout、Spot、Flood 三档入口。未选择工作区时只有 Blackout 可选；Spot/Flood 仍显示但禁用。
- 首次从未选择状态选中可用工作区时，档位静默切到 Spot。已选工作区之间切换时，保留当前选择的档位。
- 用户取消当前工作区选择时，档位降为 Blackout；取消的路径进入最近工作区列表首项。
- 用户主动选择 Blackout，或工作区不可用而被动降级时，Beacon 主页不显示该工作区的历史、记忆或运行材料。
- 用户在已有聊天详情页主动切入 Blackout，或因工作区失效被动降级时，退出详情页并进入 Blackout Beacon 主页。原聊天保留在原工作区，恢复 Spot/Flood 后从历史列表重新打开。
- 三档都可读取当前窗口已打开页面的内容，但不因此取得其本地文件、相邻文件或隐藏记录的读取权。

## 3. 概念与状态

### 3.1 工作区选择与有效消费分开

`selectedRoot` 是窗口记住的 Beacon 工作区路径，可为无选择。它只表示用户最近选择的根，不自动意味着正在消费该根资产。

`usableRoot` 表示 `selectedRoot` 当前已通过 `.beaconWork` 准备与合法性检查。只有它存在并且模式为 Spot/Flood 时，Beacon 才消费工作区聊天、记忆、运行材料和允许范围内的文件。

`mode` 始终是 `blackout | spot | flood`。Blackout 可以在仍保留 `selectedRoot` 时由用户主动选择；这时根作为可恢复的选择被记住，但不消费其资产。不可用根会被动进入 Blackout，并记住降级前的 Spot/Flood 意图，以便路径恢复后重新开放该档位。

### 3.2 两种页面状态

| 页面 | 职责 | 工作区控件 | 历史与聊天 |
| --- | --- | --- | --- |
| Beacon 主页 | 工作区选择、历史选择、新聊天和干净输入 | 显示 | Spot/Flood 下显示当前工作区历史；Blackout 下不显示工作区历史 |
| 已有聊天详情页 | 阅读、继续、编辑、暂停和重答一个已持久化聊天 | 不渲染 | 只显示这一聊天；退出后回到它所属工作区主页 |

主页不是第三种“新聊天实体”。主页中的输入框是未持久化草稿；它在首次成功发送时绑定到当前工作区并进入聊天详情页。

## 4. 交互状态机

| 起始状态 | 用户或系统事件 | 结果 |
| --- | --- | --- |
| 无选择 + Blackout 主页 | 选择一个可用文件夹 | 写入选择、准备 `.beaconWork`、进入 Spot 主页、加载该根历史 |
| 已选根 + Spot/Flood 主页 | 从最近列表选择另一可用根 | 保持 Spot/Flood，替换当前工作区和历史列表；不迁移聊天或草稿 |
| 已选根 + Blackout 主页 | 从最近列表选择另一根 | 保持 Blackout，只更新被记住的根；不加载目标根历史 |
| 已选根 + Spot/Flood 主页 | 选择 Blackout | 保留根选择，隐藏该根资产，主页进入临时 Blackout 状态 |
| 已选根 + Blackout 主页 | 选择 Spot 或 Flood | 根可用时恢复资产消费和该根历史；根不可用时保持 Blackout 并说明原因 |
| 任何主页 | 取消当前工作区 | 清除当前选择，模式为 Blackout；该路径去重后置于最近列表首项 |
| Spot/Flood 聊天详情页 | 用户选择 Blackout | 保留聊天与根，退出详情页，进入 Blackout 主页 |
| Spot/Flood 聊天详情页 | 根失效 | 同上，但以故障状态进入 Blackout 主页 |
| Spot/Flood 聊天详情页 | 退出聊天 | 返回该根的 Beacon 主页和历史列表 |
| Blackout 主页 | 首次发送 | 只建立内存临时会话，不写入工作区历史 |
| Spot/Flood 主页 | 首次发送 | 在当前根创建持久化聊天，随后进入该聊天详情页 |

运行回答、保存聊天、写 Notebook 或其他受控上下文操作时，涉及模式或工作区的状态迁移不开始。入口显示不可操作原因；不会中断运行、迁移对话或排队稍后切换。

## 5. Beacon 主页的工作区控件

主页只引入一个工作区控件，位置在顶部“连接设置”按钮左侧。已有聊天详情页不渲染此控件，也不保留可从旧 Webview 消息触发切换的能力。

| 控件状态 | 收起形态 | 展开内容 |
| --- | --- | --- |
| 未选择根 | “选择工作区” | 最近工作区绝对路径列表，每项右侧 `×` 移除该历史；底部“添加新工作区” |
| 有效根 + Spot/Flood | 当前根文件夹名 | 文件夹名平滑展开为完整绝对路径；当前项右侧 `×` 取消当前选择；下方为最近工作区列表和“添加新工作区” |
| 有效根 + 用户主动 Blackout | 隐身/不可见圆形图标 | 与有效根相同的当前路径、取消选择、历史列表和添加入口；悬停显示“{文件夹名} 未使用”，并说明切到 Spot/Flood 后恢复使用 |
| 根失效而降级 Blackout | 红色圆形感叹号 | 失效根绝对路径、重新选择、取消选择、最近列表和添加入口；悬停显示“{文件夹名} 出现问题”，并说明恢复路径后可继续使用 |

选择当前项右侧 `×` 时，当前绝对路径以连续布局动画移入下方最近工作区列表首项。若路径已在列表中，移动原有条目而不产生重复。历史项自身的 `×` 只移除最近记录，绝不删除该路径、`.beaconWork` 或其中资产。

工作区切换的可见过渡发生在主页：当前历史列表淡出并显示短暂加载占位，宿主确认目标上下文后再淡入目标列表。动画不提前伪造成功；失败保留原状态并显示已有的安全错误反馈。减少动态效果开启时取消位移动画，仅保留状态更新。

## 6. 三档能力入口

三档入口固定在输入框左下角，显示 Blackout、Spot、Flood 全部三个选项：

- 无 `selectedRoot`：Blackout 可选，Spot/Flood 禁用，并在菜单内说明需要先选择工作区。
- 有可用根：三档均可选。Spot 读取该根内非敏感材料和工作区资产；Flood 扩展到允许的本机/共享位置；Blackout 暂停工作区资产消费。
- 根不可用：Blackout 为当前状态，Spot/Flood 禁用。恢复或重选根后再可用。

切换档位不改变工作区选择本身。档位切换对后续读取和请求生效；正在进行的操作由既有上下文快照完成或被宿主拒绝交接，不能在中途静默扩大或缩小读取范围。

## 7. 数据与宿主边界

实现需要把“选中的根”与“当前可消费的根”区分到原生上下文状态中，替换现有“有效根仅允许 Spot/Flood、无效根仅允许 Blackout”的单一资格判断。模式选择、根可用性和活动聊天必须由宿主校验；Webview 的隐藏、动画和禁用状态不构成权限约束。

聊天持久化仍由原有单聊天租约、revision 检查与 `.beaconWork/conversations` 所有权负责。取消当前根、移除最近根和 Blackout 都不删除聊天、记忆、运行记录、Notebook 或 `.beaconWork`。Blackout 临时会话仍只在内存中存在，不能自动回填到根。

“退出已有聊天详情页”与“切换根”必须先释放当前聊天的窗口占用。活动会话的草稿按当前页面生命周期处理，不迁移到另一根；实现前须确认现有草稿缓存是否需要在返回主页后同一窗口保留。

## 8. 非目标

- 不改变三档的文件保护、页面读取、会话隔离、Notebook 写入或模型联网边界。
- 不创建全局聊天列表，不允许跨根迁移、复制或合并聊天。
- 不增加账号、授权账本、模式切换审批流程或新依赖。
- 不改学生 C/C++ 源文件，不自主执行或提交。

## 9. 实现与验证边界

预期改动所有者包括：`src/vs/platform/beacon` 的上下文协调与选择存储、`extensions/becoder.beacon/src` 的历史绑定/消息处理、`extensions/becoder.beacon/webview` 的页面状态和样式，以及与最终语义一致的正式 Beacon 文档。

必须覆盖的验证包括：

1. 原生单元测试：初选根自动 Spot、根间保持模式、主动 Blackout 保留根但不消费资产、取消根、根失效降级与恢复、详情页降级退出。
2. 扩展单元测试：主页首次发送才创建持久化聊天，Blackout 临时聊天不持久化，退出详情页、切根、单窗口聊天租约和旧 Webview 消息均不能越权。
3. Webview 渲染测试：两种页面结构、控件四种状态、禁用档位、列表过渡的终态、路径去重和减少动态效果。
4. 构建与项目负责人验收：扩展检查后按仓库标准构建 staged Windows 应用；实际验证主页切换、三档切换、失效根、单窗口占用及动画可读性。

## 10. 待进入实现计划前的确认

本规格已固定已讨论的用户行为。实现计划需在现有草稿缓存的保留范围、动画采用现有 CSS/React 能力的具体路径，以及原生状态兼容策略上依据源码确定，不预设额外产品行为。
