# Beacon 上下文平台架构

版本：1.1 · 日期：2026-10-14 · 状态：产品架构基线，当前实现另行记录

产品规则以[正式 PRD](prd.md)为准，笔记规则以[Notebook 正式设计](notebook.md)为准。本文定义长期上下文平台的职责与数据关系，不冻结工具协议、目录内部布局、数据库、字段或 prompt。

## 1. 架构目标与方向

Beacon 围绕当前学习任务使用代码、诊断、题面、样例与真实运行证据，同时保留会话材料和工作区学习积累。方向采用已认可的 B 架构：材料保有来源、范围和版本，由受控读取与按需组织形成每轮实际输入。

需要区分四类对象：模块产生的原始记录、会话实际使用的材料快照、每轮模型输入，以及模型形成的摘要/记忆/学习笔记。统一理解材料不要求把所有数据复制进一个中心数据库。

用户选择有效工作区时，由 BeCoder 准备合法可用的 `.beaconWork`；后续 Runner、CPH、Notebook 的区内用户运行行为产生并落盘对 Beacon 有帮助的完整证据，不等对话请求才采集。请求开始时向模型说明当前情况、来源/版本与工具和信息入口，再由模型按需取得材料；不把首次请求自动塞入大份材料正文作为前提。具体关联、索引、读取、预算与压缩策略在技术阶段比较，不强制用户每次明确题目或整理材料清单。

## 2. 所有者与能力边界

| 所有者 | 生产或维护的内容 | Beacon 与它的关系 |
| --- | --- | --- |
| 编辑器及语言服务 | 应用内当前页面内容、未保存修改、选区、诊断 | 三档可读取本窗口用户当前打开页面；页面能力不回读其磁盘文件，不将当前状态冒充当次运行代码 |
| Runner | 用户发起的编译运行、当次主代码和实际输入输出/状态 | 读取现场或近期记录；模型不启动、停止、重跑 |
| CPH | 样例、整轮评测、逐样例判定、相关配置 | 读取实际材料，不视作完整题面或 OJ 判定 |
| 内置网页/PDF | 用户正在阅读的资料及明确选区 | 提供可用线索，显示成功不等于准确完整的模型材料 |
| Beacon 会话 | 问答、工具使用、实际材料、会话摘要与归档状态 | 按固定归属保存，隔离其他会话 |
| 工作区记忆与查询许可 | teach tips、student status、记忆归档及用户明确的网络个人信息查询许可/限制 | 主模型简单追加，用户直接管理；联网许可由 prompt 引导依据真实用户决定和适用范围，不增加独立许可凭据系统 |
| BeCoder NoteBook | 用户笔记、程序块、input、最近实际结果、文件保存，以及工作区内用户运行的行为证据 | 独立文档能力；区内运行证据另存 `.beaconWork`，不占 Runner/CPH 队列；Beacon 仅按显式请求辅助写笔记 |
| 模型与联网服务 | 生成、推理、外部资料 | 服务能力不扩大本地权限；来源与限制可解释 |

Beacon 的有限写入对象是自身资产，以及用户明确要求的 Notebook、讲义、图示等学习资产。教学代码可存在回答或笔记中，学生的 C/C++ 源文件不被 Beacon 新建或改写。运行和 OJ 账号操作仍由用户发起。

## 3. 三种根与资产位置

| 对象 | 位置或作用域 | 是否随编辑器目录切换 |
| --- | --- | --- |
| 编辑器打开的文件夹 | 原有编辑器语义；可以多根 | 用户通过编辑器操作改变 |
| Notebook 关联根 | 当前源码所属的已打开文件夹，根下 `.notebook` 镜像相对目录 | 根据当前源码和已打开根朴素匹配，不同步搬迁笔记 |
| Beacon 工作区 | 本窗口在 Beacon 设置中独立选择的目录，根下 `.beaconWork` | 不自动跟随编辑器；由用户选择 |

`.notebook` 与 `.beaconWork` 不合并为 `.becoder`。独立手写笔记可以保存到用户选择的位置；关联笔记使用 `.notebook`。`.beaconWork` 负责会话、日志、专属附件、材料快照、符合范围的近期队列、记忆及归档，不能成为 `.bcnb` 文件的默认存放地。

工作区内的持久化资源由该工作区内行为产生，供该工作区 Beacon 消费；授权后的外部主动材料和 flood 学习材料可成为该工作区会话自己的快照，但范围外源码的 Runner/CPH 记录不因此进入工作区队列。

## 4. 工作区状态与多窗口

工作区选择和当前状态按窗口维护；最近工作区列表跨窗口共享。多个窗口选择同一有效工作区时共用其持久化资产，选择不同工作区则分别使用各自资产。

| 当前状态 | 模式资格 | 持久化责任 |
| --- | --- | --- |
| 未选择工作区 | 仅 blackout | 会话和材料只在临时内存中使用 |
| 首次选中有效工作区 | spot（静默默认）或 flood；首次选择自动 spot | 本窗口新会话与自身资产归该根 |
| 选定工作区有效 | blackout、spot、flood | blackout 暂停消费工作区资产且会话仅临时保存；spot/flood 按原规则消费并保存该根资产 |
| 原选择被记住但路径不可用 | 保留选择并提示，仅 blackout | 不写替代根；已有资产归属不变 |
| 原路径恢复可用 | 重新开放 spot/flood | 可继续访问原资产，不自动回填临时对话 |

用户选择目录时建立或检查该根的 `.beaconWork` 资产目录合法可用，之后开始随区内用户行为记录证据；准备失败不得静默覆盖同名文件或换落盘位置。打开普通文件夹、Runner、CPH 或 Notebook 操作不初始化 Beacon 工作区。窗口重启恢复自己记住的选择，不要求打开编辑器文件夹。

Beacon 主页同时承担工作区选择、历史列表和新聊天入口。唯一的工作区控件紧挨连接设置按钮左侧，悬停向左、点击向下展开；用户在主页选择/清除工作区或最近项。已有聊天详情页隐藏该控件，并由宿主拒绝工作区切换消息。Spot/Flood 首次输入可建立归属工作区、但不进历史的草稿对话，首次发送将原实体转正；空白主页不建实体。Blackout 草稿及会话只在内存中存在。

草稿正文及已采集附件归对话保存并复用单对话租约，不按窗口分库存储。页面返回保存详情草稿并恢复主页草稿；主页“新聊天”明确清除主页草稿，详情按钮按主页是否存在草稿区分返回恢复和新聊天。工作区保存轻量的最后关闭恢复引用（页面、目标对话或显式空白），不复制草稿正文。窗口关闭顺序由宿主协调，不能用异步保存完成顺序覆盖；自动恢复遇占用静默回主页，不回退寻找其他非空草稿。完整规则见[专项方案](workspace-ui-draft-design.md)，源码与实际验证边界见[实现状态](implementation-status.md)。

工作区或档位切换前，本窗口有关任务、回答和必要落盘必须已结束；否则拒绝并提示，不中断、不迁移、不排队。只有主页可以切换工作区。空闲切换刷新目标根历史列表；原对话资产留在原处。主动 Blackout 或根失效会让详情页返回主页，主页隐藏该区的历史、记忆和运行材料。临时对话不自动转存，目标区从打开已有或首次发送创建的对话继续。

同一对话全局仅允许一个窗口打开。第二个窗口只提示已占用，不提供跳转或副本；归档会话同样适用。对话占用与工作区资产共享是不同约束，不能用锁整个工作区代替单对话限制。正常释放、窗口退出和异常终止后的识别需技术验证。

## 5. 受控材料读取

材料读取分为页面内容和文件/记录两层。三档都可按需读取本窗口用户当前打开的编辑器页面内容，包括未保存修改；对应文件是否位于 Beacon 根内不决定页面读权。页面入口只取页面内容，不能重读对应磁盘文件、补读邻接/引用文件、自行打开文件或取得隐藏历史。

spot 的自动文件/工作区记录访问范围是 Beacon 选定根，flood 扩展允许的本机文件范围；blackout 除主动材料和当前打开页面外，没有自由本地文件读取、工作区行为记录检索或持久化记忆消费入口。大量用户行为信息由工作区记录入口组织，因而 blackout 缺失这些入口也是隔离手段，不需逐条把历史结果塞入临时会话。当前打开的本人 OJ 提交/判题页面同样三档可读，默认用户知情页面可能被 Beacon 阅读，不因个人信息额外询问；凭据过滤和会话内部资产隔离仍有效。

进一步联网查询个人信息仍须依据真实用户的明确许可及适用范围，已有匹配许可可以复用，缺失或超出范围时由模型先问询。负责人于 2026-10-14 确认采用 prompt 软约束，不新增宿主许可凭据、审批门或查询意图分类拦截；页面、登录状态、flood 和模型自行追加的记忆不能被当作用户新许可。本地根/档位/会话隔离、敏感信息过滤及学习资产写入条件继续由宿主执行。主模型可把用户许可/限制简单追加到 teach tips；blackout 不自动消费工作区许可记忆或查询额外本人记录。

宿主在读取前校验操作、参数、真实目标和权限，模型描述或 UI 状态不能扩大授权。主动提供一个外部文件只采集该文件当时内容，不获得父目录、相邻/引用文件或持续追读权。

模型工具可借鉴 CLI 的简明命令组织，经受控入口分发到内部能力。命令形式不等于 Shell 或外部 CLI。工具数量、名称、schema、帮助发现和返回形式均留待研究，不默认把整本命令手册注入上下文。

入口说明应交代哪些页面可读、哪些工作区记录存在及其版本/范围、怎样定位和读取，缺失或不可读的来源如实说明；不要求宿主先读取并注入整份运行正文。页面、工作区记录、文件和本会话材料由宿主分开授权，工具隐藏入口的同时也在执行时核验，不能只靠模型自觉。

对运行材料需要能定位当前文件最近记录，也能按需要查近期条目并取详情。列表与详情必须引用同一记录；当前文件没有记录时返回缺失，不拿其他文件顶替。定位路径是能力要求，不冻结成两级调用次数或摘要/详情硬性协议。

已发出请求的输入与设置不被中途修改悄悄替换；热更新针对后续有效请求。权限撤销与生成中的新读取怎样交接需形成明确状态设计，不能以模型当前输出为准。

## 6. 原始运行记录与现场材料

### 6.1 归属与生命周期

每个工作区有两条独立 FIFO：Runner Run/Run With Input 合计约 10 次，CPH 完整评测约 10 轮。只持久化发起窗口当前有效 Beacon 根内源码的记录；根外记录临时使用，不重定向到其他窗口或代码祖先的工作区。

Runner/CPH 原始产物属于可淘汰的近期缓存，负责人选择朴素实用的队列方向，存储占用可接受即可。它们不要求用户资产等级的恢复或保留；缓存损坏可以舍弃本产品确认拥有的条目，不牵连会话已复制的材料、独立笔记、附件或记忆。具体文件格式和容量是技术选择，不为低价值缓存引入复杂的事务/恢复平台。

Notebook 位于发起窗口当前有效 Beacon 根内时，其用户程序块运行也向 `.beaconWork` 产生独立行为证据；这不是第三条已冻结次数的 FIFO，不占前述两条队列，也不改变笔记每份 input 只留最近结果的规则。笔记与关联源码的路径分别判断，关联源码在根内不自动使根外笔记取得记录归属。证据保留/容量策略进入技术设计；没有可归属路径的临时笔记不能借关联猜出落盘根。

运行所有者在用户行为过程中采集版本正确的代码、input、编译计划、实际输出/状态及其他对诊断有用的事实，并随行为进展落盘；不因对话尚未打开、BYOK 未配置或模型不可用而漏记合法范围内的行为。模型不负责启动记录、触发执行或补造过去未采集的信息。必要记录写入失败如实呈现，不伪称完整，不阻断无关编辑功能。

取得主代码快照并开始编译后，任何实际终态都计一次；编译前失败不计。CPH 全轮含多个样例只占一条。运行对象、工作区归属和当次代码要保持一致，不能因当前文件或根之后改变而重写记录身份。

记录保存当时主源码，不首版扩大到本地头文件历史快照。输入尽量完整保存并设置容量上限；输出、单记录和工作区总容量待技术设计。限制触发必须标明缺失/截断，不能伪称完整。

### 6.2 全面但真实的数据

诊断需要的覆盖目标包括：运行身份与时间、源文件和代码快照、编译器及参数、实际编译输出和状态、实际输入、程序输出、退出/取消/超时状态及实际耗时。CPH 还包括样例输入、期望和实际输出、逐样例判定、checker/cerr 等影响判定的实际配置。

Notebook 行为证据还须定位所属笔记/程序块、真正运行的最新代码和选中 input、当次编译与实际结果；不能从笔记后续修改倒推执行版本。工作区证据与 `.bcnb` 文档输出、程序块结果清除和 Notebook 备份不是同一个存储对象，具体生命周期在专项技术设计明确。

只记录所属模块真正观测到的事实。合并 PTY 流不能伪装成独立 stdout/stderr；实际耗时不能混淆为算法性能；程序正常退出不能被写成样例通过，CPH 通过不等于 OJ AC。

程序运行中支持按需读取现场证据，不要求停止或等待完成。终端可见内容、回滚缓冲与模块采集流是不同来源，应说明覆盖范围及采集时点，并尽可能关联当次运行身份与代码。现场证据不冒充完整事后记录，不授予模型新增运行或持续监控能力；BeCoder 所有者随已发生行为采集并落盘证据是独立职责。

### 6.3 当前编辑稿对照

运行快照解释当次错误，编辑器最新内容含未保存修改用于理解后续变化。二者分别标记来源和版本，不互相覆盖。没有新的运行证据时，模型只能说明当前代码看起来已调整，不能宣称已验证。

## 7. 会话材料与上下文整理

持久化会话固定归属自己的 `.beaconWork`。实际用于对话的运行证据、题面等形成会话快照，即使来源队列淘汰、网页变化或文件修改仍能解释当时对话。

附件直接归会话独立保存，不共享大附件池、去重池或引用计数。存盘完整性与工具返回覆盖程度分别表达：磁盘有完整材料，不等于本轮全部返回；省略或截断需可辨，并支持权限内按需补读。

当前会话只能使用自身历史、摘要和留存材料。其他会话内部消息、摘要、附件及材料即使在 flood 中也不自动读取；独立工作区记忆是可复用资产，不是跨会话检索通道。此边界落实在受控读取，而非只写进 prompt。

自动压缩解决单轮模型输入容量，长期历史留存由会话存储解决，两者独立。较早内容可摘要，近期原文优先，界面提示整理；原始历史和证据不被摘要替换或删除。必要时回读本会话材料，blackout 不新增磁盘留存。

材料定位、来源/版本及权限信息和模型生成的摘要应保持可区分。阈值、预算、工具返回预留、重复压缩误差、失败处理与成本进入技术设计；模型生成成功不能证明摘要忠实。

## 8. 工作区记忆与个人信息查询许可

teach tips 默认带入，student status 按需使用；主对话模型日常对两者均只需简单追加，不自主改写旧 tips 或设计复杂维护机制。用户通过查看和直接编辑把关记忆质量，允许模型本轮不追加，不逐条批准。用户明确的网络个人信息查询许可与限制也可由主模型记入 tips；许可来自用户，不能因模型写入或 status 推断新增/扩权。文本热更新不追改已发出的请求。

模型产出的观察与推测不能反复被包装成已验证事实；职业底线不由 tips、用户调教或 dream 改写。记忆格式、分类和检索方式未冻结，不默认引入通用生活画像或大型后台提取系统。

dream 由用户主动触发，成功后新 status 直接生效；原完整 status 保存为人类可读、应用内只读的历次归档。归档默认不被模型日常使用。用户取消归档仅追加回现有 status，不自动覆盖、去重或调用智能合并。

网络个人信息查询许可不限竞赛场景，提示模型从真实用户指令和可读的 tips 判断已有范围、必要时问询；用户撤销或修改限制后应依新决定行动，不由模型自行追加、status、dream 或外部材料产生许可。OJ 仍需按平台、账号、题目范围理解用户意图。不设计独立宿主许可凭据或授权表单。

## 9. 资产生命周期

| 操作或事件 | 保留/变化的对象 |
| --- | --- |
| 近期队列淘汰 | 淘汰所属队列旧原始记录；会话已使用快照、记忆与 Notebook 不受影响 |
| 会话压缩 | 改变模型输入组织；完整历史和材料不删除 |
| 会话归档 | 普通列表隐藏，数据不搬迁；归档只读，取消归档后回原区继续 |
| 会话删除 | 移除本会话消息、专属材料和附件；记忆、独立学习资产、源码和原始队列不级联删除 |
| dream 成功 | 新 status 生效，旧完整内容进入记忆归档 |
| 取消记忆归档 | 朴素追加回现有 status，恢复日常可用与可编辑 |
| Notebook 改写 | 遵循专项最新编辑稿与完整备份规则；失败沿用原生编辑/保存反馈，不额外回滚原稿；不生成执行结果 |
| 源码改名/移动/删除 | 笔记和备份留原处，由用户处理；不维护身份跟随 |
| 工作区切换/不可用 | 资产保持原归属；不静默迁移、复制或写入替代存储 |

会话、独立记忆、近期记录与学习文档是不同资产，不通过删除来源自动撤销派生内容。工作区整体导出、分享或删除的产品范围仍需决定。

## 10. 下一阶段技术验证

按[技术调研议程](technical-research.md)先核对现有上下文和工具路径，再比较宿主复用、记录接口和材料预算方案。关键验证包括真实代码/运行绑定、权限与隔离、单对话跨窗口占用、工作区共享写入、最新编辑稿的 Notebook 保护、OJ 身份与证据、摘要和记忆质量。

运行中路径突然失效、写入失败和窗口崩溃的交接需区分各对象与实际保存结果，不伪称成功。Notebook 改写失败按负责人最新决定借鉴原生机制，不额外要求恢复原稿；其改写前完整备份规则仍有效。若技术限制暴露新的用户行为取舍，再集中返回产品层。不能用静态格式检查或文件写入成功代替模型教学质量、真实 OJ 接入和产品运行验收。
