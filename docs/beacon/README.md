## 必须保留的边界

- Beacon 是算法与编程导师，不改学生 C/C++ 源文件，不自主运行、停止、登录或交题；用户明确请求时才写学习资产。
- Beacon 根按窗口独立选择，最近列表共享；同根共享历史，同一对话仅一个窗口打开。忙时立即拒绝操作，不排队或补发。
- Blackout 只使用主动材料、当前打开页面及已加载上下文，不新增工作区资产读取或临时消息落盘。Spot 的文件及学习资产范围限所选根；Flood 扩展文件范围，仍执行敏感过滤、会话隔离及资产种类限制。
- 页面读权不授予 backing file、邻接文件或隐藏记录读权。联网查询额外个人信息依真实用户许可，由 prompt 引导，不新增宿主许可台账或审批门。
- `.beaconWork` 与 `.notebook` 分属独立根。运行模块生产事实；Runner/CPH 各自保留近期 FIFO，Notebook 证据独立。会话实际消费的材料独立保存，不随缓存淘汰。
- 草稿按对话保存；主动切档保持页面和输入，跨临时/持久化类别后首次接受新问题才形成独立完整快照。切根不搬运对话。
- Notebook 四条完整流程、四平台 OJ 本人同题材料、主模型简单追加 tips/status 和主动 dream 仍是已确认范围。当前实现不完整时必须说明缺口，不能把候选或文件写入成功当作真实旅程验收。

完整行为以各专项文档为准。历史桌面稿和旧提交仅用于追溯，不是另一套现行要求。
