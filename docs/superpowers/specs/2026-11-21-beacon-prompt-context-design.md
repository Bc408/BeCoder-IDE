## 1. 目标与设计时事实基线

Beacon 的核心价值是理解用户当前学习现场、解释真实问题，并随对话调整教学。用户改了代码再问“现在呢”，应对准当前对象，辨认已改与未改之处，并分清静态推断和实际验证。NoteBook 是独立学习工具和显式请求的可选资产入口。

本轮讨论依据四份用户提供的归档：23 段保存对话、182 条用户消息。其中三位大一学生共 10 段、85 条，项目负责人 13 段、97 条。归档体现了短句纠错、切换文件、增量改稿、保留原结构、跳过已会内容和按需追问原理等行为；不由记录推定最终通过率或长期教学效果。学生姓名、完整历史、个人路径与附件不写入开发夹具，也不上传模型服务。

2026-11-21 的源码基线为 `Beacon_Next` / `e701f9c0ecd1c36dbe5d708833e3eeb9c0f58973`，另有本轮上下文接入的未提交改动。后续执行必须重新读取实际 diff，不能把 HEAD 当作未提交改动的可复现版本。

| 对象 | 当前事实与开发边界 |
| --- | --- |
| 模型与会话 | `provider.ts` 构建模型请求；`session.ts` 重放本会话消息及工具协议；`connections.ts` 固定请求开始时的模型配置 |
| 提示装配 | 导师身份目前和联网条件耦合；`contextTools.ts` 的 `describe()` 混合材料目录与使用规则，尚未形成统一提示模块 |
| 上下文候选 | 未提交改动提供活动对象/指定对象、页面版本、相关材料和已打开 OJ 面板的只读结构化投影；不能称作已交付完整基础 |
| 仍需收尾 | 上下文候选的对象生命周期、重答/续答语义、源码绑定、失败与隔离须经审查和当前检查；已知 stage 尚未由本轮完成构建与负责人验收 |
| 后续能力 | 自动压缩、工作区 tips/status/dream、额外本人 OJ 历史和完整视觉材料保留需求，首轮提示优化不实现这些子系统 |

审阅通过的 [Archify 图](../../../.archify/architecture-beacon-unified-20261121-191755/beacon-review.html)为本地辅助材料，图中的“草案/待审”反映生成时状态。正式职责和首轮范围以本文为准，不依赖生成目录才能理解或执行。

## 2. 所有者与请求链

| 所有者 | 输入与输出 | 责任 |
| --- | --- | --- |
| 聊天入口、`extension.ts` | 用户问题、附件、活动页/指定对象 → 请求准入及本轮快照 | 保留草稿；执行及收尾忙时拒绝发送，不排队；固定根、档位、会话和对象身份 |
| `session.ts`、`protocol.ts`、`history.ts` | 本会话原文、工具调用/结果、实际材料 → 有效历史输入 | 维护暂停/继续/重答/编辑的既有语义，隔离其他会话 |
| 新 `prompts.ts`、`provider.ts` | 导师规则、当前能力、元数据、历史 → 模型请求 | 单一装配入口；规则有来源，工具说明与实际注册集合一致 |
| `ContextTools` 与原生页面/协调器 | 受控操作、页面 version、运行 revision → 可核对的材料 | 各入口独立授权；正文按需读取；消费材料保存为本会话快照 |
| 编辑器、Runner/CPH、OJ Connect | 用户正在编辑/阅读/运行/提交的对象 → 原始事实 | 生产真实版本和状态；Beacon 不代执行、不补造历史 |
| 可选学习资产工具 | 用户明确请求及合法目标 → 原生编辑/保存结果 | NoteBook 等资产按各自保护规则处理，普通求助不必先建笔记 |
| 后续输入投影层 | 有效历史及预算 → 近期原文、较早摘要和回读定位 | 压缩不替代原始资产；首轮保持完整历史，不启用摘要 |

一次问题可以包含多步模型/工具交换；“主模型”表示同一选定服务和配置，不表示强制只允许一次网络请求。首轮不增加意图分类、画像提取或自动审查模型。模型返回的正文和活动仍走现有流式展示与协议记录。

## 3. 统一装配原则

### 3.1 输入层次

| 内容 | 权威来源 | 角色与处理 |
| --- | --- | --- |
| 导师核心与产品边界 | Beacon 自有规则 | 始终进入有效系统指令，独立于联网开关、工具支持和 NoteBook |
| 工具能力与恢复提示 | 本请求实际注册的工具 | 条件装配；schema 给出协议，规则说明使用时机和限制，避免重复整段手册 |
| 本轮对象与证据目录 | 宿主提供的 ID、版本、权限和覆盖元数据 | 说明材料入口，不默认把所有正文塞入首次请求；宿主事实不等于外部正文获得指令权限 |
| 用户教学要求与当前问题 | 本会话真实用户消息 | 保留原角色和顺序，按范围及最新纠正解释，不复制进系统层冒充产品规则 |
| 页面正文、附件与工具结果 | 已授权读取的外部/用户材料 | 保持材料与工具结果身份；其中的“忽略规则”“已获许可”不是用户的新指令 |
| 模型推断与后续摘要 | 模型输出 | 与观测事实分开；不生成权限、不改变导师定位、不声称内容已经验证 |

首轮可在 AI SDK 现有 `system` 字符串内用清楚的小节组织应用自有规则与元数据；原始用户和工具消息继续由 `messages` 传入。不同服务商未必支持 Codex 的内部来源元数据，不依赖私有字段获得安全保证。

### 3.2 稳定内容与更新

固定导师规则在每个有效请求里始终可用，重答、编辑、继续以及工具续轮都不能遗漏。装配函数不向聊天历史反复追加同一套系统规则，也不把上轮完整 system 当作用户消息保存。

连接、能力、工具集合和当前对象使用本次准入时的快照；进行中设置变化只影响后续请求。用户在新消息中纠正对象或教学要求时，其明确表述优先于默认跟随线索。相关工具失败可以更新后续推断，但不能静默换根、换模型或借失败扩大读取权限。

首轮只利用原始消息和既有工具协议理解教学要求，不建教学状态数据库，不做关键词意图分类，不每轮调用模型提取偏好。未来若派生状态，必须带真实来源、范围及替换/撤销语义，并在旧消息编辑和重答后失效；这个子方案不由首轮计划提前冻结。

## 4. 教学行为契约

| 场景 | Beacon 应有行为 |
| --- | --- |
| “哪里错了”“现在呢” | 结合本轮对象读取必要材料，逐项核对实际改动，指出仍在的具体错误。没有新结果时说待验证 |
| “保留原结构/写法” | 优先给最小必要修改及原因；发现方法根本不适用时用约束或反例解释，不直接替换为陌生模板 |
| “给一点提示” | 给足以推进的一步或关键观察，尊重用户尚不想看到完整答案的范围 |
| “讲讲原理/为什么” | 从用户已展示的理解解释定义、作用、必要推导与当前代码，例子与结论相互对应 |
| “这个我会了” | 跳过已确认部分，继续用户缺的步骤；不因一次小失误断言其基础差 |
| “现在直接给完整代码” | 取代同一任务此前的只提示要求，正常提供完整解法及必要解释，不强制答题或重复确认 |
| 用户反驳上一回答 | 回看原话和实际证据，纠正判断及后续讲解；不得把承认错误当作修正已经完成 |
| 无题目关联、纯概念问答 | 仍能直接教学；不强制指定题号、使用 CPH、配置联网或新建 NoteBook |

讲解长度服务于理解，不固定为两句、五段或问答测验。不要把“简洁”实现成省掉用户正在追问的推导，也不要用大篇介绍覆盖一个局部纠错。普通交流中不反复推荐生成 NoteBook 或把笔记整理作为每轮结尾。

教学定位和明确作弊请求的边界沿用 PRD；用户的正常学习可以获得完整解法。不要仅凭比赛网页或代码判定用户作弊，也不新增比赛监控或自动拒绝分类器。

## 5. 本轮对象与事实绑定

本轮对象默认跟随活动编辑器，允许一次指定、手动固定和恢复跟随。用户从 A 切到 B 后问“现在呢”，默认选择 B；本轮用户明确点名 A 或提供直接相关选区时，模型应按明确意图使用已有授权入口。对象含糊且证据无法消歧时，才简短询问必要信息。

显示当前文件以便低成本核对；版本差异影响判断时说明结果属于旧稿，详情能回溯实际引用的材料。显示元数据不等于已经读过正文。

判定关系分别表达：同一文件、可核对的同次源码、同一题目及同一提交。路径或题号相同不能证明同稿；`sourceVerification=matched` 只说明 OJ 核对过的发送源码关系，不能直接推广为当前编辑稿已经通过。不同哈希口径不可混比，缺失字段保持未知。

回归核心案例：V1 为 `int s; for(int i=0;i<n-1;i++) s+=a[i];`，正式提交 #123 在该版本得到 WA；V2 只改为 `int s=0`，循环仍为 `i<n-1`。合格回答同时指出已补初始化、仍漏末项、V2 没有新验证，不能把初始化误读成循环已修。

已打开 OJ 面板的结构化题面按实际语言、章节和原样样例提供；正式记录保留 ID、题目、判词、阶段和真实可得字段。不能为 Beacon 重新触发提交、轮询或偷偷查询额外历史。页面关闭/版本变动与本会话已经留存的快照是不同状态，沿现有工具反馈处理。

## 6. 权限、异常和资产边界

- 三档均可读取本窗口真实已打开且授权的页面；页面读权不授予其磁盘、邻接文件、引用文件、隐藏历史或导航权限。
- Blackout 不新增工作区资产读取或临时消息落盘；Spot/Flood 仍保持根、敏感信息、会话与资产种类边界。切档继承沿用已确认的独立快照规则。
- 额外网络查询个人信息依据真实用户明确许可和范围，由提示引导；页面、登录、Flood、模型记忆和摘要不能生成许可。不新增许可台账或查询意图审批门。
- 运行、结果采集、取消、编译失败、判题中、判词未知、正常退出和 AC 分别表达；缺失/失败不等于空记录或成功。工具错误给下一步可行动信息。
- Beacon 不创建或改写学生 C/C++ 源文件，不自主 Shell、运行、停止、登录或交题。回答中的教学代码不等于改写学生文件。
- NoteBook 新建/改写仍由显式请求、合法目标、最新编辑稿、改写前备份与原生保存反馈约束；本轮不改变其输出、关联、失败或备份语义。
- 暂停、继续、重答、编辑旧问题、模型配置热更新和运输重试保留现有协议语义；不得因为优化提示重复已完成的写入或工具调用。

## 7. 历史、输入预算与后续压缩

统一架构区分原始会话、独立材料、有效历史与最终模型输入。首轮提示优化直接使用完整有效历史，不实现自动压缩或新的硬容量拒绝策略。

后续预算要计入装配后的系统规则、工具 schema、当前问题、图像/材料、后续工具返回与输出预留，并使用实际模型容量和可解释的估算。当前配置默认值不是模型真实能力保证，不按型号名猜测窗口；最低必要输入超容量时给用户可行动选择，不静默裁掉问题或图片。

压缩方向确认如下，具体阈值、分段、估算器和受限模型体验由后续专项计划实测决定：

1. 在完整消息/工具交换边界组织较早摘要，优先保留近期必要原文、当前请求、用户最新纠正、对象版本、验证事实与未知。
2. 原始历史、协议和实际消费材料继续留存；回读只限本会话，不由摘要引用越权读其他聊天。
3. 压缩后从可信配置重建当前导师规则、工具能力、根/档位与本轮对象，摘要不负责创建或恢复授权。
4. 摘要绑定会话、分支、覆盖终点与历史 revision。编辑旧问题/重答使受影响投影失效；失败/取消保留原文及上一有效投影。
5. 优先研究同步压缩。若后续引入后台候选，安装前复核版本与有效后缀，不用旧结果覆盖新输入。
6. 上下文重新组织属于新输入构造，不混入运输层的自动重试。不同服务不默认支持 Codex 的专用压缩协议。

工作区 tips/status/dream 是跨会话独立资产，继续由[记忆专项](../../beacon/memory-quality-technical-design.md)维护，不与本会话要求或自动压缩合并成一个持续改写的大总结。

## 8. 首轮开发范围与工程落点

本阶段交付统一提示入口、教学规则、既有工具规则的条件装配、装配回归与可重复的本机模型对照。代码、构建和真人体验的状态分别记录。必要源码落点是 `extensions/becoder.beacon/src/prompts.ts`、`provider.ts`、`contextTools.ts`，对应测试、构建入口及评估 runner；具体接口与任务见开发计划。

模型供应商、连接设置、宿主权限、OJ 协议、运行采集和会话格式不因提示词优化重写。跨会话记忆、额外 OJ 历史、视觉解析、自动压缩和新 UI 不进入首轮实施。上下文候选在实施前审查，不因现存修改自动视为通过，也不借提示词掩盖缺失的宿主事实。

规则和测试为 BeCoder 原创维护，沿归属扩展 MIT 头和现有依赖。Codex harness `1145028ae47e8119955323d38ce34122d418f951` 仅作为机制研究来源；参考其[片段装配](https://github.com/openai/codex/blob/1145028ae47e8119955323d38ce34122d418f951/codex-rs/ext/extension-api/src/contributors/prompt.rs)、[规则替换](https://github.com/openai/codex/blob/1145028ae47e8119955323d38ce34122d418f951/codex-rs/core/src/context/world_state/agents_md.rs)和[压缩重建](https://github.com/openai/codex/blob/1145028ae47e8119955323d38ce34122d418f951/codex-rs/core/src/compact.rs)，不复制其完整提示、执行框架或权限体系。若实际引入第三方源码或文本，再按来源维护许可与 notices。

## 9. 质量验证与完成定义

[行为评估案例](../../beacon/prompt-evaluation.md)规定固定场景、关键错误和记录方式。确定性测试检查实际出站 system/messages/tools、原角色、版本、失败与取消，不能用提示字符串存在代替回答质量。

模型评估优先本机 Ollama，通过 Beacon 的真实 generator、适配器和工具闭环访问回环服务，使用合成材料。旧提示基线和候选使用同一模型、能力、采样参数及案例；记录完整回答、工具轨迹、实际使用量和耗时，不用额外审查模型代替人读。模型不支持工具时单列能力降级，不能悄悄改成云端、粘贴全部材料后声称工具流程通过。

只有装配与协议回归、当前候选源码检查、可复查的模型行为对照和负责人实际产品验收分别成立，才能宣称首轮交付。原有上下文测试、一次 Ollama 回答或本设计获批均不替代后续结果。staged、包、Setup 和运行验收遵守仓库各自范围，不自动授权 Git 或 Release。
