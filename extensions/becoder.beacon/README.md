# Beacon

Hover descriptions share BeCoder's compact product tooltip layer with CPH and the PDF toolbar. They follow the editor-hover theme colors, Modern UI corner radius and workbench hover delay. Keyboard focus, Escape, viewport edges, dynamic labels and reduced motion are supported; button layout and actions remain unchanged.

悬停说明与 CPH、PDF 工具栏共用 BeCoder 的紧凑提示层，沿用编辑器悬停主题颜色、Modern UI 圆角和工作台悬停延时。支持键盘焦点、Esc、视口边缘避让、动态文案和减少动态效果；按钮布局及操作保持不变。

Temporary connection resets, transient DNS/connect/header timeouts and HTTP 408/409/425, 500/502/503/504/520/522/524/529 or 429 can recover automatically before any text, reasoning or tool activity is committed. Exact structured error codes distinguish quota/account/context/request rejections from temporary rate limits and overloads; free-form provider messages do not determine retries. A response shares at most two retries across connection establishment and an early stream failure. Network/timeout retries start at 350/700 ms, overload retries at 1/2 seconds, and rate-limit retries at 2/4 seconds, with up to 25% positive jitter. Valid Retry-After seconds/dates take precedence over retry-after-ms and x-ms-retry-after-ms and are not jittered. Waiting remains capped at 10 seconds in total; longer cooldowns require a later manual retry. The original model, connection, input and overall three-minute deadline stay fixed. Stop cancels requests and waiting. Reconnecting appears in the existing activity label; final network failures use a muted notice with the existing manual retry action. Authentication, balance, parameters, invalid addresses and certificate errors are not retried. Output or completed tools are never replayed automatically. The local Beacon Connections output channel records only provider ID, a generated request ID, classified codes, attempts and elapsed time, without prompts, images, keys, addresses or response bodies. Only the final failure category/count is saved with the message; reconnecting progress is temporary.

尚未输出文字、思考或工具活动时，连接重置、临时 DNS/连接/响应头超时及 HTTP 408/409/425、500/502/503/504/520/522/524/529、429 可自动恢复。精确匹配结构化错误码，区分额度、账户、上下文及请求拒绝与临时限流、过载，不根据服务商自由文本猜测重试。一轮回复的连接建立与早期断流共用最多两次重试额度；网络及超时默认等待 350/700 毫秒，过载等待 1/2 秒，限流等待 2/4 秒，并增加最多 25% 的随机延迟。有效 Retry-After 秒数或日期优先于 retry-after-ms、x-ms-retry-after-ms，服务端等待提示不增加随机延迟。累计等待仍不超过 10 秒，较长冷却时间交由用户稍后重试。原模型、连接、输入及整轮三分钟期限保持不变，停止会取消请求与等待。重连显示在已有活动标签中，最终网络故障使用灰色提示并保留原手动重试按钮；鉴权、余额、参数、无效地址与证书错误不自动重试。已输出内容或完成的工具不自动重放。本地“Beacon 连接诊断”输出通道只记录服务商标识、随机请求标识、分类错误码、次数与耗时，不记录提示词、图片、密钥、地址或响应正文。消息仅保存最终故障分类和次数，重连进度不写入历史。

BeCoder's built-in conversation companion. Use the persistent Beacon button in the editor's upper-right toolbar, or **Beacon: Toggle Beacon Sidebar** in the command palette, to open or close chat in the right sidebar. The chat settings button, **Beacon: Open Settings**, and the extension's Features tab open the same independent settings editor. Each provider has one connection and each model ID has one configuration. Save/Cancel applies to connection and model drafts; list switches and chat model selection save immediately with feedback. Saved API keys stay in SecretStorage and are never read back into the Webview. A blank key field preserves the key; removal is explicit. This fresh configuration document does not read or migrate old settings or credentials. During generation, connection, key, capabilities and parameters remain frozen; saved changes apply to the next send, continuation or regeneration.

Supports DeepSeek, Alibaba Cloud Bailian, Moonshot and Ollama through Vercel AI SDK. Open Beacon settings, save the provider connection, fetch models or add one manually, then select a chat model. Local Ollama needs no key. Capability corrections and optional temperature, Top-P, output budget and legal thinking options are edited as a model draft. Disabled parameters use model defaults; streaming remains enabled. The composer shows the selected model and each new answer records its actual provider and model. It supports streaming multi-turn conversations, pausing, continuing paused answers, regenerating responses, copying answers, Markdown, code highlighting and math. When a provider returns reasoning, Beacon saves it with the local conversation in a collapsed section that users can expand; reasoning and provider metadata are retained in protocol history for requests to the same provider endpoint. Availability depends on the selected provider and model. Beacon offers No file access (default), Workspace read-only and Computer read-only permissions in the composer. The application remembers the selection. Each response captures its permission and workspace roots; changing permission during generation shows a notice and applies to the next send, continuation or regeneration. It can list directories, find filenames, search literal text and read files in chunks. Text chunks are at most 128 KiB, binary chunks are at most 8 KiB as hex, and PNG/JPEG/WebP/GIF images are at most 4 MiB and need a vision-capable model. Directory operations inspect at most 2000 entries and return at most 200 results; search checks the first 128 KiB of each file. Each response has an 8 MiB file-result budget and at most 20 model steps. Open text documents include unsaved edits. Computer mode also accepts UNC network shares under operating-system permissions. Workspace mode checks canonical targets against all open local folders, including linked targets. Both reading modes exclude known credential and private files. File operations appear as activities. It cannot write files, run commands or read known credential files. Messages and explicitly requested file contents are sent to the selected service.

Chats share a local history.json in Beacon's global extension storage across workspaces. Each chat retains its creation workspace metadata. No earlier workspace-history data is read or migrated. Shared saves merge locally changed conversations, write atomically, and reject conflicting edits from another window. Focusing an idle window refreshes its history list. New chat keeps previous conversations. Return to the chat list to scroll through all conversations, resume, rename or delete a chat (deletion requires confirmation). Timestamps show the local clock today, yesterday or a weekday for recent dates, and a calendar date for older conversations. One response runs at a time; pausing retires that request before another operation can start. A paused answer retains its text, reasoning and tool activities. Continue starts a new model request with the saved context and appends output to the same answer; Regenerate discards that answer and its later conversation branch. Sending a new message includes paused answer text in context. Completed file-tool results are saved locally and replayed as tool context, without sending file contents to the Webview. Unfinished tool calls are not replayed. Completed tool calls keep their actual IDs and order. A provider/endpoint switch removes private reasoning and provider metadata while retaining ordinary text and tool results. Reloaded interrupted answers can also continue. Elapsed time adds generation attempts and excludes pauses. Partial output is checkpointed every 500 ms; completed turns and normal shutdown flush pending changes. Storage failures remain visible with a retry action. Unreadable history is preserved and blocks new sends until the window can load it again. Each request has a three-minute timeout; failed requests can be regenerated, while a failed continuation preserves its existing answer for another continuation attempt.

Build from the repository root with `npm run compile-oi-extensions`. Beacon's own commands are `npm run typecheck`, `npm run build`, and `npm test` in this directory. Tests use a synthetic provider SSE responses and do not prove live account connectivity or Webview visual acceptance.

The chat renderer keeps code blocks stable during streaming, with copy feedback, optional line wrapping and plain-text fallback for oversized code. It shows a concise running status, elapsed time and workspace-file tool activities; provider reasoning is collapsed by default and can be expanded by the reader. Waiting text follows Captain Who's shimmer treatment and respects reduced motion. Scrolling follows content growth until the reader scrolls away; the return-to-bottom control restores following.

## 中文

点击编辑器右上角常驻的 Beacon 按钮，或运行 **Beacon: 打开/关闭 Beacon 侧边栏**，切换右侧聊天界面。聊天设置按钮、**Beacon: 打开设置**命令与扩展详情的“功能”页打开同一个独立设置标签页。每个服务商只有一组连接，同一模型 ID 只有一份配置。连接与模型详情使用保存／取消；列表开关与聊天模型选择即时保存并显示结果。已保存的密钥通过 SecretStorage 管理，不回显到网页；密钥输入框留空表示保留，移除需明确选择。新配置不读取或迁移旧设置、旧密钥。生成中固定连接、密钥、能力与参数；修改只影响下一次发送、继续或重新回答，不打断当前输出。

本版支持流式多轮对话、停止、重试、复制、代码高亮和公式。服务商返回思考内容时，Beacon 会将其保存在本地对话中并默认折叠，用户可自行展开；思考内容及协议元数据会保留，并回放给同一服务商接口，是否提供取决于服务商与模型。输入框提供“不读取文件”（默认）、“工作区只读”和“全机只读”三档，在应用内记忆选择。每轮固定权限与工作区范围；生成中切换权限会提示下一轮生效，不打断输出。可按需列目录、按名称查找、搜索文本和分段读取；打开的文本优先读取编辑器内容，包含未保存修改。文本每段最多 128 KiB，二进制以最多 8 KiB 的十六进制返回，PNG/JPEG/WebP/GIF 图片最多 4 MiB，图像理解需要模型支持。每轮文件结果预算 8 MiB、最多 20 个模型步骤；目录操作最多检查 2000 项并返回 200 项，文本搜索检查文件开头 128 KiB。全机档包含 UNC 网络共享路径，沿用系统权限；工作区档检查链接解析后的目标。两种读取档都排除已知敏感文件，不提供写文件或执行命令的工具。消息以及明确要求读取的文件内容会发送给所选服务。支持深度求索、阿里云百炼、月之暗面和 Ollama。在 Beacon 设置中保存服务商连接，获取或手动添加模型，再选择聊天模型；本机 Ollama 无需密钥。能力校正、温度、Top-P、输出预算及合法的思考选项属于模型草稿，未启用的参数使用模型默认值，始终流式输出。输入框显示当前模型，每条新回答记录实际使用的服务商和模型。聊天记录统一保存在 Beacon 全局扩展存储的 history.json，不按工作区分区；每条会话保留创建时的工作区信息，重启后恢复当前聊天。不读取或迁移本轮之前的工作区记录。共享保存合并各窗口实际修改的会话，原子写入，并拒绝覆盖另一窗口的冲突修改；空闲窗口重新获得焦点时刷新历史列表。新聊天保留旧会话，返回聊天列表后可滚动选择会话、继续、重命名和确认后删除。生成中需先暂停才能切换；重启时中断的回答显示为已暂停，可继续或重新回答。未发送的草稿只在当前界面中保留。保存失败会提示重试，读取失败保留原有数据。

暂停会保留已输出的正文、思考与工具活动，并等待当前请求结束。“继续”携带已有上下文发起新请求，将新增正文接到同一条回答后；“重新回答”舍弃该回答及后续分支，重新回答原问题。暂停后也可直接发送新消息，部分回答会进入上下文。已完成的文件工具结果保存在统一历史中，续接与后续消息可引用这些结果；文件正文与图像字节不传入网页界面；降低权限后已有文件上下文继续参与会话，未完成工具不重放；已完成工具保留真实调用编号与顺序。同一服务商接口保留推理及协议元数据，切换服务商或接口时移除私有推理与元数据。重新打开历史后仍可继续暂停回答，耗时累计实际生成时间，不包含暂停等待时间。续接失败保留原有内容，可再次继续或重新生成。

代码块在流式输出中保持稳定，支持复制反馈、自动换行，超大代码降级为完整纯文本。界面显示简要生成状态、耗时和工作区文件工具活动；服务商返回的思考原文默认折叠，用户可点击展开。等待文字参考 Captain Who 的扫光效果，遵循系统减少动态效果设置。回复增长时跟随底部，向上阅读后暂停跟随，点击回到底部恢复。

All chat code languages share an incremental TextMate Worker with Oniguruma and the default One Monokai token theme. BeCoder's bundled grammars take priority, including C/C++, Python, Shell, JSON, YAML, Markdown and TeX; other previously supported languages retain their pinned Shiki grammar assets in the same renderer. The build derives languages, aliases, scopes and injections from those sources. It colors incremental lines during streaming, preserves cross-line grammar state and bounds queued work. Markdown's presentation newline stays outside syntax snapshots so an unfinished line can grow without discarding its colored prefix. The Webview window loads the worker and WASM resources before transferring them to the worker. Unknown languages, unavailable resources or exceeded processing budgets fall back to readable plain text. Code uses the editor's font size and computed line height. It does not follow user theme changes or invoke language servers.

所有语言的代码块统一使用增量 TextMate Worker、Oniguruma 与默认 One Monokai 一次着色规则。优先使用 BeCoder 内置语法（含 C/C++、Python、Shell、JSON、YAML、Markdown、TeX）；其余已有语言的 Shiki 语法资产也进入同一渲染路径。构建时从语法来源生成语言、别名、作用域与注入规则，保留跨行状态并限制待处理任务。Markdown 补充的显示换行不进入语法快照，未完成行增长时保留已着色前缀。资源由 Webview 页面加载后传入 Worker；未知语言、资源不可用或超出处理预算时保留可读纯文本。代码字号与计算后的行高同步编辑器，不跟随用户主题，不调用语言服务器。

Model capability settings distinguish chat, embedding, reranking and image generation, with vision, reasoning and tool support marked supported/unsupported/unknown. The conservative built-in catalog applies only to official endpoints. Selected Ollama models use /api/show metadata; declared context size is not the actual runtime window. Manual corrections, thinking options and generation parameters belong to each provider's saved model. Changing a provider address clears endpoint-specific discovery metadata. Unknown models permit text chat; tools and image input require confirmed support. Non-chat models and output limits are checked before sending a request. Restore model defaults removes manual corrections and thinking options.

模型能力区分聊天、嵌入、重排与图像生成，视觉、推理与工具能力标记为支持、不支持或未知。保守的内置目录仅适用于官方接口；Ollama 按需查询当前模型的 /api/show 元数据，声明的上下文窗口不代表实际运行窗口。能力修正、思考选项及生成参数保存在服务商的模型配置内；更换服务地址会清除原接口的发现元数据。未知模型允许文本聊天；工具与图像输入必须确认支持。请求前检查模型用途和输出上限。“恢复模型默认”移除能力修正与思考设置。

Attachments follow file permissions: none rejects all drops; workspace accepts only native BeCoder drags whose actual targets are inside the current roots; computer accepts both BeCoder and Explorer drops and shows the native Add files picker. The workbench reports the native origin through a separate Beacon-only event, not webview-supplied MIME or paths. Private files and escaping links remain blocked. Disk drafts are re-read on send, preferring unsaved editor buffers. Successful sends capture file content in the user message for history, continuation, regeneration and followups; rejected sends preserve the draft. Text uses bounded excerpts, binary files use explicitly labeled hexadecimal excerpts (no document/audio/video decoder). PNG/JPEG/WebP/GIF images, up to 4 MiB each, are actual image inputs and require confirmed vision support; no OCR or automatic model switch. The combined captured content budget is 8 MiB with up to 64 attachments. Image-only messages are supported. Streaming snapshots carry metadata; previews retrieve captured image bytes once per mounted card. Attachment preparation is cancellable and owns the same window's busy boundary. Native picker results are rechecked after permission changes.

Paste a Windows screenshot into the composer with Ctrl+V. Explicitly pasted image bytes are user input in all three permission modes, have no filesystem path, and use the same image and combined-content limits. They retain their captured bytes on send and in history. Click a draft or message image card to preview its captured content with fit, zoom, drag, same-group image navigation and Escape to close; closing restores the card's focus. Other attachment cards open their original files in BeCoder's existing editor or registered viewer (including PDF), after checking current source, permission and workspace boundaries. Missing or inaccessible originals show a notice. Local preview does not send data to a model or change the model's document-format support.

附件严格遵循文件权限：不读取文件档拒绝所有拖入；工作区档只接受 BeCoder 内拖入、实际目标位于当前工作区的文件；全机档接受 BeCoder 与资源管理器拖入，并显示本地“添加文件”选择器。工作台通过独立的 Beacon 专用事件提供原生来源，不信任 Webview 自报的 MIME 或路径。敏感文件、越界链接继续拦截。发送时重新读取磁盘草稿附件，优先纳入编辑器未保存修改；成功后将内容快照保存至用户消息，供历史、继续、重新回答及后续消息复用。失败保留文字和附件。文本取有界节选，二进制取明确标记的十六进制摘要，不解析文档、音频或视频；PNG/JPEG/WebP/GIF 单张不超过 4 MiB，作为真实图片输入发送，必须确认模型支持视觉，不自动 OCR 或换模型。附件内容总量上限 8 MiB，最多 64 个，支持只发图片。流式快照只传元数据，预览按需读取已捕获的图片内容。准备过程可取消并阻止并发操作；本地选择器关闭后重新检查当前权限。

Windows 截图可在输入框中直接 Ctrl+V 粘贴。主动粘贴的图片字节在三档权限下都属于用户输入，不对应磁盘路径，仍使用现有图片与内容总量限制；发送与历史恢复复用捕获的图片内容。点击草稿或消息中的图片卡片可打开预览，支持适合窗口、缩放、拖动、同组图片切换和 Esc 关闭，关闭后恢复卡片焦点。其他附件卡片在检查当前来源、权限与工作区范围后，交给 BeCoder 已有编辑器或查看器打开原文件，包括 PDF；原文件丢失或不可访问时显示通知。仅本地预览不会向模型发送数据，也不会改变模型能理解的文档格式。

Web search is on by default and has a globe toggle in the composer, remembered across workspaces in this installation. Confirmed tool support is required; unknown or unsupported models cannot use the web tool, and the toggle explains that limitation. Each response captures the switch, so changing it during generation applies to the next send, continuation or regeneration. Closing the switch prevents new lookups, while already saved evidence remains in the conversation. Beacon uses the fixed Exa hosted endpoint with no search credentials, independently implemented from the public protocol and verified responses. It exposes only search and single-page reading, with at most 6 calls, 5 sources per search, 32000 source characters per response, a 1 MiB response limit and a 25-second lookup timeout. Public HTTP(S) page addresses are accepted; credentials, custom ports, IP literals and local/private names are rejected. Search excerpts and page excerpts are marked separately in a collapsible source list; actual source URLs open in the browser. Sources and native tool protocol survive pause, continuation and reload. Regeneration discards the old answer and its sources. Stopping aborts pending web calls; failures and rate limits remain visible and do not manufacture evidence. The backend may receive model-generated search queries or public page URLs, but it receives no provider key or conversation history. It is a limited free service, not a guarantee of network availability. No generic MCP configuration or runtime is added. 联网默认开启，输入框的地球按钮可切换，并在当前安装内跨工作区记忆。模型必须确认支持工具；未知或不支持时不可查询，按钮提示说明这一限制。每次回复固定联网开关，生成中修改只影响下一次发送、继续或重新回答；关闭后不发起新查询，已进入上下文的来源仍保留。通过固定 Exa 接口免密钥查询，依据公开协议与实际返回独立实现；仅提供搜索与单网页读取，不引入通用 MCP 配置或运行时。每轮最多 6 次查询、每次搜索最多 5 个来源、来源内容总计最多 32000 字符；接口回复最多 1 MiB，单次查询超时 25 秒。只接受公开 HTTP(S) 网页，拒绝携带凭据、自定义端口、IP 和本地/私有名称。来源折叠列表区分搜索摘要与网页节选，可打开实际网址；来源和工具上下文随暂停、继续及重载保留，重新回答丢弃旧回答的来源。暂停取消正在进行的联网请求；失败、超时和限流会显示，不伪造成功证据。搜索服务只收到模型生成的搜索词或公开网页地址，不收到模型密钥或完整对话。免费服务有使用限制，实际连通性仍取决于网络。
