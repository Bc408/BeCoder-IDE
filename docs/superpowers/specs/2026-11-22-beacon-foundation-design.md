# Beacon 底层材料与上下文基础设计

日期：2026-11-22。状态：负责人已逐项确认本文的产品取舍，现形成书面设计，供文档重整与下一阶段细化。本文不表示相关代码已经实现、构建通过或真实体验已经验收。

## 1. 目的与本轮范围

Beacon 是跟随用户当前学习活动的算法与编程导师。底层负责准确记录、关联、保存和供应用户实际产生的材料，让模型理解当前代码、题目与真实结果。

本轮收敛采集、关联、持久化和读取。优先复用现有生产者、原生存储、协调器和工具入口，补齐小接口，不新建通用代理框架或中心事实数据库。

本设计依据负责人本轮直接决定，并更新旧共享材料方案中只列 Runner、CPH、Notebook、题面尚无统一近期机制的表述。旧文件在文档重整副本中完整保留；其历史实现和评估事实不改写为新方案已经完成。

## 2. 正常使用流程与支持边界

完整能力闭环的设计与验收范围为洛谷、Codeforces、AtCoder、牛客和蓝桥。标准使用流程是内置浏览器拿题，经 Get Problem 或支持 Get Problem 的对象 Import to CPH，取得题目与代码文件的明确关联，再跟随用户编码、运行、测评和提问。

Get Problem 成功即可建立代码与题目关联并采集题面，不以之后完成 CPH 导入为前置。Import to CPH 的对象支持 Get Problem 时，也可在成功导入后建立关联并采集题面。仅能导入 CPH 的其他来源不自动获得完整能力闭环承诺。

非规范操作造成的材料缺失或关联不完整保持未知，Beacon 不为此增加猜题、启发式补链或操作习惯兼容机制，相关完整上下文回答质量不作保证。来源真实性与权限边界仍须遵守。纯概念讨论不因没有题目而被强制要求拿题或建立笔记。

当前问题以本轮目标代码为准。上一道题仅可作为候选背景，不能仅凭同路径、打开页面或时间接近认定题目关系。

## 3. 材料归属与采集

| 材料 | 产生时机 | 归属与保留 |
| --- | --- | --- |
| 本轮目标代码快照 | 每个新问题被接受前取得目标代码，包含未保存修改 | 当前 `.beaconWork` 内共享，并绑定本轮问题；不扫描全部打开文件 |
| 结构化题面 | 成功 Get Problem，或支持 Get Problem 的对象成功 Import to CPH | 当前根的持久化近期材料，同题同版本复用内容，按规则淘汰 |
| Runner 凭证 | 用户实际发起编译与运行 | 当前根的持久化近期记录，保留代码、实际输入、编译诊断、输出与状态 |
| CPH 凭证 | 用户实际发起整轮样例测评 | 当前根的持久化近期记录，保留当次样例、expected、checker 和逐样例结果 |
| Notebook 凭证 | 用户实际执行程序块与 input 块 | 当前根的持久化近期记录，保留笔记、执行块、输入与真实结果 |
| OJ 测评凭证 | 用户交题或查询过程中，现有 OJ Connect 流程真实取得结果 | 当前根的近期材料，保留提交标识、题目、状态、已取得的源码关系和来源明细 |
| 会话消息、回答、摘要、许可、普通附件与草稿 | 既有会话操作 | 会话私有，不通过共享材料入口向其他聊天开放 |

运行凭证采集不依赖聊天已经打开或模型已经配置。队列只记录既有用户行为，不因模型需要材料而新发起程序、提交、登录、后台查询或采集。

继续、重答复用原问题代码快照；工具续轮与运输重试不重复保存新副本。保存不等于模型已经读取完整代码。

Blackout 使用内存中的代码与已加载材料，不新增工作区落盘或查询持久化近期队列。既有当前页面读取能力保持。

## 4. 统一持久化近期机制

复用 `.beaconWork/cache/<producer>/records.json` 所在的既有文件存储与近期队列机制。题面、Runner、CPH、Notebook 和在线测评材料平权保存和消费，使用共同的身份、来源、版本、时间、状态与覆盖描述，保留各来源自身结构，不将题面强行包装为程序运行事件。

Runner、CPH、Notebook 各来源采用相同保留数量且互不挤占，不合成混合总额 FIFO。题面与在线测评沿用同一近期淘汰原则；具体来源标识、队列映射、容量和单条上限在执行计划统一明确，不把讨论中的“各 10 条”当作已批准数值。

不新增长期评测归档、独立索引、数据库、pending 文件、引用计数或历史 revision 文件。已有 revision/sequence 服务当前更新与一致性读取。

题面同题同版本不重复保存正文。用户重新了解旧题时主动 Get Problem，采集结果重新进入近期材料的可用范围；不依靠永久题面库或模型自动寻回。重复获取的队列更新细节在执行计划明确。

真实运行开始后，记录随生产事件更新，结束时保留真实终态。正常结束、编译失败、运行错误、取消、TLE、OLE 均可成为凭证。CPH 整轮完成不等于全部样例通过，本地样例通过不等于 OJ AC。

活动记录按协调器实际任务占用保护，收尾后恢复 FIFO。进程消失但缺少终态时保持未收尾或结果未知，不补造取消、失败或成功；重启后无对应任务的旧记录不永久占用活动保护。

超长输出保留实际采集内容的头尾并标明省略范围。编译诊断与程序输出分别保留阶段、流和顺序；身份、终态、覆盖字段完整，不截坏结构。来源未采集的内容不能恢复，保存规则不改变既有运行时限和 OLE 行为。

## 5. 目录、按需读取与一致性

扩展现有 `inspectContext` 及 `records / record` 入口。模型首次获得当前对象和相关材料目录，正文按需读取；不另设评测消费者或共享库工具。

默认目录包含当前题目下的近期记录，包括修改前的代码所产生的记录。每条标明与本轮代码一致、不同或无法核对。旧结果可以解释修改背景，但不能验证新代码。

统一工具支持按来源已有结构取材，同时保留整条读取和分页：

| 来源 | 可按需读取的部分示例 |
| --- | --- |
| 题面 | 题目描述、输入格式、数据范围、指定样例等已解析章节 |
| CPH | 整轮状态概览、指定样例输入、预期输出和实际输出 |
| Runner | 编译诊断、实际输入、程序输出 |
| Notebook | 指定程序块或 input 块的执行结果 |
| OJ 测评 | 实际已取得的判定、编译信息、测试点或分组详情等来源字段 |

模型判断需要什么，工具准确返回对应部分。部分读取不生成第二份持久化记录，未读取部分仍可按需取得。没有来源字段时保持缺失，不推断出隐藏测试数据。

按 producer、id 和 revision 首次成功读取后，在本回答内固定对应内存快照，后续部分读取与分页沿用该版。队列更新或淘汰不使同一回答混版；首次读取前已失效则明确失败，不用最新记录替换。回答结束后释放内存快照，下次准入重新核对当前队列。

工具不再通过 `consumeRuntimeRecord` 把整条原记录复制进每个会话。实际返回内容仍沿正常工具协议留在本会话；队列淘汰不删除既有聊天工具返回，也不能承诺未返回的原记录永远可读。其他聊天的消息和材料不能成为恢复入口。

## 6. 保存失败与用户体验

存在目标代码时，保存本轮代码快照是新问题准入条件。保存失败则停止本次发送，保留输入和附件草稿，明确提示并允许用户重试。Blackout 按其内存规则处理；无目标代码的概念问题不要求伪造代码快照。

Get Problem 或 Import to CPH 已成功，但题面写入 `.beaconWork` 失败时，拿题与导入照常完成，明确提示 Beacon 材料保存失败，用户可重新 Get Problem。Beacon 的材料保存失败不阻断核心做题流程。

读取时区分无记录、版本变化、已淘汰、保存或读取故障和来源覆盖不全，不将错误当作成功的空记录。反馈沿现有本地化入口实现，具体文案与存储错误映射在执行计划细化。

## 7. 既有职责与权限

Beacon 不创建或修改学生 C/C++ 源文件，不自主 Shell、运行、停止、登录或交题。回答和学习资产中的教学示例代码仍可提供；Notebook 是独立工具和显式请求的可选学习资产。

根按窗口选择，Spot/Flood 的共享近期材料读取仍限当前有效根；不得借执行 cwd、关联文件、旧快照或 Flood 扩大凭证生产归属。当前页面内容与其磁盘文件读权分开，敏感过滤、会话私有内容隔离和原生执行时校验保持。

普通附件、消息、摘要和许可归会话私有。共享材料不创建个人联网许可，不继承其他会话的要求或授权；进一步联网查询个人信息仍依据真实用户许可和既有提示规则。

## 8. 下一阶段所有者与验收

| 所有者 | 底层夯实的调整方向 |
| --- | --- |
| OJ Connect 现有拿题、导入、交题与结果读取 owner | 在真实成功节点提供题面、明确关联与结果材料，接入近期机制，不新增后台采集 |
| `BeaconStore` / `BeaconCoordinator` | 复用持久化队列、统一保留策略、活动保护和当前根共享窄读取 |
| `BeaconEvidence` 与 Runner / CPH / Notebook | 保留来源明细、真实终态、覆盖及头尾策略 |
| `ContextTools` / 原生上下文接口 | 目录关联、按部分读取、分页与本回答一致性 |
| `extension.ts` / `history.ts` / `session.ts` | 本轮目标代码快照、发送准入、轮次绑定与私有历史边界 |
| `prompts.ts` / `provider.ts` | 供应真实入口和来源说明，维持统一导师规则，不以提示补造材料 |

执行计划应明确容量、接口、字段、错误、受影响源码与具体回归命令，不由实现者临时补产品规则。底层验收至少覆盖：

1. 五站各自的正常拿题或支持的导入路径，题面与源码关联正确，新聊天和重启后在队列有效期内可读。
2. 新问题捕获未保存目标代码；继续、重答和运输重试不改原快照；保存失败保留草稿。
3. 题面及各运行、测评来源同权可读；重复获取、等额保留、FIFO、活动收尾与重启未知终态符合设计。
4. 同题旧结果列入目录且代码关系明确；不同题不因同路径自动合并。
5. 指定章节、指定失败样例或执行块可直接读取，整条读取与分页保持来源、版本和覆盖。
6. 首次读取前失效明确失败，成功后的同回答分页不因更新或淘汰混版。
7. 输出头尾与省略范围正确，来源未取得的内容和新代码验证状态不被补造。
8. 题面保存失败不阻断拿题与导入，Blackout、跨根、敏感过滤与会话隔离不退化。

工程检查、模型语义质量与负责人真实体验分别验收。历史 `.4` 提示评估和构建不替代新代码验证。
