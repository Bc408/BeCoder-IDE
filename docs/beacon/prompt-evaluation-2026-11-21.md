执行日期：2026-11-21 至 2026-11-22（北京时间）。首轮实现、确定性检查、staged 构建及已授权模型批次已完成；整体教学质量门槛尚未达成，负责人体验验收待进行。强模型下换文件案例有可复查改善；原理解释首组因预算截断，追加足够预算后新旧各三次完整正确。范围与质量门槛见[设计](../superpowers/specs/2026-11-21-beacon-prompt-context-design.md)、[计划](../superpowers/plans/2026-11-21-beacon-prompt-optimization.md)和[评估案例](prompt-evaluation.md)。负责人进一步要求考虑 4B 能力局限：本机结果属于小模型压力测试，不能据此把失败一概归因于提示或架构，也不能推广为其他模型的质量结论。

## 实现与输入准备

统一入口 `extensions/becoder.beacon/src/prompts.ts` 将导师核心、证据规则、实际工具能力及宿主目录分别装配。当前规则版本为 `2026-11-21.2`，保留首版 `2026-11-21.1` 的失败记录。导师规则不依赖联网、工具支持、ContextAccess 或 Notebook；生成器用实际 tools 的 keys 生成能力说明。系统规则不反复追加到用户历史，用户消息及工具结果保留原角色，连接测试仍只发固定 `Reply with OK.`。

前置审计发现并修复了几个会影响输入真实性的问题：

- 编辑、重答和继续恢复原用户轮次的目标版本；本轮真正消费过的快照记录精确 key，包括 PDF 物理页。目标元数据不能解锁其他轮次才读取的正文。
- 材料按有效历史前缀投影，删除后续分支后，不再从材料目录复活其独占内容；原始留存资产保留。固定目标按稳定会话身份保存，pending Blackout 的选择不改写来源会话。
- OJ 页面句柄绑定真实面板生命周期；关闭重开不能复用旧句柄，源码绑定失效不造成两个面板碰撞。题面、判词继续只投影已加载状态，不触发额外网站请求。
- Cookie/Set-Cookie 完整值在工具分页前过滤，覆盖源码、编译信息、字符串头及结构化键，同时保留普通代码。

必要的可选 `Message.target`、`capturedKeys` 与 `Conversation.pinnedTarget` 元数据仍使用会话 version 1，恢复时校验。它们是对象和消费来源记录，不是个人查询许可台账。未实现自动压缩、工作区记忆、额外 OJ 历史或新的执行权限。

## 当前结论与下一步

统一提示入口及输入真实性修补已有工程证据；强模型的 P01 对照支持该规则改动确实能改善换文件行为，P07 在追加预算后完成且未观察到退化。本地 4B 和云端仍存在具体失败，强模型只覆盖三个场景，不能将首轮标为教学质量验收通过。下一步优先检查工具选择、未定义行为解释及冗余展开，再按所选思考模式的实际生成预算补齐强模型 P01–P10 对照。当前两组云端尝试已结束，扩大范围另行确定。

自动压缩尚未实施。应在完整上下文的质量与参数基线可解释后，再用同一套对象、版本、授权和推理案例验证压缩；压缩不能掩盖当前输入或解释错误。负责人可先使用已构建候选体验，反馈与模型评估分别记录。
