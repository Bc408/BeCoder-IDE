# 三档切换、连续输入与对话继承

日期：2026-10-20。状态：负责人已确认设计并明确授权文档与实现；验证和体验验收另行记录。

本文替代工作区草稿方案中“主动切档恢复两侧独立输入”“临时内容不能随主动切档发送而转存”“主动 Blackout 必须退出详情”的旧规则。异常根失效、工作区 A/B 切换、对话独占和文件权限边界继续有效。

## 产品规则

- 切档不导航、不创建聊天、不清空输入；文字和已捕获附件连续，空输入也覆盖目标侧旧草稿。
- Spot/Flood 属于同一持久化类别，两者之间继续当前聊天。
- 跨越 Blackout 与持久化类别后，首次新问题被宿主接受时才建立独立对话。发送前切回来源类别则继续来源对话。
- 新对话继承当前已加载消息、附件、工具结果及协议快照；不重读原文件，不追踪来源后续变化，不建立跨会话读取入口。持久化新对话保存完整快照；删除来源不影响副本。
- 当前 Webview 连续展示。新问题之前插入细线提示：进入 Blackout 为“已继承上文，开始临时对话”；进入 Spot/Flood 为“已继承上文，建立持久化对话”。分隔信息归新对话保存，不作为模型消息。
- 来源聊天的已发送内容不变。发送接受后清除被消费的来源草稿；接受前失败保留输入，网络失败不回填已成为消息的输入。来源清理失败明确反馈，不能伪称已清理。
- Blackout 修改和新消息只在内存中。为已接受的分流发送清理原持久化草稿，是宿主对自己持有租约的来源进行的一次窄操作，不向模型开放存储。
- Blackout 主动切到 Spot/Flood 并发送，明确允许完整临时上下文落盘。新对话不回写先前来源 C。
- 分流前保留来源租约，避免另一窗口抢写；导航、关闭或实际分流后按当前任务生命周期释放。临时输入不跨重启保存。重启后仍按有效档位和既有恢复引用恢复，不能将待分流 Blackout 输入写回来源。
- 跨类别待发送时，编辑旧消息、重答、续答不隐式创建分支；需先切回来源类别或发送新问题。导航离开按目标类别保存当前未发送输入，保持工作区切换不搬运上下文。

## 所有者与实施边界

Webview 仅渲染分隔及持续输入。扩展维护来源类别、待分流内存输入和发送交接；ChatHistory 保存独立对话及分隔元数据。原生协调器保留受控来源租约，并仅允许按来源 ID/revision 清除草稿。模型读取严格使用当前档位，不以页面仍显示旧消息扩大权限。
