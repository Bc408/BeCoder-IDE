# Beacon

BeCoder's built-in conversation companion. Use the persistent Beacon button in the editor's upper-right toolbar, or **Beacon: Toggle Beacon Sidebar** in the command palette, to open or close the single-conversation chat in the right sidebar. The Beacon activity icon on the left opens the API Key configuration panel. The Beacon extension's Features tab also provides a configuration button. An empty value removes the saved key. The key is stored with BeCoder's SecretStorage and is never sent to the Webview.

Supports DeepSeek, Alibaba Cloud Bailian, Moonshot and Ollama through Vercel AI SDK. Choose a provider in the left Beacon panel, save its key, fetch models and select a chat model. Local Ollama needs no key. Settings > Extensions > Beacon also provides provider, per-provider base URL and model settings; credentials remain exclusively in SecretStorage. The composer shows the selected model and each new answer records its actual provider and model. It supports streaming multi-turn conversations, stopping, retrying interrupted/failed responses, copying answers, Markdown, code highlighting and math. When a provider returns reasoning, Beacon saves it with the local conversation in a collapsed section that users can expand; reasoning is excluded from later model context. Availability depends on the selected provider and model. Beacon can read up to three user-requested UTF-8 text files (each at most 128 KiB) from the open workspace per response, and shows each read as an activity. It cannot write files, run commands or read known credential files. Messages and explicitly requested file contents are sent to the selected service.

Chats are saved locally in BeCoder's extension workspace storage. Each workspace has its own history; reopening the same workspace restores its active chat. New chat keeps previous conversations. Return to the chat list to scroll through all conversations, resume, rename or delete a chat (deletion requires confirmation). Timestamps show the local clock today, yesterday or a weekday for recent dates, and a calendar date for older conversations. One response runs at a time; pausing retires that request before another operation can start. A paused answer retains its text, reasoning and tool activities. Continue starts a new model request with the saved context and appends output to the same answer; Regenerate discards that answer and its later conversation branch. Sending a new message includes paused answer text in context. Completed workspace-file tool results are saved locally and replayed as tool context, without sending file contents to the Webview. Unfinished tools and raw reasoning are not replayed. Reloaded interrupted answers can also continue. Elapsed time adds generation attempts and excludes pauses. Partial output is checkpointed every 500 ms; completed turns and normal shutdown flush pending changes. Storage failures remain visible with a retry action. Unreadable history is preserved and blocks new sends until the window can load it again. Each request has a three-minute timeout; failed requests can be regenerated, while a failed continuation preserves its existing answer for another continuation attempt.

Build from the repository root with `npm run compile-oi-extensions`. Beacon's own commands are `npm run typecheck`, `npm run build`, and `npm test` in this directory. Tests use a synthetic provider SSE responses and do not prove live account connectivity or Webview visual acceptance.

The chat renderer keeps code blocks stable during streaming, with copy feedback, optional line wrapping and plain-text fallback for oversized code. It shows a concise running status, elapsed time and workspace-file tool activities; provider reasoning is collapsed by default and can be expanded by the reader. Waiting text follows Captain Who's shimmer treatment and respects reduced motion. Scrolling follows content growth until the reader scrolls away; the return-to-bottom control restores following.

## 中文

点击编辑器右上角常驻的 Beacon 按钮，或运行 **Beacon: 打开/关闭 Beacon 侧边栏**，切换右侧单会话聊天界面。左侧活动栏的 Beacon 图标打开 API Key 配置面板，Beacon 扩展详情的“功能”页也提供配置入口。配置时留空可删除密钥。密钥通过 BeCoder SecretStorage 保存，不传入网页界面。

本版支持流式多轮对话、停止、重试、复制、代码高亮和公式。服务商返回思考内容时，Beacon 会将其保存在本地对话中并默认折叠，用户可自行展开；思考内容不会进入后续模型上下文，是否提供取决于服务商与模型。模型可按用户请求读取当前工作区中最多 3 个 UTF-8 文本文件，每个文件不超过 128 KiB，并在对话中显示读取状态；不会写入文件、运行命令或读取已知凭据文件。消息以及明确要求读取的文件内容会发送给所选服务。支持深度求索、阿里云百炼、月之暗面和 Ollama。左侧面板选择服务商、保存密钥、获取模型并选择聊天模型；本机 Ollama 无需密钥。“设置 > 扩展 > Beacon”同步提供服务商、各服务商地址和模型设置，密钥仅保存在 SecretStorage。输入框显示当前模型，每条新回答记录实际使用的服务商和模型。聊天记录保存在 BeCoder 的工作区扩展存储中，不同工作区相互隔离；重启后恢复当前聊天。新聊天保留旧会话，返回聊天列表后可滚动选择会话、继续、重命名和确认后删除。生成中需先暂停才能切换；重启时中断的回答显示为已暂停，可继续或重新回答。未发送的草稿只在当前界面中保留。保存失败会提示重试，读取失败保留原有数据。

暂停会保留已输出的正文、思考与工具活动，并等待当前请求结束。“继续”携带已有上下文发起新请求，将新增正文接到同一条回答后；“重新回答”舍弃该回答及后续分支，重新回答原问题。暂停后也可直接发送新消息，部分回答会进入上下文。已完成的读文件结果保存在工作区历史中，续接与后续消息可引用这些结果；文件正文不传入网页界面，未完成工具与原始思考不重放给模型。重新打开历史后仍可继续暂停回答，耗时累计实际生成时间，不包含暂停等待时间。续接失败保留原有内容，可再次继续或重新生成。

代码块在流式输出中保持稳定，支持复制反馈、自动换行，超大代码降级为完整纯文本。界面显示简要生成状态、耗时和工作区文件工具活动；服务商返回的思考原文默认折叠，用户可点击展开。等待文字参考 Captain Who 的扫光效果，遵循系统减少动态效果设置。回复增长时跟随底部，向上阅读后暂停跟随，点击回到底部恢复。
