# Beacon 底层材料与上下文基础设计

修订日期：2026-11-22。本文定义下一阶段底层建筑夯实范围，产品行为采用已确认决定；工程契约由执行计划承接并待审阅。当前实现和验证缺口见[实现状态](implementation-status.md)。

## 1. 目的与交付链路

本轮让用户真实做题行为与 LLM 主动取得的材料准确进入当前问题的上下文，完善存储、来源、读取、连续对话和输入预算。沿既有生产者、BeaconStore／Coordinator、ContextTools、history／session／protocol 和 provider 补窄接口，不搭通用代理框架。

[总体架构](architecture.md)定义职责，[能力需求](prd.md)保留 141 条完整条目，[代码队列](code-snapshots.md)与[压缩设计](context-compaction.md)分别细化生命周期，[执行计划](../superpowers/plans/2026-11-22-beacon-foundation-implementation.md)定义源码、接口和测试。取舍追溯见[队列决策记录](decisions/context-queues.md)。

本轮包括四个执行来源与 Get Problem 近期队列、对话代码队列、题目线索与只读题面工具、结构化读取、已完成工具恢复、分支／换模型以及首版同步压缩。模型设置、草稿／模式／历史和独立 Notebook 保持原行为。

## 2. 工作区资格、模式与正常流程

必须先选择Beacon工作区且该根正常可用，软件层才对真实用户行为生产持久材料；无根或根异常不采集、不落盘、不写备用根。该资格与模式独立：有效根下Blackout／Spot／Flood都持续保存Get Problem和四类执行／测评记录。Blackout只禁止Beacon列目录、读取、调用持久上下文操作，不能作为软件层采集开关。切回Spot／Flood可消费仍在近期队列中的记录，不重放用户行为。

完整闭环的设计和验收覆盖洛谷、Codeforces、AtCoder、牛客、蓝桥。用户 Get Problem 成功即可形成“实际看过的题目＋对应代码文件＋查看时间＋题面正文”；支持 Get Problem 的对象 Import to CPH 提供实际导入关联。其他仅能 CPH 导入的来源不自动获得五站完整能力承诺。

底层分别提供 Get Problem 真实行为、当前 CPH 关联、现有规则解析的文件名／目录候选，记录来源和实际依据；不以硬编码优先级替 LLM 选择唯一题目。模型结合用户提问选择一个或多个对象，无法判断时再问。查询线索不触发代码正文捕获、联网、建题、改样例或文件重命名。

这些依据服务当前材料发现，不为执行／提交历史补写未观测事实。缺少可靠题目身份的历史记录保持未知；不因后续文件名、路径相同或时间接近就宣称同题。非规范操作不增加复杂补链；概念讨论或普通代码问答不强制拿题或建笔记。

## 3. 数据对象与配额

| 对象 | 来源、归属与配额 | 更新规则 |
| --- | --- | --- |
| Get Problem 记录 | 当前 `.beaconWork` 内跨对话共享，上限 13 条；含题目标识、对应代码文件、用户查看时间及题面正文 | 以题目＋代码文件去重；用户再次获取同一对更新查看时间并移到队尾，同题不同文件分别保留 |
| Runner Run／Run With Input | 当前根内用户实际主编译和执行凭证，各保留 20 条 | 保实际编译稿、输入、诊断、流与终态，活动记录按真实句柄保护 |
| CPH 测评 | 当前根的整轮样例凭证，各保留 20 条 | 整轮一条，逐例 input／expected／actual、checker 与状态保留来源结构 |
| Notebook input 运行 | 当前根内真实笔记／程序块／input 凭证，各保留 20 条 | 文档当前输出与近期凭证生命周期独立，不以关联源码扩大采集根 |
| OJ Connect 结果 | 当前根内既有交题／查询流程实际取得材料，各保留 20 条 | 正式记录按真实提交身份更新；无正式编号的真实尝试阶段保持独立身份，不伪造编号 |
| 对话代码快照 | LLM 读取当前编辑器代码时，同次保存到当前对话；默认 10 份，单份完整 UTF-8 正文最多 256 KiB | 同文件同内容复用并移到队尾；新内容新增；历史读取不改次序，正常自动淘汰 |
| 模型联网题面 | LLM 显式工具取材，实际结果进入上下文 | 无专门缓存或队列，不回写 Get Problem 正文、时间或次序 |

共享“全局”只指当前 `.beaconWork`，不同根互不混合；各来源配额独立，不合并为总 FIFO。会话消息、解释、摘要、许可、附件和代码快照不能作为其他聊天的读取入口。

用户行为凭证采集不依赖聊天打开、模型配置或当前模式，仅依赖正常的所选工作区及既有真实对象归属；不因材料需求新增运行、交题、登录或后台查询。开始主编译后才记真实尝试；编译前准备失败不计。CE、RE、取消、TLE、OLE、正常和未知收尾保持真实，整轮完成不等于 CPH 全过，本地通过不等于 OJ AC。

## 4. 持久化与原子交接

共享近期材料复用 `.beaconWork/cache/<producer>/records.json`，保共同身份、来源、版本、时间、状态和覆盖，正文按来源结构表达。对话代码队列放本对话目录，独立于 conversation 消息的有效分支；具体文件名由执行计划固定。共享用户行为生产的校验独立于Beacon消费校验：固定发起窗口工作区身份／根选择代数，保存时重核根，模式切换不使其失效；不复用包含mode的消费epoch当采集资格。复用已有锁、根校验与原子JSON发布，不新增数据库、独立索引、pending 文件、引用计数或历史 revision 文件。

真实活动记录受协调器实际任务保护，终态收尾后恢复裁剪；重启无对应任务的旧记录不能永久占保护，也不能补造成功／失败。超长输出保实际采集头尾，分别标来源遗漏、存储省略和工具分页，不截坏 JSON 或改变运行时限／OLE。具体字节预算和队列格式属于本轮待审阅工程参数。

写入或去重更新失败保留原已发布队列，不先淘汰旧记录。Get Problem／导入的材料保存失败明确反馈，已成功的核心操作继续。普通读取不得隐式迁移旧数据；旧记录未知身份不借当前文件补证。

## 5. 当前代码、历史快照与失败

发送、继续、重答和运输重试不自动读存代码。LLM 新调用代码工具时解析有效目标与当前编辑版本，包含 dirty，新的调用能取得用户后续改稿；同一次取得的完整原文用于保存和返回，不在保存时第二次读取。当前代码读取明确返回正文、文件名和路径，Blackout同样保留；普通文件或题面工具不自动生成编辑器代码快照。

保存最多 262144 个 UTF-8 正文字节，不按 token、字符数或 JSON 序列化长度判断。工具按实际返回预算提供局部正文或分页，并明确其未返回覆盖；快照保存完整不代表模型看过全部代码。权限与敏感过滤在读取、列表及回读路径继续执行。

读取成功但保存失败／超限时，仍交付实际可用代码，保存状态如实报告；不提供虚假 ID、不存截断快照、不修改原队列，不阻止或撤销用户问题。读取本身失败则反馈读取错误，不能返回旧缓存冒充新代码。

编辑旧问题／重答不隐藏或删除本对话队列中的历史代码，不需维护快照分支引用；其他分支消息、要求、许可和普通私有材料仍受有效历史限制。真实读取可通过后续工具调用可视化呈现，但本稿不宣称该 UI 已完成。

代码快照按 ID 分页，没有跨调用额外保留；被淘汰就明确不可得。无法保存的超限／失败读取，只能在源页面和版本仍一致时继续分页，变版或关闭明确失败，不为此建跨调用全文缓存。历史快照读取不新增或移到队尾。

## 6. 目录、题面工具与共享凭证一致性

沿现有 inspectContext 扩展目录、代码队列、题目线索和指定题面读取，不新建任意文件写工具。目录只给身份、来源、时间、版本、覆盖和入口，不将队列全文自动注入模型。旧同题执行／提交结果仍可用于讲解改稿背景，源码关系标明实际代码观测与哈希口径；无法核对保持未知。

Spot／Flood默认读LLM指定的Get Problem记录（或对应文件）保存的题面；Blackout禁该来源，直接通过OJ Connect只读联网取得题面，不读取编辑器中的题目页面。同题多文件时不静默选唯一正文。LLM可显式联网补取／刷新；工具调用现有五站只读解析 owner，不运行完整 showProblem／import 动作。返回正文、样例、限制、取得时间、来源及覆盖；联网结果仅上下文，不另持久化，不更改用户行为。刷新失败保留原已存题面并反馈失败，无定时刷新。权限／登录失败、解析不全、无记录与成功空字段分别处理。

共享 record 继续按 producer／id／revision 精确读取，支持题面章节、指定 CPH 样例、Runner 诊断／input／output、Notebook 执行块和 OJ 已有字段，保留整条和分页。首次成功读取后，本回答内固定该版本；队列后续更新或淘汰不混版，首次读取前失效明确失败，新回答重新核对。该保护针对共享凭证，不保护代码快照的跨调用分页。

运行／测评事实仅通过持久化记录作为一等来源供给；不另读Runner／CPH／Notebook运行输出页或OJ判题页，不再通过Notebook功能页面投影自动供应正文或outputs／attempt上下文。editNotebook.read的模型可用schema与执行层同时关闭outputs／attempt，不能以合法资产工具绕过凭证来源；宿主完整备份和真实输出保留不受影响。该单一路径适用于所有档位，Blackout裁切记录后不提供页面替代。Notebook自身编辑／保存／用户运行、用户主动提供的材料和明确请求的资产操作保留各自职责，不能冒充运行凭证。

不再 consumeRuntimeRecord 复制整条共享正文到会话。实际工具结果仍按协议保留，来源淘汰不删除已经返回的片段，也不保证未返回内容永存。

普通inspectFiles.read／search对`.bcnb`及`.bcnb-backup`先通过既有Notebook格式owner取得内容表示，排除outputs、metadata.becoder.attempt、executionSummary，再分页或搜索；磁盘与打开文本路径均适用，无法安全解析则明确失败，不交付原始JSON／base64兜底。直接打开为普通文本的笔记页同样不能暴露运行字段。该处理不新增持久化、不改宿主完整稿／备份，也不裁切用户主动提供的材料。

## 7. 请求、分支与协议

每次实际请求重建可信导师规则与实际工具说明，用户原话保留原角色，材料与摘要不变成产品指令。模型和连接配置在当前回答内稳定；输入准备在首发、继续／重答及工具续轮执行。

完成工具调用及配对结果即使后续回答失败／中断，仍在有效历史内保留，重放不执行工具。停止后的迟到正文不覆盖当前执行，未完成调用不补成功。普通私有材料在内存命中和原生回退前均检查有效分支；代码快照读取仅按当前对话队列和 owner 校验，不借此恢复旧分支文字或许可。

换模型保留正常文本和工具交换，按 provider／baseURL／model 兼容性过滤旧私有 reasoning／providerOptions，不能改写成普通文本继续发送，也不删除工具业务 JSON 的同名数据。

## 8. 同步压缩与阶段权限

本阶段实现当前模型的同步摘要投影；代码队列按容量自动淘汰，不参与模型删除决策。B=min(最大输入额度,总窗口−本次实际输出预算)，T=floor(0.90B)，G=floor(0.60B)；计量系统、工具 schema、目录、消息、实际返回及媒体适配。输出只预留一次，usage 锚点必须对当前模型与投影有效。

完整工具批次后才整理；保当前问题及必要完整尾部，较早闭合步骤可被总结。摘要绑定覆盖前缀，纯追加不使其失效，覆盖区编辑／重答则重建有效投影。先校验合法摘要及缩短后的最终输入，再经ChatHistory可确认的串行提交保存后发布；失败候选不混入普通checkpoint，旧正文与合法投影保留。每个普通待发步骤最多一次整理修复，整理及其取材续轮不递归整理，装不下则停止。详见[压缩设计](context-compaction.md)。

根按窗口选择，Spot／Flood 共享记录读取与生产仍限当前合法根；不借 cwd、关联源码或 Flood 扩大归属。Blackout仅对Beacon朴素裁切持久化上下文来源：代码队列、共享近期、Get正文、其他持久材料及持久摘要的目录／读取／写入均不可用，不建立临时镜像队列或替代引用。打开的代码编辑页正文、文件名和路径正常返回，已加载消息及普通输入投影沿既有临时会话处理，不为Beacon这些动作读写磁盘；软件层仍对有效根内的真实用户行为持续采集和落盘。跨模式继承遵守既有独立快照规则，不追源补读。忙时冲突拒绝，不排队补发；Beacon 不改学生源码、不 Shell、不自主运行／停止／登录／交题。

## 9. 验收与后续范围

| 验收链路 | 必须观察的行为 |
| --- | --- |
| 用户事实生产 | 无根／根异常零行为材料落盘；有效根下三档都持续采集，Blackout禁止Beacon读取但软件写入照常，切回Spot／Flood可读仍保留记录；Get Problem13条含正文，四类各20条，活动保护和未知收尾真实 |
| 代码工具 | 发送零捕获，同回答 dirty 改稿可再次读取；读取即保存，10 份／256 KiB、去重复用、超量和写入失败保持原队列 |
| 隔离与分页 | 代码快照整个对话可读且跨聊天隔离，淘汰后分页失败；共享凭证本回答固定版本，下一回答重核 |
| 题目与题面 | 多来源线索不强推唯一题；Blackout代码正文／文件名／路径仍可读，题面只调OJ Connect联网；所有档位不以题面／判题功能页面补读，联网零专门持久化，无get／import UI副作用 |
| 请求协议 | 中断完成事实不重演；其他私有材料按有效分支检查；换模型不混私有字段；检查 SDK 最终出站 body |
| 压缩 | T 边界、有效 usage、工具批次、摘要前缀有效性、提交前取消、原子保存失败、重启、上下文超限一步有界恢复 |

执行计划将每行落实到具体源码 owner、测试和命令。工程检查、模型语义观察、五站真实流程及负责人体验分别验收；Ollama 4B 只用于链路和兼容冒烟，已授权强模型仅在实施后的合成案例中观察。历史评估／构建不复用为本次完成证据。

tips/status、dream、完整视觉、更充分的本人同题历史、学习资产完整质量和工具调用可视化完整界面继续保留后续；知识库等候选不自动扩大本轮。源码检查、staged应用、Setup、真实运行和发布按各自授权与证据记录；本设计不视为已完成实现。
