# Beacon 底层设计

更新：2026-11-25。本文维护采集、持久化与执行边界；工具字段见[工具合同](tool-contract.md)，模块分工见[架构](architecture.md)，验证与缺口见[实现状态](implementation-status.md)。

## 1. 采集资格与共享队列

“共享”指当前所选 `.beaconWork` 内的所有对话，不跨工作区。只有正常所选Beacon根才采集；根外源码／笔记照常运行，但不错误入队。无根或根异常不采集、不写备用位置、不补采。采集scope固定发起窗口、根身份与选择代数，晚到结果不能改投新根；模式或聊天变化不使合法采集失效。

| 队列 | 容量 | 单位与更新 |
| --- | --- | --- |
| problem | 13条 | 五站Get／Import读题行为；problem（oj＋problemId）和filePath完全相同则移除旧项，新ID、新viewedAt入尾；不同路径分别占位，不存题面 |
| run | 共30条 | Runner／CPH／Notebook共用；一份程序本次编译及关联input结束／失败／取消后入队，不去重，无活动占位 |
| verdict | 20条 | OJ Connect完整取得最终结果才入队；同站同题实际提交代码严格相同替换旧项入尾，缺代码仍保存并跳过去重 |

problem无可靠文件路径时保存null；同题同为null按字段相同去重。读取不更新查看时间，旧ID不转指替换记录。verdict不归一化空白、换行或注释，不用当前代码补历史提交稿；同次观测重复交付幂等，独立再次观测仍按正常规则入队。

软件采集和Beacon消费分开：有效根Blackout仍采集；模型不能列／读持久来源，不建立内存镜像队列。切回Spot／Flood只读仍保留的材料，不补采。当前代码和五站fetchProblem依原权限可用。

## 2. 存储、并发与发布

当前文件格式为 `{version:1,records:[...]}`，分别保存到：

```text
.beaconWork/cache/context/problem.json
.beaconWork/cache/context/run.json
.beaconWork/cache/context/verdict.json
```

复用现有Store、锁和原子发布；不另建索引、逐条正文库、归档、pending记录或引用版本协议。目录从实际保留记录确定性生成，最新入队在前展示，不调用模型。

发布前失败保旧队列，不先淘汰再尝试保存；发布后的确认不明须区别于未写入，不能盲删新文件、回滚或重复追加。校验根身份、目标身份、临时文件所有权及scope；同根并发写不丢结果。文件串行写入不构成用户操作等待／重放队列，忙时仍由原执行owner立即拒绝。

采集观察异常和落盘失败不改变核心编译、运行、取消或清理。运行占用随真实进程与必要清理退役，不等待Beacon磁盘写入。工作区刷新只发布与当前选择代数匹配的完整状态。

## 3. run粒度与来源差异

每条run是“一份实际程序／编译信息＋输入结果列表”。实际编译尝试开始后才有记录；运行请求编译失败保失败尝试，关联input标not-run；未开始编译的后续程序不造记录。

| 来源／操作 | 单条内容 |
| --- | --- |
| Runner Run／Run With Input | 一份编译稿与本次输入、合流终端输出、退出／停止；不保存输入编辑按键，回显不补成stdin |
| CPH单点／全部 | 一份编译稿、一个或多个测试点、原测试点序号、输入／expected／分流stdout与stderr、实际check；单点和全部等权各一条 |
| CPH仅编译 | 零条，无论成功、失败或取消；不改变原生仅编译能力 |
| Notebook | 一份代码块及其多个input、笔记路径、执行时代码块序号；多个程序分别成条 |

共同保存真实代码、编译器／参数／诊断／时间和input结果；不保存运行限制配置，不嵌入题目或CPH配置。CPH仅保check，不保存检查器类型、配置、路径、代码、命令或诊断。学生程序status、CPH check和整组status分开解释，本地通过不等于OJ AC。

Runner无法可靠取得交互stdin时为null并标gaps，不以按键流或回显伪造；Run With Input保实际输入文件正文。空正文、未知、未执行和读取失败各自表达。

## 4. Notebook执行与采集解耦

点击运行全部／选区时固定本次代码、input及关系，含dirty，中途编辑下次生效。codeBlockNumber只数C/C++块，从1开始；inputCellNumber按整个笔记单元格位置从1开始，均指执行时位置，不是永久绑定。

同一代码块本次操作编译一次，每个input独立进程、计时、限时和输出限制。不同代码块即使正文相同也不合并，不增加跨次编译缓存；临时产物由执行层持有和清理。每个input真实展示共享编译耗时，不能累计成多次编译。

编译失败跳过本块input继续其他块；input RE／TLE／OLE继续后续。用户Stop立即终止整批，未开始内容不执行；删除或调序不改变冻结计划，失效页面停止展示，关闭仍取消。普通非BeCoder Notebook的原生取消规则保留。

执行层提供普通结果／观察回调，不导入Beacon根、队列或持久化类型。采集适配器消费事实并按程序成条，无Beacon根或观察者失效时照常执行。当前观察接点仍有unknown适配技术债，不能写成已完成的有限联合类型合同。

## 5. 输出保留与完整读取

每条run的编译输出和所有input实际程序输出合计最多8192 UTF-8正文字节。不是每input、整个Notebook批次或整条记录的额度；源码、输入、expected和元数据不计。原执行器时限和OLE不变。

保留算法对非空流均分额度，短流剩余额度回配给其他流；每流按UTF-8边界保头尾。完整输出用字符串；发生省略时用head／tail／omittedBytes，并独立标来源已省略量。保各input身份与状态，不截坏结构，不把已丢输出称作可恢复全文。

记录工具按ID返回完整已保存记录，不增加part／测试点分页，不依模型剩余额度二次裁剪。目录不固定正文，首次合法成功读取后在本回答固定事实；实际返回只沿普通协议留存，不额外复制成私有material。完整交换闭合后在下一请求准备处计量；沿既定同步压缩，仍无法容纳则有界失败。8KiB不推广成题面、verdict或当前代码上限。

## 6. 旧数据、历史与读取边界

当前代码无独立快照API、正文库或队列；实际工具返回沿普通历史，执行稿和提交稿只属run／verdict。发送、继续、重答和协议回放不额外捕获代码。

旧cache/runner、cph、notebook、problem、oj及会话code-snapshots.json不自动迁移或删除，新队列从真实后续行为形成。旧文件保留不授inspectFile／readMaterial回读权；`.beaconWork`内部数据仍由各owner保护。

原聊天、附件、已完成旧工具交换保原名和配对，继续只提供当前工具；不执行旧inspectContext／editNotebook，不补读快照。有效分支约束消息、材料、摘要和许可，其他聊天或弃分支不恢复权限；契约变化重建usage锚点。

运行／测评不从功能页、终端或Notebook输出旁路读取；笔记／备份供模型的内容投影排除运行字段，投影失败不回raw JSON，用户完整资产保留。fetchProblem只进入普通上下文，不采集用户看题记录或建立专门题面存储。

## 7. 验证责任

回归应覆盖配额／去重、根与模式、并发发布、晚到结果、采集失败不阻执行、三来源粒度与状态、Notebook编译次数／取消／删除、8KiB及UTF-8边界、当前代码零额外落盘、旧交换不重演、完整读取及压缩。

源码回归、模型选材与教学质量、stage构建、真实五站和桌面体验分别验收。实际结果与待办集中在[实现状态](implementation-status.md)，不在设计文档重复存放测试成绩或已经完成的实施待办。
