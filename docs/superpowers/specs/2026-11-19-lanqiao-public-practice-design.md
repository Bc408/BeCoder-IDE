## 1. 已确认范围与本轮新增决定

为蓝桥公开题库的普通 C/C++ 编程练习接入既有“源码识题 → 共同题面 → 同源码 CPH → 提交 → 正式评测记录”流程。界面复用洛谷组件，实际会话由浏览器宿主拥有，本地测试继续由 CPH／Runner 拥有。

负责人已确认蓝桥编译器例外：首次 C++ 选择官网 `C++（g++17）`／`cpp`，C 使用官网唯一的 `C（gcc8.3.0）`／`c`；以后优先保留有效的本人选择，提交前核对当前可用项。该例外不改四站的 C++20／C17 向上选择规则，不把官网标签改写成更高标准，不推断 C 的语言标准。

负责人本轮确认交付节奏：**内部逐阶段实现、检查与审查，完整闭环后交付一个最终 stage**。不单独交付“只能登录／看题”的中间 stage。内部合成验证不等于产品真实闭环；最终 stage 的负责人实测仍是验收环节。若需为构建失败或实际缺陷重建，应记录失败及重建原因，不能以“一次 stage”为由跳过修复。

不纳入课程 lab、运行中赛事、考试、云环境挑战、交互题、付费购买／会员权益管理、题解、题库列表或社交入口。公开普通编程练习仍按当前账号实际访问权限判断，不仅凭免费标签纳入或排除。不绕过权限，不新增独立 Cookie／账号存储、持久绑定库或事务数据库，不给予 Beacon 登录／提交能力。C++ 一次 AC 已采证；C、CE／WA、全部题型与故障情况尚未实证。

## 2. 路线比较与推荐

| 路线 | 方式与收益 | 代价与门槛 |
| --- | --- | --- |
| **A：采用** | 官网人工登录；当前原生 BrowserSession 的固定题面／身份／提交／执行／报告／详情操作；不依赖编辑器 DOM，适合现有 SessionClient 与共同控制器 | 默认安全配置下的真实产品登录与固定读取已验证；原生发送、精确执行路径和当前语言目录获取仍需分别验证 |
| B：固定网页事务 | 官网人工登录；每次使用有明确所有权的页面执行本站提交与取报告事务，可沿官网运行环境处理确有必要的页面依赖 | 仍需解决相同网页登录问题，并增加页面、导航、草稿和脚本生命周期；目前无证据表明它是必需路线 |

## 3. 原生登录与传输前置验证

研究器失败并不能证明当前产品 BrowserSession 也失败：研究器是 BrowserWindow／自建 partition，产品使用 BrowserSession／WebContentsView、自己的 preload、权限与信任管理。后续真实产品开发宿主已在默认安全配置下完成三源原生 GET、真实登录表单、负责人手动登录和同 Session 固定读取。研究记录没有实际协商协议，不能认定 TLS1.3 或 HTTP2 为先前失败的根因，也不把固定样本写成长期稳定率。

下列为已批准并执行的**真实产品宿主匿名验证卡片边界**；结果与编排失败见会话验证记录，不因进入规划重复执行：

1. 只使用现有 stage 或正确的源码运行入口，不为匿名检查先构建；卡片记录实际可执行文件、可核对的构建源码快照、Electron／Chromium 版本与实际启动配置。不能绑定源码时，结果只代表被测 stage，不证明当前源码路径。准备全新独立数据根，导航前核验产品实际 userData／portable／浏览器 Session 路径均落在该根。不能只检查命令参数；无法确认隔离即不导航。
2. 在产品真实持久 BrowserSession 中，固定主站 `/problems/`、Passport `/login/` 和一份已采证官网静态 JS，各进行一次匿名 GET；必要时完整重启后再做一轮，最多六次受控 GET。版本、有效 UA、必要参数、各源 `resolveProxy` 和 DNS 只作脱敏投影；不读取或复制 Cookie。
3. 受控 GET 不创建网站页面、不执行官网脚本、不发 POST，不增加任意 URL 或脚本接口。保留 HTTP、固定重定向目标、错误码、耗时；有可信来源才能记录协商 TLS／ALPN，拿不到就标未取得。
4. 三源读取通过后，另行检查真实 WebContentsView 的匿名登录表单是否就绪。该检查按官网正常匿名导航观察，允许官网页面自身的匿名初始化／统计等自然请求，不主动构造、重放这些请求；它不是 GET-only 检查。自然请求与前述六次受控 GET 分开记录；不输入凭据、点击认证或触发提交／报告。若某项检查限制为 GET-only，须在导航前拒绝非 GET，并将因此无法就绪记为受限结果，不能据此归因为 TLS 或产品故障。表单就绪也不等于已完成登录。
5. 读取失败则先停在该层；原生 GET 成功而页面失败时，只调查确切失败资源及同 Session 同 URL 差异。不得无边界组合尝试 HTTP2／TLS／UA／代理开关。

产品主窗口设置代理与实际 BrowserSession 的代理不等同，必须读取目标 Session 的有效结果。不能全局降低 TLS、关闭证书校验／sandbox、伪造浏览器身份或接管所有静态资源。Session 级 TLS 改动也会影响共享该 Session 的其他站，不能称蓝桥单域修复。确需宿主修复时另列具体变更与四站回归范围。

登录由用户主动在内置浏览器完成；扩展只接收安全的登录摘要和不透明任务句柄。Cookie 保留在宿主。普通凭据轮换先重新确认身份，不直接当作换号；身份、存储范围或窗口变化使旧准备和迟到响应失效。403／网络失败显示未知，不伪装退出。

| 源码 | 沿用原 TextDocument／文件身份与动作开始时的未保存快照；只规范换行，不保存、改写或临时换文档 |

样例按题面中的输入／输出语义配对，不能扫描整页所有代码围栏按奇偶配对；254 中有多段教学代码，正是必须覆盖的回归材料。结构化样例的文本与空白保留原文，展示与 CPH 接收同一份结构化数据。浏览器 Get 只创建／打开源码与共同题面；题面 CPH 动作显式关联该源码，已有样例替换沿用确认机制。

首次显示真实官网编译器名称，按 C／C++ 筛选并采用已确认的蓝桥例外。个人设置仍是唯一偏好权威，蓝桥分别保存 `c/cpp` token；没有额外标准或优化选项就不展示虚构项。未登录时如使用采证目录，沿用现有来源说明；有效偏好失效时要求重新选择，不悄悄替换。提交前以当前本站目录／题目允许语言为准，固定采证标签不保证永久可提交。

当前证据中的语言目录来自官网前端 `availableLanguages` 固定数组，并非已验证的目录 API；`limit_details` 仅表示题目语言族限制，也不单独证明服务端允许某编译器。实施任务 0 必须冻结当前目录的生产获取方式、版本发现和静态提取规则，以及本题允许项的证据来源。无法满足时停下修订该契约，不能用内置数组冒充已实时刷新。源码语言族须从快捷键快照传到读题；浏览器 Get 新建 `.cpp` 采用 cpp，四站原有调用保持兼容。

## 5. 提交、执行与报告的边界

```text
固定本次题目、源码、账号、语言与 Session
  → 消费源码发送权，POST source 一次
  → 取得并校验本次执行标识／执行地址
  → 有限 GET 跟踪执行
  → 执行结束，任务仍有效时消费 report 发送权
  → POST submit-report 一次
  → GET 同 ID 正式详情，核对题目、语言与归一化源码
  → 交付正式 RecordRef，打开共同记录页
```

官网正常调用链已采证，服务器内部落库时点未证实。执行标识不提前冒充正式记录；`execute_status >= 2` 只沿用官网执行停止条件，不映射成 Accepted。执行中继续显示提交进度；没有正式记录时不打开伪造的记录页，也不制造测试点总数。因此首版共同记录页可能直接以终态打开，不承诺在官网正式详情出现前绘制逐点评测。

source 和 report 的发送权分别在宿主内存中、dispatch 前同步消费；重复调用、迟到回调和并发动作不能再次消费。每窗口提交期间立即拒绝并发，不排队、不保存待发源码；不得为蓝桥建立通用网页操作／重试框架。已发请求不能被界面承诺撤回。

source 为 `/api/v2/problems/{id}/submit/`，正式提交使用 `language/submit_content/judge_client:2/is_submit:true`，不发送调试输入或本期以外的比赛／题单参数。report 为 `/api/v2/problems/{id}/submit-report/`，仅传本次 `submission_id/is_submit:true/problem_type:6/judge_client:2`，没有再次发送源码。

执行地址必须来自本次回执；只接受已采证官网 opcenter 来源、经核实的执行操作路径、同一个执行 ID 和允许的 query。执行 pathname 已通过任务0本次人工官网提交补证，见[运行时契约](../../oj-connect/lanqiao-runtime-contract.md)；不能只因主机是 opcenter 就放行整个 API 或猜路径。遇到未知地址时保留受理不明，不自动跟随或重发。

本次实际标识是 24 位小写十六进制。首版按已采证形状作本站校验，变化时明确不支持，不能据此称平台永久固定格式；四站正整数记录规则保持各自约束。源码回读只规范 CRLF→LF，不删除末尾空白或重排程序。

报告只有在安全校验后参与当前任务展示；正式 `record` 成功仍要求详情中的 ID／problem／language／source 关联成立。详情没有 owner 时不编造 owner 核验，使用同 Session 的当前本人身份和本题本人记录作为账号证据。源码、语言或题目不匹配不能认领。

## 6. 不明、取消与生命周期

| 情况 | 首版行为 |
| --- | --- |
| source 明确未发送 | 返回 `not-sent`，用户可修正后重新发起 |
| source 已发／不能排除发出，回执没有合法执行 ID | 返回 `unconfirmed`；保留当前尝试，不猜认本人最新 AC，不重发源码 |
| 已知 ID，执行查询失败或达到本地期限 | 保留 ID 与最后真实进度；停止自动操作，继续查询只 GET，不重新启动 report |
| report 尚未 dispatch 时取消／身份失效 | 不再发送 report，不声称服务器执行已取消；已知 ID 只允许在仍有效的原上下文查询 |
| report 已 dispatch，但回包丢失／错误／无法解析 | report 权限保持已消费，只 GET 同 ID 正式详情，不重放 source 或 report |
| report 成功但详情暂时 404 | 继续有限 GET 核对；404 不是明确未受理，也不能改投新提交 |
| 正式详情可确认 | 即使 report 回包丢失也能交付该正式记录；逐点缺失如实处理 |
| 换号、存储范围变化、窗口关闭或扩展停止 | 使旧权限失效，停止本地读取；不向新会话交付旧结果，不通过新账号继续旧任务 |
| 窗口／扩展重启 | 不恢复任务、最近记录或 report；无新持久事务库，通过用户主动官网入口处理 |

自动执行／确认采用有界本地期限，沿用四站约 120 秒的跟踪体验；单个 HTTP 请求另有超时。网络请求超时不证明 POST 未送达。正式记录与发送资源分开释放，迟到结果、取消及重复释放按实例身份处理。继续查询永远不自动发 POST；尚未发 report 的中止任务也不借“继续查询”偷偷补发。

report 的重放幂等性和落库作用不作为首版成立的假设。保守的一次发送、GET 核对和明确未决可以封闭这些未知；如果以后要求自动补 report、重启续办或重新取得逐点报告，应另行采证和授权。

## 7. 共同评测体验

沿用洛谷记录页、英文判题术语、状态颜色、测试点和编译信息组件；操作提示按界面语言显示。只有真实有值的字段才显示，保留真实零值，未知判词保留原始信息。通过率不冒充比赛分数，`elapsed_minutes` 不当程序耗时，官网 kb 未确认基数前不擅自转 KiB。

当次 report 的逐点投影可附于现有当前记录内存模型：点序、通过结果、耗时、内存和有充分依据的判词。不得保存原始 `result`、输入输出、答案或隐藏测试数据；失败布尔值不能单独推断 WA／TLE 等具体原因。正式详情只提供汇总时就展示汇总；缓存丢失不为补齐逐点重新 POST，不新增磁盘报告缓存。

未取得全量数量或执行状态映射时只显示整体等待，不伪造测试点；没有编译诊断时沿用缺失说明，不制造 CE 日志。查看源码使用官网回读快照，不改当前学生源码；链接只进入内置浏览器，外部打开继续由明确 UI 动作触发。

## 8. 所有者与必要接点

| 所有者 | 本期负责 |
| --- | --- |
| 蓝桥 adapter／task | 规范题号／文件名、共同题面转换、语言语义和本站结果解释 |
| 蓝桥 SessionClient／protocol／受限传输 | 固定认证上下文、source/report 一次发送、执行与正式记录核对、取消与失效 |
| 原浏览器宿主 | 当前窗口、真实 BrowserSession、人工登录导航、固定命令和 opaque handle；不暴露任意网络或 Cookie |
| 共同领域／偏好／面板 | 只扩充真实第五站接点、本站 ID/token 校验及默认例外；不重写四站协议或共同组件 |

快捷键与提交沿用 Global／Workspace 持久会话约束；浏览器 Get／CPH 保留现有页面 Session 行为，不能因蓝桥收窄四站已有临时会话路径。蓝桥若发现额外限制，以具体证据另行说明，不复制网页登录态到另一份会话。

## 9. 验证与交付门槛
