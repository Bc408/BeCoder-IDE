# Beacon 工作区控件、草稿与重启恢复方案

日期：2026-10-15。状态：负责人确认自动淘汰规则并授权实施；实现、验证与验收分别记录。

依据：[正式 PRD](prd.md)、[架构](architecture.md)、[视觉规范](../../DESIGN.md)及本轮连续对话中的负责人最新决定。本文取代[上一轮交互方案](../superpowers/specs/2026-10-15-beacon-workspace-conversation-mode-design.md)中有关工作区控件展开、首次发送前实体、草稿与恢复的旧规则；其他产品边界仍以正式基线为准。

## 1. 解决什么问题

让工作区选择成为一个位置稳定、逐步展开的控件；让返回、新聊天、档位切换分别承担自己的作用；让用户写好的文字和附件在切换、返回与重启后按明确规则恢复。

工作区仍是一级容器，对话固定归属工作区。草稿随对话保存，复用单对话占用，不再新增“按窗口划分工作区草稿”的存储体系。窗口只维护当前页面及其引用，不取得独立草稿所有权。

负责人已确认方案并授权产品实现、自测、自行纠错与应用构建；实施计划见 [任务计划](../superpowers/plans/2026-10-15-beacon-workspace-drafts.md)。不安装新依赖、不操作 Git 写入。最终通过真实应用截图与负责人试用验收，源码测试和构建只证明各自范围。

## 3. 工作区控件

### 3.1 位置与渐进展开

主页顶部同一操作组从左至右为：工作区选择、连接设置、右上角聊天动作。工作区必须紧挨连接设置，二者之间不能有弹性空隙或其他控件。详情页隐藏工作区控件，连接设置和聊天动作仍可用；连接设置页不再提供第二个工作区入口。

控件以靠近设置按钮的一侧为固定右锚点，向左取得展开空间。设置、新聊天按钮与中部内容不因动画位移。展开作为覆盖层处理，不能因更改整组 flex 宽度推挤其他控件。

| 阶段 | 有效根 + Spot/Flood | 无根 | 已选根 + Blackout / 故障 |
| --- | --- | --- | --- |
| 收起 | 文件夹名 | “选择工作区” | 隐身圆形图标 / 红色圆形感叹号 |
| 悬停 | 整体向左展开为绝对路径 | 向左展开，显示“选择工作区”及“选择后可使用 Spot / Flood” | 保留状态图标，向左显示绝对路径及“未使用”/“出现问题” |
| 点击 | 从横向展开状态向下整体展开管理面板 | 同左 | 同左；不因打开控件而退出 Blackout |

Blackout/故障收起时仍提供“{文件夹名}未使用”/“{文件夹名}出现问题”的提示。长路径在可用宽度内中间省略，保留盘符/共享根及末级文件夹，完整路径通过统一悬停提示提供；不自动横向滚动，不挤出右侧按钮。

### 3.2 面板结构与动作

一个连续面板，由顶部当前区域、下方最近列表和底部“添加新工作区”组成：

- 有当前根：顶部是当前绝对路径，右侧 `×` 取消选择。当前根不在下方列表重复。
- 无当前根：顶部为选择提示，没有当前项 `×`；有历史则展示历史，没有历史仍有添加入口。
- 最近列表每项为绝对路径及右侧 `×`。列表项删除只移除最近记录，不删目录、`.beaconWork`、聊天或草稿。
- 当前项取消经宿主成功确认后，路径从顶部连续移入历史首项、去重，其他行顺移；面板保持打开。该操作不删除原区草稿，输入框切为临时草稿。
- 删除最近项后面板保持打开，其余行补位。
- 选择最近项后关闭面板，宿主确认切换后显示目标历史与可恢复草稿；失败不假装切换成功。
- 添加新工作区先收起面板，再打开现有系统目录选择器；取消选择器不改变原状态。

### 3.3 开合、焦点与动画

鼠标悬停只展开横向信息，点击才向下打开列表；离开控件与面板整体后关闭。移动到下方列表的路径属于连续交互区，不因短暂经过接缝而收起。键盘焦点在面板内时，鼠标离开不强行关闭；Esc 关闭并归还焦点。触屏/键盘不必先制造 hover，直接操作可到达完整面板。

工作区、权限和模型浮层互斥。复用成熟焦点/定位机制与项目共享 tooltip，不为这次效果新增完整 UI 框架。

动画遵循 DESIGN.md 的轻量方向；具体曲线、时间和图标形状属候选细节，需视觉样例调整。先保证固定锚点、连贯重排和不推动正文，再微调数值。动画可中断，不排队演示过期状态；Blackout 下的持久化内容先隐藏，不为退场动画延长显示。减少动态效果时即时更新状态且保留焦点。

## 4. 草稿对象与占用

### 4.1 一份对话、一份当前输入

持久化对话的输入草稿包括未发送文字与已采集附件内容。不能只存附件路径，否则源文件变化或删除会让重启恢复失真。发送复用已采集材料，不重新读取外部文件，不扩大已有授权。

已有聊天的草稿保存到该聊天。主页首次输入文字或成功添加材料时，建立归属当前工作区的草稿对话；草稿对话没有已发送消息，不进入历史列表，也没有“草稿列表”或额外标签。第一次发送后，同一实体转成正式历史聊天，不另建一份 ID 或复制材料。

空白主页不立即创建实体。单纯聚焦、hover 或点击展开菜单都不创建实体；输入过程以实际输入内容为准，不能因输入法尚未提交而发起模型请求。文字全部删除且附件为空可保留内部空状态或移除未发送空实体，用户可见效果必须是明确空白，不能复活旧内容。

输入文字和添加材料都受现有单对话占用保护。两个窗口可分别拥有不同草稿对话，不能共享同一草稿对话写入；无需引入“窗口草稿文件夹”或按窗口永久分区。

### 4.2 主页与详情可以各有草稿

一个窗口可以有一份暂存的主页草稿引用和当前详情引用，但只对当前真正打开的对话持有占用。离开对话时先保存草稿，再释放租约；回来时重新取得占用。保存的草稿不是持续占有多个对话的理由。

进入已有详情前保存主页草稿；返回主页先保存当前详情草稿，随后恢复主页草稿。若待恢复草稿已被另一窗口占用，遵循不抢占原则显示空白主页，后续输入新建独立草稿；不覆盖或删除被占用实体。

同根 A、B 两个窗口分别输入时形成不同草稿，不会因相同工作区路径或空 activeId 相互覆盖。无需显示草稿选择列表。

### 4.3 工作区与 Blackout

| 操作 | 草稿结果 |
| --- | --- |
| A 根切 B 根 | 保存 A，恢复本窗口已关联的 B 草稿；没有本窗口引用时按该根可用恢复位置处理，不复制 A 的内容 |
| B 切回 A | 恢复 A 对应草稿；若被占用，不抢占 |
| Spot 切 Flood 或反向 | 保持当前对话与草稿，不另建副本 |
| Spot/Flood 进入 Blackout | 保存原工作区草稿，退出持久化消费，切独立内存临时草稿；不自动带入原材料 |
| Blackout 恢复 Spot/Flood | 恢复对应工作区草稿；临时内容不自动转存 |
| 取消根 | 原区草稿留原区，切无根临时草稿 |
| 根失效 | 不写替代存储，不伪称最新草稿已保存；退出持久化页面，保留必要的尚未保存内存内容用于如实反馈和后续恢复 |

Blackout 临时草稿包含无根与已选根但未使用的情况，均不落盘。原区草稿已保存不代表 Blackout 期间可以读取它；恢复需等待有效根和 Spot/Flood。主动切换需先完成必要保存，失败则保留原输入并反馈，不先清空界面。

## 5. 返回与右上角按钮

右上角按钮根据页面和主页草稿变化，不与“返回”无条件共用清空动作。

| 所在页面 / 状态 | 文案 / 图标 | 点击结果 |
| --- | --- | --- |
| 详情，主页有草稿 | “已有未发送草稿”，区别于新聊天的图标 | 保存详情草稿，回主页恢复主页草稿，不清空任何一份 |
| 详情，主页没有草稿 | “新聊天”，普通新聊天图标 | 保存详情草稿，回空白主页 |
| 主页，有或无草稿 | “新聊天”，普通新聊天图标 | 清空主页文字与附件，删除对应持久化草稿；保留正式历史聊天 |
| 详情的返回按钮 | 返回图标 | 保存详情草稿，回主页恢复已有主页草稿；与“已有未发送草稿”到达同一状态 |

“已有未发送草稿”点击一次回主页后，同位置恢复“新聊天”；再点一次才明确清空主页草稿。不能在第一次点击时暗中丢弃主页输入，也不能清空原详情的未发送内容。

按钮保持原点击区域与位置，状态变化只换图标和可访问名称；具体替代图标在视觉样例中选择。忙碌和保存交接继续执行既有宿主边界，不通过 UI 隐藏绕过。

## 6. 跨重启与多窗口恢复

### 6.1 已确认的规则

工作区以最后关闭窗口留下的页面和输入状态作为下次默认恢复目标：页面可以是主页，也可以是已有对话详情；草稿直接回填输入框，看起来像刚输入好，不显示草稿标签。

“最后关闭”不是最后输入、最后保存完成或最后聚焦。最后关闭窗口的输入为空，就恢复空输入框，不寻找更早的非空草稿。空白是显式恢复状态，不能用缺少记录或“搜索最近草稿”代替。

| 关闭顺序与状态 | 下次默认恢复 |
| --- | --- |
| A 有草稿先关，B 有另一份草稿后关 | B 的页面、对话及草稿 |
| A 有草稿先关，B 空白主页后关 | 空白主页，不回退 A |
| 最后关闭时在详情且有草稿 | 该详情与其未发送文字/附件 |
| 最后关闭时在详情且输入为空 | 该详情与空输入，不读取其他草稿填充 |
| 恢复目标被其他窗口占用 | 静默回主页，输入保持安全空白；不提示、不抢占、不寻找别人的替代草稿 |
| 窗口 A 正使用恢复目标，窗口 B 打开同根 | B 显示空白主页，可建立独立草稿对话 |

自动恢复遇占用静默处理，不等于撤回“用户主动点击已占用历史聊天时说明被占用”的既定规则。

工作区选择仍按窗口记住；工作区内默认恢复位置按本节共用。不会因为默认恢复指针更新而热切换其他仍打开窗口的输入或页面。

### 6.2 已确认的实现方式

草稿正文、附件归对话；工作区只保存一个轻量恢复引用：目标页面、对话引用或明确空白，以及宿主分配的关闭顺序。无需复制整份输入到恢复索引，避免两份数据不一致。

关闭先由宿主确定顺序，再完成待保存草稿与恢复引用，最后释放占用。按顺序检查更新，防止 A 先关但慢保存，反过来覆盖 B 后关的结果。不能靠文件 mtime 或渲染器自报时间裁定顺序。

窗口关闭、Webview 隐藏/销毁、扩展停用、重载和异常退出必须分别识别。不能把每次 Webview dispose 都算成“最后关闭窗口”。复用 Code-OSS 的实际窗口生命周期接点与已有关闭交接，不能仅依赖卸载时最后一条 postMessage。

草稿随输入节流保存，在切页、切根、切档位和关闭时完成最终交接。保存请求携带目标对话及 revision；晚到的旧输入不得写入切换后的对话。发送清空与用户随后输入的新草稿必须按版本区分，不能由较晚的发送确认清掉新内容。

首次发送被宿主接受后才清除所发送版本的草稿；模型网络失败不等于消息未被接受，不应重新恢复已成为消息的输入。宿主尚未接受的发送失败保留草稿。

若根不可写/消失，保留上次已成功保存的恢复状态并如实反馈本次未保存，不能宣称已经可靠复现最后输入。异常断电只能恢复最后成功持久化内容，不承诺未完成写入或无法确定的真实关窗顺序。Blackout 不写根内恢复引用或草稿；只由窗口原有选择/模式恢复机制处理，绝不从其临时输入生成持久化记录。

## 7. 未发送主页草稿自动淘汰

负责人已确认：A、B 不同草稿分别保存，默认只恢复最后关闭的那份；不新增草稿列表。由此会出现“较早关闭窗口留下的未发送草稿实体已保存，但当前没有 UI 引用”的情况。

负责人已明确允许自动淘汰：用户只关注最后关闭时的输入，冗余输入历史无长期价值。因此，保留最终恢复目标及仍被活窗口占用或引用的未发送主页草稿，淘汰其他不再引用的旧草稿，不新增找回入口。最后关闭状态为空时，旧非空主页草稿也不能成为替代恢复目标。自动淘汰不作用于已发送聊天或其中的未发送输入，不删除用户原始文件、笔记或记忆。

## 8. 技术职责与复用边界

推荐路线是扩展现有对话存储与租约，而不是继续叠前端 Map，也不是另起全局草稿库。

| 路线 | 能解决什么 | 问题 |
| --- | --- | --- |
| 仅 Webview Map / 本地 UI 状态 | 同页短暂切换 | 跨重启与附件保存不足，不能作为占用权威 |
| 独立按窗口草稿库 | 容易按窗口隔离 | 重复身份与清理体系，不符合本轮已否决方向 |
| 现有对话存储 + 草稿阶段 + 工作区恢复引用（推荐） | 统一附件、revision、占用、首次发送和恢复 | 需把导航、草稿保存、窗口关闭顺序接通并验证 |

Webview 只维护呈现状态、输入反馈和动画；扩展负责意图分发与快照；原生协调者负责根有效性、占用、草稿/对话保存与关闭排序。租约标识、草稿阶段和恢复引用的具体字段进入实施计划，不在产品文档冻结协议。

不新建通用事务平台，不做开发期快照迁移兼容，不影响用户已发送聊天、笔记、记忆和独立资产。新增附件删除只针对明确清空的对应未发送草稿专属内容，不能删已发送消息引用或原始用户文件。对话草稿不得成为模型跨会话检索入口。

本方案不引入外部依赖或第三方源码复制；视觉参考为负责人录像与已有 DESIGN.md，复用现有 React、Code-OSS、共享 tooltip 和项目存储实现，其现有许可证责任保持。

## 9. 实施顺序与验证方案

已授权实施按三个依赖步骤组织，每步完成回归后再推进：

1. 草稿/对话底座：统一文字与附件，加入未发送阶段，复用租约，拆返回/恢复/清空动作，验证发送竞态。
2. 工作区恢复：切根/Blackout 草稿交接，接入真实关窗流程，最后关闭与显式空白，双窗口占用与恢复。
3. 控件与动画：主页唯一相邻入口，悬停横向/点击向下，状态形态、当前项移入、互斥浮层；自行查看截图与录像后迭代样式，收敛旧覆盖规则。

实施范围只涉及这些路径的必要代码、测试与文档。Notebook、四平台 OJ、teach tips、模型供应商、联网策略和源文件执行能力不因本次 UI/草稿工作改造或缩水。

| 验证层 | 必须覆盖 |
| --- | --- |
| 原生/存储 | 草稿不进历史、首次发送原实体转正、单对话占用、两个独立草稿、附件内容恢复、显式空白、关闭排序逆序完成、旧 revision 拒绝 |
| 扩展集成 | 返回不清草稿、主页新聊天真清空、详情按钮动态、切根不串材料、Blackout 不落盘、自动恢复占用静默、保存失败不假成功 |
| 交互渲染 | 相邻位置、向左后向下、无根说明、Blackout/故障路径、长路径中间省略、面板移入动画、鼠标接缝与键盘焦点、互斥/边缘避让 |
| 真实双窗口 | A/B 分别输入，按两种顺序关窗；最后空白；同时重开；目标被占用；同根共享恢复指针不修改其他活窗口 |
| 真实生命周期 | 关闭窗口与隐藏面板区分、扩展重载、应用退出、草稿保存中关闭、根失效与恢复 |

| 回归与构建 | 当前聊天读写、附件、流式/停止/续答/重答/编辑、页面与文件权限、Notebook 入口；完成源检查后按仓库流程完整构建 |
