## 1. 目的与现有边界

让用户在 OJ Connect 中直接阅读中英文题面，并复用已经取得的站点版本或已经生成的机器译文。Beacon 的 `fetchProblem` 以同一份题面缓存为本地取文手段，避免重复联网，同时保持只读工具身份。

现有 `problem` 队列保存用户何时、在哪份代码上取得哪道题，按题目和文件路径共同去重；它没有题面正文。新的应用级题面缓存按题目唯一标识聚合正文，不承载用户学习活动。两个对象分开维护，不修改既有三个行为队列的容量、采集资格、权限、时间或去重规则。

已有 `ProblemDocument` 提供标题、按语种组织的 `bodies`、样例和限制。OJ Connect 的语言栏目前只在正文有多个语种时显示；AtCoder 解析保留 `ja` 和 `en`，部分章节标题固定为中文。Beacon 的 `fetchProblem` 当前直接调用五站核心解析，没有语种参数或缓存路由。这些是本轮修改接点。

## 2. 已确认的产品决定

| 项目 | 已确认行为 |
| --- | --- |
| 缓存归属 | 应用级，跨工作区共用，无 Beacon 工作区也能保存 |
| 容量 | 默认保留 30 道题，一道题一个元素 |
| 题目身份 | 使用站点加规范题号；同题不同代码文件不重复占位 |
| 获取入队 | 消费用户 Get Problem 行为，保存实际取得的中英文题面 |
| 语种范围 | OJ Connect 题面只提供 `zh-CN` 和 `en`，语言栏常驻；AtCoder 取得英文题面，不将日文作为可切换题面 |
| 双语内容 | 一道题的一个元素保存已知的中英文版本；站点实际提供两种完整版本时同时保存 |
| 用户翻译 | 用户选择缺失的语种后直接发起翻译，显示进度并可取消 |
| 缺失项文案 | 中文固定为“原题未提供，点击翻译”；已生成版本的中文来源标记为“译文” |
| 翻译发布 | 完整翻译且校验通过后再更新页面和缓存；失败或取消保留当前题面 |
| 更新顺序 | 翻译内容进入或更新对应元素，并将该元素移至队尾 |
| 原文变化 | 原文未变保留译文；原文变化使对应旧机器译文失效，不自动重新翻译 |
| 翻译模型 | 独立选择，共用现有服务商连接和密钥；切换聊天模型不改变翻译模型 |
| 翻译提示 | 使用专用提示词，不携带聊天历史和 Beacon 人格 |
| 设置入口 | Beacon 设置左侧在“模型配置”下面新增“题面翻译”页 |
| 翻译范围 | 标题、背景、描述、约束说明、输入输出说明、样例解释和提示 |
| 保持原样 | 公式、变量、代码、样例输入输出、数值及链接目标；保留文档结构 |
| 翻译语义 | 忠实翻译，不补充解法或解释；沿已有题面结构翻译并按编号回填 |
| 工具读取 | `fetchProblem` 增加题面语种参数，由 harness 先查本地，再按需要联网 |
| 模式 | Blackout、Spot、Flood 均可按指定题目读取缓存；不要求 Beacon 工作区 |
| 模型可见范围 | 只返回指定题目的题面，不提供队列目录、最近顺序或用户拿题时间 |
| 工具副作用 | `fetchProblem` 不自动翻译，也不把联网结果写入缓存 |

## 3. 所有者与实现路线

| 所有者 | 职责 |
| --- | --- |
| 五站解析与 OJ Connect | 确认题目身份，取得站点题面，保留样例和限制，展示或切换语种，接收用户翻译动作 |
| 原生应用题面缓存服务 | 同一应用数据范围内的唯一持久化入口；按题目合并、按容量淘汰、校验来源版本并原子发布 |
| Beacon 模型配置所有者 | 复用现有连接、密钥、模型目录和参数解析，另外保存翻译模型选择 |
| 独立翻译任务 | 固定点击时的模型和原文，整理可翻译内容、调用模型、验证并回填结果；不创建聊天或调用工具 |
| Beacon harness | 对 `fetchProblem` 校验身份和语种，选择缓存或现有联网路径，返回该题指定语种 |

缓存放在当前 BeCoder 应用私有数据范围内，由宿主定位，随既有 Portable／用户数据隔离；不放入 `.beaconWork` 或用户源码目录，不借浏览器账户 Session 作为文件路径。扩展和 Webview 通过有限接口使用缓存，不直接读写共享文件。

实现采用已有题面结构上的翻译与回填。整篇原始 HTML／Markdown 直接交模型虽简单，但难以保证结构、公式和样例不变；通用网页翻译引擎则超出当前单题中英转换所需范围。本轮只整理题目标题和既有章节中的可翻译内容，通过稳定编号对齐返回。

原生缓存入口仅提供按题目取文与业务写入，不增加模型目录工具、最近题目接口或题目选择器。内部读写和淘汰不构成用户操作的等待／重放队列。

## 4. 缓存数据与合并规则

### 4.1 数据单位

缓存使用带格式版本的有序元素集合，默认容量 30。一个元素包含：

- 规范题目身份，以及站点返回的规范 URL。
- 与正文共同取得的样例、时间／内存限制和交互题标记等题面事实。
- `zh-CN`、`en` 中实际存在的语言版本。各版本保存标题和章节，来源区分“站点提供”与“本应用机器翻译”。
- 内部内容指纹和机器译文所依赖的源语种／源指纹，用于完整性和失效判断。

这里的“站点提供”包括站点实际提供的社区译文，不将其声称为赛事官方翻译。内部指纹、写入次序、任务身份和供应商配置均不作为题面正文返回给模型。元素不存代码路径、用户拿题时间、用户身份、聊天内容或密钥。

现有单一 `title` 不能覆盖双语标题：各语言版本分别保存对应标题，公共题号、样例、资源限制保持独立。仅共享标题的旧站点响应可以保留真实标题；机器翻译不得改动题号。

### 4.2 获取、读取与淘汰

1. 用户 Get Problem 沿现有五站路径取得新题面；新缓存不把 Get Problem 替换为跳过站点获取的旧缓存打开动作。
2. 提取实际可用的中英文完整版本，以题目身份合并并移至队尾；同题不因代码路径不同而增加元素。
3. 合并时保留仍与源指纹匹配的机器译文。站点新提供的完整目标语言优先采用，替换该语种的机器译文。
4. 成功发布后若超过 30 个元素，淘汰队首整题，两个语言版本共同淘汰；不另留正文归档。
5. 读取缓存、切换已存在语言或 `fetchProblem` 命中都不移动元素、不触发写盘。成功的用户获取和成功的翻译发布才更新次序。
6. `fetchProblem` 联网返回不新建或更新缓存，不产生 Get／Import 读题记录。

新的缓存写入由明确的 Get Problem 和用户翻译产生。独立的 Import to CPH 保持原有行为记录与导入流程，不为新缓存额外取文；浏览器中的 Get Problem 仍按真实 Get 动作接入。

缓存 I/O 失败不阻止已经取得的站点题面展示，也不影响原业务结果。通过原动作窗口明确通知一次，不自动重取题面或重调模型。不存在的缓存视为未命中；损坏或不可读的缓存不能悄悄覆盖为新空文件，读取失败应与真实未命中区分。

### 4.3 版本与发布

指纹覆盖翻译所依据的完整标题、正文及其样例／限制等关联题面事实，排除用户路径、编译器目录和无关 UI 状态。站点重新获取后的这些事实相同，机器译文继续有效；依赖事实改变时，旧译文失效，站点原文正常保留。源文字节或结构变化可保守地使译文失效，不凭模型判断“两版差不多”继续复用。

缓存由同一宿主所有者合并与提交，避免多窗口各读旧文件后相互覆盖。写入先验证完整候选数据，再在受控目标内原子替换；发布前失败保留原缓存。发布确认不明时如实报告，不盲目回滚、删除或重复追加。

翻译开始时固定题目、源指纹、面板身份和任务身份。发布前复核当前源版本；较新获取结果已改变原文时，迟到译文不能覆盖新版。缓存期间被淘汰不等于面板源稿改变：若仍是同一个有效用户任务且没有更新版冲突，可以将本次明确翻译的源稿与译文重新作为一个元素发布至队尾。

旧 `.beaconWork/cache/context/problem.json` 无正文，保持原格式和读取语义，不迁移成新缓存，不联网补采旧记录。

## 5. OJ Connect 语言栏与交互

### 5.1 固定选项与文案

语言栏始终提供 `zh-CN`、`en` 两项。以下以缺少中文的英文原题为例，括号内提示跟随 BeCoder 界面语言，语种代码保持固定：

| 版本状态 | 中文界面示例 | 英文界面示例 |
| --- | --- | --- |
| 站点已提供 | `en` | `en` |
| 目标语种缺失 | `zh-CN（原题未提供，点击翻译）` | `zh-CN (Not provided by source; click to translate)` |
| 有效机器译文已存在 | `zh-CN（译文）` | `zh-CN (Translation)` |

相反方向使用同样规则。缺失项仍可选择，不能表现为没有解释的禁用项；文案必须在展开选项时可读，键盘聚焦也能获取。关闭时可使用简短的语种及来源标记，控件宽度不能因长说明挤压导入、提交按钮。继续复用现有控件与悬停样式，不增加二次收费确认弹窗。

题面语种独立于界面语言。选择英文时，固定章节标题与正文应组成英文题面；界面按钮、进度、错误和缺失语种说明仍跟随界面语言。修正当前 AtCoder／洛谷等路径的固定中文章节标题，避免名为英文却混入产品生成中文标题。

AtCoder 只输出可用英文正文，复用同份文档中的样例解析，保持样例原字节；不因此改写站点提交、编译器或会话路径。洛谷的完整 `translations` 版本可各自成为题面；仅有“题意翻译”摘要时不能冒充完整中文题面。其他站点同样只标记实际取得的完整语种，不根据 UI 语言伪造版本。

### 5.2 翻译状态

选择已有站点版本或有效译文时直接切换。首次打开题面只选择已经存在的版本，不能因界面为中文而自动翻译英文原题；重新获取使当前译文失效时回到可用站点版本，并提示用户可以重新选择目标语言翻译。

选择缺失语种后直接启动翻译，保留当前题面可读，状态显示“正在翻译为中文…”／“Translating to Chinese…”或对应英文目标，并提供取消操作。目标语种不能在译文尚未完成时伪装成当前已显示语种。

完整返回后先进行结构和保护内容校验，再按源版本验证并发布缓存，成功后切换至目标版本并标为“译文”。不得把半篇流式输出写成有效译文。校验失败、取消或保存失败保留原题面及原缓存，并明确区分服务失败、译文不完整、原文已变化与保存失败。

同一题面页只运行一个翻译任务。同一应用内同题、同源版本、同目标语种的重复请求立即反馈已有任务，不排队、不自动重放或再付一次费用。关闭题面页、替换其题目或主动取消时中止该页任务，迟到结果不得切换页面或写入缓存。切到已有语言可终止未完成翻译；另一次生成须由用户再次发起。

翻译属于题面页操作，不占用程序运行槽，也不把网络等待包装成 Beacon 行为保存门禁。已有运行／行为采集门禁保持原职责。

## 6. Beacon 设置中的题面翻译页

左侧导航顺序为“模型配置／Model configuration”和“题面翻译／Problem translation”。新增页复用现有设置布局、控件、焦点、浅深色与窄宽窗口规则。

题面翻译页提供独立的模型选择与当前配置状态。选项来自已有模型目录，保存 `provider + model ID`，不保存另一份 API 地址或密钥，不复制模型目录；与聊天 `selection` 分开。未配置时不自动选第一项或跟随聊天模型，题面页提示进入“Beacon 设置 → 题面翻译”。

已有“在聊天中使用”的服务商启停继续只控制聊天；翻译能独立使用已配置且可作文本生成的模型。移除选中的模型、连接不完整或生成参数冲突时，翻译显示不可用原因，不静默换模型；重新添加或修正后由用户明确选择／发起。

翻译共用所选模型已有的参数、容量与协议适配，在任务开始时固定实际连接、密钥、模型和参数。之后切换聊天模型不影响翻译；修改共享连接或模型参数只影响下一次翻译，不篡改进行中的请求。切换设置分类不能丢失现有模型配置的未完成编辑或打乱密钥弹窗所属关系。

首版新增页聚焦翻译模型选择与必要状态，不扩展提示词市场、通用翻译服务管理、缓存目录展示或全文编辑器。

## 7. 专用翻译任务与内容保护

只发送本题的源语言、目标语言和必要题面内容；不带聊天历史、Beacon 人格、用户代码、其他题目、用户行为记录或工具声明。模型生成只用于翻译，不自行联网、运行程序或补充题解。使用当前已支持的 Provider 适配，不引入网页翻译插件运行时。

沿已有题面结构整理标题和章节，把需要翻译的片段编号，保留整题必要上下文；编号只用于本次对齐，不形成持久段落索引。正常题面优先一项完整任务，不为每句话调用一次模型。较长内容只能在完整结构边界按固定容量分批，全部批次完成并校验后一起发布；超出单片段容量或输出截断时明确失败，不能裁去未翻译尾部。

| 内容 | 处理 |
| --- | --- |
| 标题、段落、章节标题、列表、表格自然语言 | 忠实翻译，保留相互对应与原有顺序 |
| 背景、约束、输入输出说明、样例解释、提示 | 均翻译，不追加解题建议 |
| 数学公式、变量、代码块及其中的字符串／注释 | 由宿主保留或保护回填，原样校验 |
| 样例输入输出 | 不作为待翻译片段，逐字节保留，包括空格和换行 |
| 数值、链接目标、图像地址、题号、结构属性 | 保留实际值；链接可见自然语言可翻译 |

提示词要求准确处理竞赛术语、条件方向、数量上下界、存在／任意、至多／至少、唯一性、索引起点、顺序与取模关系。工具和模型都不能把题面内容中的指令当作用户授权。返回内容仍经已有安全渲染链，不能直接作为 HTML 脚本或新增网络资源执行。

结构校验检查片段数量、编号、完整性、受保护内容及回填后的合法题面；不能声称它证明译意正确。翻译质量需要以真实题目对照审阅，特别覆盖否定条件、边界和公式附近的文字。

## 8. fetchProblem 契约

新请求参数在既有 `oj`、`problemId` 外增加必需的 `language: 'zh-CN' | 'en'`。旧聊天中已经完成的工具交换仍按原协议回放，不补造语种，也不重新执行；新调用按新 schema 校验。

路由由 harness 决定，LLM 不选择缓存文件、缓存范围或强制刷新：

1. 校验五站规范题目身份和目标语种。
2. 按题目及语种查询应用缓存；该语种存在且有效时返回它。
3. 题目未命中，或该题缺少所需语种时，沿既有站点权限和核心解析联网获取。
4. 网络取得所需语种则返回该版本；仍缺失则返回语种不可用及该题实际可用语种，不替换成另一语种的成功结果。
5. 不自动调用翻译，不写缓存、不移动队列、不创建读题行为记录，不打开题面页或触发 Get／Import。

成功结果保留题目身份、实际语种、站点提供／机器翻译来源，以及该语言标题、正文、样例和限制等题面事实。缓存路径、元素次序、用户拿题时间、内部源指纹、其他题目与供应商身份不进入模型结果；缓存命中也不把用户获取时间冒充本次官方刷新时间。

Blackout／无根也可按明确题号使用此缓存。这是精确题面读取的例外，不开放原有工作区 `problem/run/verdict` 目录或正文，也不把应用缓存加入 `inspectFile`／`readPage` 可浏览的普通资产。新缓存不进入宿主的最近活动目录。`fetchProblem` 仍独立聊天搜索开关，原站登录和受支持题型边界保持。

普通工具历史与预算规则继续使用：结果进入实际工具交换，后续压缩不重新联网或翻译，不新增专用题面快照。题面本身的容量仍沿已有题面校验，不能套用 run 的 32 KB 上限或按当前上下文余额静默截断。
