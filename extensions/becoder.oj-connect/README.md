# OJ Connect

BeCoder 内置刷题扩展，接入洛谷、AtCoder、Codeforces、牛客 ACM 和蓝桥公开普通 C/C++ 练习。五站均已获得负责人核心闭环确认，2026-11-20 的 2.1.0 Setup 整体验收也已通过；具体站点范围、语言例外与验证边界见下文及[交付记录](../../docs/oj-connect/release-2.1.0-regression.md)。扩展依赖 BeCoder 的浏览器宿主；标准 VS Code 不提供这些私有业务接口。

题面和评测页的标题、所属题目及正文 HTTPS 链接统一在内置浏览器打开，页内锚点仍在当前题面跳转。扩展不自动打开外部默认浏览器；需要外部打开时，用户可在内置浏览器选择明确标注的外部浏览器动作。查看记录源码在本地文本编辑器打开快照，保留记录页滚动位置。

侧栏蓝桥下方的 **ACM 模式** 默认关闭，选择写入个人设置，跨项目和重启保留。开启后，五站题面隐藏难度与标签，评测页隐藏难度颜色、分数、测试点及数量／编号进度、编译详情（CE 仅显示 Compile Error）；保留整体评测状态、语言、提交时间、代码长度、总用时／内存、源码入口及查询失败后的恢复操作。已打开页面即时同步；关闭后恢复完整展示。模式仅调整显示，不改变交题、结果查询或 CPH 行为，官网正文及内置浏览器网页仍按原站展示。

再次看题仍重新读取官网内容；已有同源码、同题目面板同步替换标题、正文、样例及元数据，提交和 CPH 操作使用同一份当前文档。AtCoder 采用保存的英／日偏好，缺失语言仅对本题回退；其他站保留仍有效的当前题面语言。评测读取失败会停止等待显示、保留最后真实结果并提供原记录的继续查询，不引导重交；首次尚无结果时明确显示“暂未读取到评测结果”。

聚焦 C/C++ 源码，**Ctrl+Alt+P** 查看题面，**Ctrl+Alt+S** 主动提交当前编辑稿（含未保存内容），并查看本次评测。蓝桥从准备阶段先显示共同评测页，正式 ID 确认后同页接管记录；其余站点确认正式 ID 后打开记录页。五站题面显示 C／C++ 编译器，按绑定源码语言族筛选，快捷键沿用相同选择。AtCoder、CF 未登录时也可从已采证目录预选；来源在悬停说明中标明，登录后自动刷新，提交前以当前官方目录为准。洛谷使用内置浏览器同一持久会话直接请求，常规操作无需保留网页；验证码按上游图片面板输入，留空刷新。AtCoder 按快捷键才建立本次官网提交页，正常验证后将源码直接放入完整表单请求发送一次，共用持久登录，不覆盖用户已有网页草稿；取得正式回执即释放任务页，结果查询独立进行；快捷键提交、受理核对和结果跟踪全程不自动显示网页。未登录时提示从侧栏主动登录；准备阶段未发送的请求可在登录后重新发起；原站验证在后台自动就绪时继续同一任务，若在期限内仍需人工验证则结束尚未发送的任务并提示主动到内置浏览器手动提交。保留用户自行打开的网页。

牛客仅接入公开 ACM 标准输入输出题及已结束、公开、个人可提交的比赛题。常规题面、编译器、单次发送和结果使用同一原生 Session，不创建网页；验证码拒绝提示主动到内置浏览器手动提交。题霸函数模板题、PAT、进行中／私有／团队／付费比赛及未核准题型不支持，不切换到另一判题通道。缺少正式分数、代码长度或测试点时省略，不将通过率当分数；“本次提交源码”指本地实际发送的快照，不表示已回读官网源码。牛客评测状态和悬停说明沿用洛谷风格英文术语。

CF 仅支持 `codeforces.com` 普通公开比赛题的赛后练习。宿主核对当次官方表单的 Finished／Practice 与题型信息，拒绝 output-only；Gym、进行中比赛、虚拟参赛、group、私有／团队及镜像入口不在范围内，也不静默转换。准备、一次原生 POST、回执核对与结果读取共用当前窗口及存储范围的持久 Session，不创建或导航提交页，不预热。只有新记录的账号、题目、编译器及官网回读源码唯一匹配才确认正式 ID；受理不明只核对，不自动重交。题面复用 CPH 解析和共同内容管线；评测保留 `Running on test 18` 等原站进度，显示实际返回的测试点，并为明确报告的当前测试点显示洛谷样式蓝色卡片与白色转圈，不推测总数或补造先前结果。测试点悬停仅显示英文结果说明及实际退出码，不包含输入、输出、答案或 checker 内容。总用时取同一记录、同一终态的官方列表值；总内存优先采用该列表的非零值，缺失或为零时使用已返回测试点的最大内存兜底，不推定测试点已全部公开。测试点内存保留精确字节到显示格式化时再换算。若详情先结束且资源仍缺失，最多补读一次列表；仍不可得的字段分别省略，保留真实零值。缺少分数或代码长度时省略，CF 不显示用户字段。

CF 官网完整表单明确报告重复源码时，提示该题已提交过完全相同代码、本次未生成新记录，并结束本次尝试；不再提供该尝试的“继续查询”，也不使用旧 AC 作为新回执。未知响应仍保留受理不明和只读核对。

AtCoder 题面首次默认英文，主动选择的日／英偏好跨题、跨重启保留，缺失时仅对本题回退。五站分别按 C／C++ 保存本站编译器标识，互不覆盖；同一站点的题面和快捷键使用同一选择。无偏好时，洛谷、AtCoder、CF 和牛客统一从当前目录选择默认项：以 C++20／C17 为基准，优先 GNU/GCC、O2 和 msys2，组合偏好不能满足时向更高标准查找；同等条件选择较近的标准及较新的编译器版本。蓝桥保留本站 C++17／唯一 C 选项例外。除该例外外，明确低于基准的选项不自动选择；未标明标准的官网选项仅作最后候选，保持原名，不根据编译器版本猜测标准。已有有效偏好优先，失效或格式错误的偏好保持未选择，要求明确更换。看题时的默认选择不写入设置，用户选择或实际提交时才保存；实时目录不固定版本或语言 ID；内置采证目录用于未登录预选，不承诺当前仍可提交。输入格式保留数学排版；样例输入／输出采用双栏，对应说明置于该组下方。

五站题面统一使用“时间限制”“内存限制”“题目难度”“题目标签”，限制值沿用洛谷的简洁单位格式（如 `2.00s`、`256.00MiB`），有语言区别时仅采用 C/C++；无法确认的值省略。难度和标签保留站点特色，缺失不显示。CPH 和提交按钮仅显示图标，悬停和无障碍名称保留动作说明。

内置浏览器的 OJ Connect 分体按钮固定执行 **Get Problem**：按当前题页在工作区的站点子目录创建／打开 `.cpp`，同时打开共同题面，不自动初始化 CPH。右侧菜单保留 **Get Problem** 和 **Import to CPH** 两项；主按钮不支持当前页面时置灰，箭头仍可展开。Import to CPH 继续使用 Competitive Companion 解析页面；已接入站点支持题目采用相同站点目录和 adapter 文件名，其他题源保留 CPH 默认行为。

题面上的 CPH 图标将结构化样例关联到该题面绑定的源码。两种 CPH 入口复用同一文件，已有源码和未保存稿保留，仅新建源码执行 CPH 模板；替换已有样例仍需确认。缺失限制会在 CPH 明示使用本地默认限制，不伪造网站数据。

Beacon协作的[下一阶段设计](../../docs/beacon/foundation-design.md)将用户Get Problem／导入／提交取得的事实与模型只读取材分开：正常所选Beacon根内三档持续采集，Blackout仅禁Beacon消费；题面保存与模型联网结果各守生命周期。模型不获得登录、提交、改写学生源码或完整Get／Import副作用。当前仍使用打开题面／判题页投影，新队列和只读题面工具的[实现差距](../../docs/beacon/implementation-status.md)单列，不影响本扩展已有用户流程。

`becoder.ojConnect.directories` 默认 `luogu`、`codeforces`、`atcoder`、`lanqiao`、`nowcoder`，设置修改不会移动已有文件。直接父目录优先，再猜文件名；失配提示输入，不建持久绑定库。例：`luogu/P1001.cpp`、`codeforces/4_a.cpp`、`atcoder/abc086_a.cpp`、`lanqiao/254.cpp`、`nowcoder/18204.cpp`、`nowcoder/5657_A.cpp`；牛客保留公开题库／比赛身份，无站点目录时不从纯数字或通用比赛文件名猜测牛客，目录外纯数字文件名也不认领蓝桥；显式上下文例 `P1001@123.cpp`、`tenka1-2019-beginner@tenka1_2019_a.cpp`。CF 身份 `4/A` 对应 `codeforces/4_a.cpp`，真实题号后缀保留为 `4_a1.cpp`；站点内支持 `4/A`、`4_a` 和普通官网 contest／problemset URL，通用下划线文件名不在目录外自动猜成 CF。无目录的 `AT_abc086_a.cpp` 有歧义时提示，不静默选站。

设置页搜索 `OJ Connect` 可调整以下设置。编译器与题面语言是跨项目的个人设置，页面选择写入对应设置，不另存隐藏偏好：

| 设置（前缀 `becoder.ojConnect.`） | 用途 |
| --- | --- |
| `acmMode` | 五站统一的 ACM 精简展示；侧栏勾选后跨项目及重启保留，默认关闭 |
| `luogu.cCompiler`、`luogu.cppCompiler` | 分别保存洛谷 C／C++ 的语言 ID，含本站支持的 `:o2` 后缀 |
| `atcoder.cCompiler`、`atcoder.cppCompiler` | 分别保存 AtCoder C／C++ 的数字语言 ID |
| `codeforces.cCompiler`、`codeforces.cppCompiler` | 分别保存 CF C／C++ 的数字语言 ID，从当次官方表单选择 |
| `nowcoder.cCompiler`、`nowcoder.cppCompiler` | 分别保存牛客 ACM 的数字语言 ID，题面与快捷键使用实际目录 |
| `lanqiao.cCompiler`、`lanqiao.cppCompiler` | 分别保存蓝桥本站 `c`／`cpp` token；首次使用官网唯一 C／C++17 选项 |
| `atcoder.statementLanguage` | 默认英文 `en`，可选日文 `ja`；本题缺失时仅临时回退 |
| `panelLocation` | 新题面／评测页的位置；默认 `auto` 复用源码右侧编辑组，否则并排；已有面板不移动 |

AtCoder、CF 题面先显示，编译器目录后台只读各自官方提交页，不建立提交事务或读取本人提交列表；关闭或重开面板会取消旧目录请求。未登录或目录暂不可读时仍显示已采证选项，登录后自动读取当前目录。CF 的采证选项来自此前官方表单，AtCoder C++23 来自实交采证，C23 名称来自官方规则页；尚未核实的 C23 数字 ID 不猜测，预选在登录后按名称及语言族唯一匹配真实 ID，匹配失败必须明确重新选择，内部预选标识绝不发送。牛客看题只读题页引用的实际语言资源，目录失败仍保留题面。重新打开题面、准备提交取得新目录时也同步刷新同题面板，提交前仍重新校验。建议从实际目录选择版本；清空编译器设置后恢复当前默认选择。旧版 AtCoder 本机偏好首次激活时迁入设置，不覆盖已有显式值，迁移成功才删除旧键。迁移写入失败会提示并保留未迁移项，扩展仍可使用。

独立 OJ Connect 活动栏入口提供五站登录摘要，与内置浏览器共用登录。CF 摘要读取当前持久 Session 的官方账号；蓝桥读取主站 basic，名称动作固定打开已采证 Passport 登录入口，不猜个人主页。无法可靠读取时显示未知；退出登录在官网页面完成。没有题库、比赛、社交或专栏入口。

AtCoder／CF 快捷键看题使用当前存储范围的真实 Session，对固定官方题页作一次只读 GET；在断网、无账户的本地沙箱中解析原始 HTML，不创建或导航官网题页。浏览器 Get 保留该网页自己的 Session，包括临时会话；普通网页和 Import to CPH 保持原行为。取消、窗口关闭或存储范围改变后不交付迟到题面。没有持久题面缓存或自动重试，CF 同题重开也重新读取官网文档。性能对照与限制见[本轮结果](../../docs/oj-connect/statement-optimization-2026-11-19.md)。

牛客普通 Cookie 补设／轮换只触发账号校验，确认真实 userId 改变或退出后才使旧提交／记录失效，避免首次请求取消自身。

主动登录只复用当前存储范围的同一登录地址，保留其他官网页与草稿。共享同一持久 Session 的窗口同步 AtCoder／CF 账号变化；切换浏览器存储范围时先清除旧账号摘要，再读取当前范围。普通会话 Cookie 轮换不视为退出。

每窗口一项提交；洛谷明确验证码拒绝后人工输入可继续，同一次提交中已输入答案连续被拒绝三次即停止，并在右下角提示“请到内置浏览器中提交，并手动完成认证。”首次挑战、留空刷新和取消不计入次数，不实现新的认证形式。受理不明只查询，不能自动重交。发送后不提供取消提交；关闭记录只停止本地跟踪，线上评测继续。五站正式记录的每轮本地自动跟踪约 120 秒，到期或查询失败保留正式记录和最后状态，允许继续查询同一 ID，不重交；洛谷推送、AtCoder 官网 Interval、牛客与 CF 2 秒查询分别保留。五站的整体评测状态及测试点悬停统一使用洛谷风格的英文术语；保留官网英文 checker 描述、Score、Received signal 和 Exit with code，缺少详情时仅显示英文状态，不编造分数或退出码。未知状态与官网诊断保留原文，CE 显示实际可读的编译诊断；标题、按钮和操作提示仍按界面语言显示。AtCoder 返回评测进度总数时，沿用洛谷蓝色测试点卡片与白色转圈；尚无数量时只显示整体等待，不虚构点数。扩展重启不恢复任务或最近记录；五站的各自编译器偏好与 AtCoder 题面语言通过用户设置保留。

洛谷推送失败后停止本地跟踪，保留最后结果并提供“继续查询”；点击后重新读取同一正式记录，按需重建推送，不自动重连。隐藏或未知状态显示原始信息与说明，停止自动查询及转圈，允许手动继续查询；正常排队和评测状态仍自动更新。

蓝桥仅支持公开普通标准输入输出练习，拒绝课程 lab、云挑战、进行中比赛／考试、交互和 output-only。`lanqiao/254.cpp` 或显式官方题目 URL 可识题；浏览器 Get 保留页面原 Session（含临时会话），快捷键与提交使用当前持久 Session。默认 C++ 为 `C++（g++17）/cpp`，C 为 `C（gcc8.3.0）/c`；四站的 C++20／C17 向上偏好不变。当前目录静态发现失败时看题可保留已采证预选，提交前必须重新核对当前官网项，未知标签明确停止。样例只从有明确配对标签的输入输出围栏提取，保留教程代码、说明及空白。

蓝桥 source/report 各最多发送一次；执行标识经同题本人列表、当前账号、语言及官网回读源码（仅 CRLF→LF）核对后才成为正式记录。取消、超时或受理不明后只 GET，不能通过继续查询补发 report。准备阶段先打开共同评测页，随后展示发送、Judging 和核验正式记录；确认后同页升级，保留已有报告点卡、语言和本次提交代码大小，正式快照字段优先，回读源码可计算实际 UTF-8 字节数。正常核验仅在状态行提示，失败／受理不明时保留解释与继续查询。阶段查询仅读本次活跃事务的本地投影，不增加官网请求，也不提前授予正式记录权限。逐点报告仅保留当前进程内投影，不保存或展示隐藏输入、输出、答案及原始 result；没有真实测试点或汇总时不显示测试点区，仅保留上方实际阶段反馈，不补造等待卡或模拟逐点完成。信息与标题按实际内容自然撑开，保留已显示报告。题目右上复用共同限制、难度徽标及标签交互，保留蓝桥自己的等级与颜色；缺失或未知可选元数据省略，限制格式统一显示。资源零值保留，官网 kb／MB 不擅自改为 KiB／MiB。浏览器存储范围／信任变化使旧权限与迟到响应失效；重启不恢复任务。本轮体验细化已随 2.1.0 Setup 获负责人验收；未逐项采证的异常和语言组合见交付记录。

蓝桥正文中可识别的主分节（含“问题描述”“评测用例规模与约定”）沿用洛谷二级标题样式，保留章节ID；实际子标题保留原层级和锚点。重复题名只处理开头与页头完全相同的独立文本块，紧邻主分节的同文纯标签至多省略一次；链接、代码及正文解释保持。标题归一化在原Markdown完整安全解析后进行，不拆断跨节引用，不改变原题文档或CPH样例。蓝桥纯Markdown中已采证的纯数字百分比双反斜杠写法仅在数学片段中兼容为单次转义，防止误生公式换行及丢失百分号；代码、混合HTML及复杂公式保持原样，普通站点与蓝桥分别缓存解析树。蓝桥评测页保留真实点卡，省略重复的“通过测试点”汇总；没有真实点卡时不显示空的测试点区。未知结构保持原样。

题面与评测前端按 vscode-luogu 4.20.0 对齐，直接复用其核心 React 组件、CSS 与宿主 Markdown 渲染链，移除题解、比赛及其他外围能力；原组件及必要适配对照见 UPSTREAM.md。
