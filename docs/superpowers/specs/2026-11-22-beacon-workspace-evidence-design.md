# Beacon 共享材料与持久化近期运行凭证

日期：2026-11-22。状态：负责人已采纳下列五项技术取舍，更新后的书面方案待审阅，尚未实施。评测仅使用持久化近期队列，统一、平等对待 Runner、CPH、Notebook 的用户行为凭证；撤回额外归档库、独立索引和不可变多版本存储的建议。

已确认：三来源各自等额保留；共同外壳加来源明细；目录先行、正文按需读取；本次读取固定内存快照；超长输出保留头尾并标明中间省略。

## 1. 材料归属

- 每个被接受的新问题保存本轮目标代码，包含未保存修改，不扫描全部打开代码。继续/重答复用原问题快照，工具续轮及运输重试不重复保存。
- 代码快照、题目及近期运行凭证在当前 `.beaconWork` 内共用；题面同一版本只保存一次，更新后保留可辨的版本。
- 用户原话、回答、摘要、许可、普通附件和草稿仍归会话私有，共享材料不提供其它聊天读取入口。
- 保存代码不等于模型已读取正文；Blackout 仅使用内存材料，不新增落盘或查询持久队列。

这些要求更新[请求生命周期方案](2026-11-22-beacon-request-lifecycle-design.md)的材料归属部分，产品边界见 [PRD](../../beacon/prd.md)和[平台架构](../../beacon/architecture.md)。

## 2. 仅复用持久化近期队列

保留现有 `.beaconWork/cache/<producer>/records.json`，`runner / cph / notebook` 各自 FIFO、各保留相同 N 次，互不挤占，不合成混合总额队列。使用共同记录外壳，保留来源明细；N 和单记录字节上限由执行计划统一定值，本轮对比中的“各 10 次”只是示例。Notebook 的文档输出不代替其工作区凭证。

队列在真实尝试开始时写入，随 producer 事件更新并落盘，结束时追加真实终态。已有 `revision/sequence` 只用于当前记录更新和一致性读取，不保存各历史 revision 文件。进程消失而缺少终态时保留“未收尾/结果未知”，不能补成取消、成功或失败。

不新增长期评测归档、独立索引、pending 文件、数据库、引用计数或自动迁移平台。超过队列容量按 FIFO 淘汰；不能再承诺被淘汰的完整原记录长期可回读。正在执行的记录在收尾前不被后续记录挤掉，收尾后恢复常规 FIFO，不另建活动记录库。

活动保护依据协调器实际任务占用，不按“缺少 finished”永久保护；重启后未收尾但已无对应任务的记录保持结果未知，仍可按普通 FIFO 淘汰。

| 统一记录内容 | 来源保留的必要细节 |
| --- | --- |
| id、producer、revision、sequence、发生时间及状态 | 一次真实用户尝试，来源不同但同权 |
| 真正使用的主代码/源码身份、输入、编译及实际输出 | 字节与读取表示、来源采集遗漏及返回截断分别说明 |
| 真实终态与覆盖 | 正常结束、CE、取消、TLE、OLE、运行错误等均记录，不只保存成功或 outcome 摘要 |
| 结构化来源明细 | Runner 的实际流和输入；CPH 的整轮样例/expected/checker/逐样例结果；Notebook 的笔记、程序块、input 块及实际结果 |

Notebook 页面仍只展示各 input 最近结果；其工作区近期凭证与 Runner/CPH 平等查询。保存证据不依赖聊天打开或模型配置，也不触发新的运行。范围由发起窗口的有效根与真实源路径确定，不借 Flood、执行 cwd 或关联文件扩大生产归属。

超长输出按采集到的内容保留头尾，分别保留编译诊断与程序输出的阶段、流、原顺序和省略范围；不把整个 JSON 字符串截成无效片段，不删记录身份、终态和覆盖字段。源头已遗漏的内容不能恢复；触限终止程序后也不能声称取得了本来尚未输出的末尾。既有运行时限、OLE/输出停止规则不因保存策略改变。

## 3. 一个工具读取入口

扩展现有 `inspectContext` 的 `records / record` 消费者，读取当前 `.beaconWork` 三类持久化近期队列，不再新增 `inspectEvaluations` 或共享库工具。

- 首次请求只给当前对象及相关记录目录，列出来源、对象、时间、状态和覆盖，不默认注入最近结果正文。`records` 可按 producer、当前源码/题目等已有真实字段过滤，未关联题目保持未知。
- `record` 按 producer＋id＋revision 首次成功读取后，在本回答内固定该版内存快照；后续分页复用，即使队列更新/淘汰也不混版，不另存历史版本文件。首次读取前版本已变或已淘汰则明确失败，不拿最新记录补位。
- 内存读取快照沿本回答现有材料预算管理，回答结束即释放；下一次新准入重新核对队列，不把上次内存缓存当作仍可用的共享记录。
- 当前工作区的合法会话共用队列。原生读取按窗口/根/模式及 epoch 校验，不要求记录属于某个聊天，也不以读取为由创建占位会话。
- 工具读取不再通过 `consumeRuntimeRecord` 额外复制整份原始记录到会话目录；实际已返回内容仍按正常 tool 协议进入该会话历史。本回答之外再次读取时，队列尚在且版本匹配才供应，不能用旧会话内容冒充当前队列记录。
- Spot/Flood 可以读取当前根队列；Blackout 执行层拒绝。工具不运行/停止/重评程序，不联网、不登录或提交，不接受任意根或其它聊天 ID。

旧会话材料保持兼容，不删除、不自动推广为共享记录。有效前缀限制继续保护私有历史；共享近期凭证可独立查询，不能借其恢复被删后缀的用户要求或模型结论。

OJ 已打开题面/判词继续由页面入口提供；已有题面持久化方向保留，本次不扩建 OJ 长期评测库或后台采集。任何结果都必须绑定真实来源和源码关系，旧判词不验证新编辑稿。

本轮仅修订设计，不改产品代码、历史数据或提示版本。下一步执行计划围绕现有队列和消费者展开，源码/构建、模型质量与负责人实际体验分别验收。
