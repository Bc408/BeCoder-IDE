## 1. 目标与起点

让 Beacon 在正常学习过程中自然完成：**理解本轮问题 → 选择相关材料 → 正确调用工具 → 理解实际返回范围 → 必要时补读或纠错 → 给出直接、有据的教学回答。** 这是一条由模型自主执行的取材思路，不是 harness 强制流水线。

当前 `Beacon_Next@c54e9e4970c59fb1553b38581dc951fc3fb9d8fa` 有大量未提交的底层候选改动，本专项继续保护这些改动。依据为现行[需求](../../beacon/prd.md)、[架构](../../beacon/architecture.md)、[底层设计](../../beacon/foundation-design.md)、[实现状态](../../beacon/implementation-status.md)，以及负责人审阅后的[17项质量要点](../../beacon/review/2026-11-23-output-quality-improvements.md)。设计、源码检查、真实模型表现和负责人体验分别验收。

| 已确认的测试问题 | 本专项应解决什么 |
| --- | --- |
| G08-01：只返回样例完成事件，模型误说没有输入和期望 | 指定对象的组合读取更完整；让模型知道本次返回什么、还可读什么 |
| G09-05、L09、L11：快照保存被说成源码保存 | 消除工具返回的保存身份歧义，不靠每次回答附加免责声明 |
| G11-05 r1、G11-08 r2：13次反复漏operation | 参数约束、执行校验和错误反馈一致，能据错误修正下一次调用 |
| G07-05：问刚才运行却只读当前代码 | 说明不同工具／部分可证明什么，引导取材与问题匹配 |
| G02-07、G05-04：题面来源选择错误或冲突未澄清 | 返回可核对的多来源线索与精确读口，仍由LLM选题 |
| G11-03：并行首读与变版的归因不确定 | 用确定性试验区分首次固定之前的失效和固定之后的混版；复现再修 |
| 负责人反馈：工程信息、整稿复述与工具局限说明过多 | 模型内部保留核对信息，对外只讲当前学习所需的内容 |

其中G13的低辅助分不作为已确认分支缺陷，案例机制通过率也不作为逐次tool正确率。[原始能力报告](../../beacon/evaluation/2026-11-23-context-foundation-report.md)保持原始身份，不覆盖旧分数或回答。

## 2. 方案选择与专项边界

| 路线 | 取舍 |
| --- | --- |
| 仅调说明／提示 | 改动小，可作为对照；无法消除指定样例all漏相关字段、泛化错误等实现问题 |
| **说明、schema、返回与局部实现一起迭代（推荐）** | 保留现有owner与工具主入口，针对真实失败减少参数和语义歧义，能分别评估每项收益 |
| 一开始拆成大量新工具 | 可能减少单个工具的参数混淆，也会增加工具定义、路由与兼容成本；尚无证据需要全面拆分 |

主范围是 `inspectContext` 及其与provider、导师提示、普通文件读口的协作。可改选择器投影、分页续读、组合读取、局部状态表达及参数错误处理；发现确凿owner缺陷时修最小接点。`inspectFiles`只检查合法回退、单位和来源表示，不扩大权限。`editNotebook`、通用联网、存储格式、生产者和UI不是本轮扩展方向。

以下合同保持：

- Get Problem当前根共享13条，Runner／CPH／Notebook／OJ各20条；对话代码快照10份、完整正文最多262144个UTF-8字节；不新增数据库、索引或另一套材料存储。
- LLM主动读当前代码才同次捕获／保存，发送、继续、重答不自动读；不恢复讨论对象选择、绑定或“上轮对象”。不增加独立保存／删除快照工具。
- 软件采集资格与模型模式权限分开。Blackout可读合法打开代码的正文／文件名／路径及只读联网题面，对持久来源无目录、读取或调用写入能力；正常根的软件用户行为采集持续。
- 运行／测评只从持久凭证消费，不从功能页面、终端或Notebook输出旁路补读。其他聊天、被排除分支的私有材料与许可不恢复。
- 共享凭证首次成功读取后本回答固定revision；新回答重新核对。代码快照跨调用分页不额外保护，淘汰后如实失败；实时重读仍可取得新稿。
- 不修改学生源码、不自主Shell／运行／停止／登录／交题；忙时拒绝，不加用户操作等待队列。保留取消、敏感过滤、完整协议、原始历史与输入硬容量守卫。

压缩本轮只做工具schema／只读能力兼容与信息流回归，**不顺带重设计摘要格式、触发线、恢复额度或模型选择**。已知摘要结构及语义瓶颈单独归因；若工具返回诱发新退化，则回退或修正该工具改动。

## 3. 拟收敛的工具契约

### 3.1 操作说明与参数校验

保留 `inspectContext` 主入口和已有operation，优先建立小型共享契约模块，供普通回答工具和压缩只读工具复用允许操作、参数规则及简短描述，避免两处schema分别漂移。契约不替代owner的根／会话／版本校验。

| 操作 | 应明确的使用条件 |
| --- | --- |
| currentCode | 首读可指定页面ID，省略则读调用当下活动代码；无快照的续页必须携带原页面ID、版本和返回偏移 |
| codeSnapshots／codeSnapshot | 前者列本对话保留稿；后者按快照ID读指定稿，分页不晋升，不证明编辑器仍相同 |
| records／record | 前者仅列元数据；后者必须给producer、id和正revision；part与样例／块／输入选择器需合法组合 |
| problemHints／problem | 前者是独立来源的候选，不是题面正文或唯一绑定；后者区分精确已存题面与显式只读刷新 |
| page／material | 页面ID、页面版本和PDF物理页码各守其身份；私有材料仍检查有效分支，不成为执行事实旁路 |

schema按operation表达所需字段，执行层对未知operation、缺字段、非法组合和范围作同样校验；不根据缺失参数猜测用户对象、默认revision或自动补出模型未传的operation。

源码核对已确认：当前contextSchema只给 `jsonSchema(...)` 传入声明，未传validate；本机锁定SDK的 `safeValidateTypes` 在缺validate时直接接受已解析值。因此“required写了operation”不等于运行时一定拦截，缺operation仍会到ContextTools才得到泛化错误。S1需落实实际执行校验，并用出站＋故意非法tool调用验证整条链路，而不只测试schema字面量。

先在生产SDK和当前DeepSeek适配器上验证条件schema能否可靠出站、调用及纠错；不能仅因本地JSON Schema合法就假定服务支持。若复杂条件不兼容，保留兼容的简单出站schema并落实严格执行校验、字段描述和明确错误。不同适配器的离线出站回归必须通过，不宣称未实测服务已支持。

### 3.2 返回内容先让模型能分清事实

保留既有正文与必要来源、版本、时间、哈希及分页字段；不为减少回答中的工程信息而删掉模型核对依据。只增加或调整有实际消费者的局部表达，不套一层大而全的通用材料协议。

| 返回内容 | 设计要求 |
| --- | --- |
| 本次选择范围 | 显式表达part、实际样例号或块／输入／流选择。`truncated=false`只证明此选择表示已完整返回，不代表整个原记录全部字段已读 |
| 可继续读的部分 | 根据已合法取得的同版材料给出简短availableParts，区分可读、源未保留和未知；不得为生成目录预先读其他私有材料或联网 |
| 正文覆盖 | 源自身缺失、存储保留头尾、工具分页和脱敏分开；空字符串不变成缺字段，长整数／空格／换行原样保留 |
| 续读参数 | 确实需要分页时返回一个同来源、同表示的完整continuation调用参数，包含operation和必要身份，避免模型重新拼参数。仅指向本次材料，不创建token、句柄或新缓存 |
| 保存身份 | 新工具返回用明确的snapshotSave表达“本对话代码快照”的保存结果，替代含糊save；与本次编辑器观测、返回覆盖分开。native保存DTO及已有磁盘格式保持 |
| 失败与歧义 | 未取得正文不能伪装成功内容；保留候选、selectionRequired与实际错误，候选列表不是模型已读题面 |

首次读取可在预算内返回局部正文，而完整快照已保存；两件事分别表达。快照保存失败／超限仍可交付实际读到的代码，不给虚假回读ID。工具不从snapshotSave推导学生文件是否保存；当前原生代码观测不直接携带文件保存事实，本轮不为回答增加磁盘保存探测。

continuation由模型主动调用，每次重新执行原权限和版本检查。已有快照可指向codeSnapshot；未保存实时稿指向原currentCode ID／版本。失效、淘汰、取消和预算不足时不偷偷切换来源，也不自动续读全文。新增元数据和示例均计入实际输入／结果预算。

模型实际出站的选择范围和数据状态只能由工具观测支持；availableParts与continuation不授予权限，材料正文仍是不可信参考。历史协议中的save继续原样回放，能力说明需解释其旧字段同样表示对话快照，不能通过改写历史消除歧义。

### 3.3 针对来源改进tool实现

**CPH指定样例组合读取。** `record + sampleIndex + part=all`应是该样例的完整相关视图：原始样例号、实际保存的input／expected、实际结果／stdout／stderr／verdict，以及这些字段的可用状态；关联真实整轮执行稿，不生成“该样例单独编译”的事实。直接从同一已固定记录提取，不作网站查询、不新存材料。样例只跑第2例时仍为第2例，内部batch index不冒充用户序号；缺失值与显式空值分开。整轮默认all及各part保留其真实语义，不强制每问返回整轮全文。

**Runner、Notebook与OJ。** 明确输入、编译、输出、终态及执行／提交稿各自能证明什么。Notebook按实际blockId／inputId校验；Runner两条输出流不合并为答案；OJ排队、缺源码和未核实状态不补造。只提供本次请求相关的结构，不把四来源重新做成一份持久化通用记录。

**题目线索与题面。** 将“查询接口可用”“已查但无匹配”“未获授权／不可用”分开，不再用一个available暗示有题面。默认已存材料与显式刷新返回清楚来源／时间；同题不同文件及Get／CPH冲突保留各自身份，让模型选择或澄清。显式刷新无用户Get／Import副作用、无题面队列回写。名称、题号和路径不替代正文。

**共享凭证并行首读。** 增加带屏障的定向复现：同ref并行读不同part，首读前变版／淘汰，首次固定后继续读取，以及根／模式切换。固定后的同ref结果不得混版；固定前失效应如实失败。只有证明确有不一致时才修本回答内的固定逻辑，不给过期快照增保护、不引入新的产品操作队列。

### 3.4 能帮助纠错的错误返回

保留现有稳定错误码与UI白名单。面向模型的错误提供简短、结构化issues：具体字段、缺失／类型／范围／组合问题，必要时列合法operation或正确参数形态。仅在调用意图与目标已明确时给同目标修正例子；目标不明时返回所需字段，不代选对象。

修正例子是应用生成的调用数据，不授予新权限；下一次调用仍从执行层校验。未知字段、原生异常、网站内容、密钥和不可读路径不能直接回显到模型／UI。SDK在execute前拦下的非法输入也要有配对错误结果与可恢复反馈，不应因schema严格而让整轮无声失败。

模型应纠正错误再继续；相同错误无进展不反复盲试。沿现有20工具步与180秒请求边界，不添加自动补参、后台重试或新重试队列。

## 4. 模型说明与最终回答

导师提示只保留跨场景的取材原则，操作的详细参数和例子放在工具契约中：

- 问当前改动，读取相关最新稿；问某次运行，消费那次凭证；问新旧比较，分别取得所需版本。概念、用户已给足的材料不为使用工具而使用工具。
- 根据实际返回范围判断是否还缺关键证据，优先补读现有材料；无法消除的对象冲突才问用户。一个字段本次没出现，不证明记录没有保存。
- 读失败不拿旧观测冒充当前稿；旧结果不替新稿背书；静态推理可以确认局部逻辑，不因没有新判词就否认已能判断的修改。
- 内部核对身份与覆盖，对外讲原因与必要下一步。默认不报ID／哈希／路径、整稿、工具细节或长篇局限；用户问来源或确需定位时简短说明。

每项规则配少量跨来源例子，避免把测试编号逐条写进系统提示。保留提示深度／完整解答切换和学生源码保护，不靠输出后处理删除代码块或元数据来制造简洁。

## 5. 实施与验证顺序建议

| 阶段 | 主要工作 | 可审查产物 |

| S3：取材说明与题面线索 | 简短导师原则、问题匹配、候选状态、默认已存／显式刷新；对外表达约束 | 读对来源、合理补读、不滥用工具、无保存身份误述的旧／新问答 |
| S4：冻结候选与独立验收 | 新保留集、连续轨迹、旧保护集和拥有者检查；独立只读review并修具体问题 | 完整能力报告、失败归因、原始问答审阅包；源码与模型验收分开 |

S0必须验证基线bundle运行的是冻结的生产owner，而不是动态加载之后改动的候选源码；记录所有参与owner、评估器和依赖锁的指纹。评估器同时识别旧save／新snapshotSave及新旧局部投影，只按实际模型可见事实评分，不能让新返回形状本身成为通过条件。

实施方式建议沿用当前Native连续推进：主代理负责相互依赖的契约改动，独立代理只读核查边界和模型负例。先审阅本设计，再形成逐任务实施计划；不在当前dirty tree另作清理或自动Git提交。

## 6. DeepSeek效果实验

费用不作为削减覆盖的依据。沿本机已配置的 `deepseek-flash` 和批准配置，只发送合成案例；密钥不进聊天、日志、仓库或交付包。开始执行时核对实际模型、参数与能力；不宣称服务可复现到逐字一致。

### 6.1 案例与分组

预先写 **10组×6项＝60项** 专项案例，每组4项开发、2项全新保留。旧失败仅作为开发锚点，不能重新命名为未见保留集。

| 组 | 覆盖重点 |
| --- | --- |
| T01 | 问当前稿／历史稿／执行事实／概念的不同取材需求 |

开发先用12个失败／成功对照锚点各3次作小批诊断。按“仅说明变化”“工具契约／实现变化”“两者合并”分层比较，尽量每次只改变一类影响；不把两者同时改善误归为某一句提示的功劳。复杂schema及拆分候选只在原来混淆集做受控对照；若需要改变工具数量，提交具体候选及实测证据，不默认扩张所有工具。

最终冻结后，基线与候选分别对60项各跑5次，**共600个场景槽位**；开发诊断另计。每组保留集直到最后才打开审阅，若用于调优须另建未见案例。

另做 **8条自然连续对话×12轮×3次重复**，基线／候选各一套，共48条轨迹、576个用户问答轮次。前6条围绕改稿、换题、指定样例、旧记录追问和失败恢复；后2条在相同问题链中比较压缩前后信息流，压缩格式本身失败仍记录，不用手工摘要替换。自然材料使用多种小算法与真实格式，不靠大段重复字符代表全部长教学体验。

### 6.2 比较口径

- 模型、参数、同一案例材料与权限固定，基线／候选分块交错运行，记录服务变化；总并发先设4。按可验证服务限流调整调度，不改变产品并发规则。
- 原始出站、实际模型收到的工具正文、每次调用参数／结果／阶段、问答、摘要与每轮状态保留。模型原生未返回的完整记录不能补作已读证据。
- 首次错误、纠正后的结果与语义失败分别保留。只允许外部网络／服务失败作有记录的有限补测；完整回答或真实模型失败不能因为得分低重跑替换。
- 逐调用统计合法性、对象／版本／选择器匹配、是否需补读、重复错误与纠错；逐问题统计充分取材与教学。允许多个合理路径，不把固定tool序列写成答案。
- 人工先校准原问与判据，复核所有关键负例／无效裁判，并抽查自动通过；独立review不按模型自评放行。缺免责声明、没有无关工具调用不直接判错。
- 保留每例5/5稳定性、各组分母、每轮失败和整条全轮通过。最终一轮complete不是整条轨迹完成；不把服务失败、摘要失败和工具语义失败合并。

### 6.3 拟定验收门槛

以下是专项目标，提交报告时同时列实际计数和偏差，不以小样本比例宣称线上保证。

| 层面 | 拟定通过条件 |
| --- | --- |
| 硬边界与确定性回归 | 权限、scope、分支、协议、取消、真实读存、版本和字节保真用例全部通过；越权或工具实际副作用立即阻断 |
| 按需取材 | 每组适用案例至少95%取得回答所需材料或正确识别确实不可得；概念题的合理不调用也算正确 |
| 参数纠错 | 可修正参数错误至少90%在随后两次模型工具调用内纠正或合理停止；同时报告首次合法率和重复同错。此为评测窗口，不增产品重试次数 |
| 回答质量 | 每组适用回答至少90%达到人工校准的“正确且有用”，评分覆盖至少95%；严重证据捏造、错误来源和源码保存误述单列，不被平均分掩盖 |
| 连续性 | 无压缩自然轨迹逐轮完成且正确率分别报告，目标全轮完成；压缩轨迹含已知冻结问题单列，任何退化必须解释，不能称全能力达标 |
| 成本与容量 | 实际工具定义／返回计量、请求步数、延迟、工具往返数和输入开销与基线对照；不得用漏读、删必要字段或静默丢材料换取更少调用 |

原128项×5及12条×3作为旧保护集在候选冻结后回归，特别保留当前代码、Blackout、题面刷新、分支与压缩工具能力；旧案例不再充当新保留集。遇已确认模型能力瓶颈，冻结相关项并交付真实缺口，不以全部绿灯为由无限调优。

## 7. 迭代停止与交付

连续两轮针对同一失败类别的受控修改没有可复核改善，停止追加提示，检查是否是工具实现、信息缺失或模型能力问题；确定性实现缺陷继续按红灯／绿灯修复，不因调参无收益而放弃。需要新产品决定或改变固定合同则暂停该项讨论，其余独立工作继续。服务故障先在原层修调度／连接，不伪装成模型瓶颈。

建议交付：

1. 工具契约和局部实现的源码差异、红灯／绿灯与边界回归；更新相应使用说明／实现状态，不宣称其他模型已验收。
2. 分组能力报告：基线／候选、开发／保留集、逐调用／逐问／逐轮、工具／模型／压缩／服务归因及冻结项。
3. 代表性原始问答审阅包，含实际工具返回、失败恢复和完整连续轨迹；保留首败和有争议判词。
4. 在后续实施计划明确交付范围后，执行最终源码检查和一次干净Windows stage构建。保留原个人数据，默认工具链与首次启动文件属于标准产物。源码通过、stage、五站真实流程与负责人体验分别成立；不自动Setup、提交、推送或发布。

正式实施计划应从实际package脚本预检并冻结命令：Beacon `typecheck`、`build`、`test`、`lint`；评估器离线回归；根 `typecheck-client`、统一 `compile-oi-extensions`；改native则加拥有者原生测试与分层检查。源码／扩展检查120秒，stage300秒；不使用 `npm run compile` 代替类型检查。失败按层记账、修正受影响检查，最后构建成功后停止交付。

本方案把工具主入口与现有架构作为起点；允许根据真实对照证据改进tool实现，但不将费用授权解释为无限重试、无限扩功能或本轮已获实施批准。
