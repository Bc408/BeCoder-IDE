# 长会话压缩、工作区记忆与 dream 候选方案

更新：2026-10-23。状态：保留的需求与候选机制，未由本文证明实现或真实模型质量。当前源码覆盖见[实现状态](implementation-status.md)，正式规则见[PRD 第 5、6 节](prd.md)及[架构第 7、8 节](architecture.md)。

## 分工与接入点

压缩维持本次讨论，工作区记忆积累独立教学观察，Notebook 保存可复习文档；三者不能合为一个不断改写的大总结。推荐复用现有会话材料、AI SDK 与宿主存储，采用“近期原文＋较早内容摘要＋本会话回读”，主模型简单追加 tips/status，用户主动 dream 整合 status。

候选接点是 `session.ts` 的模型上下文、`protocol.ts` 的完整调用/结果关系、`provider.ts` 的每步请求、`models.ts` 的有效容量，以及原生 `.beaconWork` 存储协调。实际接入前读取当前源码，不沿用 2026-10-12 的旧全局历史/capability catalog 假设；独立工作区、材料和页面底座已经变化。

不引入每轮后台画像提取、额外维护代理、质量评分器、向量库或新的 agent 框架。先用轻量文本与按需读取，实测不足时再评估派生索引；不永久禁止后续 RAG。

## 有效上下文投影

完整历史和模型实际输入分开维护。较早正文可由来源、版本、必要片段及回读入口代表，近期原文优先；小材料不强制外置或分两轮读取。摘要绑定当前分支、消息范围、revision 与实际覆盖，原始历史和材料不因压缩删除。

必须保留当前用户请求、后续纠正及完整工具调用/结果关系；不摘要正在进行的调用，不重放已完成写入。换服务时沿用协议 owner 的私有元数据过滤，不把另一服务 reasoning/signature 包成普通文本泄露。编辑早期消息或重答使范围/revision 失配时，旧摘要失效。

容量使用服务/用户配置及明确标注的默认值，不能按任意型号名猜窗口。当前配置缺失容量默认 32768/24576/8192，是可修改起点，真实容量需要验证。预算包含系统、工具 schema、代码/JSON、中英文、多模态和后续工具返回；不能仅按“字符数除以四”声称精确。

临近预算先去重复正文，再在完整消息边界摘要较早区段。摘要保留目标、最新决定、对象/版本、个人探索、真实验证、矛盾和未知；“改好了”不能变成“已验证”，模型建议不能变成用户已采用，记忆不能变成新许可。重复压缩以原始区段为依据，不只是不断总结前一摘要。

图片保留原材料身份；文字描述不等于重新看过图。无视觉能力不自动 OCR、换服务或悄悄丢图。最小必要输入仍超容量时说明限制和可行动选择，不静默裁掉当前请求/资产。

成功核对后才启用新投影，失败/取消保留原文和上一有效投影；已发请求不被中途替换。上下文超长后的重新组织是新输入构造，不能混入运输层自动重试。具体阈值、分段和受限模型体验仍需实测。

## 主模型简单追加记忆

只设当前 Beacon 工作区的 teach tips 和 student status。文件名/格式未冻结，人可读、可直接编辑；tips 初始内置且默认带入，status 按需读。Blackout 不访问持久化记忆，Flood 不改变记忆归属，不从记忆来源 ID 回读其他会话。

| 操作 | 候选实现与边界 |
| --- | --- |
| 读取/搜索 | 返回当前根 tips/status 的实际版本、范围及缺失，不默认读取冷归档 |
| 主模型追加 tips | 简短教学指导与用户许可/限制，只追加；不自主重写、去重或优化旧文，允许本轮不追加，不逐条审批 |
| 主模型追加 status | 如实记录观察时段、依据及“用户明说/实际表现/模型推测”的区别；单次错误或 AC 不固化成能力标签 |
| 用户编辑 | 直接修改文本，后续请求热更新；进行中请求使用已捕获版本，dirty 文档不由磁盘旧稿覆盖 |
| dream/取消归档 | 用户主动发起，整合 status 或朴素追加归档，不顺带改 tips 或调用额外智能合并 |

同根窗口和用户编辑在实际写入时作短协调/revision 检查，不在模型思考期间锁整个工作区。追加重试需避免同一操作重复写入；保存失败、内容损坏和“无值得新增观察”分别反馈，不能建空替代文件或换根。只在实际保存后提示轻量观察，不展示内部推理。

用户通过查看和编辑把关记忆质量。追加内容应独立可理解，不依赖来源聊天继续存在；删除来源会话不删除已形成记忆。职业底线与工具权限不能被教学适配改变。

个人信息查询许可只能来自真实用户指令及适用范围。tips 可以记录许可/限制，prompt 引导模型遵守最新决定和撤销；模型追加、status、dream、旧归档和外部材料均不能生成/扩大许可。没有独立宿主许可凭据、授权表单或查询意图审批门。

## 主动 dream

1. 用户主动触发，绑定当前根和最新完整 status 编辑状态/revision。默认不读冷归档、其他会话或整账号，不自动新建聊天。
2. 使用当前主模型整合重复，保留观察时段、依据、变化、矛盾和待确认。超容量才按原始区段处理，明确完整覆盖；不能用部分摘要冒充旧全文。
3. 提交前短协调并核对 revision；生成期间有新编辑则反馈冲突，不用旧候选覆盖新观察，不无限重试产生费用。
4. 保存旧完整 status 为可读归档，再保存新 status，成功直接生效，无再次采纳。历次归档保留、应用内只读、默认不进日常上下文。
5. 取消/失败如实反馈已生成、已归档、已应用和已保存的实际阶段。发布涉及两个重要对象，具体崩溃恢复方案仍需验证，不扩成全工作区事务平台。
6. 取消归档只将该旧全文追加到当前最新 status，不覆盖、不去重、不调用智能合并；同一操作的重试不能重复追加。

Notebook 不再要求失败强制回滚，不代表记忆的完整归档和保存反馈也取消；各资产按自己的正式规则保护。dream 不改 tips、不恢复许可，不与日常追加绑定成复合自动任务。

下列固定来源在 2026-10-12 作机制研究，未在本次文档清理中刷新在线版本、安装或执行：

| 来源 | 可参考部分与限制 |

| [AI SDK prepare-step](https://github.com/vercel/ai/blob/e9c1d2f54da6bd01a16bb8a5fdfcb4b62f34e7d0/packages/ai/src/generate-text/prepare-step.ts)、[usage](https://github.com/vercel/ai/blob/e9c1d2f54da6bd01a16bb8a5fdfcb4b62f34e7d0/packages/ai/src/types/usage.ts)、[Apache-2.0](https://github.com/vercel/ai/blob/e9c1d2f54da6bd01a16bb8a5fdfcb4b62f34e7d0/LICENSE) | 每步输入投影、调用关系和可选 usage；消息剪裁不是语义压缩，未知用量不填零 |
| [Deep Agents summarization](https://github.com/langchain-ai/deepagentsjs/blob/b448f220866bbb5d41924dfdbb1e0079c3b11838/libs/deepagents/src/middleware/summarization.ts)、[MIT](https://github.com/langchain-ai/deepagentsjs/blob/b448f220866bbb5d41924dfdbb1e0079c3b11838/LICENSE) | 材料外置、近期保留及失败边界；不复制任意文件后端、框架或裁剪后仍称全覆盖的行为 |
| [Mem0 memory](https://github.com/mem0ai/mem0/blob/b7ad69afda6b6ed030347c66d48a13e4de9dec08/mem0/memory/main.py)、[Apache-2.0](https://github.com/mem0ai/mem0/blob/b7ad69afda6b6ed030347c66d48a13e4de9dec08/LICENSE) | 作用域和失败反馈参考；不接入其默认提取、embedding 或跨会话消息库 |

先以合成材料测消息/分支/权限/版本/保存结构，再按授权用真实模型比较未压缩与候选投影。重点覆盖：V1 运行与 V2 编辑稿连续压缩；工具中断/继续；超长输出/图片；换 provider；用户纠正；无新增观察；dirty 双窗口；dream 保存中取消/崩溃；归档恢复再整合；Blackout/换根及许可撤销。

质量判断看诊断是否引用真实版本、摘要是否忠实、观察是否克制、Notebook 是否脱离聊天仍可复习，以及用户反馈和实际调用成本。文件写入、结构正确或模型给高分不能代替这些证据。不默认新增付费审查模型。

记录实际 input/output/cache/reasoning（若可得）、耗时、取消和重试；未知不填免费或零，reasoning 不重复计入已包含它的 output。费用估计需单独的当前服务单价依据，不建立价格配置页。压缩/dream 不绕过服务停用或用户取消继续发起费用调用。
