# Beacon 底层设计

更新：2026-11-26。本文维护采集、持久化与执行边界；工具字段见[工具合同](tool-contract.md)，模块分工见[架构](architecture.md)，验证与缺口见[实现状态](implementation-status.md)。

## 1. 采集资格与共享队列

“共享”指当前所选 `.beaconWork` 内的所有对话，不跨工作区。只有正常所选Beacon根才采集；根外源码／笔记照常运行，但不错误入队。无根或根异常不采集、不写备用位置、不补采。采集scope固定发起窗口、根身份与选择代数，晚到结果不能改投新根；模式或聊天变化不使合法采集失效。

| 队列 | 容量 | 单位与更新 |
| --- | --- | --- |
| problem | 13条 | 五站Get／Import读题行为；problem（oj＋problemId）和filePath完全相同则移除旧项，新ID、新viewedAt入尾；不同路径分别占位，不存题面 |
| run | 共30条 | Runner／CPH／Notebook共用；一份程序本次编译及关联input结束／失败／取消后入队，不去重，无活动占位 |
| verdict | 20条 | OJ Connect完整取得最终结果才入队；同站同题实际提交代码严格相同替换旧项入尾，缺代码仍保存并跳过去重 |

problem无可靠文件路径时保存null；同题同为null按字段相同去重。读取不更新查看时间，旧ID不转指替换记录。verdict不归一化空白、换行或注释，不用当前代码补历史提交稿；同次观测重复交付幂等，独立再次观测仍按正常规则入队。

软件采集和Beacon消费分开：有效根Blackout仍采集；模型不能列／读持久来源，不建立内存镜像队列。切回Spot／Flood只读仍保留的材料，不补采。当前可见C/C++与Notebook内容和五站fetchProblem依原页面权限可用，含无根、根外及未命名现场，不授磁盘backing file读权。

## 2. 存储、并发与发布

当前文件格式为 `{version:1,records:[...]}`，分别保存到：

```text
.beaconWork/cache/context/problem.json
.beaconWork/cache/context/run.json
.beaconWork/cache/context/verdict.json
```

复用现有Store、锁和原子发布；不另建索引、逐条正文库、归档、pending记录或引用版本协议。目录从实际保留记录确定性生成，最新入队在前展示，不调用模型。

发布前失败保旧队列，不先淘汰再尝试保存；发布后的确认不明须区别于未写入，不能盲删新文件、回滚或重复追加。校验根身份、目标身份、临时文件所有权及scope；同根并发写不丢结果。文件串行写入不构成用户操作等待／重放队列，忙时仍由原执行owner立即拒绝。

problem／verdict的文件路径是已捕获的历史事实。原源码或父目录已改名／删除时，沿最近存在祖先核验原根范围，不因缺失旧叶子丢弃完整结果；重定向、dangling junction、失效根和旧scope仍拒绝。该校验不读取替代源码，也不扩大当前根权限。

采集观察异常和落盘失败不改变核心编译、运行、取消或清理。运行占用随真实进程与必要清理退役，不等待Beacon磁盘写入。工作区刷新只发布与当前选择代数匹配的完整状态。

普通窗口关闭保持独立；应用最终退出的lifecycle join等待已开始的记录发布明确完成或失败，避免最后窗口退出时中断发布。不增加新队列、重放或采集重试。

collectionPending是独立原生只读状态，在应采集事实进入适配前登记，覆盖校验和原子发布；Store发布确认或失败明确结束后释放，不用上游void命令返回代替成功。同根多个任务及窗口共享未完成状态，无关根不互锁，Blackout／Spot／Flood同规则；不进入模型、持久记录或scope epoch，也不预占运行槽。切根、关闭和迟到结果沿既有根身份／scope处理，不改投或残留禁用。

主页／详情发送、快捷键、继续、重答和编辑旧问题的新请求均受门禁，宿主在实际受理前复核；保存提示严格为“正在保存用户行为上下文”。保文字附件，恢复后由用户主动发送；不增加操作等待队列、重放、采集重试、自动发送或备用存储。OJ尚在queued／judging且无最终事实时不增加保存门禁；无须采集的动作不制造保存等待。

应采集事实的适配、校验、32KB拒收或I/O／发布失败由原动作窗口右下角通知，同动作至多一次，Notebook批次可合并；明确来源、原因及原业务结果不受影响。发布确认不明须说明无法确认是否已保存，不冒称未写入，不重复追加或回滚。既有mismatch通知复用；无根、根外、Compile Only等按规则不采集不报保存失败。业务编译失败、错答、取消与保存失败分别表达。

## 3. run粒度与来源差异

每条run是“一份实际程序／编译信息＋输入结果列表”。实际编译尝试开始后才有记录；运行请求编译失败保失败尝试，关联input标not-run；未开始编译的后续程序不造记录。

| 来源／操作 | 单条内容 |
| --- | --- |
| Runner Run／Run With Input | 一份编译稿与本次输入、合流终端输出、退出／停止；不保存输入编辑按键，回显不补成stdin |
| CPH单点／全部 | 一份编译稿、一个或多个测试点、原测试点序号、输入／expected／分流stdout与stderr、实际check；单点和全部等权各一条 |
| CPH仅编译 | 零条，无论成功、失败或取消；不改变原生仅编译能力 |
| Notebook | 一份代码块及其多个input、笔记路径、执行时代码块序号；多个程序分别成条 |

底层保真实代码与执行事实；模型使用固定允许字段投影，编译只保结果／诊断／standard／optimization，去掉编译耗时、命令参数与临时路径，运行毫秒取整、只显开始时间到秒；不保存运行限制配置，不嵌入题目或CPH配置。CPH仅保check，不保存检查器类型、配置、路径、代码、命令或诊断。学生程序status、CPH check和整组status分开解释，本地通过不等于OJ AC。

目录摘要按compile.status、runs[].status及实际check确定性生成，分别统计已执行和未执行输入、已有检查结果；not-run／start-failed不计为已执行。Runner／Notebook没有自动答案检查；CPH编译失败或检查阶段异常可无check，不据此称已通过或CPH不支持检查。

编译成功后、学生进程启动前取消，关联input保not-run及skipReason:cancelled；实际已启动后停止才记cancelled。批次取消不把尚未执行的输入计为运行次数。

Runner无法可靠取得交互stdin时为null并标gaps，不以按键流或回显伪造；Run With Input保实际输入文件正文。空正文、未知、未执行和读取失败各自表达。

## 4. Notebook执行与采集解耦

点击运行全部／选区时固定本次代码、input及关系，含dirty，中途编辑下次生效。codeCellNumber与inputCellNumber统一按整个笔记全部单元格从1开始计数；正文每格有cellNumber。均指执行时位置，不是永久绑定。旧codeBlockNumber无法可靠换算，不冒充新坐标。

同一代码块本次操作编译一次，每个input独立进程、计时、限时和输出限制。不同代码块即使正文相同也不合并，不增加跨次编译缓存；临时产物由执行层持有和清理。每个input真实展示共享编译耗时，不能累计成多次编译。

编译失败跳过本块input继续其他块；input RE／TLE／OLE继续后续。用户Stop立即终止整批，未开始内容不执行；删除或调序不改变冻结计划，失效页面停止展示，关闭仍取消。普通非BeCoder Notebook的原生取消规则保留。

执行层提供普通结果／观察回调，不导入Beacon根、队列或持久化类型。采集适配器消费事实并按程序成条，无Beacon根或观察者失效时照常执行。当前观察接点仍有unknown适配技术债，不能写成已完成的有限联合类型合同。

## 5. 输出保留与完整读取

run长文本按Unicode码点独立保留前缀：program.code最多8192字符，input.text／expectedOutput／每个编译和程序输出stream各4096字符，record／compile／各run的error各1024字符。完整字段仍为字符串，截断字段为{text,truncated:true}，未知交互输入仍为null。无共享分配、头尾拼接或额度回配；上游先已省略的正文也标不完整。

字段处理后，以包含ID和截断标记的完整紧凑JSON计算UTF-8字节，单条最多32768字节。超限明确报错并拒收入队，不进一步裁掉测试点或正文凑大小，不先淘汰旧记录。该规则只作用于Beacon证据副本，不改变原执行器时限、OLE、CPH判定或用户页面显示。

旧格式保留识别，不迁移或删除旧记录。旧超大记录仍可列目录，按ID读正文时返回单条容量错误，不阻塞其他记录或新记录入队。旧head／tail结构只作为历史格式读取，新记录不再产生。已进入聊天历史的巨大工具结果不由本规则自动修复。

记录工具按ID或latest返回完整已保存模型投影，可按filePath筛选；不增加part／测试点分页或include投影参数，不依模型剩余额度二次裁剪。目录不固定正文，首次合法成功读取后在本回答固定事实；实际返回只沿普通协议留存，不额外复制成专用页面材料。完整交换闭合后在下一请求准备处计量；沿既定同步压缩，仍无法容纳则有界失败。run字段／32KB规则不推广成题面、verdict或当前代码上限。

## 6. 旧数据、历史与读取边界

当前代码无独立快照API、正文库或队列；实际工具返回沿普通历史，执行稿和提交稿只属run／verdict。发送、继续、重答和协议回放不额外捕获代码。

现场读取在取得正文前按canonical URI／模型文档身份合并C/C++与BeCoder Notebook视图，目录复用同一整理，汇总visible／active；关闭一份分屏不撤销另一份。不同文件同正文、多个未命名文档及同笔记相同代码cell分别保留，不按hash或filePath:null合并，不扩展为浏览器URL或PDF身份重构。

可见Notebook只由实际已加载内容owner识别，返回整本Markdown／C/C++／input当前正文，含dirty、未命名及根外内容；全部cells从1编号，每个C/C++代码格独立计算完整源码hash。与inspectFile复用内容投影，但现场读取不走普通文件权限或磁盘fallback；不打开／保存文件或追读附件，排除执行字段。单次读取中关闭、改版或可见集合变化明确失败；跨轮合法重读和不同来源同正文继续沿普通历史，不全局删除协议内容。

旧cache/runner、cph、notebook、problem、oj及会话code-snapshots.json不自动迁移或删除，新队列从真实后续行为形成。旧文件保留不授inspectFile回读权；`.beaconWork`内部数据仍由各owner保护。

原聊天、附件、已完成旧工具交换保原名和配对，继续只提供当前工具；不执行旧inspectContext／editNotebook，不补读快照。有效分支约束消息、材料、摘要和许可，其他聊天或弃分支不恢复权限；契约变化重建usage锚点。

运行／测评不从功能页、终端或Notebook输出旁路读取；笔记／备份供模型的内容投影排除运行字段，投影失败不回raw JSON，用户完整资产保留。fetchProblem只进入普通上下文，不采集用户看题记录或建立专门题面存储。

完整代码hash在采集截断前按CRLF→LF后SHA256确定并随记录保存；旧完整代码读取时可补算投影，旧截断代码不伪造。verdict严格原文去重继续独立；源码mismatch在业务owner和入队口拒收，旧mismatch正文不供模型消费。

专用readMaterial工具、目录、contextSnapshots新采集／恢复和回读接线退出。readPage仅接收id及范围，harness取得当前内部version并验证读取身份，不再额外缓存完整正文；返回片段沿普通历史。旧会话附属副本被动保留且不复制入新分流会话，普通附件、原协议配对与摘要不受影响。

## 7. 验证责任

回归应覆盖配额／去重、根与模式、并发发布、晚到结果、独立collectionPending及所有请求入口、同根多窗口／失败通知去重／草稿保留、采集失败不阻执行、三来源粒度与状态、Notebook编译次数／取消／删除、字段Unicode码点及单条32KB的UTF-8边界、当前可见Notebook全本内容与无执行字段、文档身份去重和同文异源保留、当前代码零额外落盘、旧交换不重演、完整读取及压缩。

源码回归、模型选材与教学质量、stage构建、真实五站和桌面体验分别验收。实际结果与待办集中在[实现状态](implementation-status.md)，不在设计文档重复存放测试成绩或已经完成的实施待办。
