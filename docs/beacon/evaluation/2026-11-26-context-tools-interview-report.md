## 3. 最值得处理的具体问题

### 新活动未取材，旧事实被当成“刚才”

W07提问前，带`runner-note`诊断的Runner记录`e3e4a77c`已经发布；Beacon零调用，直接回答先前CPH的`1 2 -1`及`check:passed`。实际新运行输入不同、输出含诊断文字，Runner无自动答案检查。不是记录尚未准备好，也不是工具读失败。

F01明确指出“临时加调试文字、Run With Input那次”后，它按ID成功读取同一条原记录，解释了`1 -1 5 -1 runner-note`及无自动检查。说明能力存在，而自然连续追问中的事件选择不稳定。W07只说“刚才”，没有在文字中明示操作来源，这是场景歧义的一部分；仍不能据此把已有旧结果无保留地回答为新事件。

下一步应保留这对原问／澄清问作固定评测，检查模型何时应更新材料、何时应澄清目标。不要规定每轮重读所有队列，也不要恢复harness讨论对象绑定。

### 错误路径被扩大成产品缺能力

W05沿run的临时`workingDirectory`查CPH会话目录，返回`material-missing / path does not exist`，随后断言CPH当前配置不在可读范围。实际配置位于源码旁`.cph/*.prob`，现有inspectFile可以读取；F02经过目录定位后成功取得当前保存配置。

CPH产品知识已有存放位置，本轮此前没有读取该主题。应优先讨论CPH临时执行目录返回给模型的价值，以及源码位置／持久配置／临时目录的表达是否清楚；接口去噪和知识可发现性分别处理。不能把“某路径不存在”解释成“整个产品能力不可用”，也不需要新增CPH配置工具。

### 正确数据之后仍发生过度推断

- W08从截断数组及输出前缀推断完整结构、查询覆盖和“几万个答案”；真实完整可见答案只有719个。I06自行更正数量并部分收窄范围，值得保留；仍不能据此核对全部输入或输出。
- W12从AC推断具体边界及“官方满量级数据”；隐藏输入并未提供。I07后来能说清“有逐点结果，没有测试数据内容”，但不能回写为原答已正确保留边界。
- S03将182ms归为大部分启动固定开销；记录没有这种耗时分解。
- F04正确列出两条近期记录后，又说“没有更早的看题活动”。近期队列只证明当前保留范围。
- W13正确发现dirty稿初值由-1改为0，但又暗示恢复相同源码后必须重交才能引用旧验证；旧提交仍可作为相同源码的历史证据。

先把这些作为共性事实强度评测；提示若调整，应维持少量共性原则，不逐句追加禁止项。

### 位置、来源与调用历史仍易串位

W09／W10的Notebook核心对应成功，但随后多次把“历史位置不再是当前位置”说成“历史编号失效”。W16混用了建议的6格排布和当前7格笔记，给出无法按当前位置执行的修改建议。W18把merged称作stdout；F01虽结合源码正确解释了诊断来源，仍须区分记录分流事实和依据源码的解释。

I03将W16才读取的Notebook产品知识说成决定W10答法；F03承认因果倒置。它又把后期的笔记目录版本回填到W01，制造了“首轮可见笔记漏读”的伪时间线。当前请求的宿主目录不能当作某个历史回合的目录。
