## 1. 产品目的

Beacon 是 BeCoder 中可选的算法与编程导师，帮助学习者理解代码、题意与真实执行结果，随追问和纠正继续讲解，并在用户明确要求时形成可复习的学习资产。主要价值是减少材料搬运、辨认讨论对象及重复纠正的负担；目录正确、工具成功和文字流畅各自只是一类证据，教学质量仍须真实问题检验。

完整上下文闭环的设计与验收范围为洛谷、Codeforces、AtCoder、牛客、蓝桥的规范流程：内置浏览器拿题，经 Get Problem 或支持 Get Problem 的对象 Import to CPH，再随用户编码、运行、测评和求助。底层同时提供真实 Get Problem 记录、既有 CPH 关联和现有文件名／目录解析结果，LLM 根据用户问题判断讨论对象；线索冲突且无法判断时向用户询问。宿主不强制优先级、不建永久绑定库、不把不同题目的材料混合。

非规范操作造成的证据缺口保持未知；现有解析能提供线索，不保证任意命名或个人习惯都能自动补齐闭环。普通代码讨论、概念问答、PDF、多网页和主动材料仍可直接求助，不以题号、拿题、CPH 或 Notebook 为准入条件。

## 2. 主要学习过程

### 2.1 围绕当前问题求助

用户拿题、编写代码、运行或测评后自然提问。Beacon 先给材料目录，再通过受控工具取得题面、代码和真实结果，区分旧稿、当前编辑稿及实际验证。

LLM 自主决定何时读当前编辑器；每次主动读取取得调用时的完整真实代码，含 dirty。harness 同次保存这份内容到当前对话代码快照队列，再按工具覆盖返回模型；不通过第二次读取或模型重写取得保存正文。一次回答内修改后可再次读取新稿，无需再发问题。发送、继续、重答、协议回放本身均不触发代码捕获。

题面默认读用户 Get Problem 已保存正文。缺失或需刷新时，LLM 可按需调用五站现有只读取题链路，结果仅进入上下文；不创建源码、不导入 CPH、不展示或切换面板，不回写已保存题面、用户查看时间或队列次序。登录仍由用户完成，失败如实说明。

### 2.2 随追问调整讲解

用户可以先要提示、随后要完整解答，也可要求保留语言和结构、跳过已会部分或补讲原理。Beacon 遵从最新要求，修正被指出的问题，区分事实、推测和未知。旧结果可解释改稿背景，不能证明当前代码通过验证。

### 2.3 按明确请求沉淀资产

用户明确要求时，Beacon 使用已获准材料创建或修改笔记、讲义或图示，保留探索过程及真实验证状态，按目标资产规则交付。Notebook 仍是独立学习文档与用户执行工具，不依赖 Beacon，普通求助也不以建笔记为前提。

当前代码工具读取后的快照保存属于本对话上下文管理，无独立模型保存／删除工具，不需先请求生成笔记，也不修改学生源码。读取成功而保存失败或超限时，仍返回实际代码并明确未保存，不阻止发送、不撤销已接受的问题、不伪造可回读 ID，原队列保持。

### 3.1 当前队列与读取规则

工作区选择是软件层用户行为采集的资格；有效根下三档持续采集落盘，Blackout只裁切Beacon消费。该分工不使Blackout聊天、代码工具读取或模型联网取题获得额外持久化。

| 材料 | 作用域与数量 | 顺序和更新依据 |
| --- | --- | --- |
| Runner、CPH、Notebook、OJ 执行／测评凭证 | 当前 `.beaconWork` 跨对话共享，四个 producer 各 20 条，互不挤占 | 真实功能 owner 更新；实际活动记录受保护，收尾后回普通淘汰规则 |
| Get Problem 题面记录 | 当前 `.beaconWork` 跨对话共享，13 条，键为题目＋代码文件，保存正文和实际用户查看时间 | 用户再次 Get 同题同文件更新正文与查看时间并移队尾；同题不同文件分别保留；模型读／联网不改变队列 |
| 代码快照 | 当前对话私有，Spot／Flood下默认10份，单份完整正文最多256 KiB＝262144 UTF-8字节；Blackout禁该来源能力 | 实时重读同文件同完整内容复用并移队尾，内容变更新增，不同文件不合并；历史读不晋升；自动淘汰 |

目录只给来源、时间、版本和可读入口，不把全部正文自动注入请求。代码快照跨编辑旧问题／重答仍按整个对话可读，不查原分支成员关系；其他私有材料、消息、要求和许可继续受有效分支约束。代码分页不跨调用 pin，淘汰后如实失败；共享近期精确凭证首次成功读取后在本回答固定 producer/id/revision 的规则另行保留。

### 3.2 共同边界

- 算法导师定位保持，正常学习可讨论完整解法，明确作弊请求按既有边界处理。
- Beacon 不创建或修改学生 C/C++ 源文件，不自主 Shell、运行、停止、登录或交题；用户功能由各自 owner 负责。
- 页面、工作区材料、文件和历史执行真实权限与敏感过滤；共享事实和本对话代码队列不开放其他聊天的消息、摘要、附件或许可。
- 进一步联网查询个人信息依真实许可及范围，由既有提示规则引导；页面、登录、摘要或自写记忆不扩大许可。
- Blackout只裁切Beacon能力：对话代码快照、Get正文、共享近期及其他持久材料的目录／读取／调用写入均不开放给Beacon，也不设内存镜像队列。BeCoder软件层在正常所选工作区仍持续采集Get Problem和四类用户执行／测评记录；这不额外持久化Blackout聊天或代码工具结果。打开代码编辑页正文、文件名和路径以及普通已加载对话沿既有流程可用，代码只正常tool返回；题面走OJ Connect联网，运行／测评及Get持久记录不从页面补读；切回持久化不补存先前读稿。
- 模型不可用时，核心编程流程和独立 Notebook 继续可用。

工具调用可视化是负责人已提出的后续需求，用户应能看到实际代码读取行为；精确界面尚未设计、尚未交付。本阶段保留真实调用与结果的协议依据，不把完整可视化 UI 静默纳入基础阶段。三档、草稿、分流、备份、占用和取消规则见附录。

## 4. 保留的候选愿景

- 私有学习资料与知识库：笔记、题解、模板和队内材料的可追溯使用与管理。
- 成长与复习：描述性学习观察、训练节奏和复习建议。
- 个人风格与模板：依据用户自己的代码辅助生成，保留用户控制。
- 翻译、图示、文献与其他学习资源。
- 比赛资料、找题、官方题解优先及 PDF 到评测材料等扩展。
- 更多材料入口与格式、对话标题、搜索、导出、分享及可解释性体验。

对应 FUT03–FUT12。教学记忆、主动 dream 和完整视觉是已确认后续能力，不能统称候选。候选技术、独立开关及具体费用体验保持各自未决，不因入表排入本阶段。
