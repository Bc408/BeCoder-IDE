# Beacon 模型输入压缩提案

日期：2026-11-22。状态：按负责人最新[队列修订](decisions/context-queues.md)整理的当前设计稿，供书面审阅。已认可的取舍包括：每次实际模型请求前检查、完整工具批次之间同步整理、当前选定模型、有效输入预算 90% 主动线／60% 目标线，以及同一普通待发步骤至多一次整理修复。本文落实摘要投影、前缀有效性和整理自身的容量边界，不代表执行计划已批准或产品已实现、测试通过。[固定版本源码对照](research/2026-11-22-compaction-comparison.md)另列观察证据。

## 1. 压缩对象与独立生命周期

压缩只生成后续模型输入所用的上下文摘要投影，不管理代码队列淘汰。以下对象分别保留各自身份：

| 对象 | 本方案的作用 |
| --- | --- |
| 原始聊天、普通工具完整结果与真实协议 | 保留实际已有内容和调用／结果配对；摘要不覆盖 UI 原文，不将原本完整返回的结果改成摘要，不伪造被工具分页省略的部分 |
| 有效模型输入 | 使用适用摘要、保留尾部及之后的有效消息；被摘要覆盖的原始前缀不再逐次全量装入 |
| 本对话代码快照队列 | 独立按整段对话管理，默认 10 份，自动淘汰；压缩不决定保存、晋升或删除 |
| 共享近期材料及其他私有材料 | 按原 owner、作用域、版本和分支规则读取；压缩不改动它们的队列或凭证 |

发送不自动捕获代码。只有 LLM 主动调用当前编辑器代码读取工具，harness 才保存同次取得的完整真实内容，包含 dirty 修改；保存与返回不得偷换成第二次读取。单份正文最多 256 KiB，即 262144 个 UTF-8 字节。同文件同内容复用并移到队尾，变更内容新增；不同文件不合并。超限或读取成功但保存失败时，仍返回实际代码和诚实的未保存状态，不保存截断副本、不伪造可读快照 ID，原队列保持。工具结果的实际分页覆盖与完整快照保存状态分别说明。没有独立的模型保存／删除工具。

历史代码读取不晋升队列、不新建副本。编辑旧问题或重答不使本对话队列内的代码快照失去可读性；跨对话读取仍禁止。代码队列不校验原分支成员关系，也不为跨调用分页额外固定快照：目标已淘汰时如实失败，不用当前稿补齐旧版本。已返回的普通工具内容仍在原协议中，不能据此声称独立快照仍可取得。其他分支私有材料、旧消息、要求及许可继续按有效分支过滤；历史代码可读不恢复被舍弃的许可，也不表示旧执行结果验证了当前代码。

Runner、CPH、Notebook、OJ 四类执行／测评来源在当前 `.beaconWork` 跨对话共享，各 20 条；Get Problem 队列为 13 条，按题目＋对应代码文件去重，保存题面和真实用户查看时间。用户再次 Get 同题同文件才更新正文、时间并晋升，模型读取不改序。共享近期精确凭证的首次读取固定版本规则独立保留，不将代码分页无保护的规则推广到它们。题目线索由现有文件名／目录解析、CPH 关联和真实 Get 记录提供，LLM 结合提问选择讨论对象；不新增永久绑定库或宿主强制优先级。

模型联网补取／刷新题面只将实际结果交给上下文，不新增缓存、不回写 Get Problem 正文、查看时间或次序，也不触发创建源码、导入 CPH、打开面板等完整拿题副作用。正常用户五站 Get／导入流程保留。上述生命周期由对应设计负责，此处只规定压缩不能改变它们。

Blackout保留本窗口已打开代码编辑页正文、文件名和路径及普通已加载对话内容；题面直接调OJ Connect只读联网，不读取编辑器题目页面。运行／测评只以持久化记录作一等来源，所有档位不增对应页面读取，Blackout裁切记录后不从页面补读；所有持久化上下文来源的目录／读取／写入能力对Beacon不可用，不用镜像内存队列替代。压缩可处理其当前正常临时输入投影，但不读取或保存持久摘要／材料，也不借缓存重新开放被裁切来源。软件层用户行为采集独立于本段模型能力：有正常所选Beacon根时，三档都持续保存真实Get Problem／执行／测评记录，Blackout不关闭生产者；未选根或根失效则不落盘这些材料。工具调用可视化是已记录的用户需求，具体 UI 尚未设计，不能因本方案写入而声称已交付或将完整 UI 默认为底层阶段工作。

## 2. 同步关卡与安全切点

每次实际模型请求准备完成后先本地计量，需要整理时由同一会话 owner 同步完成，再准备普通请求。使用本次问题已捕获的连接和当前选定模型，不自动切换模型，不引入后台整理、并发安装或排队补发。

切点必须在已闭合的消息／工具交换单元之间。不能在流式半句、工具参数半段或当前批次工具仍在执行时替换投影。较早已完成调用和结果成组进入摘要，最近完整批次成组保留；不能留下孤立结果或通过协议重建重演已完成工具。

当前问题原话、已有材料引用、最近完整工具批次和必要的未完成回答状态作为尾部保留，不要求预先为 focus 创建快照。一个问题跨很多步骤时，较早已完成步骤可被摘要，不强制保留整个用户轮全文。

工具新增分页应适配本次可返回预算，给出 nextOffset 和真实覆盖。问题、附件或必须保留的单个交换自身过大时，明确反馈容量不足，不默默截断、不用反复压缩旧历史掩盖单条超限。

2026-11-23候选修正：普通请求发出后，工具结果按剩余输入硬容量B保留余量，不再要求结果始终留在主动整理线T之下；完整工具批次闭合后，下一待发步骤仍按T检查和整理，最终出站硬检查保持。当前问题同时属于摘要覆盖前缀与保留尾部时，整理请求只在尾部提供该同一观测一次，不删除独立用户消息或原附件。

## 3. 每次请求的预算与计量

### 3.1 输入硬容量、主动线和目标线

```text
C = 当前模型已解析的总上下文额度
I = 当前模型已解析的最大输入额度
O = 本次实际请求的有效输出预算，与 maxOutputTokens 一致
B = min(I, C - O)          # 本次请求的输入硬容量
T = floor(0.90 × B)        # 普通待发步骤的主动整理线
G = floor(0.60 × B)        # 普通待发步骤整理后的输入目标
```

B 必须为正。O 只预留一次，10% 是输入估算和整理材料的余量，不再扣一次输出。用户没有手设输出上限时，采用已解析输出额度并显式约束实际请求，不能只预留 8K 却允许适配器请求更大输出。reasoning 计入输出时一并预留；配置、提供方限制和估算口径保留来源，不按模型名称猜真实窗口。

以当前配置缺省值 C=32768、I=24576、O=8192 为例，B=24576、T=22118、G=14745 token。缺省配置不证明服务真实支持该容量；90%／60% 是 Beacon 的已认可取舍，不是三项目共同默认。

服务或用户已明确提供C但未单列I时，I由该C约束，不能继续套用无容量信息时的24576缺省上限；B仍扣除本次实际O。显式I继续优先。例：C=1048576、O=393216且I未提供，B=655360；不能将正常目录和工具定义误判为超出24K输入。

每个请求都必须满足其实际完整输入 E <= B，才能发出。主动线不是硬容量：普通请求 E >= T 时先申请本步骤唯一一次整理；若整理请求本身不能合法装入，不得先发一个已知超 B 的请求试运气。服务仍可能因估算误差拒绝，按第 7 节有界处理。

普通待发请求与整理请求分别按各自实际 O 计算 B。整理提示、只读工具 schema 和取材续轮结果都计入整理输入；不可用普通请求的较小输出预算替整理请求预留。普通步骤的 T／G 不被整理内部请求的预算替换。

### 3.2 完整输入与有效 usage

E 包含实际出站的导师规则、工具 schema、动态目录、适用摘要、有效消息、附件表示、工具调用与结果，以及适配器附加内容。未读入请求的磁盘代码正文不计入 E，目录和引用本身需要计量；不能因为文件仍在就自动加载 10 份全文。

优先使用同提供方、模型、输入投影及契约下最近有效 usage，再加尚未计量的新内容。模型、摘要、分支内容或系统／工具契约变化后重建锚点；纯追加可用有效锚加真实增量。错误、取消和全零 usage 不作锚；缓存输入仍占窗口，不扣除、不重复累加，更不能用累计费用代表窗口。

没有可靠 usage 时，对完整准备输入保守估算，优先匹配 tokenizer，否则按 UTF-8 字节和协议开销估算；图片及其他媒体单列覆盖与未知。不把中文、代码、图片统一按字符串长度除以四称为准确计量。估算性质与服务端真实拒绝分开记录。

2026-11-23负责人补充确认：图片token无法可靠估计时，保留图片并允许请求，明确标注媒体估算未知，不将缺失用量填0或声称完整精确计量。此时先对所有可计量／可估部分执行本节容量与触发检查，未知图片本身不单独阻止发送；服务端明确超限后仍沿同一步至多一次恢复，无合法容量则诚实停止，不静默丢图、裁图、OCR或换模型。整理中的未知媒体同样保留并标注，整理自身若被拒绝则停止，不递归整理。

### 3.3 普通请求入口

| 入口 | 必须核对 |
| --- | --- |
| 新问题首发 | 原问题、附件、实际 focus 元数据和目录；没有发送时读存代码 hook |
| 继续／编辑／重答 | 当前有效消息、摘要适用前缀、原问题身份和本次模型；失效锚点重新估算 |
| 工具续轮 | 当前批次全部真实结果及 JSON／媒体适配；闭合后再检查 |
| 换模型 | 新模型 C／I／O、协议可用性和完整输入；旧 usage 不能证明新窗口可装入 |

最终适配如再增加材料，必须回到同一步准备入口复核，不能在计量后悄悄扩充输入，也不因重新装配刷新整理修复额度。

## 4. 摘要前缀身份与编辑／重答

摘要记录必须能证明“当前有效历史的哪段前缀被概括”，不能只凭最后一个消息 ID 或整段对话 revision 判断。由 harness 记录本对话身份、覆盖终点、覆盖前缀内消息及实际协议内容的身份／修订指纹；若输入含旧摘要，还记录其覆盖依赖。前缀身份覆盖顺序与内容，复用消息 ID 后正文或工具结果变更也会被发现。具体字段可沿已有消息 ID、协议与会话存储补最小记录，不另建历史索引库。

每次装配和重启恢复先从当前有效原始消息核对，只有覆盖前缀及其依赖仍匹配的摘要才能使用。可用的未受影响前缀摘要可以保留；不要求为了本方案无限保存每个旧摘要版本，没有合法摘要时从有效原始消息重建。

| 变化 | 摘要选择 |
| --- | --- |
| Q1–Q8 已摘要，编辑 Q3 | 覆盖 Q3 及其后旧内容的摘要失效；如已有仅覆盖未变化前缀的合法摘要可用，则保留该份，否则从有效原文重建 |
| 重答摘要覆盖区内的回答 | 回答及工具协议已变化，相关摘要及依赖它的后续摘要失效，即使问题文字不变 |
| 只编辑／重答摘要终点之后的尾部 | 覆盖前缀不变则保留摘要，尾部从当前有效历史重建，重新计量 |
| 纯追加新问题或新工具批次 | 覆盖前缀不变则继续使用，不能只因对话 revision 增加使全部摘要失效 |
| 重启 | 重新核对原始有效前缀及依赖；失配摘要不安装，不恢复旧要求、许可或旧分支正文 |

提交时的并发 revision 校验仍沿原生保存机制执行；它与摘要长期适用性不同，不能把“整个会话 revision 相等”当作唯一有效性条件。换模型需重新计量、清理不支持的协议字段；历史摘要是否仍适用取决于前缀内容与权限，不因旧模型 usage 失效就断言摘要语义一定失效。

本节只约束摘要与其他有效分支材料，不给代码队列增加分支归属检查。被舍弃回答的代码快照仍可按整段对话队列读取，但不得将其周围旧文字、许可或未完成动作重新纳入摘要。

## 5. 整理阶段输入、产出和禁止递归

整理输入包含可信整理目标、当前问题和必要尾部、仍适用的旧摘要、本次待整理有效前缀及必要材料目录。材料继续保持不可信身份，摘要不能被提升为系统授权。模型保留题目和代码版本、用户最新纠正、已理解与仍卡住的点、真实验证与未知、完成工具事实和下一步，不压成通用教学套话，不把执行稿当作当前编辑稿。

模型最终只返回：

```ts
{ summary: string }
```

覆盖边界、前缀身份、会话／根／模式／epoch 和捕获连接由 harness 绑定，不由模型编造。没有代码删除 ID、模型价值淘汰或摘要与代码队列联合提交。

必要取材只允许对已有且获授权材料作无写入读取，如仍可取得的历史代码和已消费凭证；历史读取不晋升代码队列。整理不开放新建代码快照、首次固定共享凭证、编辑 Notebook、运行、交题或完整 Get Problem 等会改变资产的工具。需要新鲜编辑器代码时由普通回答阶段另行真实读取，不用新稿冒充旧版本。

整理活动具有明确阶段身份：

- 初次整理请求及每次只读取材后的续轮均按本次实际 C／I／O 和完整 E 检查硬容量，保留真实调用／结果与计量。
- 整理请求即使达到其 90% 主动线，只要仍在硬容量内，可在现有整理活动中继续；不触发第二层整理，不对整理本身或其只读工具续轮再次摘要。
- 只读取材沿既有工具步数限制有界执行，不因续轮重置总步骤、取消或恢复状态；没有合法容量、步骤耗尽或返回截断则结束失败。
- 整理内新增工具结果不创建新的普通待发步骤，不重置、递归消耗或补发原普通步骤的整理修复额度。整理协议如被记录，保持整理身份，不伪装为原普通回答已执行的步骤。

## 6. 摘要校验、发布与恢复

1. 当前工具批次闭合后捕获本次有效前缀、保留尾部、会话和执行身份；模型完整返回，结构合法，非取消、非截断。
2. 重核本对话、覆盖前缀及旧摘要依赖、根／模式／epoch 和捕获连接仍有效。发生变化时不安装过期结果；在普通步骤原有额度内结束，不自动另开整理。
3. 预览“当前可信规则＋新摘要＋保留尾部＋当前请求”的最终输入并计量。目标是 E_after <= G；最低可发布条件为比整理前严格缩短、E_after < T 且满足实际硬容量。低于 T 但未达 G 可如实记录目标未完全达到；不立即再整理相同材料。
4. 持久模式由ChatHistory串行writer的明确提交入口保存摘要及覆盖身份，确认成功后切投影。候选提交前隔离于普通this.data／pending，等待在途checkpoint后从最新合法会话克隆提交，失败候选不能被之后普通checkpoint补存；成功后合并更新内存及待写状态，后续checkpoint不得回滚已提交摘要。沿现有revision冲突处理，不新增pending文件或恢复队列。
5. Blackout 仅在当前内存会话发布，禁止读取／写入持久摘要。重启恢复持久会话时只加载并核对已完整保存的摘要；没有已提交摘要则使用合法旧投影或有效原文。

生成、校验、保存失败或提交前取消不发布草稿，原始聊天、普通完整工具结果、原有合法摘要与代码队列保持。若旧摘要已因编辑失效，不因本次失败重新启用它；从当前有效原始消息重建，无法合法装入则停止。取消与提交竞争由现有会话 owner 串行确定，已提交则如实报告已生效；后续普通请求失败也不伪称摘要未提交。

摘要发布不改变队列次序或删除代码，不触发清理缓存来回收代码正文，更不在重启时追补模型删除。代码自动淘汰是否发生由独立队列正常操作决定。原始协议中仍有旧代码片段不代表独立全文存在；摘要仍有旧版本说明也不恢复已淘汰正文。

## 7. 普通待发步骤的有界恢复

| 情况 | 处理 |
| --- | --- |
| 普通步骤 E >= T | 同步整理一次；发布合法投影后准备并发送原步骤 |
| 服务明确拒绝上下文过长，本失败步骤尚无正文／reasoning／工具参数输出，也未执行本步骤工具，且未用过整理额度 | 整理一次后重建该步骤；之前步骤已完成工具和实际结果保留，不重执行 |
| 本步骤已整理仍超限、无可整理前缀，或结果未缩短至 T 以下 | 停止本次 Beacon 请求，保留真实状态，说明容量不足，不循环整理 |
| 当前失败步骤已开始输出或执行 | 保留真实部分回答和完成事实，沿用户显式继续／重答处理，不透明从头重演 |
| 整理自身／取材续轮超 B、服务拒绝、输出截断、结构非法或失败 | 停止本次整理及依赖它的普通待发请求，保留原始有效材料；不递归整理、不任意砍掉旧输入并声称已概括 |
| 网络瞬错 | 沿既有有限运输恢复；改变历史后的请求属于新语义请求，不冒称原请求同字节重发 |

一次额度绑定同一个普通待发模型步骤，主动整理和上下文拒绝修复共用。真正完成普通工具批次并取得新结果后才进入下一普通步骤并重新检查；整理阶段自身的读取结果不满足此条件。SDK 重试、重新装配和模型响应开始均不擅自重置额度；已完成工具次数、回复身份及工具总步数保持。

可记录本步骤的有效前缀／模型预算指纹，避免未变化材料重复尝试。切换到小窗口仍用当前模型；若连合法整理请求也装不下，明确停止。后台预摘要、跨模型整理、分层历史批处理和任意舍弃旧原文不在本轮首版。
