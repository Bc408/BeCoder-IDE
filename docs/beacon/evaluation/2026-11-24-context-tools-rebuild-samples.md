## S02-1／第1轮

审阅：正确定位漏项；仍有额外边界展开。

用户：

左边A.cpp求和漏了最后一项，右边B.cpp只是参考；帮我定位A.cpp，不要改B。

实际工具：readCurrentCode

模型原答：

A.cpp 里求和漏最后一项，问题就出在循环上界：

```cpp
for(int i=0;i<n-1;i++) s+=a[i];
```

`i < n - 1` 使最后一个下标 `n-1` 从未被访问，所以只累加了 `a[0]` 到 `a[n-2]`，共 `n-1` 项。比如 `n=4` 时只加了 `a[0..2]`，`a[3]` 丢掉。

最小改动（只动 A.cpp，B.cpp 保持原样）：

```cpp
int sum(int*a,int n){int s=0;for(int i=0;i<n;i++)s+=a[i];return s;}
```

也就是把上界从 `n-1` 改成 `n`。这样 `i` 取到 `n-1`，正好覆盖全部 `n` 项。

顺带确认一下边界情况：如果 `n` 可能为 0，上面的写法返回 0，是正确的（空数组和为 0），不需要额外特判；原写法在 `n=0` 时 `n-1 = -1`，循环条件 `0 < -1` 为假，也是返回 0，所以这次改动只影响漏掉的最后一项，不改变空数组的行为。

## T03／第4轮

审阅：明显数学错误：两个任意64位整数相加仍可能溢出，long long只能在已证范围内保证。

用户：

上一问改成：只解释C++中long long为何适用，不需要题面、运行和磁盘。

实际工具：本轮无新调用，沿有效历史。

模型原答：

`long long` 适用的原因只看类型本身：

1. **宽度有下限保证**：C++11 起标准规定 `long long` 至少 64 位（实际平台基本就是 64 位）。因此它一定能表示约 `±9.22×10^18` 的整数（有符号范围 `[-(2^63), 2^63-1]`，具体精度由平台决定，但下限已足够大）。

2. **加减不溢出**：两个同量级的 64 位整数相加，结果仍远在 `long long` 范围内，不会触发有符号溢出。相比之下，`int` 标准只保证至少 16 位，常见平台是 32 位（上限约 `2.147×10^9`）；一旦和超出该范围，有符号溢出在 C++ 中是**未定义行为**，结果不可预测，不能靠“溢出后回绕”来碰运气。用 `long long` 就从类型层面排除了这个风险。

3. **与代码配套**：你写的是 `long long a,b; std::cin >> a >> b;`，`cin` 直接按 `long long` 解析，`a + b` 的运算也在 `long long` 下进行，最后 `cout` 按 64 位整型输出，类型链路一致，不会在中间被截断或提升错位。

简言之：`long long` 不是“够用就行”的经验选择，而是有标准保证的最小宽度，使这类整数加法的结果必然可表示，从根上避免有符号溢出这一未定义行为。
