# Beacon 总体架构

修订日期：2026-11-22。本文为现行架构设计，直接合入负责人已确认的产品决定；接口与执行计划待审阅。当前代码差距见[实现状态](implementation-status.md)，不将设计表述作为已交付能力。

## 1. 目的与文档职责

Beacon 是 BeCoder 中可选的算法与编程导师，跟随用户当前学习活动理解代码、题目和真实结果，通过对话推进理解。Notebook 是独立、可选的学习资产；普通求助不以生成笔记为入口。

[能力需求](prd.md)维护完整能力与验收条目；本文描述所有者与数据流；[底层阶段设计](foundation-design.md)定义本轮交付；[执行计划](../superpowers/plans/2026-11-22-beacon-foundation-implementation.md)给出源码差量、接口和检查。已确认取舍的追溯依据见[队列决策记录](decisions/context-queues.md)，源码研究见[三项目对照](research/2026-11-22-compaction-comparison.md)。设计、当前实现与实际验收分别成立。

## 2. 工作区、模式与材料链路

工作区选择与模式选择分别控制两件事。**软件层采集只依赖发起窗口已选择且正常可用的Beacon工作区**；未选根或根异常时不生产这些持久记录、不写替代位置。有效根下，用户Get Problem、Runner、CPH、Notebook、OJ Connect的真实行为持续按规则采集和落盘，不依赖聊天、模型或Blackout／Spot／Flood。**模式只裁切Beacon可消费的上下文能力**：Blackout看不到这些持久来源；Spot／Flood可按权限消费。切回Spot／Flood后可读取队列内仍保留的Blackout期间记录。

1. **用户行为形成共享近期凭证。** 用户 Get Problem、支持的导入、Runner Run／Run With Input、CPH 测评、Notebook input 运行、OJ Connect 提交或查询，由对应 owner 记录实际取得的内容。采集不依赖聊天打开或模型配置，材料在当前 `.beaconWork` 内跨对话共享。
2. **LLM 读取当前代码形成本对话快照。** 模型按需调用编辑器代码工具，宿主取得当下完整代码含 dirty，同次保存到本对话有界队列，再按预算返回正文。发送问题不捕获代码；模型决定读取时机，队列执行保留策略。
3. **LLM 读取题面形成当前上下文。** 模型默认消费已保存题面，也可通过五站现有只读解析链路补取或刷新。联网结果仅进入上下文，不新增题面缓存，也不改写用户 Get Problem 记录。

模型负责理解、选择正在讨论的对象及教学；owner 负责取得事实、执行真实读写并反馈结果。用户明确要求写笔记等学习资产时，沿资产原生 owner 执行，不改变以上记录归属。

## 3. 所有者

| 所有者 | 职责 | 边界 |
| --- | --- | --- |
| 编辑器／页面 owner | 打开的代码编辑页正文、文件名、路径、版本、未保存修改及用户主动材料 | Blackout也保留代码页正文／文件名／路径；页面读权不授backing file或目录访问，不以功能页面供应题面／运行／测评事实 |
| OJ Connect／内置浏览器 | 用户真实 Get Problem／导入／交题／查询结果；五站只读题面解析 | 用户行为与模型取材区分；Beacon 不获得登录、提交或任意浏览器执行能力 |
| CPH | 已有代码—题目关联、样例与用户整轮测评 | 查询关联不建本地题、不导入、不改样例；其他 CPH 题源不自动获五站完整闭环 |
| Runner／CPH／Notebook 执行者 | 实际编译稿、输入、配置、诊断、输出与终态 | 保留来源结构、合流和覆盖，采集不新增执行 |
| BeaconStore／Coordinator | 根与模式、会话占用、共享队列、对话代码队列、原子发布及受控读取 | 执行时校验真实窗口、根、epoch 和 owner；不另建数据库、绑定库或永久归档 |
| ContextTools／原生接口 | 元数据目录、题目线索、实时代码及历史队列读取、局部 selector 和分页 | 返回真实版本与覆盖；共享凭证和代码快照有不同的分页生命周期 |
| 会话／协议 owner | 原始消息、工具交换、有效分支、摘要投影和恢复 | 重放不执行工具；代码队列按整个对话可读，其他分支私有内容仍按有效历史检查 |
| 提示与 provider | 每步导师规则、实际工具能力、最终输入计量、模型适配 | 用户原话、外部材料和摘要不成为新的产品规则；活动回答固定起始模型配置 |
| 学习资产 owner | 明确请求的 Notebook／讲义等合法编辑、备份和保存 | 不修改学生源码，不伪造执行结果；独立文档不随聊天队列淘汰 |

这些是已有模块内的逻辑职责，不要求一行对应一个新服务。

## 4. 数据归属与保留

| 对象 | 保存与读取范围 | 生命周期 |
| --- | --- | --- |
| Get Problem 记录及题面 | 当前 `.beaconWork` 共享，含题目、对应代码文件、用户查看时间、解析正文与来源 | 上限 13 条；按题目＋代码文件去重，用户再次获取同一对更新查看时间并移到队尾；同题不同文件分别保留 |
| Runner／CPH／Notebook／OJ 凭证 | 当前根共享，保留各自结构 | 各来源 20 条且互不挤占；真实活动记录额外保护，任务收尾回归正常裁剪 |
| 对话代码快照 | 仅当前对话，来源为模型实时编辑器代码工具读取 | 默认 10 份，每份完整 UTF-8 正文最多 256 KiB；相同文件相同内容复用并移到队尾，否则新增，自动淘汰旧项 |
| 模型联网题面 | 实际工具结果进入上下文 | 不增加专门持久化、不回写题面队列；不能伪造用户查看行为 |
| 消息／附件／草稿／旧私有材料 | 当前会话 | 有效分支与原始留存区分；归档、删除、切档继承沿既有规则 |
| 摘要投影 | 当前会话有效历史 | 同步发布；绑定覆盖前缀，受编辑／重答影响时失效；不删除原始聊天或代码队列 |
| Notebook、工作区记忆 | 各自资产 owner | 与聊天、队列、压缩独立；记忆与 dream 的进一步实现保留后续 |

共享限定当前 `.beaconWork`，不是应用跨根的全局材料库。代码快照即使来自被重答舍弃的回答，也在本对话队列有效期内可读；不会恢复该回答的文字、用户要求、许可或其他分支私有材料。工具调用可视化已列为需求，其界面设计和交付单独审阅。

## 5. 题目识别与题面

完整正常流程覆盖洛谷、Codeforces、AtCoder、牛客、蓝桥。Get Problem 成功即提供题目与代码文件线索，不等待 CPH；支持 Get Problem 的对象 Import to CPH 后，已有 CPH 关联也可作为依据。仅能导入 CPH 的其他题源不自动得到完整闭环承诺。

底层向模型分别提供 Get Problem 历史行为、当前 CPH 关联和现有文件名／目录解析候选，保留来源、对象和实际时间；不硬编码唯一题目或优先级，不为关联再建持久绑定库。用户提问可指向另一题或要求对比，由 LLM 结合语意判断，无法确定时询问。

推导用于发现相关材料，不改写历史执行或提交记录的题目身份。队列记录缺少可靠题目身份时保持未知，不能用后来更改的文件名给旧记录补证。非规范使用不增加复杂补链或历史寻回承诺。

Spot／Flood默认读取用户Get Problem保存的干净题面，返回取得时间与来源；Blackout不读Get Problem来源，题面直接通过OJ Connect只读联网工具取得，不读取编辑器中的题面页面。模型联网补取／刷新仅消费既有只读解析能力，不创建源码、导入 CPH、打开或切换题面面板；登录由用户完成。成功只产生新观测，失败反馈真实状态；既有 Get Problem 正文、查看时间和队列次序都不因模型取材改变。无定时刷新或后台抓取。

## 6. 代码工具与两种分页契约

模型每次新读当前代码时，按跟随／显式指定的有效目标解析当前版本，包含未保存修改，不被发送时旧版本锁定。同次实际读取提供保存正文与本次返回，不能保存时再读一次替换内容；无需跨调用保留未沉淀全文，也无独立模型保存或删除快照入口。

保存失败或正文超过 262144 个 UTF-8 字节时，工具仍可返回实际读取及分页，明确保存状态，不给虚假快照 ID，不保存截断快照，不改变原队列。快照保存不是发送前置。

- **对话代码快照：**按快照 ID 读取稳定正文。历史读取不新增或刷新队列次序；跨次分页没有额外占用保护，若已淘汰则返回不可得，不拿新版本补齐。无法保存的实时稿只能在原页面身份与版本仍匹配时继续分页，变版后明确失败。
- **共享近期凭证：**首次成功读取精确 producer／id／revision 后，在当前回答内保持固定版本；后续 selector／分页不被队列更新或淘汰混版。首次读前已变化或淘汰则明确失败，下一回答重新核对队列。

共享记录读取不再调用 consumeRuntimeRecord 将整条原记录复制到每个聊天；实际工具返回继续保持正常协议身份。完整快照仍在磁盘不表示已全量进入模型上下文，部分读取也不表示模型见过全文。

## 7. 请求、协议与压缩

新问题准入固定连接、模型能力与参数、合法会话范围，不自动读取代码正文。每次实际请求重建可信导师规则、实际工具说明、有效历史、材料目录与用户原话；模型按需取正文。目录中同题旧结果保留真实代码关系，比较注明哪次代码观测和哈希口径，不将历史 AC／WA 认作新稿验证。

回答失败／中断后的已完成工具交换在有效历史内保留，恢复和重放不能再次执行。编辑或重答丢弃的分支不进入后续文字输入；普通私有材料的内存命中与原生回退均检查有效分支。对话代码队列单独按会话 owner 校验，不与原工具消息的分支存活绑定。

换模型保留正常消息和工具交换；只有 provider／baseURL／model 完整兼容才保留相应私有字段，其他来源的 reasoning／providerOptions 不转成普通文字，不递归删除业务结果的同名字段。

[同步压缩设计](context-compaction.md)仅管理有效模型输入。沿当前模型，B=min(最大输入额度,总窗口−实际输出预算)，90% B 主动整理，目标约 60% B；首发及每次工具续轮都在完整批次后计量。同一个待发步骤至多一次整理修复，整理自身及其取材续轮不递归整理，合法输入装不下则停止。完整摘要经可确认的串行会话提交成功后才发布新投影，失败候选不能混入之后的普通checkpoint，原文保留；代码队列仍独立自动淘汰。

## 8. 权限、失败与并发

页面、磁盘文件、工作区共享记录、私有会话和模型联网分别按现有根／模式／敏感信息边界执行。Blackout相对Spot／Flood只对Beacon作能力裁切：Beacon不能列举、读取或调用写入这些持久上下文来源，包括代码队列、共享近期、Get正文及其他持久材料；不额外建立内存队列或替代机制。本窗口已打开代码编辑页的正文、文件名和路径，以及正常已加载对话仍可用；代码工具只返回实际内容、不保存；普通临时输入的摘要投影不读写持久来源。跨类别继承只复制已合法加载内容，不跟随原持久目录补读；根或模式失效不回退到别的保存位置。

Runner／CPH／Notebook运行结果及OJ测评事实的唯一一等来源是持久化记录；不提供对应功能页面、终端渲染或Notebook outputs的备用自动读取通道，Spot／Flood同样遵守。Notebook学习资产工具的模型读口也不得返回outputs／attempt；宿主完整备份、真实输出保留和合法内容编辑继续保留。Blackout裁切这些记录后直接不可用，不从页面补读。Notebook独立文档／学习资产操作不因此取消，用户主动提供的文本仍保持主动材料身份。软件层行为凭证在Blackout也持续采集落盘；消费能力关闭不关闭生产者。运行凭证只归发起窗口有效根内的实际源码／笔记，不借 cwd、关联源码、Flood 或其他窗口扩大范围。实际执行稿采集与代码工具快照是不同链路。真实活动由协调器占用保护；停止、未知收尾和进程消失均不补造终态。保存、读取、变版、淘汰、来源缺失和截断分别反馈。

忙时冲突直接拒绝，不引入等待队列或自动补发。模型不自主 Shell、运行、停止、登录、交题或修改学生 C/C++ 源码；用户明确请求的学习资产操作仍沿原生备份和保存机制。

同一来源规则覆盖普通文件工具：自动读取／搜索`.bcnb`与`.bcnb-backup`只能取得笔记内容投影，排除outputs、metadata.becoder.attempt与executionSummary后才分页或检索；不能读取原始JSON／base64作为备用执行事实，也不能从打开为普通文本的笔记页面绕过。解析失败或不支持格式明确失败，不回退原文。投影只改变模型可见表示，不改笔记、备份、用户运行结果或用户主动提供材料的身份。

## 9. 阶段与后续能力

下一阶段覆盖材料生产、队列、线索、工具读取、模型输入与压缩，并补齐完成工具事实、有效分支和换模型协议。Notebook 独立使用、三档、草稿、历史和既有教学要求均提供保护回归。

工作区 tips/status、主动 dream、完整视觉、更充分的本人同题历史及学习资产完整体验继续保留为后续能力。知识库、复习、风格模板和其他候选不自动扩入本轮；工具调用可视化的真实事件接口需兼容本轮，但完整 UI 不在本计划中默认交付。

## 10. 验证与交付

[执行计划](../superpowers/plans/2026-11-22-beacon-foundation-implementation.md)把上述契约分配到各 owner 和回归。工程检查验证机制与出站事实；合成场景的强模型观察验证材料使用与教学语义；五站真实流程和负责人体验分别验收。Ollama 4B 仅作工具兼容和链路冒烟。历史模型评估、文档检查或旧构建均不代表本轮实现和体验通过。

旧设计与评估只保留历史身份，来源见[来源索引](sources.md)。文档状态、源码验证、模型观察和负责人验收分别记录。
