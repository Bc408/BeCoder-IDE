# 内置浏览器题目按钮与导入分工设计

日期：2026-11-17。状态：负责人已确认设计并授权实施；本轮源码已进入实现与验证，stage 与负责人真实验收分别记录。本文定义目标，不用设计批准替代运行验收。

## 目的与基线

在内置浏览器找到题目后，用户通过一个带副菜单的按钮选择“打开 OJ Connect 题面”或“导入 CPH 样例”。前者衔接看题和线上提交，后者保留既有开源解析器与本地测试；同一支持题目的两种入口应使用同一份源码。

编写时基线为 `OJ_connect@569cfb3b84e2e42ad712fd8925c2c0b37c7b1a9b`，跟踪 `origin/OJ_connect`，工作树在新增本文前干净。三站为洛谷、AtCoder 和牛客当前已接入的题目范围，不因域名相同而扩展到尚未支持的题型或入口。

设计时的 `browserProblemFeature.ts` 只有 Import Problem：识别三站题目时读取 OJ Connect 题目并调用 `importFromBrowser`，其他页面才调用 CPH `parseProblem` 和 `_becoder.cph.importProblem`。本轮以两个明确动作替换这个分流行为。

产品边界继续遵循 [VISION](../../../VISION.md)、[OJ Connect 架构](../../oj-connect/architecture.md)和负责人最新决定。原架构中“浏览器 Import 导向源码与插件题面”的描述属于设计前的实现；现行架构说明已按两个明确动作更新。

## 已确认的交互

浏览器工具栏只占用一个分体按钮位置：

- 左侧主按钮使用 OJ Connect 现有图标，固定执行 `Get Problem`，悬停显示动作名称。
- 右侧是独立下拉箭头，始终可以展开菜单，不跟随主按钮置灰。
- 菜单上项为 `Get Problem`，下项为 `Import to CPH`；后一项使用 CPH 现有图标。
- 选择 CPH 后不切换主动作，不保存上次所选项，也不增加用户设置。
- 沿用编辑器分体按钮的尺寸、菜单、键盘与焦点行为，不新建 Webview 或菜单框架。现有 `DropdownWithDefaultActionViewItem` 提供固定主动作选项，可作为复用入口；不得启用记住上次动作的模式。

| 当前页面的 URL 匹配范围 | 主按钮 | 菜单 Get Problem | 菜单 Import to CPH |
| --- | --- | --- | --- |
| OJ Connect 与 CPH 均支持 | 可用 | 可用 | 可用 |
| 只有 OJ Connect 支持 | 可用 | 可用 | 置灰 |
| 只有 CPH 支持 | 置灰 | 置灰 | 可用 |
| 均不支持，或没有当前页面 | 置灰 | 置灰 | 置灰 |

主按钮置灰时提示当前页面不支持 OJ Connect 题面。菜单中的禁用项保留显示。页面加载期间禁止开始依赖完整页面的读取或解析；右侧菜单仍可打开。

可用状态只表达 URL 属于现有规则支持的入口，不代表已验证登录、权限、页面内容或网站当前结构。点击后的权限或解析错误如实提示，不为提前确认这些条件在导航时预读题面。

本页固定使用以上英文动作名，以保持本轮确认的入口文案；通过现有本地化入口组织，不顺带修改其他命令、题面按钮或 CPH 设置的文案。

## Get Problem

1. 固定本次操作所属的浏览器页面、窗口、存储范围和规范题目身份。
2. 复用当前 OJ Connect 的站点读取能力取得该题面，不通过 CPH 解析结果重建插件题面。
3. 使用当前打开的工作区根、站点目录设置和 adapter 文件名，在对应单级子目录创建或打开 `.cpp`。
4. 打开源码及其绑定的 OJ Connect 题面，题目来自本次浏览器页面，不从其他活跃编辑器文件名猜测。
5. 不初始化 CPH 元数据，不导入样例，不执行代码或提交。用户仍可在题面上显式导入 CPH。

同名源码存在时仅打开，保留磁盘内容及未保存稿。没有工作区时沿用明确提示；多根工作区只选择一次目标根。目录修改影响后续导入，不迁移已有文件。

## Import to CPH

浏览器菜单的 Import to CPH 对所有题源都继续使用已内置的 Competitive Companion 解析器；匹配三站时也不得改为读取 OJ Connect 题面，再用其样例假装完成浏览器 CPH 导入。题面内“发送到 CPH”是已有的独立入口，按下一节复用结构化题目样例，不受此处浏览器解析路线约束。

解析成功后，由 OJ Connect 对规范题目 URL 提供有限的目标定位：

| 场景 | 示例目标 |
| --- | --- |
| 洛谷 P1001 | `luogu/P1001.cpp` |
| AtCoder ABC086 A | `atcoder/abc086_a.cpp` |
| 牛客公开题 18204 | `nowcoder/18204.cpp` |
| 牛客比赛题 5657/A | `nowcoder/5657_A.cpp` |

以上目录是默认值，使用实际 OJ Connect 设置。AtCoder 非自然命名题目、洛谷必要上下文等继续由当前 adapter 的 `fileName` 规则处理，不在浏览器或 CPH 中复制规则。

命中三站支持范围时，目标为上述 `.cpp`，优先于 CPH 的自动题名和短文件名设置；不修改用户的全局 CPH 设置。新建源码继续由 CPH 执行现有模板初始化，已有源码不初始化或覆盖。CPH 接收本次明确目标并保存解析器提供的样例，显示源码和 CPH 面板，不自动打开 OJ Connect 题面。

无法匹配 OJ Connect 支持身份时，包括仅 CPH 支持的其他 OJ 或同站其他入口，继续原有 CPH 根目录、命名、C／C++ 语言选择和模板行为。不得把牛客 PAT 等入口仅按域名归入 `nowcoder`，也不转换题目归属。

目标定位失败、目录设置非法、文件冲突或读取失败不等于题源失配：此时停止并提示，不能静默退回工作区根目录创建另一份源码。样例覆盖仍由 CPH 的既有确认流程处理。

## Get Problem 后从题面发送到 CPH

保留现有第三条完整使用路径：浏览器 Get Problem → 打开对应源码与插件题面 → 在题面点击“发送到 CPH” → 显示该源码关联的 CPH 样例。它必须纳入本轮三站回归，不能只验证浏览器菜单的直接 CPH 导入。

此入口沿用题面绑定的 `sourceUri` 和 `ProblemDocument`，通过现有 `cphSamples` 与 `_becoder.cph.importSamplesForSource` 导入。无需重新解析、打开或保留原浏览器题目页；浏览器之后切到其他题目，也不能改变已打开插件题面的源码与样例归属。

只向题面绑定的已有源码关联样例，不重新选择目录、计算文件名或创建第二份源码，不重新执行模板初始化，不覆盖或保存用户未保存的源码，不自动运行或线上提交。源码绑定失效时沿用现有失效提示，不改绑当前活跃编辑器。CPH 忙碌、未保存样例及样例替换确认继续由 CPH 处理。

## 职责和必要接口

| 所有者 | 本轮职责 |
| --- | --- |
| 浏览器 feature | 当前页面、分体按钮、状态刷新和显式动作调用；验证异步操作后页面仍匹配 |
| OJ Connect | 规范题目身份、配置目录、adapter 文件名、Get Problem 的源码与题面流程 |
| CPH parser | 已有题源匹配和页面解析，保留原始样例 |
| CPH 导入与 ProblemStore | 模板、源码与样例发布、重复导入、覆盖确认、本地测试展示 |

只补足“浏览器页面适用性”和“CPH 使用指定目录及文件名”的窄接口。目标由本窗口所选工作区和扩展设置计算，网页不能提供任意写入路径。工作区根选择和校验只有一个拥有者，同次导入不连续询问两遍。

Get Problem 和 CPH 目标定位使用同一套站点身份及文件名规则。CPH 导入时不先调用会打开插件题面的完整 OJ Connect import；Get Problem 也不调用 CPH 进行空样例初始化。不引入通用导入策略框架、持久题目绑定库或第二套目录配置。

CPH 目前在 `companion/entry.ts` 根据 parser 的 `getMatchPatterns()` 选择解析器。可用性信息须从同一份既有规则取得或在构建时派生，不能手写另一份站点白名单，也不能每次刷新按钮时注入并执行整套 DOM 解析器。导航状态刷新不新增联网请求、定时轮询或题面预热。

## 并发、失败与资产保护

- 同一浏览器题目导入正在执行时，两种入口都不得再启动重叠导入；不排队，不自动重放。CPH 原有忙碌和未保存样例保护继续生效。
- 操作开始时固定 URL 和题目身份。读取／解析期间发生页面跳转、关闭、编辑器换页或工作区变化，放弃旧结果，不把旧题写入新页面对应目标。
- 两个动作共享的是文件位置规则，而非隐式级联：任一路失败只报告本路错误，不自动换成另一路。
- 重复导入、先 Get 后 CPH、先 CPH 后 Get，都复用规范目标源码；已有代码和未保存稿必须保留，样例替换仍需原有确认。
- 两次操作间修改目录设置后，按新设置定位，不自动搜寻、搬迁或删除先前文件。
- 路径合法性、目录逃逸／链接及普通文件保护继续由现有存储所有者执行；仅调整本轮需要的目标传递，不另建文件事务系统。

## 验证与交付边界

实施计划应覆盖以下验收，不在本轮设计阶段宣称通过：

1. 三站支持 URL、CPH 独有 URL、普通页面、加载和导航切换时的主按钮及两个菜单项状态；禁用主按钮时箭头仍可用，主动作不会切换。
2. CPH 匹配规则与解析入口的一致性；状态刷新不读取题面、不新增网络等待。
3. 三站默认及自定义目录、adapter 文件名、多根工作区；非支持题源保留 CPH 默认行为。
4. 两种入口的先后顺序、重复导入、已有源码、未保存稿、CPH 模板、样例替换取消，以及操作重叠与中途导航。
5. 对生产工具栏进行实际渲染检查，核对图标、分体按钮、菜单顺序、置灰、悬停与键盘操作；不能用组件测试替代页面效果。
6. 三站分别验证 Get Problem → 题面“发送到 CPH”：第一次只打开源码与题面、尚无 CPH 数据；点击后关联同一路径，样例数量、顺序、空白和换行正确，限制单位正确，缺失限制沿用 CPH 既有本地默认值提示。使用隔离练习源码显式运行本地样例，核对 CPH 确实运行该文件并显示结果，不触发线上提交。
7. 对上述题面入口验证重复点击、接受／取消样例替换、CPH 未保存样例和运行中保护；已有源码、未保存稿与用户模板均不得被重写。浏览器切题／关闭或活跃编辑器切到其他源码后仍使用原题面绑定；绑定源码删除、重命名或关闭导致失效时明确提示。
8. 验证浏览器直接 Import to CPH → Get Problem → 题面发送到 CPH，以及 Get Problem → 题面发送到 CPH → 浏览器直接 Import to CPH 两种顺序。目录设置不变时始终复用同一源码及其 CPH 关联，样例替换遵守原确认流程，不因两个解析来源不同而追加重复样例或生成第二份文件。

实施完成后按仓库要求执行拥有者回归、client typecheck、OI 扩展编译及 stage 构建，由负责人在新构建中验收。继续沿用现有许可证和组件来源；若实际搬入新增上游代码则同步登记。

登录、微信认证、会话摘要、三站提交与评测协议、题面和记录布局、共享渲染均不在本轮改动范围。不新增依赖，不重写内置浏览器底层，不自动提交真实代码。产品实现、测试、构建、Git 发布和负责人验收分别记录。
