## 原生事务与数据边界

扩展 adapter 负责题目标识、偏好和共同界面；原生 SessionClient／protocol／transport 负责固定请求、账号及发送权，bridge 只提供语义命令与 opaque handle。快捷键和提交使用当前窗口持久 Session；浏览器 Get 使用原网页 Session，含临时会话，不复制登录状态。

source/report 的发送权各在 dispatch 前同步消费一次。执行地址必须是本次 source 回执中的精确 opcenter 路径，question_id 与 problem ID 分开核对。执行完成条件只终止执行轮询，不等于 AC；正式记录须核对同 ID、题目、语言、当前账号、本题本人列表及官网源码（仅 CRLF→LF）。准备阶段保存本人记录边界以拒绝旧 ID。

每窗口立即拒绝并发，不排队、重放或恢复任务。初始执行查询3秒后有界退避，总跟踪约120秒；单请求15秒、响应4MiB、源码1MiB。取消、超时或受理不明后只 GET，包括尚未发出的 report 也不补发；无执行 ID 不扫最新 AC。report 回包丢失可用正式详情确认，不能恢复 POST 权限。

report 逐点只保留当前进程内的点序、状态、耗时和内存投影，不保存原始 result、输入输出或答案；失败布尔值不推断 WA／TLE。没有逐点时只展示正式详情汇总，关闭记录释放投影，不为补齐结果重发 report。存储范围、工作区信任、账号、窗口或扩展生命周期变化使旧权限失效，迟到结果不能交付新上下文；重启不恢复事务或最近记录。
