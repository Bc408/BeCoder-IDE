# OJ Connect AtCoder 体验补全设计

日期：2026-11-16。状态：负责人已逐项确认本文的主要体验决策，并在成稿后确认进入实施。实施依据见[实施计划](../plans/2026-11-16-atcoder-experience.md)，本文不是实现完成、性能改善或真实网站验收记录。

## 1. 目的与依据

在已有 AtCoder 快捷键提交能力上补全日常刷题体验。题面、提交区、评测页和反馈方式尽量复用洛谷前端，允许题目内容、语言目录、验证方式与结果更新机制保留站点差异。

依据为负责人本轮 brainstorming 的逐项确认、[产品方向](../../../VISION.md)、[共同流程设计](../../oj-connect/shared-workflow-design.md)和[技术架构](../../oj-connect/architecture.md)。此前已知问题与源码差异见[讨论准备](../../oj-connect/atcoder-experience-preparation-2026-11-16.md)。洛谷源码参考固定 vscode-luogu v4.20.0 / `987ca974b5419230a07b59a195ec44026e16f6f4`。

当前分支为 `OJ_connect`，HEAD 为 `df2807f3`；工作区包含既有未提交的渲染优化与已知问题修复。本设计不整理、覆盖或提交这些变更。此前 stage 成功与旧 AtCoder 真实提交记录不验证本设计的未来修改。

## 2. 当前实现与本轮差距

| 环节 | 当前源码 | 本轮目标 |
| --- | --- | --- |
| 共同界面 | 已复用洛谷题面、提交区和记录页；内容采用共享渲染能力 | 继续在同一套组件内补齐 AtCoder 数据与行为，不复制第二套界面 |

| 提交表单 | `browserOjConnectFeature.ts` 的页面取得逻辑可能复用用户已打开页面；共同流程包含替换草稿确认 | 为本次提交独立准备表单，保留原网页及其草稿，共用真实登录 |
| 提交反馈 | 状态栏提交项绑定停止命令；内部已有清理与受理不明核对 | 按发送边界区分放弃准备与线上提交；发送后不提供取消提交入口 |

| 结果跟踪 | `recordController.ts` 默认每次读取后等两秒，整轮两分钟超时 | AtCoder 正常评测持续更新，直到终态或关闭页面；查询失败明确提示重试 |
| 结果细节 | 已有状态、分数、耗时、内存、源码与测试点；CE 编译诊断尚未映射 | 保留原站状态标识与实际数据，补齐可取得的编译诊断和中文说明 |

以上是设计编写时的源码快照。原站 DOM、登录后可读字段和验证流程必须以实施时实测为准，不能由目标设计反推已经可用。

## 3. 确认的使用过程

1. 用户在内置浏览器找题并 Import；源码放入当前工作区配置的 AtCoder 子目录，同时打开源码和共同题面。重复导入保护已有文件及未保存内容。
2. 用户也可聚焦已有源码按 Ctrl+Alt+P，沿用站点目录和文件名猜题，不能可靠识别时输入题号或链接。不新增持久题目绑定库。
3. 题面首次默认英文；用户可切换可用语言。样例通过题面按钮显式传送至 CPH，切换正文语言不重建源码、不重导样例。
4. 用户调试后按 Ctrl+Alt+S，以按键时的编辑器内容建立源码快照，包括未保存修改。之后在编辑器继续修改不改变本次待提交快照。
5. 首次提交选择原站实际可用的具体语言与编译器版本。有效偏好存在时直接使用；题面提交区与快捷键共用该偏好。
6. 本次提交在独立准备的表单中执行。正常路径留在编辑器；需要登录或人工验证时展示本次使用的网页，完成后自动继续，无需再手动点击 Submit。
7. 发送时显示“正在提交”。取得经核对的正式 ID 后进入共同结果页，不等待最终判定才打开，也不等待官网记录页完全呈现才交付回执。
8. 结果页持续显示等待、评测中和最终结果。正常跟踪不因固定两分钟而结束；用户关闭结果页只停止本地跟踪，线上评测继续。

## 4. 语言选择与本机偏好

### 题面语言

AtCoder 无已存偏好时优先英文；英文不存在则使用实际可用正文。用户主动切换后记忆其选择，跨题、跨窗口重建及重启后继续使用。

某题缺少偏好语言时仅对本题回退，不将回退值写成新的用户偏好。切换正文不改变题目标识、关联源码或 CPH 样例；原始样例继续由站点解析与 CPH 所有者提供。

### 提交语言

按站点和源码语言族 C/C++ 保存具体选项 ID。首次未明确选择时，题面可以显示“选择提交语言”，不能因打开题面或自动展示首项就跳过首次提交选择。

题面主动选择和首次提交选择均更新同一偏好；后续提交仍对照本次真实可用目录检查。选项消失时重新询问，不自行切换另一编译器版本，不把旧偏好伪装为当前有效选项。用户退出选择则结束发送前准备。

两项偏好使用扩展现有本机持久化能力保存，不建立新配置框架、账号存储或同步服务。语言目录本身仍以原站当前表单为准，不将偏好存储扩展为跨账号表单缓存。洛谷既有默认策略不因 AtCoder 首次选择规则而改变。

## 5. 独立提交表单与浏览器边界

独立表单属于本窗口的本次提交任务，使用与普通持久内置浏览器相同的站点会话。独立页面不等于独立账号、隐私会话或第二份 Cookie 存储。

快捷键提交不复用用户手动打开的网页表单，不改写其代码，不因此要求替换网页草稿。任务自己的页面可以承载源码和原站验证；只有真实需要用户操作时才显现。普通网络或解析失败在插件内反馈，不以任意异常推断需要登录或展示官网。

完成验证后继续同一题目、源码快照和语言的提交，取得正式 ID 后展示共同结果页。只释放本任务拥有的页面、监听和引用，保留用户原有浏览器标签及草稿。结果读取不得借机导航或覆盖用户原提交页。

实施先核实独立页面共用会话、验证交互和表单初始化的实际行为。若原站证据表明该路径无法保护原草稿或必须增加新的认证形式，应带证据回到边界讨论，不堆叠认证实现或备用发送链路。

## 6. 发送、放弃与不确定回执

| 阶段 | 用户行为与含义 |
| --- | --- |
| 发送前的题目、语言选择或人工交互 | 用户可以放弃；确认尚未发送时结束本次准备并清理任务 |
| 已进入实际发送或受理核对 | 不显示“取消提交”按钮，不承诺可以撤回；窗口关闭或页面销毁仍执行内部生命周期清理 |
| 已有正式 ID | ID 与题目保留；结果加载或展示失败不撤销回执，不重发源码 |
| 可能发送但无法确认受理 | 明确显示受理不明并提供查询确认，不能描述为“已取消”或自动再次提交 |
| 记录评测中 | 关闭结果页只停止本地查询，重新打开同一记录后按实际状态继续 |

洛谷参考流程为“正在提交”提示、取得 rid 后读取初始记录并打开详情、后续推送更新。上游没有发送后的撤回评测功能。AtCoder 沿用这套用户语义，不复制洛谷的图片验证码或传输协议。

内部 AbortSignal、资源释放与停用处理仍需保留；移除有误导性的用户按钮不等于移除防止晚发、迟到结果恢复和资源泄漏的保护。

同一发送通道忙时及时告知，不增加提交等待队列。取得正式回执后释放发送占用，已经受理的评测跟踪不阻塞下一次显式提交。

## 7. 共同结果页与站点差异

尽量复用洛谷页面的布局、元信息、卡片、颜色表达、蓝色转圈、编译输出和复制控件；代码显示沿用负责人已认可的效果，正文和代码继续使用现有共享渲染能力，不另建 AtCoder 渲染器。

主状态保留原站 AC、WA、TLE、CE 等标识，配合共同视觉样式；悬浮显示中文解释。无法识别的状态保留原文，不猜成已通过或最终失败。

分数、时间、内存、源码、测试点及真实分组按实际可读字段展示。缺失项不占位，不把原站测试集汇总伪造成测试点，不补造洛谷式分组、满分或百分比。题面缺少难度和标签时继续按既有规则隐藏，不引入第三方难度数据。

CE 补齐原站可提供的编译诊断，使用共同编译输出组件和复制能力。诊断在实施前核对真实登录后页面与可读权限，不预先猜 DOM 或错误内容；不可读时明确说明，其他已有结果仍显示。

## 8. 跟踪生命周期与失败反馈

AtCoder 保留查询式更新，复用现有读取、串行查询和取消清理，不引入洛谷 WebSocket 订阅或通用更新框架。正常读取完成后沿用现有两秒查询间隔，不并发累积同一记录的查询。

结果页仍打开且未获得终态时持续更新；切到其他编辑页不等于关闭结果页。移除 AtCoder 的固定两分钟整轮跟踪截止，不取消单次网络请求与页面准备所需的超时保护，也不改变发送阶段的受理不明处理。

等待与评测中的有效跟踪显示蓝色转圈；终态、关闭、扩展停用或查询失败后停止当前跟踪动画。查询失败保留最后一次结果，在页内提示“更新失败”并提供重试；重试只查询原正式 ID，不发送源码，不暗示线上评测已停止。

重新打开或重试时立即查询原记录；已终态只显示结果，未终态恢复更新。关闭／停用后的迟到响应不能恢复查询、映射或面板。洛谷现有推送路径和生命周期保持回归保护。

## 9. 实施所有者与去冗余约束

| 所有者 | 本轮责任 |
| --- | --- |
| `extension.ts`、`workflowController.ts` | 快捷键源码快照、偏好装配、发送提示及防重，正式回执与跟踪分离 |
| `views/problemPanel.ts`、共同 Webview | 题面语言默认与选择、具体提交语言选择、复用既有页面效果 |
| AtCoder adapter、site-scripts 与结果解析 | 解释原站语言、题面、状态与编译诊断，按既有受限操作适配 |
| 浏览器宿主与 `atcoderTransaction.ts` | 同会话独立表单、人工交互、实际发送边界、正式记录与源码核对、任务页面释放 |
| `recordController.ts`、`views/recordPanel.ts` | AtCoder 持续查询、失败重试和关闭清理；保护洛谷推送 |
| CPH 与共享内容模块 | 继续负责样例及既有内容呈现，不取得账号或提交职责 |

优先修改已有所有者的小接口。只因两个实际消费者需要才提取共同能力，不新增账号库、持久题目绑定、任务队列、统一网页操作引擎或并排的站点 UI。替换旧路径时检查真实消费者并删除无用链路，保留必要保护，不靠重复校验或多层回退掩盖问题。

## 10. 检查、测量与负责人验收

先以受控回归确认：英文默认与缺失回退、主动偏好跨重启、自动首项不覆盖偏好、过期编译器重选、原网页草稿不变、发送前放弃、发送后不误报取消、受理不明只查询、正式 ID 与源码一致、结果超过两分钟继续更新、失败重试和迟到响应清理。

共同页面检查英文／日文正文、窄宽布局、各类原生状态、空字段、无测试点的等待、真实分组、编译诊断与复制；洛谷题面、图片验证码失败收尾、推送结果与 CPH 另做相关回归，不能为 AtCoder 效果破坏已接受基线。

实施计划按 AGENTS.md 完成命令预检及验证台账，运行拥有者聚焦测试、类型检查、OI 扩展编译和最终 Windows stage 构建。具体测试入口由计划依据当前脚本确定，不在设计稿中预报通过。检查结果、构建与真实网站验收分别记录。

真实验收使用负责人既有授权的 AtCoder ABC086 A 范围，手动登录与人工验证，记录本轮新 ID、实际提交源码和最终判定。CE／WA 优先使用可读的已有记录与受控样本；如必须新增故意失败的线上提交，先取得对应范围，不为测速反复交题。

分别记录按键到准备完成、人工验证等待、实际发送到正式回执、回执到共同结果页、状态取得到页面更新的耗时。区分冷暖路径、站点排队和本地成本，不以合成测试或渲染速度替代真实端到端性能，不预设未经测量的毫秒 SLA。

## 11. 本轮范围与后续

本轮只补全现有 AtCoder 的确认体验及直接相关缺陷。登录仍与普通持久浏览器共享，侧栏继续承担账号管理，普通未知状态不冒充已退出。不随本轮增加账号同步体系或重设计侧栏。

保留目录配置、简单文件名猜题、同源码 CPH、源码与样例保护、固定代码配色和当前洛谷基线。比赛管理、题库、题解、社交、其他站点接入、新认证形式和第三方难度服务不在范围内。

负责人已整体审阅并要求进入实施，具体任务与验证见实施计划。设计、实施计划和检查不隐含 Git 提交、推送、清理历史数据、Setup 或发行授权。
