# Beacon 总体架构

更新：2026-11-26。本文定义模块职责和数据流；字段见[工具合同](tool-contract.md)，存储与执行边界见[底层设计](foundation-design.md)，实际交付见[实现状态](implementation-status.md)。

## 1. 产品与分工

Beacon跟随学生当前学习活动，取得必要代码、题意和真实结果，提供算法与编程教学。Notebook保持独立、可选的学习文档和用户运行功能。

业务模块提供事实，harness负责采集、字段整理、权限、历史与预算，LLM决定讨论对象、材料选择和讲解。宿主不固定当前题目，不设置上轮对象、发送绑定或强制取材流水线。

## 2. 数据流与所有者

1. 用户Get Problem／Import to CPH产生五站读题记录；Runner、CPH、Notebook执行结束产生运行记录；OJ Connect完整取得最终结果产生测评记录。
2. 采集所有者在应采集事实进入适配前登记生命周期，Store原子发布到固定合法 `.beaconWork` 的三个近期队列；发布完成或明确失败前，独立collectionPending阻止新聊天请求，不拖延执行清理。
3. LLM按需列目录、按ID或latest读完整模型投影，可按filePath筛选；现场读取取得可见C/C++及BeCoder Notebook完整内容，需要五站题面时调用fetchProblem。
4. 普通文件、页面、主动材料和网页沿各自权限补充。实际返回进入有效对话；下一模型请求前检查预算，必要时同步压缩。

| 所有者 | 职责 |
| --- | --- |
| 编辑器／Notebook内容／页面 | 已加载可见C/C++及BeCoder Notebook内容、获准普通页面、文档身份和dirty；读取前合并同文档视图，目录与正文一致，不打开资源 |
| OJ Connect／浏览器 | 五站身份、核心题面解析、用户看题和测评事实，独立维护登录／提交流程 |
| Runner／CPH／Notebook执行层 | 点击时执行计划、编译、各input进程、取消、输出、状态与清理；不依赖Beacon队列 |
| 采集适配器 | 归并实际执行事实、统一共同字段、保留来源差异、独立字段字符上限及截断身份；不控制执行 |
| Store／Coordinator | 根资格、三个共享队列、并发与原子发布、采集和消费scope校验；同根共享collectionPending，不进入模型／记录或改变scope epoch |
| 业务通知／聊天宿主与Webview | 原动作窗口右下角报告保存失败，同动作至多一次；界面和实际受理前复核所有新请求门禁，保草稿、不排队或自动发送 |
| 工具／Provider | 语义接口、参数校验、真实结果、当前回答内同版读取、模型装配与预算 |
| 产品知识／版本桥 | 七主题随包英文产品事实；固定topic读取；运行宿主IProductService.version提供发行号，不访问用户配置或工作区服务 |
| 会话／协议 | 原消息、工具交换、有效分支、材料、摘要和恢复；重放不重新执行 |
| 系统提示 | 精简英文导师原则：教学深度、按需取材、证据与未知、自然讲解及权限；回答跟随用户语言 |

## 3. 材料身份与生命周期

| 材料 | 归属 |
| --- | --- |
| problem／run／verdict | 当前 `.beaconWork` 跨对话共享，按各自容量和规则淘汰；只保用户业务事实 |
| 当前C/C++／Notebook内容／fetchProblem题面 | 实际工具返回进入普通历史，无独立代码库、笔记快照或题面缓存 |
| 消息／附件／草稿 | 按会话及有效分支隔离；同根不授其他聊天访问权 |
| 摘要 | 有效历史的输入投影；不覆盖原文或修改业务队列 |
| 产品知识 | 随扩展打包的公开事实，不是用户持久材料；按主题整篇读取，返回以普通配对工具事实进入历史，不自动注入所有主题 |
| 学生源码／Notebook | 独立用户资产，不随业务队列淘汰，当前模型工具不写入 |

执行稿和提交稿只作为对应run／verdict的一部分。完整源码的codeHash在截断前按CRLF→LF后SHA256确定；同哈希不证明正确或已验证。readCurrentCode返回调用时全部可见C/C++及BeCoder Notebook，含dirty、未命名和根外文档，不读后台标签，不额外保存。Notebook返回全本编号内容，每个C/C++代码格独立hash，不返回outputs／attempt／executionSummary。发送、继续、重答不捕获代码。

现场读取从已加载Notebook owner取得内容，不走磁盘fallback；同文档多视图在读取前按canonical URI／模型身份合并并汇总visible／active。不同文件同正文、多个未命名文档、同笔记相同代码格分别保留；目录和正文使用同一身份整理。跨轮调用仍是新观察，普通历史不作全局文本去重。

三个记录工具空参按需列目录，带ID或latest读完整固定投影，可按filePath筛选；旧超大run正文明确拒读；目录不自动注入，不提供动态字段投影。latest只是当前队列最新入队，不替模型选择讨论对象。harness保证本回答首次成功读取后的同版一致性。目录不等于读过正文；实际缺失或淘汰如实返回，不改指其他记录。

## 4. 题目与执行事实

problem记录“用户何时在何文件上取得哪道题”，不保存题面或形成永久绑定。fetchProblem按规范oj＋problemId调用五站核心解析，无Get／Import／面板副作用，不更新用户查看时间，与聊天搜索开关互不影响。

run不嵌入题目身份、候选或原始CPH配置。LLM结合实际代码、路径、读题记录和用户问题判断关系，不把同路径当作同稿。模型run投影只保本次standard／optimization，不回传编译命令、路径和耗时；开始时间到秒，运行时间到整数毫秒。CPH只保实际check结果，不保存检查器实现与诊断；学生程序退出和check是独立事实。

run目录从真实compile.status、runs[].status／check分别生成编译、已执行／未执行输入及检查结果摘要；准备的输入数不冒充已运行次数。Runner／Notebook不自动判题，CPH检查完成时才有check；缺check不表示通过或产品不支持检查。

非五站CPH题可读取对应 `.cph/*.prob` 元数据，在搜索开启时用browseWeb获取来源。verdict源码核验由产品负责：mismatch页内与右下角提示、拒收入队且不替换旧项；其余核验状态正常承接终态。模型不接收sourceVerification，逐点行按站点映成具名对象。五站完整闭环承诺不自动扩展到其他题源。普通概念求助不以题号、工作区或Notebook为准入条件。

## 5. 模式、权限与独立执行

正常所选根控制软件采集；无根／异常不采集、不写替代位置、不补采。有效根Blackout持续采集，模型持久目录和读取关闭。各模式及无根仍可按页面权限读可见C/C++与Notebook内容、调用fetchProblem；browseWeb由聊天搜索开关控制。Spot／Flood不扩大采集根或赋予现场文档backing file读权。

runtimeBusy与collectionPending独立：前者覆盖执行及必要清理，后者覆盖应采集事实适配、校验和发布，同根窗口共享、无关根不互锁，有效根三模式同规则。保存提示为“正在保存用户行为上下文”，失败通知后结束等待并保留草稿；不重跑、自动重试采集或自动发送。所有发送／继续／重答／编辑旧问题入口在实际受理前核验原生状态；远程OJ尚无终态时不新增等待。

运行／测评事实只经持久记录自动供给，不能通过终端渲染、功能页或Notebook输出绕过。主动提供材料保其用户材料身份；页面、摘要、工具结果和登录状态不能产生许可。

Notebook代码和input坐标统一为全体cells从1开始，正文同口径编号；本次操作固定代码和input，同一代码块编译一次、各input独立运行；失败继续、主动停止结束批次，关闭仍取消。删除或调序只影响展示，不重写已捕获计划。执行和清理由原模块负责，采集失败不影响核心编程流程。

模型不写学生源码，不执行Shell、不自主运行、停止、登录或交题。未来资产写入另作设计，Notebook独立功能不受影响。

readBeCoderInfo在三模式和无根可用，只返回version／topic／content。版本来自实际运行宿主，不用扩展兼容号、扩展自身版本、源码package或联网最新版本。工具说明介绍如何使用产品，不代表模型获得操作能力。当前个人配置沿Flood既有只读权限，产品知识不增加配置查询接口。

## 6. 协议、预算与验收

完成工具交换保真实名字、参数和配对；恢复不重复执行。有效分支约束消息、材料和许可，弃分支不因残留文件恢复；换模型按提供方／baseURL／model兼容性过滤私有字段。

readMaterial及专用页面正文／目录／采集回读链已退出；readPage只传id，宿主取得当前版本并校验单次读取，结果沿普通历史。旧私有副本不消费、不升级迁移，附件和摘要独立保留。

system承载导师原则和本回答开始时的宿主事实：时间、真实模式、所选Beacon根及采集资格、过滤后的页面元数据。采集资格不授模型读权；无可靠scope时省略未知字段。contextToolContract.ts与Provider维护英文工具用途和普通参数；toolResultNotes按实际来源／字段生成相关外层短释义，toolModelOutput统一新模型投影。当前工作树提示版本2026-11-26.4，版本保内部身份，不进入system正文；七主题产品知识原文保持。各入口职责见[接入记录](review/2026-11-26-prompt-information-flow-installed.md)，不强制调用顺序或先读概览。

新工具的即时结果、完成事实、封口协议及下一请求共用投影；SDK参数拒绝和执行异常也返回安全error:{code,message}，不把原始异常送给模型。UI沿原code，原FileOutput.error仍为字符串；旧协议按原内容回放，不补生成notes或重写错误。同ID的历史交换不被新step正规化覆盖。停止与结果完成竞争时保实际完成事实，取消中断不造完成失败。

压缩子请求仅声明真实固定kind＋ID的记录工具，必需id枚举与执行／计量同源；无fixed或无hook时无工具。摘要不开放readBeCoderInfo，已读取知识按历史整理。用户附件归原消息，每份工具图片媒体前保原toolCallId／toolName，媒体包装不成为新用户请求或当前文件观察。

[同步压缩](context-compaction.md)使用当前选定模型，90%触发、约60%目标，完整工具批次闭合后切换，每个普通待发步骤至多一次恢复。完整代码／记录不因剩余额度再次裁剪；压缩后仍装不下则容量失败，不删除记录或重演工具。

源码检查、有限模型观察、stage构建和负责人真实流程验收分别记录。后续能力与已知缺口从[PRD](prd.md)和[实现状态](implementation-status.md)读取，历史计划不作为现行开发指令。
