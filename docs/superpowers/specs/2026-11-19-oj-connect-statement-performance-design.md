## 1. 目标和授权边界

降低 AtCoder、Codeforces 首次从源码编辑器看题到真实正文可读的等待，优先处理负责人报告的十几秒体验。读取正确性、四站已闭环能力和用户资产保护优先于耗时数字。

本轮获认可的方向包含：少量脱敏本地分段测量；按真实耗时决定优化位置；有证据时允许调整题面只读获取。提交、登录、认证、正式回执核对和评测查询继续使用当前实现，不通过降低这些保护改善看题指标。

本稿将性能工作分为诊断和实现两步：先以现有路径建立可解释的真实基线，再根据测量结果确定最小实现。书面设计通过后才制定实施计划；计划也需审核。诊断所得若要求扩大接口、引入依赖或改变已确认交互，先修订相关设计，不以本稿提前授权这些改动。

## 2. 当前基线和已知事实

源码基线为 OJ_connect / 4e8864641e73d6c955fae2be6b7db4fff8096b5c，加当前尚未提交的第一、二阶段修改。它们已完成各自源码和局部渲染检查，尚未生成包含这两阶段的新 stage。当前 stage 不能用于证明本工作区的性能或回归结果。

| 环节 | 当前源码事实 | 能得出的结论 |
| --- | --- | --- |
| 看题入口 | 扩展先 await adapter.readProblem，再显示源码和共同题面 | 网络与提取未结束前，没有题面正文可呈现 |
| AtCoder 取文 | 浏览器题页导航就绪后，site-scripts/atcoder.ts 又对同一题目 URL 做 no-store GET，并解析原始 HTML | 存在确定的串行二次取文；当前没有两次请求各自的真实耗时占比 |
| CF 取文 | 先用 CPH 解析当前 DOM，再执行 OJ recipe 整理同一题面的正文 | 有两段解析，没有已证实的同类二次网站 GET；不能据此假设 CF 与 AtCoder 同因 |
| 页面就绪 | 新建且仍隐藏的任务页可在 DOM-ready 后停止剩余资源；用户已有／可见网页正常加载 | 已有的快速路径受所有权与可见性限制，不能无条件扩大 stop() 范围 |
| 编译器 | 目录在题面创建后后台读取，未登录使用已采证目录预选 | 已不处于当前正文首屏的串行依赖中 |
| 渲染 | 每个正文 section 经共享清洗／公式转换后挂载，语法高亮在文本出现后补充 | Webview ready、正文可读和完整高亮是不同终点 |

现有 document-ready 与 statement-read 日志仅覆盖部分主进程阶段，缺少同一请求关联、前后交接和正文呈现，不能相加后命名为端到端首屏。旧 delayed-image 合成用例只证明特定资源停止行为；编译器目录探针、独立网页渲染和早期提交计时也不能充当真实快捷键看题数据。

## 3. 指标和有限诊断设计

### 3.1 主指标

自动采集的主指标称为“看题命令 handler 到首段正文确认”，起点是当前看题命令处理开始，终点是当前选中题面语言的首个非空正文 section 挂载后，在该 Webview 的一次 requestAnimationFrame 回报到达同一命令发起端。

终点只在对应面板和当前文档仍有效时记录；旧 section、已关闭页面、已被替换文档及非当前语言的迟到回报不得结束新请求计时。回报不携带题面内容。

requestAnimationFrame 是近似绘制边界，不能证明像素已实际上屏。真实产品画面需确认正文可读；若没有画面确认，报告只使用上述准确名称。该指标不包含 handler 之前的物理按键派发或扩展首次激活，另参考已有激活性能记录或短屏录说明其影响，不为此改动全局快捷键系统。

整体正文完成、图片和完整语法高亮作为补充指标，不能代替首段正文指标。加载框、占位题面和旧缓存正文不计为新题正文可读。

### 3.2 五个分段

| 分段 | 所有者与范围 | 诊断目的 |
| --- | --- | --- |
| 页面准备与就绪 | 扩展到 workbench／browserView：题目识别、存储范围、模型创建或复用、题页导航、可读检查 | 判断主要等待是否发生在网站文档取得或本地页面准备；保留 created/reused、hidden/visible 分支 |
| 取文与解析 | browserView 固定读取：AtCoder 二次 GET 响应头、body 与原始文档解析；CF CPH 和 OJ recipe 分开记录 | 区分额外网络、页面脚本执行与本地解析；finally 清理单列，不能从总量漏掉 |
| 面板交付 | 扩展收到文档后，显示源码、创建或更新 panel，到本次文档接收确认；新建 Webview 另记 bootstrap ready，已有 Webview 不等待第二次 ready | 检查 editor 交付、bundle 冷加载和消息启动成本，不能借用上一请求的 ready |
| 正文转换 | 当前首个正文的 renderContent 请求、renderer 首次加载／缓存命中、共享清洗／公式转换到回包 | 区分宿主同步内容转换与 Webview 等待 |
| 正文装入 | 当前正文回包到 DOM 挂载、rAF 以及发起端收到确认 | 定义可观察的结束边界，防止将通信 ready 当正文首屏 |

各进程使用本地单调时钟记录 span；总耗时由同一个发起端的起止时钟计算。不同进程的 performance.now() 不直接相减；嵌套、重叠的 span 也不相加冒充总量。跨进程交接的剩余耗时归为未分解部分，保留原始数据而不强行凑齐五段。

本次文档接收确认必须绑定本次 flow 和文档版本。新建 Webview 可能先通过初始状态取得文档，复用 Webview 则通过状态更新取得文档；两条路径分别确认接收，不能因某面板曾经 ready 就将本次交付算为完成。诊断回报仍遵循下一节的受限消息与迟到回包规则。

### 3.3 诊断数据与生命周期

为每次明确的看题命令分配临时 flow ID。新增诊断只允许记录 site、flow ID、固定阶段、有限分支、单调 duration 和白名单错误类别；不记录 URL、题号、源码路径、账号、Cookie、CSRF、HTML、正文或源码，也不将任意异常正文序列化进日志。这项约束限新增诊断，不声称现有全产品日志都具有同一字段策略。

flow ID 只关联计时，不能成为读取权限、原生 view ID 或任意命令句柄。Webview 回报必须与当前面板、文档版本和宿主已知请求绑定，受限字段／大小校验；不能新增通用写日志接口或把站点内容当阶段名。

诊断仅在本地诊断候选中启用，不新增用户设置、常驻遥测或后台轮询。诊断结束后移除不再需要的临时代码与专用消息，最终优化候选再按实际源码重跑验证；本地审计日志保留用于说明结论，不随应用分发。具体最少插入点与清理清单由实施计划列明。

请求失败、取消、窗口关闭、扩展停止或文档替换时终结对应测量，不自动重试、不恢复旧请求，不改变现有业务取消与释放。失败样本记录其停止阶段；失败或尚无正文不能记为零毫秒成功。

## 4. 真实样本与对照

第一轮沿用负责人此前报告的场景：未登录、已有 C/C++ 源码、快捷键看公开题。两站分别采三组，每组 3—5 次：

1. 本进程首次新题：每次独立应用进程首次触发看题；扩展激活是否已完成另标注。
2. 同进程后续新题：观察站点与本地模块已加载后，另一题目的首次读取。
3. 同题再次看题：沿用当前重新读取语义，区分已有 panel、隐藏 reader 与用户可见网页分支。

在隔离产品实例和任务测试工作区中运行，使用同机同网、相同题目集和相近时段作优化前后对照。只取公开题面，不使用或导出日常账号数据，不自动登录、交题、导入用户样例或改写用户源码。若出现验证阻挡，记录为失败／受限样本，不能悄悄切传输再算成功；人工验证是否另测由负责人决定。

不清除依赖、Electron 下载缓存、用户浏览器数据或机器网络缓存。首次进程不等于网络冷缓存；报告须按实际场景命名。保留各次成功时长、范围、中位数、最慢样本和失败类别，小样本不报告 p95 或长期可靠率。

一、二阶段代码必须包含在诊断候选中，避免用旧 stage 测量新工作区。启动实例、诊断构建及只读采样的精确流程在实施计划中确定并经审核后执行。

## 5. 根据测量选择优化

### 5.1 AtCoder

若页面导航和二次 GET 是主要成本，优先设计“一份原始题目文档完成读取”，保留同一持久 Session 和固定官方题目路由。不直接用经过网站脚本／MathJax 改写的 DOM 代替原始正文，不根据公开题目编号假设免验证，也不把登录凭据复制到扩展。

单文档路线必须复用当前已验证的原始结构提取语义，核对双语、公式、样例空白、对应说明、限制、标题、题目标识、响应大小、重定向／验证、取消和资源释放。测量与可行性证据足够后，先将具体取文接口及单一路径写入设计修订，获审阅后再进入对应实施计划；不能在两个生产取文策略之间静默试错。

### 5.2 Codeforces

独立按本站测量决定。若网站导航／就绪占主因，研究降低只读题面取得的页面依赖；若 CPH／recipe 解析占主因，再减少同一材料的重复处理。保留原始公式、真实样例、题目上下文和固定源校验。

CF 没有证实的同题二次 GET，本稿不将 AtCoder 的改法直接推广到 CF，也不将其提交 Session client 变成新的通用网络层。现有 CPH 的其他题源、Import to CPH 和浏览器用户网页行为不因本轮优化改动。

### 5.3 本地阶段

只有在面板、renderer 首次加载或 100ms 轮询的实测占比值得处理时，才考虑与本次已发起的 I/O 并行加载，或用已有页面事件替代轮询。并行只由当前用户看题动作触发，不能变成应用启动／账号／提交页预热。

事件改造必须先注册再检查状态，保留关闭、导航、所属窗口、存储范围和有界失败，防止漏事件或旧事件唤醒新任务。新增抽象应只服务实际已确认的调用点。

本轮不引入题面持久缓存、已有面板绕过重读、页面池、跨请求队列或后台预热；它们不解决尚未定位的真实首次新题问题，也会改变当前已确认语义。

## 6. 保护范围和必要验证

- 四站题目识别、分站 C/C++ 编译器偏好、未登录预选与提交前官网校验保持；编译器目录继续不阻塞正文。
- SourceBinding、未保存源码、当前题面与 CPH 样例一致性保持；不以新缓存或旧文档提前结束计时。
- 第一阶段的内置导航、fragment、复制和第二阶段的文案／失败恢复保持。
- 同一窗口及存储范围的会话权限、官方路由、响应和大小限制、取消、导航变化与资源所有权继续由已有宿主执行。
- 提交、登录、认证、正式回执核对、单次发送、受理不明只查询和评测更新均不在本轮改造范围。诊断或失败不触发自动提交、重交、登录或外部浏览器打开。

诊断先通过本地可控用例检查阶段顺序、单调耗时、迟到回报隔离、失败不算成功以及新增日志字段约束，再运行有限真实公开题采样。合成网络延迟用例证明因果与保护，不替代真实采样。

优化后要求题面结构和原始样例保持一致，覆盖双语与公式、非法／超大／验证响应、隐藏和可见页、取消与关闭、会话范围变化、同题重读、CPH 和四站已有回归。继续按实际改动预检并冻结拥有者测试、类型检查、渲染、lint、client 与 OI 编译命令；源码修改后的旧证据不能冒充最终结果。

优化成功的判断是相同样本的正文可读时间有可重复改善，且完整题面与边界用例不回退。若无可重复收益，不把补埋点、显示加载框或减少代码行数称为性能改善；先报告阶段占比与限制。固定秒数目标在真实基线取得后确定，不用小样本承诺网络 SLA。
