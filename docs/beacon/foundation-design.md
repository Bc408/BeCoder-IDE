# Beacon 底层阶段设计

修订：2026-11-24。汇总负责人逐项审阅决定，主文见[工具设计0.4](../superpowers/specs/2026-11-23-beacon-tool-interface-simplification-design.md)，所有者见[架构](architecture.md)，源码差距见[实现状态](implementation-status.md)。本轮只明晰文档，未实施、测试API或构建。

## 1. 目的与三个队列

harness将真实看题、运行、线上测评整理成业务事实，LLM选材和教学，不从原始事件重建运行。只有正常所选Beacon根才采集，归当前.beaconWork；无根／异常不采集、不补采、不写替代位置。有效根Blackout也采集，但Beacon持久消费关闭。

| 队列 | 容量 | 单位与更新 |
| --- | --- | --- |
| problem | 13条 | 五站Get／Import行为，按problem（oj＋problemId）与filePath共同去重；相同则旧项删除、新ID及新viewedAt入队尾，不同路径分别占位，无题面正文 |
| run | 30条总额 | 三来源共用；一份程序一次编译及其input运行为一条，结束后入队，不去重 |
| verdict | 20条 | 完整最终结果才入队；同站同题可靠提交代码完全相同替换旧结果入尾，缺代码保存但不去重 |

codesnap全部撤回，实际执行稿／提交稿属原记录，普通工具结果属普通历史；无独立代码库、回读或跨分支例外。旧数据迁移另审，本轮不删磁盘用户记录。

run目录与正文都不嵌入题目身份、标题、URL或题目候选，不透传CPH原始题目配置，关联由LLM判断。CPH仅保check结果，不保存检查器类型、配置、路径、代码、命令或诊断；检查器代码沉淀留后续事项，对拍检查器／随机生成器另作设计。

## 2. 工具与记录读取

readCurrentCode一次返回所有当前可见分屏C/C++页面的整份正文、dirty、文件名和路径，不读后台标签，不需要模型传页面ID，也不额外保存代码。

readProblemRecord／readRunRecord／readVerdictRecord各自注册，空参列全部保留条目简短目录，带ID读完整持久记录。目录按需，无独立列表工具；移除旧producer／revision／part／测试点组合，内部读取一致性仍由harness保障。不存在的ID或被淘汰记录如实失败，不以其他条目替换。

fetchProblem按oj＋problemId复用五站核心解析，与搜索开关互不影响；无Get／Import／面板／登录／交题副作用或专门存储。inspectFile、readPage、readMaterial、browseWeb保留，非五站可CPH元数据＋普通联网兜底，权限和功能页反旁路保持。editNotebook退出模型能力，独立Notebook用户功能保留。

## 3. run的统一与来源差异

每条run为“一份程序／编译信息＋输入结果列表”。Runner一次操作一条；CPH单点和全部各一条，全部包含多测试点；Notebook同一代码块多input一条，运行全部涉及多个代码块则分别形成记录。最新粒度覆盖此前Notebook整次点击一条的中间约定。

CPH“仅编译，不运行”不入队、不占位，无论成功、失败或取消；运行测试触发的编译失败仍记录。该采集裁切不改变CPH原生仅编译功能。

| 来源 | 专有信息 |
| --- | --- |
| Runner | Run／Run With Input、实际送入程序的输入和实际返回、停止／退出；不记录输入编辑按键 |
| CPH | 原测试点序号、逐组输入／期望／实际及check结果；不保存检查器代码、配置或诊断，本地过不冒充OJ AC |
| Notebook | 笔记路径、执行时代码块序号、对应input，序号只数C/C++块且从1开始 |

共同保实际源码、编译器／参数／诊断／时间、各input状态／耗时及真实采集范围，不用当前稿替换执行稿。不保存本地运行限制配置，真实超时／输出超限等结束状态照常记录；执行器已有运行限制继续生效。harness归并事件、解码、整理流、脱敏和组装正文，模型不承担内部处理。

run在对应程序全部input结束或尝试失败／取消后入队，不在持久队列维护活动项。编译失败保一条，关联input标未执行；未开始编译的后续程序不补造记录。写入失败保原队列，采集不影响核心执行。

## 4. Notebook执行优化与解耦

执行层在点击运行全部时确定本次代码、input和关系，后续编辑下次生效。同一代码块本次编译一次，各input独立进程、计时、限时和输出限制。复用只限本次操作，无新增跨次编译缓存。

编译失败跳过本块input继续其他块；input运行错误、超时或输出超限继续后续；用户停止结束整个批次。执行顺序、input原生结果和既有运行限制保留，共享编译时间展示需真实表达。

执行层不持有Beacon工作区／队列／持久化类型；它交付通用执行事实，采集适配层消费并按程序组装run，存储层负责根和模式。采集失败不改变执行、取消或清理结果。沿小型结果／回调接点即可，不搭通用事件框架。

## 5. 输出与上下文

每条run的编译输出与所有input实际程序输出合计8KiB＝8192 UTF-8正文字节，超限保头尾及省略量；保各input身份／状态，不截坏结构。源码、输入、期望与元数据不算此输出额度，整条记录可能大于8KiB。原执行器运行时限、OLE等不变。

按ID读完整已保存记录，不增加记录分页或按模型剩余额度二次裁剪。加入工具结果超上下文时由既定同模型同步压缩处理，完整交换闭合后在下一请求准备处进行；压缩仍装不下则有界失败，不丢内容或重执行工具。90%／60%及一步一次恢复保持，压缩不修改磁盘记录。

8KiB只限run输出，不推广为verdict／题面／代码的保存或读取上限。实际来源先已遗漏的部分仍如实标注。

## 6. 权限、历史与实施边界

所有工具保根、模式、敏感过滤、真实来源和有效分支。Blackout无持久目录／正文，无镜像；当前可见代码和fetchProblem可用，browseWeb依搜索开关。运行／测评不从功能页面或Notebook输出绕读。

完成工具交换保真实身份，重放不执行；换模型按兼容性过滤私有字段。共享记录一致性由harness内部处理，模型不选revision，也不从旧许可恢复撤销能力。

工具语义、业务规则与run字段方案已允许收敛。[新实施计划](../superpowers/plans/2026-11-24-beacon-context-tools-rebuild.md)已承接九工具接口、已定五站题号接线、8KiB保留表示、Notebook执行接点与时间展示，以及旧数据／历史策略；计划与执行方式已获负责人确认；当前候选及验证见实现状态。旧计划不续用，源码／模型／构建／五站体验分别验收。
